# 图片优化

仅在用户明确请求图片优化时使用；包体过大、发布准备或构建失败本身不触发优化。默认保留源图的格式、尺寸、方向和文件名；本次需求明确允许且有验证方式时，才改变格式、尺寸、裁切或图集布局。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。以下共用步骤不能跳过所选原生适配规定的操作顺序、资源格式与平台边界；必要的用户确认按协议执行。

## 输入

- 源图及许可；实际显示尺寸、缩放倍率与DPR；目标设备、Alpha/动画要求；源文件格式、尺寸、方向、文件名及加载路径；用户明确允许的变更范围。

## 共用操作步骤

1. 盘点源图真实解码尺寸、色彩模式、Alpha、方向、文件名、有效边界、帧数和用途，并在正式背景及真实显示尺寸上建立质量基线；默认属性作为需保留的约束。
2. 评估格式和质量参数：区分照片、硬边UI、像素图、透明插画和多帧资源；只有用户本次明确允许转格式时才生成候选，并为有损透明边缘安排预乘/色边检查。
3. 只有本次明确允许且存在可验证的显示/平台依据时，才裁切、缩放改尺寸或重排/拆分图集；未授权时保留原边界、像素尺寸与图集布局。保存源文件，不覆盖原资产。
4. 检查Alpha模式、边缘晕染、色彩空间、mipmap/采样和图集padding；比较相同背景、缩放、压缩后的边缘与细节。
5. 从实际加载路径验证格式解码、方向、像素尺寸和文件名；用户明确允许改变的属性逐项对照目标设备、显示效果和预算，并记录转换参数与工具版本。
6. 保留原图到优化结果的映射、差异数据和回滚方法，对视觉损失需人工审阅的项目单独标出。

## 关键边界

- 包体大、构建失败或发布准备都不构成用户明确的图片优化请求；没有本次变更许可时保持源格式、尺寸、方向、文件名和裁切范围。压缩率下降不等于质量通过。
- 透明图必须在浅色和深色背景上核对边缘；GPU纹理格式、图集和DPR做法由当前Web/引擎适配确认，不将Web工具路径套给Unity或Flutter。

## 交付

- 原图/产物映射、转换参数、尺寸与字节对照、运行加载验证和视觉审查记录。
