# 无图 3D 世界场景控制合同

仅五个游戏技术栈的世界 `SCENE` 可显式使用 `init --design-route world-3d`。未指定时使用二维世界 `world-2d`；纯游戏界面用 `game-ui`，保留原图片流程。PAGE、DISPLAY_LAYER 和 Figma 不可借此跳过原门禁。设计方法仍维护在[关卡与场景方案探索](../../app-domain-toolkit/references/game-design-exploration.md)，本页只说明控制器接线，不新增状态机、审美评分或审批轮。

## 工作项与依据

沿用 V0–V5、F0–F4、实施包、命令结果和 Evidence Manifest。`visual.domainEvidenceRef:{path,sha256}` 指向当前阶段的[三维场景合同](../schemas/world3d-scene.schema.json)；`visual.candidateId` 从 V1 运行验证起必须非空。此路线不使用 `visual.targets`、图片覆盖清单或 `visual.reviews` 的两项 V3 图稿确认。

合同绑定当前项目、技术栈、工作项、场景、候选、阶段及 `scopeIds`，每份源、规格、审查、人工消息和运行材料使用项目内真实非空文件及 SHA-256。以[场景模板](../templates/world3d-scene.json)理解字段，不能把占位路径、摘要或 APPROVED 当成实际证据。范围绑定生产总范围时，`scopeIds` 对应其中的 `targetIds`，最终集成仍须完整覆盖。

| 阶段 | 替代图片硬门的必要事实 | 保留的控制边界 |
| --- | --- | --- |
| V0 | 声明真实 3D 世界及本批范围，记录空间和内容需求 | 不自动生成审批、运行或资产 |
| V1 | 三维空间规格、版本化白模源、当前场景引擎运行记录及适用检查 | 原工程门和本场景实际执行；不能仅靠模块依赖证明白模运行 |
| V2 | 冻结的 V1 功能基线、联合单次审查、整体空间和正式方向的人工确认 | 不要求三张候选图片；人工待定、拒绝、错对象或错候选均阻断 |
| V3 | 有稳定模型身份、单位、尺寸、原点和接口的模型规格 | 不要求拆图／布局图确认，重新核对上游空间、方向及单次审查链 |
| V4 | 正式模型来源与输出、导入和消费者记录、代表模块试接、资源人工验收 | 原工程／导入证据类别；Unity 等原生约定的正式宿主装配仍在 V5 |
| V5 | 正式场景源、实际运行及当前模型消费绑定、用户显示验收 | `modelBindings` 与本工作项冻结模型规格一一对应；场景中其他未纳入本批的模型不重复登记。原工程／视觉证据类别及最终完整组合，不以白模或样本替代 |

二维与三维世界共用设计前置时机：V1 功能完成后、推进 V2 前，核对已有单次联合审查及整体空间人工确认；此时不提前要求 V2 正式方向。3D 的 V1 封套可携带 `reviewRef` 和 `spaceApprovalRef`，推进前必须实际有效；V2 再确认方向。二维使用平面／占位合同，UI 不套用世界空间工件。

<a id="persistent-hud"></a>

## 同场景常驻 HUD

3D 世界包含常驻 HUD 时，在同一 `SCENE` 的 `visual.hud` 声明非空 `scopeIds`，并在 V2 起绑定 `globalVisualBaselineRef`、原图片路线的 `targets` 和 `coverageRef`；V5 另绑定同范围 `integrationEvidenceRef`。目标使用真实宿主的 `workItemId`、`objectId/sceneId`、候选、状态及视口，不另建场景或把 HUD 改称瞬态层。HUD 的图片基线、V2 目标、V3 拆解／布局、V4 资源与 V5 实际组合继续走[场景多目标记录](multi-target-visual.md)及对应原生 UI 合同；画面由用户人工检查。世界单方向不是三候选图片基线，已有适用基线和同一次真实用户消息可直接引用，不新设审批。

V1 功能基线冻结是否存在 HUD 和声明范围；新增、移除或变更范围须回 V1 核实，控制器不能从引擎自动发现漏报的 HUD。图片目标可在 V2 建立，无 HUD 时不需要图片。HUD 的 V4 资源、目标和确认与世界模型一起写入现有 V4 归档；V5 不得重绑未验收的 HUD 资产。世界空间范围与 HUD 视图身份各自保留，不能用 HUD 目标代替世界 `scopeIds`。

仅 HUD 返工使用 `hud:V2` 至 `hud:V5` 指明最早受影响阶段，复用未变化的世界空间审查、方向和已归档模型；场景须重新提供与回退阶段一致的领域封套。旧模型试接只能引用已验证的 V4 归档，模型规格或试接变化回相应世界阶段；HUD 变化后的最终场景组合、运行和显示确认仍在现有 V5 完成，不自动确认或重复审查空间方案。

## 方向、人工确认和单次审查

全局方向使用[无图基线模板](../templates/world3d-visual-baseline.json)：`designRoute:world-3d`、`directionRef` 和 `selectionReviewRef` 冻结实际方向规格与真实用户消息，不要求虚构图片候选或把规格讨论记成美术成品通过。场景方向必须引用相同方向文件；2D／UI 不得引用此基线绕过原图片候选合同。

单次联合审查记录已有审查结果、依据、问题及处理；阻断问题未解决不能放行；版本变化或修改稿不自动重开完整审美评议，但失败项与实际变化的行为／结构必须定向复验，沿用现有验证证据，不另增审查轮次或批准。空间、方向及最终显示确认各自指向实际对象、当前候选及冻结依据。已有同一次用户决定明确覆盖相关内容时，可复用其真实消息引用，不因此增加人工询问次数；控制器只核对记录，不能证明或伪造用户身份。

V1 空间规格、白模及运行的三个引用与证据根由控制器生成的功能基线冻结；功能返修保留它们，空间或白模发生变化须回 V1 重验。V4→V5 推进时复用现有阶段归档，自动绑定 `visual.modelBaselineRef`，固定模型评审、领域合同和试接证据根；V5 重新核对这些历史材料，资源或试接变化须回 V4。该归档只保存已验证来源，不新增人工审批。当前运行、导入和原始输出均须属于相应阶段，不能把合同、规格或审批 JSON 当作原始引擎日志。

V1、V4、V5 通过时，控制器在现有执行状态与证据目录自动冻结必要场景／模型业务文件的版本，以原路径与原 SHA 区分同一路径的不同内容；它们是验收附件，不是新的可编辑或可运行场景。后续阶段的已验证上游和历史前批按相应冻结版本复核，控制记录、审批、原始输出仍严格核对。当前 V5 的正式场景和实际消费模型继续核对当前文件，不能靠历史快照沿用旧通过；历史版本缺失或受损时保留失败，不能改写旧摘要补造。此前未生成必要快照的旧工作项须按既有阶段重验，不自动回填旧验收；同一次校验内复用已核验快照清单，跨命令仍重新检查。

<a id="model-sample-reuse"></a>

## 已有模型与试接复用

仅调整空间、沿用完全相同模型时，继续使用当前 `sampleRef` 和资源评审；在当前样本记录填写当前项目／工作项／场景／候选身份、`phase:sample`、`sourceWorkItemRef:{path,sha256}` 和非空 `reuseReason`，指向同项目、同栈、同场景另一份已完成 V5 的三维来源。控制器严格检查来源历史材料，并比较单位、模型清单、尺寸、接口及已确认方向；当前资源评审的模型条目须与来源已验收条目一致，正式源／输出字节也仍须有效。符合条件时复用旧试接，不要求重跑相同样本、重新导入未变模型或新增人工批准；模型或依据变化时按原流程取得当前试接，不以复用声明绕过。

复用仅覆盖模型制作、导入与代表试接事实，不继承另一工作项的空间确认或阶段进度。当前 V1 的空间与功能、当前工程检查、V5 的模型绑定、正式组合及人工显示仍按本次范围完成；当前 `asset-import`／`asset-loading` 等适用证据类别仍须由只读资源身份、已有导入登记或加载复核的真实结果满足，不要求重新导入，也不能空写 PASS。资源人工记录可引用仍覆盖同一模型版本的真实来源决定，不新增批准；当前组合显示仍交用户检查。首次制作或含新增／变化模型的批次继续走原样本路径。只有实际新做样本或批量生产时才声明相应制作单元，不为复用伪造一条新的样本运行命令。

## 模型、替换与恢复

白模及方向经用户确认、V3 模型规格完成后，由工作项执行者按[正式生产交接](../../app-domain-toolkit/references/game-design-exploration.md#production-handoff)组织建模、按需贴图、代表试接、分批导入及正式替换。控制器校验 V4 代表模块和本批全部模型的证据，但不自动派发任务，也不证明样本先于其余模型生产。

`work.assetReviewRef` 沿用现有资源评审，模型声明 `assetType:model`，绑定真实源／输出路径及摘要、来源类型、导入和消费者证据；AI 模型另冻结生成记录。图片贴图仍按图片资源规则，不能把模型改标为图片或 native-component。实际轴向、Bounds、碰撞几何和性能仍须引擎验证，控制器不从文件存在推断几何还原或美术质量。

RETURN 继续使用原状态机，按影响阶段作废领域封套及相关审查、确认和运行观测，保留未受影响的源文件。重新填写外层封套不能重新绑定已作废确认；设计路线变化必须回到 V1，不能继承旧二维功能基线。功能重验撤销旧 V5 运行确认，普通工程复验不自动重开设计审查。

本版 `reuse-visual` 显式拒绝自动继承 world-3d 阶段批准及跨路线确认；已有有效模型、规格和方向可在当前合同明确引用并重新核对当前范围，不要求重新制作。截图和运行画面仍由用户人工检查，机器测试中的合成协议材料不代表真实引擎、真机或视觉验收已完成。
