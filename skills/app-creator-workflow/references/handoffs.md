# 协作与交接

统一流程不强制为小任务创建子代理。复杂任务存在清晰独立范围且当前宿主支持并授权委派时，按职责组织：只读探索、技术研究、限定实现、验证和独立审查。生成或编辑图片按宿主的图像技能与委派规则执行，不把生图任务交给生产代码实现者。

主代理拥有整体方案、公开接口、工作项拆分、所有权、测试等级、集成和最终证据解释权。实施者只修改任务包允许路径；验证者不修改生产代码；独立审查者不接管实现。存在依赖或同文件写入时串行交接，不能以“并行”绕过唯一编辑器写者。

游戏关卡与场景方案按[设计职责与交付](../../app-domain-toolkit/references/game-design-exploration.md#roles)安排关卡设计师和场景设计师：前者负责可玩的空间结构与节奏，后者负责玩家视角中的环境表达与视觉引导。它们是专业职责，由主代理或宿主已有代理承担；可独立委派时沿用下述任务包，不要求新增代理类型或模型配置。结构、视角和共同地标先交接，生图遵循宿主图片委派规则，正式引擎场景仍保持唯一写者。

每次正式委派任务包必须说明：目标、允许修改、已定方案与接口、禁止事项、可观察验收、测试等级/命令、受保护操作批准状态和并行修改提醒。同一工作项返修复用原实施者；新模块或独立审查使用新上下文。

游戏音效任务按[声音设计与制作职责](../../app-audio/references/sfx-production.md#design)安排输入与交付：设计职责提供风格、事件分层、变体和混音意图，制作职责交付实际音频及可再生产输入，玩法／音频实现者交付正式消费者和运行结果。复用宿主已有代理及本节任务包，不要求新增代理类型；用户负责听感确认，文件指标和代码审查不代替试听。共享素材登记和混音配置各保持唯一写者。

非游戏 App 按[App 音频工作流](../../app-domain-toolkit/references/app-audio.md)交接已确认用途、本批方案、代表用例、会话所有权、前后台策略和实际平台条件；无音频需求不派发音频任务。功能实现与必要素材制作分别交接，不要求媒体或录音任务经过游戏音效生产。共享服务、平台配置和资源清单保持唯一写者，各消费者分别回传受影响路径与未验证项。

普通任务只需[三项最小约定](output-files.md#每项任务的最小约定)：目标与结果、涉及写入／输出的路径、完成条件与验证方式；当前代理默认负责，不强制任务文档。上文完整字段用于正式委派任务包，控制器及工具现有必填项继续保留，不能用普通任务精简规则省略。

文件交接提供真实产物、关键符号、结论及验证证据引用；同一工作项返修只补实际变化、复验结果和待决事项，不重复任务包、文件全文或已知身份。接收者按实际依赖核对完整性，不接受只有预期文件名或工具成功摘要的交接，也不另建强制输出表。

清理按[任务拆解](../../app-artifact-cleanup/references/project-cleanup.md#清理任务拆解与安排时机)交接目标、范围与验证结果；涉及移动／删除时补充精确动作、引用及恢复依据，存在协作时明确写者和相关依赖。已有证据可复用，不能凭“已整理”摘要删除依赖或将未验证标为完成。

涉及技术选型的任务包引用已有计划中的[选型依据](professional-conventions.md#solution-selection)，明确复用的官方/社区能力、版本、集成边界及允许自研的缺口。实施者不得自行绕过已定方案重写通用能力；发现能力不符时，向主代理提供证据，由主代理更新方案与受影响范围。

未验证项和待决事项有则说明，无则不创建空栏目；命令和结果引用真实输出，不重复粘贴日志。不得用摘要 PASS 代替原始证据。所有状态归入同一 Work Item，禁止各角色各自维护流程总控。

按[当前项目知识](professional-conventions.md#current-project-knowledge)引用现行入口、所有权和相关限制，并区分历史冻结证据与当前结论，使没有原会话的新代理能定位、验证并继续。任务包只携带必要事实与引用，不复制说明全文。

可见内容交接复用现有布局规格、资源和证据：传递有效目标版本及参考条件、受影响元素的身份与布局依据、适用素材边界/密度/尺寸和字体文案、固定约束及已声明适配规则，并区分确认目标、测量值和估计值。实施者回传正式可编辑源及保存回读结果、运行值来源、差异与处理、受影响的复验和待用户检查的组合画面。具体记录按[还原依据](../../app-ui-layout/references/relative-layout.md#还原依据与变更边界)和[三类验收结论](verification.md#三类验收结论)执行；无需另建交接文档或补齐无关项目。

加载显示按[任务拆解与交接](../../app-domain-toolkit/references/reference-domain-display-ownership.md#加载显示任务拆解与交接)覆盖服务、设计、素材、接入及验证，交付相关结果与路径；有跨宿主复用、共享文件或前置任务时明确消费入口、唯一写者及依赖。缺项补回原计划，不用服务 PASS 代替画面交付或人工确认，也不强制创建子代理。
