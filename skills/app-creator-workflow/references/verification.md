# 验证与交付

代码完成后先推荐等级，简述影响、覆盖和拟执行命令，再自动执行，不要求用户选择普通测试。命令来自目标项目实际脚本及所选技术规范；不把下表当成可以调用不存在工具的授权。

| 等级 | 适用范围 | 执行 |
| --- | --- | --- |
| T0 | 文案、注释和无运行影响的小改动 | 检查本次改动 |
| T1 | 小范围、边界明确的实现 | 最小相关测试、类型检查或 lint |
| T2 | 模块与工作流改动 | 模块测试、类型检查、lint 和必要构建 |
| T3 | 高风险跨模块或发布前 | 全量测试、构建及已授权的关键流程冒烟 |

失败由实施者自动修复后复验。影响面扩大时更新等级与范围。已有服务或编辑器先发现并复用；不自动运行真机、Standalone/Player、签名、上传或发布。测试需要外部副作用时拆出独立授权对象，在此之前完成可执行的本地验证。

证据必须绑定当前工作项、技术栈、实施包、对象阶段和实际候选，保留真实命令、退出码、非空原始输出及运行资料。控制器只验证已提交材料及关系，不能证明材料真实产生，也不能通过命令文字或文件名推断引擎验证成功。缺少工具/平台时标记 NOT_RUN 或 BLOCKED，说明缺口。

可使用控制器的 `plan` 与 `record` 自动维护身份、路径及引用：计划只转录显式的范围和 F0/F1/F2 自评，结果报告只转录已经实际执行的命令、退出码和证据文件。空证据清单、模板占位或非零退出码不能提升为通过；F3仍由实施者根据真实工程结果登记，`unit-check`及原生必需证据检查继续生效。视觉复用只承接未变化的前置确认，当前 V4/V5 工程证据与最终人工验收不沿用旧工作项。

截图可以采集、并列展示并附检查点；默认由用户人工检查显示效果，代理不自动分析截图或据此宣告视觉通过。只有明确要求自动视觉验证时才分析，并记录授权及适用范围；自动分析仍不伪造用户确认。

## 三类验收结论

分别报告以下结论及证据，不增加控制器状态或新的审批：

1. **结构完成**：正式可编辑源中适用的元素结构、父子关系、布局配置、资源引用和宿主关联已保存，并通过重新读取或解析核实。正式源可为场景、预制体、界面文件、声明式 UI 或组件代码及必要配置；缺少回读或解析证据时如实标记未验证。
2. **工程通过**：布局保持、内容适配、交互和受影响回归已按实际适用范围验证通过。未运行或失败的检查不能计为通过。
3. **视觉通过**：用户已对目标条件下的实际组合画面进行人工确认。结构存在、参数合法、工程测试通过或截图采集成功均不能替代该确认；未确认时标记“视觉待确认”，不得笼统宣称“设计稿还原完成”。后续画面变化时按受影响范围重新确认，保留未受影响的有效结论。

在现有 V5 或等价验证职责中分别记录两类检查：**基准还原检查**使用与有效设计目标一致的参考画布、语言、内容状态和安全区，核对关键元素的目标值、正式源值和运行值；**适配检查**验证适用视口、安全区、长文案、动态状态与重入，区分已声明的预期变化和实现偏差。两类结果分别记录，避免适配掩盖基准错误，也不把合法适配误判为还原失败。无法获取准确目标或实际值时如实注明，不编造测量值、误差或通过结论。

差异及其来源按[还原依据与变更边界](../../app-ui-layout/references/relative-layout.md#还原依据与变更边界)记录在已有证据中；数值容差应与属性、逻辑单位和参考条件相符，不用统一像素阈值替代依据，也不将阴影、纹理或字体观感简化为几何误差。若用户明确授权自动视觉分析，其结果仍不等于用户对实际组合画面的人工确认。

普通检查与审阅直接输出报告；静态布局默认展示 PNG 与检查点。只有需要交互对照或动画播放时才生成 HTML，不为普通审阅另建网页或启动服务。按需生成的 HTML 仍须与本批实际工件一致，未生成 HTML 不影响必要的布局事实、人工确认及机器证据校验。

交付报告简述：实际改动、执行等级与结果、失败项和已修复情况、未执行项、待人工视觉验收或外部操作。交付前核对必要的中文注释、单文件行数、引用完整性和改动所有权。未经明确要求不创建提交或推送。
