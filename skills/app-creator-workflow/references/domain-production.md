# 领域生产交接

本文件只说明跨专业交接。实际生产进入对应公共能力，通过清单读取所选技术栈的完整 ADAPTER 与配套资源，不能用本摘要代替制作步骤、模板或校验器。每项交接复用当前 Work Item、实施包和证据，不增加状态机。

## 产品与架构

游戏定义一句话体验、核心循环、失败/重试、进程及可观察行为；应用定义首次价值、关键任务、页面语义、加载/空/错误/成功与恢复路径。两者都明确最小范围、非目标、平台、依赖和验收。内部规格与用户可见文案分开，不把策划说明直接画入图片或绑定为页面文字。

模块以状态所有权、公开契约、依赖方向和生命周期划分。运行代码、表现、平台服务与资源生产分别有清晰责任；同一状态、布局属性、位移、共享配置或动画内部控制器只能有一个权威写者。无需为每个目录预建接口、服务或管理器。

## 业务与玩法

规则层拥有权威业务状态、结算、命中/伤害、数值和事件语义；表现消费事件，不能以动画是否播完、某张图片或音效是否存在作为业务真相。对异步请求、取消、场景/页面退出、订阅、对象池与重入有明确收尾策略。

只消费已登记且通过当前交接检查的共享资产；不在局部场景或页面私改共享源来绕过资产缺陷。原生接口、实例和资源引用的读取方式由所选技术栈规范决定。

## 动态反馈

V1 明确每个关键事件要让用户理解什么；V2 记录事件来源/参数、视觉/音频/镜头/时间/触觉通道、时机、强度、时长与负责人；V3 制作和验证资源；V4 在真实对象和运行轨迹中接入。

每项反馈明确：重复时重播/合并/限频/忽略；叠加时的优先级和并发上限；中断、暂停、离场及对象池复用时如何清理并恢复属性。改变规则的击退、顿帧、全局时间或输入锁定由规则所有者决定，不由视觉制作擅自添加。适用时检查正常操作、高频重复、单事件峰值和多事件叠加。

## 音频

按核心反馈、UI、环境、音乐、语音和无障碍定义事件、优先级与静默降级。登记来源/许可、格式、声道、采样率、循环点、时长、响度、压缩、加载、大小和消费者；原生 Mixer、Web Audio 或 Flutter 音频插件路线留在技术规范与实际项目中选择。

应用失焦、后台、系统中断、手动暂停和玩法暂停用可组合的原因管理，重复通知幂等。只有所有暂停原因解除且原播放请求仍有效时才恢复；停止、销毁、离场使旧请求失效，不能恢复已取消声音。后台新请求的丢弃或排队策略需明确，不默认集中补播。测试首次播放、静音、循环、中断恢复、资源缺失与重复通知；真实设备检查仍须单独授权。

## 数值与数据

游戏经济、成长、掉落、难度或应用业务规则都使用可审阅、可解释的参数、单位、默认值、公式和边界。游戏额外记录来源/消耗、失败成本、上下限、保底和异常策略；商业承诺或风险接受不由代理猜测。

保存可复现计算、随机种子、样本规模和允许偏差；模拟与表格不代替实际产品验证。改参数时标记受影响场景、页面、存档/数据、测试和性能，复验实际影响。未经要求不引入旧数据兼容方案。

## 动画、骨骼与 3D

制作前明确视角、相机、显示尺度、动作窗口、根位移、朝向、事件和中断需求；先确认设计理念与动作方案，再制作真实动画。资产生产者维护骨架、蒙皮、内部动作控制与源文件，业务/玩法只通过公开接口触发和消费事件，不能私改共享资产或任意变速掩盖动作不匹配。

工程检查与目标角色实际播放分开：骨架/权重/材质/帧序/导入正确只是资产轮，真实场景/页面接入与重复/中断/恢复是运行轮。具体 2D/3D 工具、坐标、根运动、格式和引擎导入规则读对应 `app-stack-*`；不把 2D 专用检查器套到 3D。

## 发布准备

QA 汇总范围、真实验证、未执行项、资源与依赖来源、性能预算和已知缺陷。发布职责准备可复现候选、版本、配置、交付资料和回滚/恢复说明。完成本地准备不等于获准签名、上传、付费、真机或发布，也不自动创建提交。
