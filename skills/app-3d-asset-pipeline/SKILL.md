# 三维资源与运行管线

将已交付的三维资源接入当前引擎，核对真实资源身份、消费者、加载表现与生命周期。外部文件和引擎原生模型分别走本栈支持的接入方式。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。以下共用步骤不能跳过所选原生适配规定的操作顺序、资源格式与平台边界；必要的用户确认按协议执行。

## 输入

- 可追溯的成品文件或原生模型、交付规格、目标技术栈和设备、实际消费者、运行预算及适用的导入权限。

## 共用操作步骤

1. 确认当前技术栈的导入器或原生资源入口、消费者、资产目录及生命周期策略。外部文件使用本栈实际支持的格式，原生模型按现有资源身份接入。
2. 复用建模和贴图交付规格，核对单位、朝向、枢轴、层级、材质槽、纹理颜色空间、碰撞和已交付的动画片段，按需配置运行映射。
3. 按本栈配置资源登记、加载、失败处理、缓存及释放，并区分可在本地完成的导入和需要授权的上传。
4. 按镜头和预算设置已交付 LOD 网格的切换与资源加载；需要新增 LOD 网格或改动几何时交给[建模](../app-3d-modeling/SKILL.md)，需要制作或修改贴图时交给[贴图生产](../app-3d-texturing/SKILL.md)。
5. 在正式消费者核对资源身份、显示与交互、LOD 切换及适用的加载和释放，按本栈采集实际运行证据，并与当前资源版本关联。

## 关键边界

- Three.js 的 GLTFLoader、解码器和渲染资源管理按其原生模式执行。Roblox 原生模型继续在 Studio 内接入，外部文件按 Roblox 原生模式导入。
- 当前API和依赖版本以仓库锁定版本为准；没有验证的loader或decoder不报告已支持。

## 交付

- 按[三项最小约定](../app-creator-workflow/references/output-files.md#每项任务的最小约定)交付当前结果、实际路径或原生资源身份和验证结论，复用已有导入规格，保留适用的资产映射、失败诊断及本栈运行证据。纯方案或局部调整可在现有工件交付，未运行的目标环境验证保持未验证。

## 当前技术栈的原生流程

先根据仓库实际依赖与项目配置确认当前 `app-stack-*`，再打开同目录的 [native-adapters.json](native-adapters.json)。按 `when` 选择 `mode`，从 `path` 指向的本栈原生手册中定位 `section` 章节，只读取该模式及其明确需要的脚本、模板和校验器；同栈同能力的多个模式在同一本手册内维护。
使用共用读取工具：`node .agents/skills/app-skill-runtime/read-native-mode.mjs <技术栈> app-3d-asset-pipeline [sourceSkill]`。单模式可省略来源，多模式必须指定清单中的 `sourceSkill`；输出所选章节、直接公共依赖及按需资源路径，不递归加载其他模式。维护本技能仓库时将 `.agents/skills/` 换为 `skills/`。
若 manifest 未列当前栈，继续使用该栈 `app-stack-*` 中的原生规范/索引及适用公共流程；这本身不代表能力缺失。仅当已声明并选中的原生手册或模式章节未随安装提供时才报告阻断。公共工作流只在 `sharedWorkflows[].stacks` 包含当前栈时读取；`onDemand: true` 的参考按当前任务选择，读取器仅列出路径。不要加载其他栈模式或臆造接口；栈未确认且会影响实现时先澄清。
