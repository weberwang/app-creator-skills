# 工程基础

## 项目事实与选型

读取实际 `package.json`、锁文件、Node 版本文件、启动入口、模块系统和部署配置，确认这是服务器、任务进程还是消息消费者。记录运行平台、构建产物、监听方式、依赖服务和验收目标。前端工程中安装 Node.js 不使其成为本栈项目。

生产优先选择仍受维护的 Active LTS 或 Maintenance LTS，具体版本取决于项目、框架与部署目标，不将技能仓库自身的 Node 最低版本当成业务服务器版本。通过项目已有的版本管理与 CI 核对实际版本；`engines` 默认只是提示，不能单独证明运行环境一致。不预设 Corepack、pnpm 或 Yarn 随 Node 提供。

采用与现有锁文件匹配的包管理器，不同时维护多个锁文件。需要新增依赖时按官方、成熟社区、自研的顺序核实适用性与维护成本；不因目录名或代码示例自动安装框架、ORM、Redis、消息队列、容器与云 SDK。沿用已确认框架，新项目按路由规模、依赖注入、约束、性能与团队维护成本选择。

新项目优先评估 TypeScript `strict`。沿用工程的 ESM 或 CommonJS，不混用运行入口与不匹配的导入规则。明确源码、测试、类型声明和构建输出的边界，避免工具能读 TS 就推断生产进程也能运行该语法。路径别名、文件扩展名、ESM/CJS 和资源文件在实际产物入口验证。

## 可复现的运行入口

明确开发、静态检查、测试、构建、启动与任务进程的实际脚本。只登记工程确实提供的命令；没有构建步骤的 JS 服务不伪造构建记录，有编译步骤的服务须验证生成产物能够以实际部署方式启动。

配置在启动边界统一读取并校验，再显式传入模块，不在业务代码中散读 `process.env`。缺失必需配置时给出脱敏错误并结束启动；不为生产凭据设置貌似可用的默认值。开发/测试/生产环境和连接目标显式区分，样例文件只含占位与含义，不包含真实密钥。

`npm ci` 适用于使用 npm 锁文件的项目，会清理已有 `node_modules` 并按实际设置执行生命周期脚本；执行前核对作用目录、锁文件与脚本，不能描述为只读操作或安全审计。不因本地验证随意升级依赖或重写锁文件。

## 工程交付

实现前明确模块接口、文件所有权和验证命令。新代码按职责复用已有模块，单个业务文件不超过 1000 行；生成文件和纯配置按项目规则管理。类、函数、实体定义和不直观逻辑使用中文注释，解释业务原因与边界，不重复翻译语法。

交付依赖固定方式、实际命令、配置说明、启动与关闭入口、测试结果及当前未验证的外部服务。部署配置按实际平台选择，不默认创建 Docker、Kubernetes 或云基础设施。
