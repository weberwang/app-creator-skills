# 接口与异步边界

## 合同先于实现

明确操作、输入、输出、状态码、错误、身份与权限、分页/排序、时间与数值单位和幂等需求。只规定当前接口需要的字段，不为所有项目强制统一业务码、响应包裹或认证框架。共享合同复用同一来源，避免文档、校验规则和实现各自维护相互冲突的字段。

HTTP 参数、请求体、消息、环境变量和外部服务返回值须在信任边界做运行时校验；TypeScript 类型编译后擦除，不能替代输入校验。拒绝不合法的类型、尺寸和取值，分页与批量输入有明确上限，未知字段按实际合同处理。验证后的应用输入与框架 request/response 分开。

鉴权、资源级授权和租户隔离各有明确责任，不能把已登录等同于可操作任意对象。按实际接口用途选择认证方式；不因采用本技能自动创建账号、登录页面、JWT、跨域开放规则或管理后台。存储访问使用参数化查询/明确字段映射，不把请求字段任意展开为写入对象或排序表达式。

## 错误和异步

业务拒绝、依赖不可用、超时、取消与程序错误分开映射；向调用方提供可理解、稳定且脱敏的结果，内部细节写入关联日志。服务器不使用客户端 Toast、弹窗或截图作为 API 错误规范。

异步操作要么在当前生命周期内等待并传播失败，要么明确交给持久任务系统或具有资源所有者的后台工作；不能丢弃 Promise 后假装任务完成。使用工程实际框架的错误传播机制，按固定主版本核实自动捕获能力；例如 Express 5 对返回的 rejected Promise 的处理不能推广到任意版本或未返回的异步任务。

`uncaughtException` 不作为吞掉错误并继续正常服务的机制；按实际进程管理安排最后清理与退出/重启。重试只针对明确可重试且副作用受控的操作，不重试权限失败和确定的业务拒绝。

## 超时、取消和负载

分别设置适用的请求头/请求体接收、业务处理、下游调用、数据库与关闭期限；一个 socket 超时不能代替整条操作 deadline。取消沿调用链传递并清理资源，只有下游确实支持取消才宣称已经停止；对已经提交或结果未知的写操作先核对实际结果，不能简单标记回滚。

按实际 Node/框架事件判断客户端断开，不无条件使用新版本才有的 `signal`，也不把请求对象的 `close` 直接当成客户端中途断开。输入体积、并发请求、批处理、缓存与等待队列有界，避免一个请求耗尽所有资源。

`async` 不会自动把 CPU 工作移出事件循环。请求路径避免高成本同步 I/O、无界计算和恶意输入触发的高复杂度处理；有实际需要时使用有界工作池、分片或独立任务，并定义饱和与取消行为，不为所有服务预先引入 worker。
