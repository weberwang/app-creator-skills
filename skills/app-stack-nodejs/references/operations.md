# 运行生命周期与交付

## 启动与关闭

进程入口负责配置校验、依赖装配、启动和关闭；应用创建与网络监听分开。只检查实际必需依赖，初始化与重试有界，必要依赖未就绪时不误报可接流量。存活、就绪与诊断各表达真实语义，健康接口不泄露凭据、连接字符串或内部拓扑。

按部署环境接收停止信号，首先停止接收新请求/新任务，再等待在途操作并关闭适用的服务器、队列、连接池及定时资源。设置整体关闭期限，超期后明确处理，防止无限等待；多次关闭请求复用同一次清理过程，不重复提交或提前确认任务。不要调用 `process.exit(0)` 把尚未完成的写入与日志截断后当成正常完成。

HTTP keep-alive、活跃请求和升级连接按实际 Node/框架版本处理。`server.close()`、强制连接关闭和 WebSocket 生命周期并不相同，不把一个 API 调用当成全部清理成功。具体行为见 [Node HTTP 文档](https://nodejs.org/api/http.html#serverclosecallback)。

## 配置与可观测性

集中解析配置，生产与测试连接目标显式区分。密钥通过部署环境的适用机制提供，不进入仓库、样例、响应或测试日志；对外部 SDK 各自建立适配文件、初始化状态、错误与释放边界，不把所有 SDK 堆进总控文件。

日志使用已有结构化方案，关联请求/任务 ID、模块、操作、耗时、结果和脱敏错误；外部传入的追踪字段需限制格式与大小。禁止默认记录完整请求体、令牌、密码、私钥和连接字符串。指标标签保持有界，不以任意用户 ID 或 URL 参数制造无限基数。

按实际产品需要观测错误率、延迟、并发/队列、依赖失败和资源使用。只有测量过的指标才报告结论，不凭本地启动成功推断生产吞吐或故障恢复能力。

## 发布准备与实际发布

准备固定的 Node/包管理器/依赖、源码版本、构建产物与摘要、配置项、测试结果、数据迁移说明、启动/关闭及恢复步骤。使用实际部署平台验证入口，不默认创建容器、云资源或 CI 提供商配置。

`RELEASE` 默认 `releaseIntent=prepare`，完成本地材料与检查不等于已经部署。上传、镜像推送、基础设施创建、真实数据库迁移、重启共享服务与生产发布按具体目标和动作取得明确授权，不夹带进安装、构建或测试脚本。

回滚按实际数据与外部副作用评估：替换应用版本不能自动回滚已提交数据、支付或发信。确认范围未要求旧版兼容时不额外建设兼容层；需要数据恢复时说明实际可执行方式，不许诺不存在的回退能力。
