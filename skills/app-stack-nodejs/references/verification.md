# 服务端验证规范

涉及性能定位或优化时，遵循[公共性能优化规范](../../app-domain-toolkit/references/performance-optimization.md)，按实际瓶颈检查事件循环、CPU、GC、内存、队列与并发以及数据库或网络等待；记录负载条件、错误率、吞吐量和适用的延迟分位值，在同等条件下复验，不把模拟依赖结果冒充真实服务容量。

本栈沿用公共 T0–T3，先按范围、风险与成本推荐等级、覆盖与实际命令，再自动执行普通本地验证。服务端没有 V0–V5 或截图验收门，接口、任务和数据行为通过真实测试与原始输出验证。

## 检查范围

| 范围 | 验证重点 |
| --- | --- |
| 静态分析 | 项目实际类型检查、lint 或语法/依赖检查；不要把语法通过宣称为类型安全 |
| 业务单测 | 状态、权限、输入边界、错误、并发策略与重试条件 |
| 接口/消息测试 | 实际装配、运行时校验、响应与错误映射、鉴权上下文与取消 |
| 数据集成 | 实际需要的数据访问、约束、事务、并发和迁移，使用隔离目标 |
| 生命周期 | 缺配置、依赖失败、就绪、在途请求/任务及有界关闭 |
| 交付产物 | 有编译步骤时验证实际产物与配置；无构建步骤时验证真实启动入口 |

命令从工程已有 scripts 与固定工具版本选择。例如项目确有对应脚本时执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`；使用其他包管理器时采用其实际命令，不强制创建同名空脚本。TypeScript 常使用 `tsc --noEmit`，但 `strict` 不替代外部数据运行时校验。

profile 工程证据类别为 `static-analysis` 与 `tests`，视觉和资源导入要求为空。每类提供实际执行、退出码与合法原始输出记录；静默命令使用公共标准采集 JSON，保留真实空 stdout/stderr。缺工具或未执行不能通过填入自评 PASS 弥补。无关模块不为凑类别反复构建或测试。

## 隔离与进程

优先用实际框架的请求注入、进程内应用装配和可替换适配器，避免为普通接口测试占用固定端口。需要运行服务时先检查项目身份、启动模式、端口与健康状态，复用适合的现有实例；没有可复用实例才创建。测试拥有的实例与资源结束时清理，不终止归属不明的服务。

测试文件的进程隔离不等于数据库、队列、目录和同文件全局状态隔离。使用独立目标/命名空间与确定的初始化清理，禁止默认读取生产凭据或清空共享库。外部服务 mock 只证明对应契约假设，不能宣称真实依赖已联调；必须联调时按明确授权选择测试环境。

时间、随机数与外部调用在需要时注入，覆盖高价值边界，避免只对实现逐行镜像写测试。性能验证使用明确场景与测量记录，不把单次响应时间写成容量保证。

## 公共控制器

本栈支持 `PROJECT`、`FOUNDATION`、`MODULE`、`INTEGRATION`、`RELEASE`，默认不要求视觉基线。模块验证完成后，最终集成冻结参与模块、交付物和行为范围，再重跑跨模块场景；使用[最终集成证据](integration-evidence.md)，不伪造页面或 V5 身份。

最终集成必须核对来源模块的真实执行结果、工程证据和当前交付物，行为原始输出独立于自评 JSON。发布准备另行绑定实际产物；真实数据库、外部系统、付费或部署动作仍按具体授权执行。

收尾按[精简交付](../../app-creator-workflow/references/output-files.md#精简交付)简短反馈，仅在相关时补充外部依赖未覆盖项；不默认生成交付报告，不报告无需求的视觉验收，不把本地测试通过写成已部署。

官方参考：[Node.js 测试执行模型](https://nodejs.org/api/test.html#test-runner-execution-model)。
