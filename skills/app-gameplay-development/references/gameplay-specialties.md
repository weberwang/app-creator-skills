# 玩法专项工程参考

按本次任务选择相应章节，沿用玩法技能的 V1–V5、目标栈原生流程及既有测试和证据。以下方法服务于项目已确定的机制和体验目标。

<a id="jump-tuning"></a>

## 平台跳跃调参

调整跳跃高度、到顶时间或落点范围时，先确认角色使用的重力、起跳速度、碰撞体尺度、场景单位、坐标方向、物理步长及速度与位置的更新顺序。区分按住与短按、上升与下降，以及移动平台等实际会改变轨迹的规则。

在无额外力、起跳与顶点速度分别为 `v` 和 `0`、重力大小恒定的连续近似下，可用目标高度 `h` 和到顶时间 `t` 推算 `g = 2h / t²`、`v = 2h / t`，其中高度和时间必须大于零，速度方向按项目坐标系转换。这是初始估算，离散步进、碰撞、限速或变重力会产生差异；存在这些机制时按正式控制器的实际更新顺序模拟或测量，不套用该简化模型。

通过现有运行入口记录同一次正式跳跃的时间和位置，核对实际高度、到顶时间和适用的落点，与本项目目标及约定容差比较。按项目已有能力覆盖短按、离边宽限和输入缓冲的窗口边界，以及暂停、恢复和移动平台等相关场景；运行轨迹、模型计算与人工手感结论分别记录。空间可达性和人工体验继续按[平台跳跃专项验证](../../app-domain-toolkit/references/game-characteristics.md#type-experience)执行。

<a id="save-recovery"></a>

## 存档写入与恢复

新增或修改存档写入、自动保存和恢复行为时，先确认权威状态、保存时机、存储平台、数据格式及读写错误由谁处理。读取目标平台实际提供的提交、一致性与并发语义，再选择其支持的安全写入或备份方式；只在备份已经验证有效时用于恢复，避免失败写入覆盖唯一可恢复状态。

使用隔离测试数据，通过正式保存和读取入口验证写入中断、损坏数据、读取失败及上一份有效状态的恢复，检查实际反馈、恢复后的状态一致性和重复保存行为。平台支持并发写入时再检查重叠请求与顺序；测试模拟只证明所覆盖的实现和环境，未验证的平台行为保留未验证。跨版本读取和迁移仅在项目明确要求兼容时设计并验证；可复现状态继续沿用[运行验证](../../app-quality-review/references/runtime-validation.md#长流程状态复现与运行断言)。

<a id="dynamic-camera"></a>

## 动态镜头

调整跟随、瞄准或机位切换时，先确认正式渲染相机、跟随目标、边界及唯一位置和朝向写入者。按项目意图选择死区、移动方向预判和阻尼，核对目标反向时的过渡、场景边界以及输入与瞄准使用的当前相机。Unity 沿用当前栈工程规范中的原生镜头控制和 Cinemachine，其他技术栈复用项目已有的镜头组件和配置。

在正式宿主按适用范围验证目标瞬移、目标更换、机位切换或打断、场景切换和恢复，检查引用、边界和输入映射未失效；记录实际参数与运行结果。画面构图和镜头手感由用户人工检查，除非用户明确授权自动视觉检查。
