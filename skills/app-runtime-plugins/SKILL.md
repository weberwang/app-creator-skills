# 运行时插件与扩展

在Three.js项目中按实际需要选择和接入运行时扩展，确认扩展与核心版本、渲染器、资源生命周期和性能预算兼容；不将插件问题误扩展为线上服务架构。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。以下共用步骤不能跳过所选原生适配规定的操作顺序、资源格式与平台边界；必要的用户确认按协议执行。

## 输入

- Three.js实际版本、锁文件与renderer；需要的运行能力（物理/碰撞查询/导航、模型decoder、后处理或其他addon）；现有资源、目标设备和帧时/内存/包体预算。

## 共用操作步骤

1. 把请求归到具体扩展类别：Three addon/controls、物理模拟、碰撞与空间查询、导航、模型decoder/worker或后处理；先确认用户要解决的实际运行问题和不需要的依赖。
2. 读取锁定的Three.js与扩展版本、renderer和构建工具，核实addon是同版本示例模块、独立包还是项目已有实现；检查API、模块格式和worker/wasm资源路径。
3. 比较最小候选的功能、包体、帧时、内存、平台覆盖和维护成本；说明版本兼容依据，不凭名称推断支持关系。
4. 接入时定义创建/销毁责任、场景切换清理、缓存和异步取消；物理世界与查询数据按实际更新顺序同步，decoder释放worker及临时buffer，后处理控制render target和pass资源。
5. 把插件能力限制在明确模块边界，提供缺失/初始化失败诊断和无该扩展时可解释的降级；不让扩展擅自拥有玩法权威状态。
6. 在真实场景及目标设备验证功能、交互时序、资源释放、帧耗、内存和构建产物大小，并记录版本、复现步骤与未覆盖平台。

## 关键边界

- 此能力只处理Three.js运行时addon与插件，包括物理/查询/导航、decoder和后处理；不引入认证、云存档、支付、广告或线上服务模块。
- 所有API与兼容结论以项目锁定版本和实际构建为准；没有在目标运行环境验证的能力标为未验证。

## 交付

- 插件类别与选型依据、版本和导入约定、创建/释放责任、功能与性能回归证据和未覆盖限制。

## 当前技术栈的原生流程

先根据仓库实际依赖与项目配置确认当前 `app-stack-*`，再打开同目录的 [native-adapters.json](native-adapters.json)。按 `when` 选择 `mode`，从 `path` 指向的本栈原生手册中定位 `section` 章节，只读取该模式及其明确需要的脚本、模板和校验器；同栈同能力的多个模式在同一本手册内维护。
使用共用读取工具：`node .agents/skills/app-skill-runtime/read-native-mode.mjs <技术栈> app-runtime-plugins [sourceSkill]`。单模式可省略来源，多模式必须指定清单中的 `sourceSkill`；输出所选章节、直接公共依赖及按需资源路径，不递归加载其他模式。维护本技能仓库时将 `.agents/skills/` 换为 `skills/`。
若 manifest 未列当前栈，继续使用该栈 `app-stack-*` 中的原生规范/索引及适用公共流程；这本身不代表能力缺失。仅当已声明并选中的原生手册或模式章节未随安装提供时才报告阻断。公共工作流只在 `sharedWorkflows[].stacks` 包含当前栈时读取；`onDemand: true` 的参考按当前任务选择，读取器仅列出路径。不要加载其他栈模式或臆造接口；栈未确认且会影响实现时先澄清。
