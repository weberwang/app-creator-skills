# 全局视觉方向定位模板

定义方向前，必须按[通用分析的统一执行要求](../../app-creator-workflow/references/professional-conventions.md#product-market-research)完成或复核市场、竞品、受众与参考四项分析，将结论及来源关联产品简报的 Market evidence 与当前设计依据；有效结论核实后复用，缺失或变化部分由产品策划与视觉制作按职责补齐后再填写本模板。

本模板仅按需整理设计输入，不要求用户先批准文字方向。首次定调或实质改版按 [Figma App 设计流程](../../app-ui-layout/references/figma-app-design.md)默认由 imagegen 先生成一张专业代表页效果图，用户选图后忠实重建可编辑 Figma；只有用户明确要求比较时才按指定数量制作多方向，保持同任务、主要内容和视口并体现实质差异。展示真实效果图，由用户确认或明确选择／组合；原图确认并授权忠实还原后，结构核对即可继续 V3，不重复确认重建预览；局部增量复用有效方向。正式实现仍需 V1 功能验证，仅设计提案无需先建工程。

方向输入可保留在当前对话。需要审阅汇总时，`docs/design/global-design-freeze.md` 仅保存所选方向及公共候选/选择记录引用；公共基线为唯一权威，不建立第二套冻结状态或目录。

## 方向定义

方向探索以同一代表页、真实内容和关键状态为比较基础，再从用户所选稿提取可复用系统；共同任务与视口不强制不同方向共享造型。按[无文字意图可读性](../../app-asset-workflow/references/interface-intent.md)设计信息与交互，阅读、对话、表单和数据本身属于任务时保留具体文字内容。不得以普通 Flutter Widget 或现成 Cupertino 外观作为表达上限，也不得为了凑数制作近似方向。

制作前先将定位和感受转为有依据的层级、可读性、构图及一致性方向，保留真实硬约束与用户锁定要求；布局、字体、配色、比例、组件形态及留白的具体方案在方向内探索，不提前锁死未经验证的视觉答案。下列具体签名从实际候选中提炼并在选定后逐步规格化。多方向时各提示词独立完整，不用共享形容词叠加名称冒充差异：

## 方向比较

实际生图前按[生成前约束](../../app-asset-workflow/references/style-and-production.md#生成前约束)将适用分析转为当次真实提示词，区分源事实和设计选择，不直接发送整份模板。保留实际发送原文、依据及参考作用到现有制作记录；检查文字／状态、探索边界与输出冲突后再调用工具。

| 方向 | 品牌辨识度 | 用户匹配 | 信任与清晰 | 市场差异化 | 系统一致性 | 实现成本 | 主要取舍 |
|---|---|---|---|---|---|---|---|

多方向交由用户比较时，询问“弱化配色、隐藏候选名称后，是否仍能辨认各方向”；仅有提示词差异不能宣称视觉差异成立。文字比较不要求额外冻结确认；仅存在实质取舍时讨论。正式基线引用用户实际选择或明确组合的原效果图、摘要、范围及真实消息，选定后关联忠实重建节点与独立预览，不得由代理代选；实际预览未经人工检查时保持待确认。

## 公共基线选择核对

在公共 Figma 方向选择中核对实际相关的决定，不机械拆成多轮确认：

1. 选择哪套全局视觉方向。
2. 是否接受该方向定义的视觉签名和实现成本。
3. Global Freeze Signature Rule 适用时，签名是否可复述。
4. 是否使用 `pin`、`raise`、`loosen`，或不覆盖表达预算。
5. 公共基线所选候选身份与真实选择证据。

只有新出现且影响范围、成本或验收的实质未决项才补充讨论；已明确内容直接复用，不记录额外“不适用”。公共全局基线不代替每个新视觉对象的 V2 目标与后续资源、装配验收。
