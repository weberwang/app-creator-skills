# 非游戏 App 页面可编辑设计任务模板

本模板按需整理真实设计输入，默认按 [Figma App 设计流程](../../app-ui-layout/references/figma-app-design.md)直接制作可编辑页面，不将整页效果图生图作为默认路线。信息足够时自主推进，不要求用户先批准这份文字。仅设计提案不强制先建设运行工程；正式实施必须完成相关 V1 功能和状态验证。

## 当前任务

- 目标用户、主要任务、使用情境与本轮代表页：
- 实际页面流程、用户可见文案、真实内容和关键状态：
- 业务事实、必要功能、无障碍、平台能力及用户明确锁定的品牌约束：
- 当前支持的平台、视口、语言、文字倍率和系统区域：
- 可探索的信息架构、布局、排版、颜色、留白与组件形态：
- 现有实现中用于理解功能、状态所有权和技术条件的源码或组件：
- 用户是否明确要求忠实还原现有界面；否则按任务目标探索：

不得添加无关功能、虚构数据、装饰面板或营销文案填充页面；不把现有组件、默认控件、代码草图或某个产品的固定风格作为视觉上限。

## 方案与用户选择

首次定调或实质改版，默认围绕真实任务和内容精修一份有依据的可编辑 Figma 代表页方案；只有用户明确要求比较时才按指定数量制作多方向，保持同一任务、主要内容、状态和视口，在布局、层级、排版、视觉语言或交互呈现上体现实质差异，而非仅换颜色。局部增量复用有效方向。

先建立符合当前产品的字体层级、空间节奏、色彩及组件语言并实际绑定变量；前置检查关键组件、长文案、空／错误／加载状态及平台字体。送审前对真实节点结构、尺寸、变量绑定和可测布局做一轮有界自查并修复实际问题，争取提高首轮通过率，不承诺必过；设计截图由用户检查，不自动分析、不循环审美审查。

每个方向提供真实 Figma 节点链接、相应预览及简短取舍；用户可选择一个或明确组合部分元素。用户确定后再展开其他页面和关键状态，不提前批量制作未选方案。

## 设计结构与交接

- 直接在 Figma 用可编辑文字、组件、实例、矢量和自动布局组成界面；重复元素组件化，颜色、间距、圆角等变量实际绑定，图层按职责命名。
- 核对字体可用及平台实现方式；替代字体需说明。插画、照片、角色等独立素材按需生成或复用，遵循宿主 imagegen 技能和 image_generator 委派；不得将整页图片当作可编辑设计。
- 以控制器的 Figma 合同冻结真实 fileKey、nodeId、状态、视口、结构采集及预览快照摘要；选稿中已表达的组件、结构和适配直接复用，缺失信息定向补齐，无需重画草图、拆解图或布局图并重复批准。
- V4 在正式工程上先试接代表组件和适用素材，再分批扩展；V5 对照当前正式组合，分别记录功能、可测结构和用户人工视觉结论。

工具不可用时说明缺失能力与受影响步骤，继续不依赖它的工作；不静默回退整页生图。不得因工具可用而擅自付费、购买素材、发布或运行真机。设计稿截图及运行截图默认由用户人工检查；未经明确授权不得自动分析或代写视觉 PASS。
