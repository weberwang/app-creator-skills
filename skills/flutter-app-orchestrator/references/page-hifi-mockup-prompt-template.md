# 非游戏 App 页面可编辑设计任务模板

本模板按需整理交付任务书，默认按 [Figma App 流程](../../app-ui-layout/references/figma-app-design.md)先由 imagegen 生成一张代表页效果图，用户确认后忠实重建可编辑页面，再提取 V3。信息足够时自主推进，不要求预先批准这份文字。仅设计提案无需先建工程；正式实施仍需确认完整 V1 模块方案。

## 当前任务

按[共同体验与视觉依据](../../app-asset-workflow/references/interface-intent.md#design-basis)选择本次增量的分析深度，不重复已有效的产品分析。

- 目标用户、主要任务、使用情境与本轮代表页：
- 实际页面流程、用户可见文案、真实内容和关键状态：
- 使用压力与操作顺序、已有／拟新增／待验证能力、关键取舍及代价：
- 定位如何转为层级、可读性、构图与统一关系，参考观察与来源：
- 业务事实、必要功能、无障碍、平台能力及用户明确锁定的品牌约束：
- 当前支持的平台、视口、语言、文字倍率和系统区域：
- 可探索的信息架构、布局、排版、颜色、留白与组件形态：
- 现有实现中用于理解功能、状态所有权和技术条件的源码或组件：
- 用户是否明确要求忠实还原现有界面；否则按任务目标探索：

不得添加无关功能、虚构数据、装饰面板或营销文案填充页面；不把现有组件、默认控件、代码草图或某个产品的固定风格作为视觉上限。

## 方案与用户选择

首次定调或实质改版，默认围绕真实任务和内容先由 imagegen 生成一张专业代表页效果图，再按用户选稿忠实重建可编辑 Figma；只有用户明确要求比较时才按指定数量制作多方向，保持同一任务、主要内容、状态和视口，在布局、层级、排版、视觉语言或交互呈现上体现实质差异，而非仅换颜色。局部增量复用有效确认图与方向；原图确认并授权忠实还原后，结构核对即可提取 V3，不重复预览选稿。

分析时交接真实任务、内容、状态、平台硬约束及有依据的视觉方向，布局、字体、配色、比例、组件形态和留白的具体方案交给模型探索，不先锁死未经验证的视觉答案。按[生成前约束](../../app-asset-workflow/references/style-and-production.md#生成前约束)将适用分析转成当次真实提示词，不直接发送后台规格或整份模板。保存实际图片、真实发送原文、关键选择及来源、版本与摘要，按反馈修图再选稿。选定后重建字体层级、空间节奏、色彩及组件语言并绑定变量；核对真实节点及可测属性。设计截图由用户检查，不自动分析或循环审美审查。

每个方向先提供真实效果图及简短取舍，由用户选择或明确组合。仅对选中目标重建 Figma，提供真实节点链接及独立重建预览；原图确认并授权忠实还原后，节点核对即可继续 V3，不要求再次选稿，不伪造用户看过预览。目标、内容或交互实质变化时重新确认受影响范围。

## 设计结构与交接

- 直接在 Figma 用可编辑文字、组件、实例、矢量和自动布局组成界面；重复元素按实际复用关系组件化；变量按真实需要提供并实际绑定，不要求凑齐颜色、间距、圆角三类，图层按职责命名。
- 核对字体可用及平台实现方式；替代字体需说明。插画、照片、角色等独立素材按需生成或复用，遵循宿主 imagegen 技能和 image_generator 委派；不得将整页图片当作可编辑设计。
- 以控制器的 Figma 合同冻结真实 fileKey、nodeId、状态、视口、结构采集及预览快照摘要；选稿中已表达的组件、结构和适配直接复用，缺失信息定向补齐，无需重画草图、拆解图或布局图并重复批准。
- V4 在正式工程上先试接代表组件和适用素材，再分批扩展；V5 对照当前正式组合，分别记录功能、可测结构和用户人工视觉结论。

工具或额度不可用时说明受阻步骤，继续独立工作；不伪称图片已生成或 Figma 已重建。有效已确认且目标未变的图直接复用，用户指定其他路线时保留真实消息及范围。不得擅自付费、购买素材、发布或运行真机；截图默认人工检查，未经明确授权不分析或代写视觉 PASS。
