# three.js 场景层级与显示层分层

本规则适用于 three.js 世界对象、屏幕 UI、常驻 HUD 和独立 `DISPLAY_LAYER`。V2 声明真实 `Object3D` 根、Camera 和合成策略；V3 将结构意图写入布局/显示层合同；V4 按合同验收资源；V5 用正式场景运行证据确认遮挡与输入。

## 世界树与 HUD 显示结构

遵循[公共显示结构约定](../../app-domain-toolkit/references/reference-domain-display-ownership.md#公共显示结构约定)，同时说明世界场景图及实际 HUD 树，不能只交付 TypeScript 模块目录。以下是按需采用的职责示意，不要求新增渲染通道、固定根名或 DOM 框架：

```text
应用显示宿主（控制器组织，非 THREE.Scene 的强制父节点）
├── 世界 Scene → 地形 Group／实体 Group／世界特效
├── HUD 分支 → 导航／页面／常驻信息 → 区域 → 功能组件
└── 瞬态层入口 → 当前显示层实例
```

HUD 和瞬态层依项目采用 DOM、独立正交 Scene 或既定 UI 实现，分别给出真实根和组合关系；DOM 元素不能直接作为 Object3D 子节点。Group 表达确有需要的变换或生命周期，不能为了文件分组建立空组，也不能从场景图父子层级推断透明物体、HUD 或跨通道最终前后顺序。

世界实体的模型、碰撞/命中代理与世界反馈由实体协调；固定 HUD 不继承世界物体或相机的非预期变换。导航逻辑经公开接口切换实际内容，主页/大厅只管理自己的内容；共享模块不直接改另一场景的私有 Object3D 或 DOM。瞬态层拥有自己的实例与输入处理，按行为控制 DOM 事件和 Raycaster 命中，避免点击穿透；关闭只释放自有订阅/实例及确实不再共享的资源。

V1 可直接实现或按需用白盒验证切换、挂载释放及输入恢复；V3 落实实际 Object3D、DOM 或 HUD 场景根与 Camera/渲染通道关系；V5 验证正式组合的遮挡、命中、重入和 resize。沿用现有领域合同和世界/HUD 坐标边界，不为统一树形增加一套并行证据。

## Object3D 层级与枢轴

`THREE.Scene` 是 `Object3D` 场景图根节点，子对象通过 `add()` 建立父子关系。three.js 没有通用二维对象 `origin` 字段；模型枢轴由几何体局部坐标定义，需要共同旋转或缩放的子树使用父级 `Group`。可复用模型应在资源合同中说明局部原点、单位、朝向与接地点；不同原点应在导入或装配适配层处理。

- 需要围绕模型中心旋转时，让模型局部原点位于中心，或把模型放入专用 `Group` 并用子对象局部偏移定义枢轴。
- 需要脚底、车轮或工具接触点稳定时，在模型/实体合同声明该参照点与局部偏移；动画片段切换不得偷偷改变玩法碰撞体或状态所有权。
- 对 `THREE.Sprite`，合同中的二维锚点可映射到实际的 `Sprite.center`；其他 `Object3D` 的 `position` 是其局部变换原点，不代表纹理角点。布局锚点、Camera 坐标原点、模型局部原点和动画反馈偏移是不同事实，分别记录。
- 序列帧和状态图片要保持统一画布、对象中心与动作物理参照；若动作需要脚底等稳定接触点，用独立的定位参照/局部偏移表达，避免逐帧移动枢轴造成跳动。

## 显示层与实际合成

每个场景在 V2 列出需要的职责层及稳定 ID，并按场景选择 `Group`、Camera layers、独立 `Scene`、DOM Overlay 或多通道渲染。逐层声明坐标空间、Camera、深度测试/透明策略、输入归属、生命周期和负责人。场景图父子关系主要表达变换与所有权，不能单独保证最终像素前后顺序。

统一按[游戏层／内容层、HUD、浮窗与弹窗](../../app-domain-toolkit/references/reference-domain-display-ownership.md#游戏层内容层hud浮窗与弹窗)组织：内容 < 屏幕 HUD < 弹窗层 < 浮窗层。该关系须由实际渲染通道与 DOM 组合实现；模态期间同时限制 DOM 事件和世界 Raycaster，最上层 Toast 提示不改变当前模态输入权，不能只提高 CSS 层级或 `renderOrder`。

| 层职责 | 常见实现 | 必须明确的边界 |
| --- | --- | --- |
| 世界背景/远景 | 天空盒、雾、远景几何或世界背景材质 | 使用世界 Camera 与 world contract；交互目标应单独注册。 |
| 世界后景 | 地形、建筑、场景后部遮挡 | 使用世界坐标和深度缓冲；说明透明材质与遮挡关系。 |
| 世界主体 | 玩家、敌人、道具、交互对象 | 玩法对象、碰撞体、输入命中与资源所有者清楚。 |
| 世界前景与特效 | 前景遮挡、粒子、伤害反馈 | 声明与世界深度的关系；特效不抢交互。 |
| 页面内容 | 当前页面主体与功能区域 | 与上述世界分支共同构成游戏层／内容层，分别声明 DOM 或世界坐标。 |
| 屏幕 HUD | 常驻信息、导航、操作控件 | 高于内容；DOM Overlay 或 OrthographicCamera，遵守 HUD 坐标和安全区合同。 |
| 弹窗层 | 非模态面板，以及成对的模态遮罩与弹窗 | 高于 HUD；非模态面板低于当前模态遮罩，只允许顶层模态及其附属交互接收输入，关闭后恢复。 |
| 浮窗层 | Toast、全局短时反馈 | 高于弹窗层；默认无交互、不抢焦点、不吞输入，保持当前模态隔离。 |

世界空间血条和标签仍按世界深度关系处理。独立面板复用 `popup` 或实际 `drawer`，Toast 复用 `toast`，仍按独立 DISPLAY_LAYER 管理；弹窗附属下拉/Tooltip 跟随所属窗口，不提升到全局浮窗层，不用一个全局瞬态层掩盖输入与窗口边界。

three.js 的深度缓冲、材质透明、`Object3D.renderOrder`、Camera/Object3D `Layers` 与渲染通道共同影响画面；`renderOrder` 不是无条件压过深度测试的全局层级。需要稳定覆盖的 HUD 通常用 DOM 或单独的正交渲染通道，并清楚定义清屏、深度缓冲和 pass 顺序。多个瞬态层共存时声明互斥、覆盖顺序及最上层输入权，不能把不同父节点的局部数值直接互相比较。

布局合同中的 `regions.z_index`、`layout_nodes.z_order` 和 `display_layer_planning.inventory[].z_order` 是可审阅的层级意图，不是 Three.js API 属性。实现时映射到明确的相机/渲染通道、对象局部深度、`renderOrder` 或 DOM 层级，并以运行证据确认实际效果。V5 检查背景、世界、HUD、遮罩、弹窗及特效的同屏组合，禁止用一张整屏图代替结构化装配；至少验证代表性状态下的深度遮挡、最上层命中、关闭瞬态层后的宿主输入恢复，以及 resize 后投影与锚点稳定，并记录 Camera/合成配置和相关合同身份。
