# 候选交付与发布准备

为内部评审或正式发布准备可重现、可识别、可恢复的候选交付物；核实所有实际启用的第三方参数及目标环境，并让用户决定是否扩展性能检查、优化或图集打包。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。以下共用步骤不能跳过所选原生适配规定的操作顺序、资源格式与平台边界；必要的用户确认按协议执行。

## 输入

- 已冻结的源代码与版本标识；目标平台、渠道和环境；验证结果及缺陷状态；当前候选的配置与恢复要求。只有任务明确要求升级兼容或数据迁移时，再纳入版本范围、迁移计划与旧数据约束。

## 共用操作步骤

1. 先明确交付是检查/候选准备还是实际上线：RELEASE 默认 releaseIntent=prepare，以真实 release-preparation 材料及必需工程证据完成准备；实际发布显式使用 publish，并保留 F4、精确批准和实际 release-result。[公共收尾规则](../app-creator-workflow/references/workflow.md#发布准备与实际上线)规定两类结果，准备完成不能标成已发布。
2. 按[发布候选与证据约定](../app-creator-workflow/references/professional-conventions.md#release-candidate-evidence)冻结候选源版本、依赖锁定、构建参数、内容版本与实际目标矩阵，保证验证绑定同一输入。
3. 盘点从代码与依赖、平台/渠道构建参数、环境覆盖和远程配置到最终产物的第三方参数生效链，逐项比较目标环境的批准配置并标明证据和不确定项；秘密只通过授权的安全配置通道核对。详细检查见[第三方与正式环境核对规范](references/release-readiness.md)。
4. 汇总已有性能数据、已知瓶颈和资源情况，再提醒用户选择是否需要额外性能检查、性能优化、打包或更新图集；按[候选性能与图集决策](references/release-readiness.md)继续。
5. 完成提醒后记录每项已选择、明确不做或待决定：已有明确答复时据此冻结最终输入；未答复时保留当前输入，仍按现有授权构建候选并执行必需验证，只暂停依赖未决选择的额外检查或改动。按[发布候选与证据约定](../app-creator-workflow/references/professional-conventions.md#release-candidate-evidence)保存实际命令、工具版本、候选位置、输出校验值、警告和构建日志，不把本地开发服务当成发行包。
6. 验证干净安装、首次启动、核心流程、断网/异常恢复与目标尺寸/包体限制；仅在明确要求兼容/迁移时验证对应升级路径，平台差异分别记录结果。
7. 为当前候选记录可恢复的备份和恢复步骤；仅当用户明确要求升级兼容或迁移时，才制定受支持版本范围、迁移、回滚及兼容窗口。不可逆或需外部写入时标记阻断并等待相应授权。
8. 生成发布说明、已知问题、验证矩阵、候选位置和回滚步骤；按[发布候选与证据约定](../app-creator-workflow/references/professional-conventions.md#release-candidate-evidence)区分本地候选准备与外部提交、签名、商店发布。

## 关键边界

- 第三方参数、正式环境和候选来源不能核实的项目标为待确认或阻断，不得仅凭配置标签、正式域名或构建成功宣称正式就绪；秘密不进入日志或交付证据。
- 每次候选都要给出性能检查、优化、图集处理三项明确选择；未获用户选择时不把额外优化或重打图集列作已批准，也不把可选项设为新的强制审批门。
- 候选准备不等于批准发布；不自动上传、购买、签名、发布或修改外部服务。没有明确兼容要求时不新增旧版/API兼容工作，只维护当前候选的备份与恢复路径。
- 引擎导出、浏览器部署、移动应用签名/商店要求由当前栈适配补充。

## 交付

- 不可混淆的候选包、第三方及正式环境参数核对表、版本/构建证据、平台验证矩阵、性能/图集选择及结果、发布说明和当前候选恢复步骤；按明确要求附加迁移/兼容方案。

## 当前技术栈的原生流程

先根据仓库实际依赖与项目配置确认当前 `app-stack-*`，再打开同目录的 [native-adapters.json](native-adapters.json)。按 `when` 选择 `mode`，从 `path` 指向的本栈原生手册中定位 `section` 章节，只读取该模式及其明确需要的脚本、模板和校验器；同栈同能力的多个模式在同一本手册内维护。
使用共用读取工具：`node .agents/skills/app-skill-runtime/read-native-mode.mjs <技术栈> app-release [sourceSkill]`。单模式可省略来源，多模式必须指定清单中的 `sourceSkill`；输出所选章节、直接公共依赖及按需资源路径，不递归加载其他模式。维护本技能仓库时将 `.agents/skills/` 换为 `skills/`。
若 manifest 未列当前栈，继续使用该栈 `app-stack-*` 中的原生规范/索引及适用公共流程；这本身不代表能力缺失。仅当已声明并选中的原生手册或模式章节未随安装提供时才报告阻断。公共工作流只在 `sharedWorkflows[].stacks` 包含当前栈时读取。不要加载其他栈模式或臆造接口；栈未确认且会影响实现时先澄清。
