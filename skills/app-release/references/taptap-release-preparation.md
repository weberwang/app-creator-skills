# TapTap 发布资料与资质准备

已选择 TapTap 发布目标时，依据当前游戏的实际内容准备可填写的商店资料、真实素材与资质材料，并与同一个发布候选关联。先按[渠道与 CLI 接入](channel-platforms/taptap.md)确认目标主体、应用、地区、宿主、发行状态和版本；复用现有产品规格、发布清单与素材记录，不新增通用空表单或控制器字段。

## 核实实际内容与后台要求

1. 对照当前候选的产品规格、已实现功能、配置与依赖、入口及测试证据，整理游戏类型、核心操作、已可体验的玩法和系统、真实画面、联网／社交／交易及数据处理行为。规划中、未实现、未启用或缺少依据的内容不能写成现有卖点；无法从候选核实的细节标记待确认，继续准备不依赖该细节的资料。
2. 在已授权的只读范围使用 CLI 的 `app analyze-status`、`app get-module`、`qualification get-assessment` 和 `qualification get-status`，并通过当前版本的内置 Skill、帮助与 schema 核对方法参数、字段、要求和状态；需要核实界面实际槽位时查看当期后台。按真实返回区分必填、可选、条件触发、待核实及权限不足，缺项数量随当前游戏与草稿变化，不沿用一次页面观察的数字。
3. 核对当前草稿已有值、已绑定素材和包体、材料状态及发布方式，再决定可复用内容与缺口。页面自动保存、预览文本、资料已上传或素材库存在文件，都不能单独证明字段已填写、当前候选已绑定或相关资质已过审。

## 准备商店填写稿

在已有发布材料按当前后台字段整理可直接填写的文案、选项、素材路径与来源依据；未提供的真实信息保留待确认，不编造名称、账号、网址、版本或渠道身份。以下字段来自已查看的版本发布页面，字段是否必填、具体限制及可用选项以实际应用当前后台和 CLI schema 为准。

| 页面分区 | 按实际游戏准备与核对 |
| --- | --- |
| 游戏类型与分发 | 核实移动端、PC、Tap 小游戏或 H5 等真实目标及其可下载、预约或其他发行状态；Android 与 iOS 分别记录，只有适用且已知时准备 App Store ID。不把平台支持或上传文件推定为已上线。 |
| 游戏图标 | 使用与当前候选一致的真实图标及制作源；已观察页面要求方图、不低于 512×512 像素、JPG／PNG，执行时重新核对当前槽位。核对文件与技术规格，显示效果交用户人工确认。 |
| 游戏名称、类型 | 名称采用候选和已确认资料中的正式名称；已观察页面名称计数上限为 50 字符，避免无关词缀及特殊符号。类型依据实际玩法和后台选项选择，不为营销效果虚构分类。 |
| 游戏简介 | 根据实际类型、核心操作、目标和已实现特色写可直接填写的介绍；页面要求只介绍游戏本身，不含联系方式、外链或兑换码。内容数量、联网、交易或功能承诺须有当前证据。 |
| 首页推荐语 | 从真实特色提炼简短、客观的推荐语；已观察页面上限为 25 字符，不使用“最”“第一”等极限词或商业宣传语。执行时按当前页面计数规则检查。 |
| 厂商信息、开发者的话 | 按真实主体及后台记录选择厂商类型和名称；开发者的话可以说明制作初衷与玩家沟通，依据已确认事实撰写，避免与简介高度重合，不填联系方式、外链或兑换码。已观察页面上限为 5000 字符。 |
| 图片与视频 | 按当前槽位准备实际游戏截图、宣传图、视频与制作源；数量、比例、尺寸、格式、顺序和是否必填从后台及当期规范核实，不套用其他商店标准。截图与视频关联当前真实候选并按[商店素材制作](store-marketing-assets.md)准备，展示画面与内容由用户人工确认。 |
| 游戏包体 | 根据当前发行方式核实需要绑定的 APK、Windows、Tap 小游戏或 H5 候选；关联真实文件、版本、校验值与后台返回的包体／版本身份，再按包体类型核对适用的包名、签名或启动入口。未上传、未绑定和尚未验证分开记录。 |
| 官网与玩家交流群 | 仅在项目已有真实官网、群名、群号或群链接且当期字段适用时准备；链接按页面要求填写有效地址，不夹杂其他文字。没有信息时按当前后台规则留空或列待确认。 |
| iOS 配置 | 仅按已选 iOS 目标读取实际展开字段、App Store 身份、地区及后台要求后准备；未查看或无法核实的字段保持待确认，不根据其他平台猜填。 |

素材只使用已确认的真实来源，不以概念图、生成画面或未实现 UI 冒充运行截图；视频使用真实游戏运行过程。代理可检查文件、来源和技术规格，截图显示、截图内容差异及视频画面由用户人工检查；未取得人工结论时标记待确认。素材与截图采集遵循现有运行授权，不自动发起真机运行。

## 准备资质与证明

分别依据当前应用的 `qualification get-assessment`、`qualification get-status` 和后台项目核实适用范围与状态；复用已有效、主体匹配的认证和材料，不重复索取证件。每项在现有发布材料记录实际依据、材料位置、当前后台状态及缺口；敏感证件、银行卡和密钥通过已有安全通道处理，不写入仓库、日志或聊天。

| 页面事项 | 依据实际内容准备 |
| --- | --- |
| 开发者认证 | 核对真实主体、厂商名称及已有认证状态；已过审且仍适用于当前主体时直接复用，主体不一致或材料过期时列出具体缺口。 |
| AI 接入声明 | 对照当期表单核实游戏实际使用的 AI 功能、游戏内容及其来源、适用声明和需要的截图／佐证；不凭开发时使用 AI 编码就自动选择“有”或“无”，不虚构生成方式、功能或证明。 |
| 游戏适龄分级 | 检查当前候选的暴力、恐怖、社交、交易、随机付费等实际相关内容，对照当期官方标准准备分级建议及内容依据；信息不足时列出待核实项，不凭名称或画风指定年龄，也不把建议当作平台审核结论。 |
| 隐私政策与隐私检测 | 核对实际收集的数据、用途、SDK／第三方、系统权限、授权与拒绝／撤回流程；政策主体、可访问的真实链接、应用内说明和候选实际行为须一致。记录后台检测结果及对应修复、复验，不以模板文案或 SDK 清单代替真实检测通过。 |
| 实名与防沉迷合规 | 按实际地区、宿主和发行阶段核对适用要求，整理真实实名认证、未成年人保护、时段及消费限制的接线、测试和平台所需证明；安装 SDK 不等于功能已启用或合规已通过。 |
| 其他条件材料 | 版号、软著、备案、授权链、商户和合同等依当前 assessment、发行类型及已选功能核实；按[材料与政策](taptap-materials-policy.md)处理实际触发项，不把所有项目无条件列为必备。 |

`待上传`、草稿、已提交、审核中、已过审、驳回、不可用及未知分别记录；只有平台真实返回的状态才能作为后台结论。缺失证明时明确内容、所需来源和负责人，不生成虚假材料或自动认定不适用。

## 关联候选与完成条件

- 在已有候选材料关联源版本、目标终端／地区、构建参数、真实包体与校验值、所填草稿及其版本、文案依据、素材来源和人工确认、资质 assessment／状态及未完成项。输入或实际游戏内容改变后，只复核受影响的字段、材料与证据。
- 发布准备交付当期可填写稿、适用的真实素材与资质材料、后台已有值及缺口；必填项、素材或证明尚缺时明确记录，不能凭本地文案完成标为整套资料已就绪。默认沿用 `releaseIntent=prepare` 及[独立的发布任务](../../app-creator-workflow/references/workflow.md#独立的发布任务)的既有合同。
- 创建、修改后台草稿、上传、绑定、提审、签约和正式发布是不同操作，遵守各自已有明确授权。当前后台所显示的过审后立即发布或定时发布只是已观察到的设置，不代表已获发布授权；实际提交前按[审核与上线](channel-platforms/taptap.md#审核与上线)核对当前快照、预检和实际计划。

页面观察日期：2026-11-18。当前字段、字数和素材规则可能变化；每次执行以目标应用当期后台、当前 CLI schema 和[商店审核要求](https://developer.taptap.cn/docs/store/release/publish/agree/)、[素材要求](https://developer.taptap.cn/docs/store/release/publish/material/)为准。
