# 渠道平台接入

用于已选择 CrazyGames、微信小游戏、抖音小游戏、Google Play 或 App Store 的游戏／应用。渠道是分发宿主或商店，不等于引擎技术栈、操作系统或广告聚合网络；同一项目可有多个渠道候选，但不默认全部接入。沿用六阶段、现有 MODULE／INTEGRATION／RELEASE 和[任务最小约定](../../app-creator-workflow/references/output-files.md#每项任务的最小约定)，不增加状态机、审批层或控制器字段。

## 确认渠道与实现路线

在现有 GDD／PRD、TDD 和发布矩阵中记录已选渠道、目标终端／宿主、地区、账号主体与应用身份、实际商业能力及适用路线；未知资质或支持能力写待核实，不填造 ID、通过状态或账号。沿用已确认范围，只有影响实现或提审的缺口才澄清。

| 渠道 | 交付与宿主 | 按需读取 |
| --- | --- | --- |
| CrazyGames | 平台承载的 Web 游戏，区分 Basic Launch 与 Full Launch | [CrazyGames](channel-platforms/crazygames.md) |
| 微信小游戏 | 微信小游戏工程及其实际宿主，不是普通网页或小程序页面工程 | [微信小游戏](channel-platforms/wechat-minigame.md) |
| 抖音小游戏 | 对应小游戏工程、接入宿主及适用引擎路线 | [抖音小游戏](channel-platforms/douyin-minigame.md) |
| Google Play | Android 应用／游戏商店候选 | [Google Play](channel-platforms/google-play.md) |
| App Store | 已选 Apple 平台的原生商店候选 | [App Store](channel-platforms/app-store.md) |

Unity／Cocos 先按锁定引擎版本核对官方 Web、小游戏适配或原生导出路线。Cocos 使用 Creator 自身对应平台构建，不强套 WebView 包装。Phaser／Three.js 的 Web 产物用于适用的浏览器渠道；进入小游戏须先证实平台适配器及 DOM、网络、音频、资源等运行能力，进入移动商店按本栈已确认的原生宿主路线验证。Flutter／Expo 的 Android／iOS 路线不自动产生微信／抖音小游戏，Web 导出也不自动成为合格游戏。Roblox Place、ESP32 固件和 Node.js 服务不因共享本规范而获得这五个平台的客户端发布能力；服务端只承担已确认的登录、支付或其他接口职责。

官方包体／分包、工具与 SDK、目标 API、系统版本、资质、支付及审核要求会变化。实际接入与提审时查当前官方文档和对应后台，记录来源 URL、核对日期、适用版本／地区／终端和结论；本专项的资料核对日期为 2026-11-10，不把该日期当作持续有效的政策保证。

## 导出方案与运行时平台选择

同一导出方案确实支持多个宿主时，优先复用同一产物，通过统一平台识别入口选择当前平台适配器，再按需加载、初始化对应 SDK，不为每个渠道重复打包业务代码。构建只确定该产物可支持的宿主范围、必要适配／原生插件及配置来源；运行时识别不能突破实际导出能力。不同宿主要求专用引擎适配、入口或原生工程时，仍保留必要的独立导出，不能为了同包复用伪造支持。

| 同包使用场景 | 平台识别与能力选择 |
| --- | --- |
| Web 游戏进入 CrazyGames、普通浏览器或已确认支持的微信内 H5 | 识别实际嵌入宿主和能力，分别选择 CrazyGames、普通 Web 或按需启用的微信网页 JS-SDK 适配器 |
| 实际已适配多个小游戏宿主的产物 | 结合引擎平台标识、真实宿主 API 与必要配置选择微信／抖音小游戏适配器；未经适配的普通 Web 包不在此列 |
| Android／iOS 原生产物 | 依据实际原生桥接和分发配置选择已编入的受支持能力；操作系统不等于商店，不能仅凭 Android 判断来自 Google Play |

微信内 H5 与微信小游戏分别处理：User-Agent 显示微信、存在 `wx` 对象或引入微信网页 JS-SDK，均不足以证明当前是小游戏。H5 仅按已确认需求接入网页能力，不调用小游戏登录／广告／支付 API，也不将当前小游戏专项自动扩展为 H5 全套接入。

平台识别由唯一装配入口负责，业务不散布宿主判断。先以引擎／原生环境、真实宿主能力或受控入口配置确定候选，再加载该候选 SDK 并按其官方环境／就绪接口复核；已经由宿主提供的 SDK 直接核实，不重复注入。不得为探测平台而同时加载并初始化全部 SDK；iframe 内自身域名不等于嵌入平台，User-Agent、referrer、URL 参数和单一全局变量只能辅助选择，不能单独证明正式宿主或交易身份。

同一生命周期内复用识别结果和初始化中的任务，避免重复装配。环境未知或信号冲突时不猜选商业 SDK；只有本产物已明确允许普通 Web 运行时才回退到普通 Web，否则返回不支持／待核实。平台已确认但 SDK 加载失败、授权不足或初始化超时时，只限制该平台相应能力并按合同恢复，不能切换另一渠道 SDK 冒充成功。开发平台覆盖或官方本地模拟模式必须明确标记为测试，不能产生正式宿主通过结论。

在现有 TDD 记录支持范围、识别依据、配置来源和唯一装配入口；QA 覆盖同一产物在各支持宿主的识别、所选 SDK、未选 SDK 未加载、普通 Web、未知／冲突环境、重复初始化和加载失败，并分别记录产物身份与实际宿主，不为识别机制新增工作流字段。

## 能力适配与 SDK 边界

接入过程按[工具与能力核实](../../app-domain-toolkit/references/tool-capability-verification.md)分别证明指导资料、工具连接、实际操作和真实结果；Skill、开发工具或依赖已下载，不等于已有广告桥接、专用导出器或业务能力通过。候选准备按[实际构建输出绑定](release-readiness.md#实际构建输出与候选绑定)选择当前导出产物，避免旧包参与宿主验证。

- 复用[独立 SDK 管理](../../app-domain-toolkit/references/reference-architecture-sdk-initialization.md)：业务依赖登录、广告、支付、存储等稳定能力接口；每个渠道适配器独立管理宿主 API、初始化、回调和错误映射。只实现实际需求，不为五个平台预建一套空管理器。
- 构建时确定导出方案、支持平台范围与环境；支持同包复用时由运行时平台判断选择配置和 SDK，确需专用工程时分别导出。按实际平台隔离应用 ID、广告位、包标识和入口，原生插件遵守真实打包边界。未选中平台不导入有副作用的 SDK，不向网页注入 `wx`／`tt` 替身冒充正式能力；不支持时返回明确受限结果，测试替身只用于测试。客户端公开配置与服务端秘密分开，AppSecret、会话密钥、私钥、商店 API 凭据不进入客户端包或日志。
- 渠道 SDK 的真实初始化前置按锁定版本遵守，依赖它的调用须等其就绪；单 SDK 失败不阻断无关模块，不设置等待全部 SDK 的屏障或无限加载页。超时／失败明确恢复或限制对应能力，不能将超时视为初始化成功。平台加载事件是遥测，[应用内加载显示](../../app-domain-toolkit/references/reference-domain-display-ownership.md#场景与弹出层统一加载)和[系统启动屏](../../app-domain-toolkit/references/system-launch-screen.md)仍由各自所有者管理，不以事件上报代替内容可用。
- 按实际宿主映射前后台、暂停、恢复、音频与输入；广告展示、系统窗口和业务暂停分别持有原因，恢复时不能误解除其他暂停。退出、重进或实例重建后，阻止旧回调回写失效页面／实例；已受理的交易和奖励由独立业务所有者按请求／交易身份核验并幂等结算，页面离开不等于取消订单，不能丢弃可信迟到通知。登录结果按当前身份和请求关联处理，不恢复已过期会话。不得把所有宿主的生命周期强行映射为同一个厂商事件。

## 隐私与商业能力

隐私指引、权限用途、数据声明及实际 SDK 行为须一致，按[隐私解耦规范](../../app-domain-toolkit/references/reference-architecture-sdk-initialization.md#隐私流程与-sdk-解耦)处理。平台明确要求的必要授权与业务交互须在当前接入方案中明确并满足，不能用“默认不新增隐私流程”跳过；未满足时限制对应能力或阻断相关候选，不伪造用户同意，也不扩建无关隐私中心。拒绝、未决定、撤回及读取失败按适用接口验证，平台授权、系统权限和应用同意分别记录。

广告仅接入已确认且该渠道允许的能力。CrazyGames、微信和抖音分别使用适用的平台广告接口；Android／iOS 实际采用 MAX 时继续遵守固定七网络及其[原生合同](../../app-domain-toolkit/references/reference-ad-applovin-max-contract.md)，MAX 的 Web／小游戏 no-op 只约束 MAX 适配器，不代表禁用平台自身广告。不把 MAX 的就绪属性、回调名、冷却或重试规则套到另一平台；同一广告位由一个适配器负责，不能同时请求两套广告。继续执行非个性化请求要求，按平台的实际配置／官方合同核实；无法落实或确认时停用受影响广告路径，不以平台托管或测试成功推定已满足。奖励只依据所选 API 的实际有效完成结果幂等发放；关闭、取消、无填充、超时或失败不得冒充完成，平台控制频控时不叠加冲突的展示请求。

支付先判定数字内容、订阅、实物或其他业务性质，再按渠道、地区、主体和终端的当前规则选接口；不把微信／抖音支付、Google Play Billing、StoreKit 或第三方付款互相替代。仅按需提供商品、下单、取消、待处理、失败、恢复／权益同步；服务端按对应合同验证交易及通知并幂等发货，不将客户端成功回调当最终可信凭证。无内购功能时按[内购 SDK 必要性](release-readiness.md#内购-sdk-必要性与移除)移除专用依赖，但不误删有真实消费者的平台综合 SDK。沙箱交易、真实购买、广告点击及外部配置仍遵守对应授权边界。

## 接入任务与完成条件

每项任务明确目标、允许修改的真实路径和完成验证；直接更新已有规格、计划、实施包、QA 或发布清单，不强制新增渠道总表文件。分工和依赖按实际协作补充，账号／后台事项注明待人工处理的具体缺口。

| 时机／任务 | 产出与修改范围 | 完成验证 |
| --- | --- | --- |
| 需求期：确认渠道 | 现有产品范围与发布矩阵：宿主、地区、主体、商业能力、资质和不做项 | 已选与候选渠道区分；官方依据、未知项及影响明确 |
| 全局基线：确定路线 | 现有 TDD：锁定工具／SDK、同包支持范围、平台识别依据、适配接口、配置来源及服务端边界 | 引擎版本和宿主支持有依据，明确共享产物与必要独立导出；不把 Web／Editor 结果当宿主结果 |
| 基础工程：打通最小产物 | 正式项目的导出配置、统一平台识别、SDK 选择与初始化入口，优先验证高风险路线 | 实际构建及定向检查通过；同包在各支持宿主只选择对应 SDK，未知／冲突环境不猜选；缺少宿主时保留未验证范围 |
| 功能批次：接通能力 | 按需求实现登录、生命周期、加载、广告、支付等相关模块 | 定向检查成功、拒绝、取消、断网、失败、重复与迟到回调，退出／重建后已受理交易与奖励仍正确核验结算；模拟结果如实标识 |
| 最终集成：核对当前候选 | 冻结源、依赖、资源、环境与产物支持范围，关联各实际渠道运行和异常证据 | 同包核对同一产物及各宿主识别／SDK 隔离，独立包分别绑定身份；检查权限和数据声明，不能一端通过覆盖其他端 |
| 发布准备：完成渠道交付 | 复用[候选合同](release-readiness.md)、[商店文案与展示素材制作](store-marketing-assets.md#任务安排与完成条件)及渠道专项要求 | 填写稿、素材和包关联当前候选，外部待办明确；准备、上传、提审、审核通过、正式上线分别记录 |

普通本地验证按 T0–T3 推荐后执行，先复用现有进程；真机、签名、外部写入、上传、提审和发布仍按既有明确授权执行。开发者工具、浏览器、模拟器、沙箱、真实宿主和真机证据分别标记；截图由用户检查，不能自动填视觉通过。规范／安装测试只证明指导资料可用，不证明真实渠道接入或平台审核已通过。
