# 渠道 SDK 分类、选择与统一接入

适用于已选择 CrazyGames、微信小游戏、抖音小游戏、TapTap、Google Play 或 App Store 的项目。从[渠道接入](channel-platform-integration.md)确认真实宿主、地区、终端、上线阶段和引擎后，先完成本页选择，再接入 SDK。能力清单在现有 GDD／PRD、TDD 或实施包维护，不新增控制器状态、审批层或统一 SDK 管理器。

## 分类与执行顺序

1. **盘点**：列出本批已选渠道、候选包与引擎／语言、已有 SDK／配置和已确认功能。已有明确选择及有效来源直接沿用；依赖已存在、模板值为 false、SDK 已安装或代码里有接口均不等于用户已选择或明确拒绝。
2. **列出必须实现项**：只纳入当前发布形态的平台强制要求、已确认产品功能的必要接口，以及已选能力的真实依赖。逐项说明触发条件、官方依据和适用版本；把法定合规义务与特定厂商 SDK 分开。未知条件先核实，不把所有平台能力默认标为必须。
3. **集中展示可选多选项**：合并本批所有渠道的候选能力，按下文格式给出用途、适用候选、依赖／互斥、材料／开通条件、可复用代码覆盖和实现缺口。展示必要的必接摘要，让用户确认的是完整范围。
4. **等待选择确认**：有未决可选项时，等待用户提交选择或明确全部不选；默认勾选、推荐、空回复、未回复和等待超时都不算确认。确认前，必须项和可选项均不开始安装依赖、复制 SDK 源码、写初始化／业务接线或发起服务开通；可继续只读研究、材料盘点和不依赖这些选择的工程工作。
5. **闭合范围**：将已选可选项及其必要依赖纳入必须实现集合；依赖增加成本、材料、数据用途或权限时，在确认清单中先展示。发现互斥或实质缺口时只澄清该组，保留其他有效选择，不逐个 SDK 重复询问。
6. **统一接入**：清单完整确认后，按依赖顺序统一安排本批必接项和已选项，按语言／引擎复用代码，统一配置、唯一装配入口与验证。统一安排不等于单文件堆叠 SDK，也不等于运行时等待整批初始化。

用户已经明确了整套范围且依赖／约束无新增影响时，复用原确认即可，不强制再走一轮多选。没有适用的可选能力时，按已有明确需求安排必接项，不制造空选择。后续范围变化只重开受影响的选择，不清空其他渠道已确认结果。

## 各渠道必须项与可选项

本表是分类入口，具体强制条件在项目接入时按对应官方资料重新核实。引擎的网络、音频、文件、普通输入和资源加载不列为独立可选 SDK。所有已选 SDK 的隐私前置、生命周期、失败恢复、回调释放和合法使用要求属于其必要接线，不能让用户取消勾选来跳过。

国内渠道游戏的[首页健康游戏忠告](channel-platform-integration.md#国内渠道健康游戏忠告)作为必做显示要求随需求安排，不作为可选 SDK，也不因 SDK 选择尚待确认而暂停其独立设计与实现。

| --- | --- | --- | --- |
| CrazyGames | Basic 的 SDK 可选且不开放变现；Full 按[官方接入要求](https://docs.crazygames.com/requirements/intro/)接 SDK、GameplayStart 及适用广告；已有账号／进度、多人玩法触发的账号与联机要求一并纳入必接 | Basic 阶段适用 SDK；未被当前阶段或已选玩法强制的存档、邀请、广告格式等额外能力；购买须有平台资格 | [TypeScript／Unity 代码](channel-sdk-reuse.md)；能力与阶段限制见[专项](channel-platforms/crazygames.md) |
| 微信小游戏 | 真实小游戏适配、必要前后台事件及实际调用涉及的隐私前置；选择账号后才接临时凭证与服务端会话，选择支付／广告后其完整流程成为必接 | 登录、平台广告格式、支付、分享／邀请、关系链、云存储／排行、客服／订阅及统计等实际支持项 | [TypeScript／Unity 代码](channel-sdk-reuse.md)，按[专项](channel-platforms/wechat-minigame.md)核对主体与终端 |

| TapTap APK／原生服务 | 适用实名／防沉迷义务；采用 TapTap 合规认证才依赖 TapTap 登录。采用 TapSDK 时遵守其初始化和授权；内购、买断／DLC按已选模式落实验单和权益校验 | 登录方案、广告、内购／买断、云存档、榜单、成就、好友／联机、社区、REP、TapDB、礼包／角色／手机号服务 | [Unity C# 与 Node.js 协议](taptap-runtime-integration.md)；广告已有[Unity 官方聚合封装及三引擎 Android 桥接](taptap-ads-usage.md)，其他未交付平台按清单标缺口 |
| TapTap PC／Tap 小游戏／H5／TapPlay | PC 启动校验、主登录／账号绑定及对应合规方案按官方规范；小游戏账号业务使用对应会话协议；H5 不冒用小游戏接口；TapPlay 合规托管不重复强加游戏内认证 SDK | 本宿主实际支持的商业、账号、数据及社交能力；不同形态分别列组，不给 H5 展示仅原生支持的模块 | [宿主与语言矩阵](taptap-runtime-integration.md#宿主与语言路线)；[材料与政策](taptap-materials-policy.md) |
| Google Play Android | 商店政策与当前候选声明必须满足；选择数字内容内购后按适用计费方案接商品、购买、确认／消耗、服务端验单和权益恢复；不把某广告／统计厂商当商店普遍强制项 | AdMob 或 MAX、Firebase Analytics、Firebase Crashlytics、AppsFlyer；按实际需求另列 Billing／Play Games 等商店原生能力 | 已有[移动端 SDK 代码](../../app-domain-toolkit/references/mobile-sdk-integration.md)，商店原生能力的复用缺口另列，见[专项](channel-platforms/google-play.md) |
| App Store iOS | 商店政策与适用隐私／跟踪前置必须满足；内购和第三方登录等实际功能触发 StoreKit／Apple 登录的相关规则，不能无条件要求所有 App 接这些 SDK | AdMob 或 MAX、Firebase Analytics、Firebase Crashlytics、AppsFlyer；按实际需求另列 StoreKit／Apple 登录等商店原生能力 | 已有[移动端 SDK 代码](../../app-domain-toolkit/references/mobile-sdk-integration.md)，其他 Apple 终端不推定支持，见[专项](channel-platforms/app-store.md) |

Google Play 与 App Store 的 AdMob／MAX、Firebase 和 AppsFlyer 是两条发行路线的复用代码，共用按引擎维护的实现；商店原生能力是否已有实现分别标注。用户已明确暂缓的能力保持暂缓，不因目录列出或本规范调整自动恢复；项目后续明确变更范围时再更新对应选择和缺口。

TapTap 广告方案已统一确定为 [Dirichlet／TapADN 聚合](taptap-ad-integration.md)，不再展示聚合／非聚合、AdMob／MAX 供用户重选。按引擎、实际宿主与广告格式确认所需依赖和代码覆盖；可用聚合网络以当前官方支持、后台与已确认范围为准，不套用 MAX 固定七网络。该方案选择不自动启用其他 SDK、开通媒体、签约或授权真实广告请求。

## 多选清单与确认记录

只展示当前渠道、终端、阶段和主体有适用路径的候选。每项使用稳定、清楚的编号，例如 `微信-激励广告`、`TapTap-PC-云存档`；跨渠道共享的厂商 SDK 可以合并展示，但注明作用于哪些候选以及各自配置。账号、支付或平台 SDK 的“必接”与工程中“已有可复用代码”是两列不同事实。

在现有规格／实施包使用下列格式，无须创建另一份流程状态文件：

```markdown
SDK 选择范围：本批渠道、终端、宿主／阶段、引擎／语言

必须实现摘要：
| 项目 | 触发条件／依据 | 已有实现／缺口 | 材料或开通前置 |
| --- | --- | --- | --- |

可选能力（可多选；未勾选仅表示待选，不代表已经拒绝）：
- [ ] 选项编号：能力名称；用途；适用候选；依赖／互斥；材料；复用情况

选择方式：一次回复所选编号并确认，或明确“全部不选”；有推荐组合时同时列明其完整范围。
确认来源：实际用户消息／已有有效需求引用，待回复时写“待确认”
确认后汇总：必须项＋已选项＋必要依赖；明确未选项及本轮暂缓项
```

交互工具支持真正多选时使用多选；工具只有单选时，以编号复选清单接受用户一次回复，不能把单选按钮当多选，也不能替用户自动提交。需要依赖补充材料时，先把具体缺口准备完整后集中交接，真实证件、凭据、协议签署和外部开通沿用现有授权边界。

必须项只展示依据和依赖，不提供绕过平台或法律要求的取消勾选；用户希望移除时先调整对应发布形态或功能范围。明确“全部不选”只排除可选项，仍保留当前范围的必接项。尚未确认的清单不得写成“用户已同意”，也不以模板中的空数组或 false 代替选择记录。

未选择的能力不引入对应官方依赖、不创建空管理器、不初始化、不预建商品或修改后台。已有工程调整范围时，先说明保留、移除或新增的实际差异；不能因默认未勾选删除原有已确认功能，也不能把历史依赖作为本轮新用途授权。无内购时仍按[内购 SDK 必要性](release-readiness.md#内购-sdk-必要性与移除)处理。

## 依赖与互斥

- 同一原生产物只启用一个顶层广告聚合：TapTap 使用已确定的 Dirichlet 聚合；采用 Google Play／App Store 移动聚合路线时 AdMob／MAX 是互斥组选项。MAX 内的 AdMob 等聚合网络是所选方案依赖，不作为第二套顶层广告 SDK 勾选；平台禁止第三方广告时不展示这些无效候选。
- Firebase Analytics、Firebase Crashlytics 和 AppsFlyer 按用途分别选择；不能一次勾选 Firebase 就默认启用全部产品，也不能因发布 Google Play／App Store 自动选择。TapDB 与已有分析／归因可以按实际方案共存，但须展示重复事件、数据用途与消费者处理方式，不凭厂商名称设虚假互斥。
- 登录、实名、存档、好友、排行、支付等依赖按所选宿主的真实合同展开；TapTap 登录是部分 Tap 服务的依赖，不等于所有渠道统一强制登录。开通、账号认证、应用配置和运行时 API 不混为一个勾选项。
- 官方支持、当前主体／应用可开通、工作流复用代码和项目真实验证分别核实。只有文档的能力标“需实现”；官方支持未知的标“待核实”，不得展示成已可直接接入。明确暂缓项在本轮不可自动激活。

## 统一接入与验证

确认后将清单交给[架构与 SDK 所有权](../../app-domain-toolkit/references/reference-architecture-sdk-initialization.md)，按[渠道源码安装](channel-sdk-reuse.md#接入正式工程)和[移动端复用](../../app-domain-toolkit/references/mobile-sdk-integration.md)接入当前引擎。只安装真实需要的官方模块及选定原生依赖，服务端秘密留在服务端；缺少可复用实现时在本批范围内先补工作流代码及测试，不让各项目重写同一协议，也不拿空适配器冒充完成。

接入工具的支持范围也要与选择匹配：现有移动整包安装器要求显式选择广告提供方，并生成完整移动 SDK 的依赖清单；它不证明用户选了全部产品。只选分析／异常／归因、明确不选广告或其他部分组合时，复用现有独立模块和必要共享代码，按确认范围接入官方包与装配，不为满足整包脚本参数额外选广告，也不照单安装其完整依赖。整包方案确实与确认范围一致时才使用该脚本；需要扩展批量工具时单独实现并验证真实选择过滤，不能把不支持伪装成已自动完成。

全局基线冻结选择及依赖映射；基础工程在确认后统一接入并安排必要的依赖顺序；功能批次消费具名接口；集成与发布检查实际接入与确认范围一致、未选 SDK 无副作用、必接依赖齐全、账号／广告／支付等失败隔离以及材料与候选一致。整体规划确认与各 SDK 运行时独立启动分别处理，法定限制和平台真实前置不能被“不等待整批 SDK”跳过。

资料分类核对日期：2026-11-17。平台强制规则以项目执行时的官方文档、当前上线阶段和后台资格为准；本页不固定收费、政策阈值或长期有效的 SDK 版本。
