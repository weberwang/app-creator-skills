# 商店文案与展示素材制作

面向已选商店或游戏平台发布的游戏和客户端产品，也适用于明确要求制作商店资料的项目。根据目标用户和实际展示位准备商店文案、封面、截图及宣传视频。制作范围取自当期平台要求与本次任务，输入包括平台、设备、市场语言、现有品牌素材和可采集版本。

## 平台要求与卖点依据

- 制作前读取目标商店当期官方资料，核对实际素材槽位、必需与可选类型、数量范围、尺寸/比例、格式/透明度、文件大小、裁切及覆盖区域、允许文案和本地化要求，记录来源与核对日期。区分基础上架要求、特定展示位资格条件和建议，不把某平台的推荐条件或尺寸套到所有平台；未知要求不填假值。
- 复用[产品市场调研](../../app-creator-workflow/references/professional-conventions.md#product-market-research)中的受众、竞品与差异化依据，补充当前商店展示所需的观察即可，不重建另一份完整市场报告。目标是让合适的玩家理解“玩什么、为什么有趣、与同类有什么差别”；没有实测时不宣称某种构图一定提高下载或转化。
- 将核心玩法、特色机制、不同挑战、内容深度、成长/收集、角色或美术氛围中真实存在且有吸引力的部分，映射到可展示的场景与状态。按游戏特点选择，不强制每款游戏都展示战斗、养成或奖励；非游戏产品用其实际功能与用户收益替换玩法卖点。
- 为同一发布页面选一个主卖点，优先采用真实可体验、短时间内容易理解且有辨识度的玩法或功能。文案说明玩家会做什么，封面建立识别，截图证明不同卖点，视频展示实际过程。解谜或分类游戏优先展示局面、操作和解开后的反馈，动作游戏优先展示判断、出招和结果，经营或养成游戏优先展示资源如何转化为可见成长。仅采用与当前产品相关的取舍。
- 策划阶段可核对平台、起草文案并编排截图和视频分镜。对应功能和画面稳定后采集，发布准备阶段核对材料与当前候选的一致性。仅检查既有候选时列出可复用材料和缺口。

## 商店文案

按实际后台字段准备可直接填写的版本。简介优先说清产品类型、核心动作和目标，长介绍再说明有依据的玩法差异、场景和内容。操作说明列出实际支持的设备、输入和核心操作，使用项目内同一套术语。分类与标签依据当前内容和平台选项选择，工具、链接及下载量等字段按已核实事实填写，缺少依据时记录待核实或按平台规则留空。

按平台和目标语言检查字符数、格式、必填项与本地化。标题、术语和卖点与游戏内文字及成品素材保持一致。涉及难度、关卡数量、联网、更新、奖励、排名或评价的表述应有当前候选或可追溯资料支撑。可选字段仅在适用时准备。

## 素材类型与内容顺序

| 类型 | 制作边界 |
| --- | --- |
| 封面与主视觉 | 优先用最能代表产品的角色、道具、机制或场景作为主体。构图集中，缩小后仍可识别。不同画幅保留统一主视觉并单独构图，按实际裁切及标签覆盖区保住主体和标题。标题、边框、装饰及标志遵循平台展示位规则 |
| 原始游戏截图 | 从真实可运行版本采集，保留未作宣传加工的原图与来源；概念图、效果图或生成图片不能冒充运行截图 |
| 商店展示截图 | 使用真实原图，按平台允许的方式裁切、编排及添加必要文案；保持实际玩法、界面、功能和画质事实，不用排版遮掩尚未实现内容 |
| 独立宣传图 | 仅为目标商店实际需要的横幅、主视觉或其他槽位制作，复用已确认品牌与游戏素材，按该槽位的规则构图；不以直接拉伸截图应付不同画幅 |
| 宣传与预览视频 | 优先使用当前候选的真实录屏。按展示位制作独立画幅，优先保留核心操作、关键反馈和结果。平台允许动画时，动画应忠实表达真实玩法与功能 |

多张截图应展示不同的有效内容并形成顺序。首图优先表达主玩法和主要吸引力，后续围绕其他真实卖点展开；用场景、状态、挑战或内容差异组织系列，不能连续截取几乎相同的画面凑张数。张数由平台要求和卖点覆盖决定，展示顺序在现有发布材料中记录；每张有一个清晰主旨，不机械叠加大量解释文字。

截图、封面和宣传视频沿用同一品牌、字体、配色与本地化约定。按目标平台的展示位要求安排图标等其他素材。广告投放及 A/B 实验按实际授权和任务范围另行执行。

## 宣传视频制作

1. 在现有素材清单记录分镜的主旨、目标场景、操作、反馈和画幅。开头按平台要求处理首帧，随后尽快进入实际玩法或主要功能。中段优先保留一次完整的操作、反馈和结果，有余量再展示一个真实变化。选段时去除等待、重复操作和调试画面，按平台约定处理音频、转场、字幕和宣传文字。
2. 按平台指定画幅复用录屏或重新采集。横版可以保留目标与场景的空间关系，竖版优先保住实际操作区域、关键界面与反馈。裁切影响理解时，重新构图或按目标画幅采集。无声或自动播放的展示位应在静音状态下也能看懂主要操作。
3. 使用当前任务选定的视频工具。选用 MiniMax MCP 时，先确认当前连接和可用的素材导入、视频编排及导出能力，再使用对应封面、录屏和分镜制作。最终规格需要适配时，可用本地工具完成裁切、静音和转码。保留原始录屏、剪辑或生成来源和最终导出文件，关联当前候选。

## 真实采集与制作边界

1. 采集脚本明确目标场景/功能、状态或关卡、镜头、视口/方向、语言、操作步骤和希望表达的卖点，引用已有规格即可。使用当前稳定候选和合格资源，排除调试控件、占位内容、工具窗口及无关系统遮挡；只用产品真实支持的状态，不通过截图专用覆盖层伪造游戏能力。
2. 检查并复用当前项目的运行与采集入口。Unity 使用实际 Unity 画面，Cocos 使用 Creator 对应目标，Phaser/Three.js 使用已选浏览器或原生宿主，Flutter、Expo 使用各自实际应用；核对目标商店是否接受对应设备/模拟环境的材料，不以浏览器截图证明原生目标实况。不得因商店任务自动启动真机、Standalone/Player 或其他受保护运行；缺少授权/环境时继续可独立完成的策划与制作，并明确缺少的实际截图。
3. 保留原始截图，裁切、文字、图层和宣传装饰输出为独立制作源与成图。仅图片生产/编辑需要时，调用当前可用的 imagegen 技能和图片子代理，交接真实源图、允许改动范围及输出规格；不能由工具重画的画面充当原始截图或新增不存在的玩法/UI。既有素材和排版工具可满足任务时直接复用，不强制每张都生图。
4. 复用已确认的游戏视觉基线与品牌规范；宣传编排不是重做游戏内视觉目标，也不另走场景 V2 三候选、V3 拆解或运行资源导入。确需修改游戏本身时另行纳入受影响功能/视觉工作项，不为宣传效果静默改变产品内容。
5. 代理可检查文案的字段、格式和长度，以及文件格式、尺寸、比例、时长、音轨、体积、命名和引用。提供原始材料、成品和检查点交用户人工确认画面，重点检查缩小后能否认出主体、截图是否清楚展示所述卖点、预览能否在目标画幅和音频条件下看懂，以及画面与实际版本是否一致。未经明确要求不自动分析截图或代填视觉通过。可集中审阅整套素材，复用仍有效的人工确认。

## 任务安排与完成条件

采用既有三项最小约定，复用产品简报、发布计划和素材清单。默认当前执行者负责；实际委派策划、采集或图片制作时再明确写入范围与交接，不新建通用必填表或第二套状态。

| 任务 | 改哪里与交付 | 怎样算完成 |
| --- | --- | --- |
| 核对平台要求 | 现有发布计划中的目标商店/设备/语言、素材类型与官方来源 | 当期规格和适用范围可追溯，必需/可选及推荐条件分清 |
| 策划卖点与编写文案 | 产品和市场依据、可填写文案、各图主旨、视频分镜与展示顺序 | 文案和素材围绕同一主卖点，有真实内容支撑，字段和语言符合平台要求 |
| 采集真实画面 | 当前稳定版本的原始截图、录屏与来源引用，按本栈采集合同保存 | 版本、场景、设备或视口和语言可定位，缺失或未采集项明确 |
| 制作商店展示素材 | 对应槽位的封面、截图、视频及制作源 | 按平台和语言适配，真实表达当前功能，样式与顺序一致且素材依赖齐全 |
| 检查导出与交付 | 最终填写稿、图像和视频、对应平台规格、技术检查和用户确认结果 | 必填项与必需素材齐备，文件可解析且规格通过，人工待确认及未覆盖项如实列出 |

## 输出与版本更新

按[输出文件规范](../../app-creator-workflow/references/output-files.md)及本栈原生映射，在现有发布材料保存填写稿、原始画面、制作源、最终导出及确认记录。按平台、语言和实际候选记录来源、展示顺序、用途、技术检查和待完成项。材料就绪以实际文件和当前检查为依据。

这些是非运行的商店素材，不放入正式运行资源目录或随游戏资源包整体打入客户端；Unity `Assets/`、Creator `assets/`、Web `public/` 等目录不能充当商店图片归档区。机器证据仍遵守其实际 `evidenceRoot`，不搬迁已绑定原图/确认。可编辑源、原图和必要字体/素材的许可及依赖随交付保留，导出压缩不能覆盖原始输入。

版本、玩法、界面文案或素材变化后，核对是否影响已承诺的卖点和画面，仅更新受影响的文案、图像或视频。发布清单引用仍适用于当前候选的成品与确认结果，待检查项如实记录。商店上传、广告投放、真实市场实验及外部修改继续按现有授权执行。

## 官方要求入口

- [Google Play 预览素材](https://support.google.com/googleplay/android-developer/answer/9866151?hl=en)：截图、Feature graphic、真实内容及各展示位适用要求。
- [App Store 产品页](https://developer.apple.com/app-store/product-page/)：截图主旨、展示顺序与本地化；[截图规格](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)用于执行时核对目标设备。
- CrazyGames 的填写项、封面和预览视频槽位按[渠道专项](channel-platforms/crazygames.md#填写稿与展示素材)核对。
- 其他目标商店在实际任务中补充其官方规范，不复用未经核对的 Apple/Google 尺寸或展示限制。
