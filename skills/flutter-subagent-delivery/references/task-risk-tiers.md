# 任务风险分级与默认拓扑

风险等级只决定验证和审核深度。四个等级默认都在当前分支的 checkout 由一个写入者顺序完成，不自动创建其他分支、worktree、提交、PR、并行写入或任务 Markdown 工件。

| 等级 | 典型任务 | 默认验证与审核 |
|---|---|---|
| `light` | 文案、文档、确定性小修复 | F0、F1、F3 合并为一次自检；不创建审核工件 |
| `standard` | 边界明确的功能或单模块改动 | F0/F1；行为或验收变化才启用 QA F2 |
| `high` | 认证、支付、迁移、共享架构、跨模块契约或复杂 UI | F0/F1；QA 加上实际触发的 Product、技术、视觉或 Release 通道；需要持久独立验收时由 Controller 写 `review.md` |
| `release` | 发布准备、签名、分发、生产变更或完整平台矩阵 | F0/F1；QA、技术、Release 必审，Product/视觉按变化触发；发布证据按需留存 |

出现不可逆外部修改、敏感数据、安全边界、破坏性 API、数据库迁移、共享生成文件或难以回滚的部署时，至少升级到 `high`；只有用户明确授权才执行外部写入或发布。

## 显式授权例外

用户明确授权后，Controller 才能选择其他分支、worktree、提交、PR 或并行写入，并记录范围、所有者、基线和授权边界。显式并行仍要求互斥写入范围；只读探索和审核可并行，但不需要 worktree。授权例外不改变八字段任务契约，也不创建 YAML/JSON 状态机。

## 快照与证据

F0 先执行项目原生命令；通过后计算可复算 `snapshot-id`。普通 F1/F2 以 snapshot 绑定范围和证据，不强制提交 SHA。最终集成或发布只有在已有授权提交时才补充 commit SHA。修复后只重跑失败或受影响命令，并让输入指纹已变化的审核通道失效。

平台证据分层：共享基础做代表性启动/路由/插件烟测，关键业务流做主目标运行烟测，最终集成或发布才做完整矩阵。任务证据不得宣称全平台通过，真机验收必须单独授权。
