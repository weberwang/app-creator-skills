# Unity 文本与 JSON 国际化

## 默认路线与实施前检查

Unity 运行时所有面向用户的文本默认先评估 **UniText**，保持固定 JSON 为唯一文案源；路线按[完整还原标准](visual-decomposition-routes.md#完整还原的判断标准)核实，已验证完整则原生，已确认不能完整还原则直接图片，尚未核实则待验证。此规则不按组件类型、层级或位置限定：菜单、页面、HUD、按钮、弹窗、Toast、加载与错误提示、对话、列表、世界文字及可访问名称均适用，HUD 只是示例。屏幕 UI 使用 uGUI/Canvas，世界原生文字按需使用 UniTextWorld；编辑器工具仍可用 UI Toolkit，不把 UniText 当作 `Label` 的直接替换。图片文字和品牌图形保留同源语义，不另写翻译。

其他资料保留的 UI Toolkit/PanelSettings、UXML/USS 和 `TextElement` 配置只说明对应系统的布局或编辑器能力，不构成运行时文字的另一默认路线。实际目标使用该系统时也不能绕开默认 UniText、效果不足直接图片及统一 JSON 约定；所选宿主不能承载要求时报告能力缺口，不猜测组件互换或自行增加兼容层。

原生与图片按[完整还原标准](visual-decomposition-routes.md#完整还原的判断标准)核对字形、效果、排版和内容变化：已验证完整还原则原生，已确认不能完整还原则直接图片，尚未核实则待验证。插件声称支持某效果、生成图的外观或素材为 PNG 均不能独立决定路线，实际显示仍由用户检查。

每次具体实现前，先检查并复用目标工程已有 Editor，读取真实安装状态：

1. 记录 Unity 与 UniText 实际版本、包来源、包路径和解析结果。核对 `media.lightside.unitext`、`media.lightside.core` 及该版本声明的 Burst、Mathematics 等依赖；只有商店购买记录、下载文件或目录名称不代表正确安装。
2. 检查目标程序集可引用所需类型，Editor 编译与 Domain Reload 无相关错误；确认实际 UniText 组件、字体/字体栈、材质及 Shader 引用完整。检查所用版本的 API，不套用 TMP 属性或自行猜测接口。
3. 在已有本地 Editor 中验证本工作项需要的最小文本绑定、所选语言字符和参数更新；单语验证启动与绑定刷新，多语再覆盖各已选语言切换。WebGL 不支持系统字体访问，必须提供随包字体；其他平台依赖系统字体时也要记录设备差异。Editor 验证不代替目标平台证据或用户显示验收。
4. 记录检查命令、结果和未验证项。未安装、依赖缺失、编译失败或目标能力不可用时，明确提供“修复 UniText 安装”或“回退 TMP”选项，等待用户决定；不得静默改用 TMP，也不得擅自购买、注册或下载受限内容。继续不依赖该选择的工作。

用户选择 TMP 后，只替换渲染适配器、字体资产与相关布局测量，沿用相同 JSON 文案源、文案键、参数和语言切换服务；按 [TMP 字体图集流程](tmp-font-atlas-workflow.md)实施，不维护第二套翻译。不能使用未检查可用的 TMP 作为兜底成功结果。

## 初始化时机与阶段职责

国际化是项目级启动基础能力，必须在 `foundation-engineering`（Unity 的 S00）完成可运行实现与基础验收，不等到某个 HUD、页面或 V5 才建立。单场景或只有一个文本消费者时同样适用，不以两个场景的共享需求作为实施前置。项目后续新增的消费者复用这套能力，不另建文案加载器或语言状态。

| 阶段 ID | 国际化职责 | 本阶段交付与检查 |
| --- | --- | --- |
| `requirements-scope` | 确认支持语言、默认语言及用户可切换范围 | 项目语言清单来自用户确认；未答复不把默认选项记为确认，不擅自追加测试语言 |
| `global-baseline` | 确定 UniText、固定 JSON 源、字体策略及模块边界 | TDD 记录正式配置路径、唯一初始化入口、加载与语言服务、绑定接口、启动语言优先级、就绪/失败行为和安装异常时的用户选择；不把方案文档当作已实现 |
| `foundation-engineering` / S00 | 实查 UniText，完成 JSON 加载/校验/索引、启动语言解析和统一绑定 | 在最小运行宿主走通从正式配置到实际文本的链路，满足 [S00 验收条件](foundation-workflow.md#国际化基础能力验收)；不等待全部文案、正式视觉稿或所有对象 V2–V5 |
| `scene-production` / 对象 V0–V5 | 各对象从相关功能 V1 起接入统一键与参数，补齐本批正式文案和字体 | 每个实际消费者验证显示、参数更新、语言变化及生命周期；V2–V5 按已确认视觉与布局完善和验收，不重复创建基础服务 |
| `global-integration-validation` | 核对所有实际消费者、全部所选语言及跨对象状态 | 覆盖导航、场景切换、常驻/瞬态层、动态生成或池化对象和可访问语义；S00 代表性验证不能替代全项目检查 |
| `release` | 核对候选使用的正式配置、字体和加载路径 | 构建产物包含需要的资源，来源与版本可追溯；列明已验证平台、失败与未覆盖项，实际设备及发布仍按授权执行 |

每次应用启动，由 Composition Root 在建立首个文本消费者前触发国际化初始化：读取并校验正式 JSON → 建立查找索引 → 按基线策略确定当前语言 → 准备适用字体及已采用的图片文字资源 → 进入就绪状态并完成首次绑定。当前语言采用已确认策略，例如“有效的用户持久化选择 → 项目声明的系统语言匹配 → 默认语言”；具体匹配规则由统一服务执行，不能散布到组件。

只有依赖本地化内容的显示等待该服务就绪，不等待无关广告、统计等 SDK 完成。未就绪时不得先显示文案键、空翻译或硬编码多语言再跳变；配置读取、解析或校验失败保留可定位错误和受控失败状态，不宣称初始化成功。重复请求和场景重新进入复用同一服务及进行中的初始化，避免重复加载、重复订阅或多份当前语言。

S00 的就绪/失败结果和行为证据沿现有工作项、质量报告及独立审查记录；不增加控制器状态或将文档约定冒充已自动执行的机器门禁。首次功能通过不代表全部字体、布局或最终显示已验收，后续阶段继续按实际范围验证。

## 固定 JSON 模板

项目语言清单继续采用 `{"languages":["zh-CN"],"defaultLanguage":"zh-CN"}`，以用户确认的实际范围为准。文案使用 UTF-8 JSON 文件，固定结构见 [文案模板](../assets/localization-catalog-template.json)，字段约束见 [Schema](localization-catalog.schema.json)。模板的中英示例不授权给单语项目追加英语。

正式文案配置建议位于项目 `Assets/Localization/catalog.json`，由项目现有资源加载入口读取为 TextAsset 或文本；按目标平台支持的方式异步加载，不把 `Assets/` 当作构建后的文件系统路径。可采用项目已选的序列化引用或 Addressables，不为读取文案强制引入新加载框架。解析器应直接支持模板中的对象和数组，不在各组件复制文件加载、解析与缓存逻辑。

- `schemaVersion` 固定为 `1.0`；`languages` 和 `defaultLanguage` 必须与项目语言清单一致。
- `entries` 以稳定且唯一的 `key` 标识文案；`parameters` 声明命名参数；`values` 逐语言包含 `locale` 和 `text`，必须完整覆盖所选语言，禁止多出、重复或空翻译。
- 插值仅使用 `{name}` 命名占位符，每种翻译的参数集合必须与 `parameters` 一致；不执行表达式或代码。当前固定模板不声明 ICU、复数或条件表达式能力，需要时另行确定数据规范，不能把任意表达式塞进文案执行。
- JSON 是唯一可编辑翻译源。若项目继续使用 Unity Localization，其 String Tables 仅能由 JSON 单向生成或导入，保留可重建关系，不再手工维护第二份内容；生成后同样检查语言、键、文本和参数一致。

## 运行时职责

统一加载服务读取并校验配置，按文案键和 Locale 建立查找索引；统一语言服务持有当前语言和切换事件，按项目语言范围解析启动语言及持久化选择。启动策略须明确默认语言、系统语言匹配和用户选择的优先级，不能由各文案消费者各自决定。

所有文案消费者仅提供文案键和业务参数，交给统一绑定入口更新原生文本、图片表现或可访问语义；显示组件、业务模块、公共组件及动态生成内容均适用，不要求组件具备特定名称或专门标记为“国际化组件”。禁止在消费者中通过语言 `if`、`switch`、三元运算或内联多语字符串选择翻译；按业务状态选择不同文案键仍是正常业务逻辑。语言匹配、文案查找与图片资源选择集中在统一服务/适配器。参数使用真实业务数据统一格式化，不拼接翻译句子；玩家输入、名称等原始数据不被当作翻译文案改写。

UniText 默认通过统一 `IUniTextResolver` 接入，正式 Scene/Prefab 保存键，解析器返回翻译；语言或参数变化时按所装版本 API 通知刷新。动态生成的列表、对话、世界文字等同样复用该绑定与文案源。若使用 JSON 派生的 Unity Localization String Tables，可通过 `LocalizeStringEvent` 绑定 `SetText`，但同一个文本只能有一个内容写入者，不再并行接入第二个解析器。

图片适配器消费同一 JSON 文案键、已解析语言、状态与格式化结果，在项目资源映射中选择对应图片或组合字形；不把资源映射当作可手工维护的第二份翻译。固定文字逐语言/状态生产变体，动态内容用可组合字形或明确有限的图片状态，保留真实更新。记录资源身份、来源文案与生成依据，文案变化后重制并验证所有受影响映射；语言、参数和生命周期变化复用同一刷新入口。图片文字的原生效果缺口、资源内容、切换、可访问语义和显示效果分别取证，配置 CLI 不证明图片与 JSON 一致。

加载完成并校验成功后再显示依赖文字；解析失败不得当作空表继续。切换时先准备目标语言配置与字体，再统一更新绑定，避免同屏混合新旧语言。组件启停、池化和销毁正确订阅、补刷与取消订阅；异步结果必须确认仍对应当前语言与当前实例。配置缺键、缺参数或缺翻译需报告可定位错误，禁止回退到组件里的硬编码翻译；开发阶段明确暴露失败，交付前修复，不用默认语言掩盖未完成翻译。

## 验证与证据

先运行固定配置校验：

```sh
node .agents/skills/unity-development-workflow/scripts/validate-localization-catalog.mjs <项目语言清单.json> <正式文案配置.json>
```

同时保留现有 `check-project-locales.mjs` 的逐合同检查。JSON 校验只证明配置结构与内容约束，不证明插件安装、所有文案消费者已绑定或实际运行通过。

共用验证覆盖实际配置加载、启动语言、所选语言的完整键覆盖、参数/状态变化、切换及重新进入/池化后的更新、最长文案与内容边界。原生路线另验实际字体回退、字形、基线和行高；图片路线另验真实图片/组合字形资源、JSON 文案键及语言/状态映射、实际内容与切换/组合更新，不要求 Image 提供原生文本属性。按所有实际显示/语义入口检查覆盖和语言分支翻译，不限定 HUD 或名称带“国际化”的组件；配置校验器不自动证明这些行为。未运行的平台和人工显示确认单独记录，未经授权不发起真机验收。

Toolkit 的布局测量可检查受支持屏幕 Canvas 内的 UniText 容器几何，但当前组件快照不采集文字内容、字体、字形或语言绑定，不证明文字适配通过。独立 UniTextWorld 及 World Space Canvas 须另取真实对象、组件和布局证据；Game View 最终帧可能包含它们，但当前 UI 覆盖统计不完整识别这些对象，`NO_RUNTIME_UI_FOUND` 也不代表最终帧没有文字。截图显示仍由用户人工检查，详见[布局测量边界](ui-layout-runtime.md#文本与世界文字的取证边界)。

UniText 路线不创建 `TmpFontAtlasPlan`，不以 `uwt_validate_font_locales` 的 TMP 报告证明 UniText 通过。只在采用 Unity Localization 时使用其启动观察器，并在原初始化取得未完成操作后接线；自有 JSON 语言服务直接记录真实启动与切换结果。

当前 Unity Workflow Toolkit 为保留 TMP 回退工具，包和程序集仍附带 Unity Localization、TMP 等依赖；依赖存在不代表启用 String Tables 文案源，不要求 UniText 项目创建 TMP 图集或接线 Localization 初始化。Toolkit 并未提供本方案的项目运行时 JSON 加载服务、UniText 解析器或绑定组件；在具体工程按已装插件 API 实施并验证，不能把技能模板和 CLI 检查当作已有运行时实现。

官方依据：[UniText 组件与本地化](https://unity.lightside.media/unitext/docs/getting-started)、[IUniTextResolver](https://unity.lightside.media/unitext/docs/api/IUniTextResolver)、[商店及依赖要求](https://assetstore.unity.com/packages/tools/gui/unitext-text-engine-for-unity-357844)。具体 API 和依赖以项目安装版本为准。
