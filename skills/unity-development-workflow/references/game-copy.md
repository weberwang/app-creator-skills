# Unity 游戏内文案

本指南覆盖 HUD、按钮、弹窗、奖励、Toast 和状态反馈中的交互与状态信息。它复用现有 V0–V5 阶段、阶段人工确认及美术质量/动态体验验收，不新增文案审批门、Schema、关键词计数器或词库门禁。

- 通用工作流步骤见[完整规范](../../app-domain-toolkit/references/ui-game-copy.md#游戏内文案)。

- 同一表达在 HUD、弹窗、Toast 和奖励浮字中保持一致；只有显示状态、数据或语气确有区别时才采用不同文案。

## 资源拆解与界面实现

- 通用工作流步骤见[完整规范](../../app-domain-toolkit/references/ui-game-copy.md#资源拆解与界面实现)。

Unity 的文字拆解发生在 V3，节点显示内容与来源指向玩家可见表达。
- **文字来源**：按[文字路线判定](./visual-decomposition-routes.md#文字路线判定)区分低显著性系统文本、固定美术字图与可复用字形风格。路线变化不删改文案，系统文本保留独立拆解编号，动态数值与本地化保持可变；既定字形和效果不得在实现时静默简化。
- **V4 组合**：按已确认文字路线装配；系统文本使用项目选用的 uGUI/TextMeshPro（TMP）或 UI Toolkit `Label`/`TextElement`，固定美术字图、复用字形与效果依赖按各自资产路线接入，文案语义由原功能组件保留。动态数值和本地化文字来自同一玩家可见表达及真实玩法数据，不直接绑定 GDD、brief 或验收描述。动态/本地化文字不烘焙进固定图片。
- **V5 运行**：验证正常运行与适用的重复反馈、事件峰值、同屏叠加情境中，文字、数值、条件和来源是否正确；沿用[美术质量合同](./art-quality-contract.md)和[阶段人工确认](../../unity-domain-contracts/references/stage-confirmation.md)，不以本指南取代既有人工验收。

消费时按以下约定保持显示内容与运行状态一致：

- 动态数值读取权威玩法状态或已确认的事件参数；效果图代表值只用于表达布局，不作为实现常量。
- 数值格式、单位、正负号、倍率和精度按玩家可见表达及项目现有本地化规则转换；不要通过拼接内部调试说明补足上下文。
- 同一状态在首次进入、数值变化、暂停/恢复或事件重播后仍应显示当前真实值；按 Work Item 的行为范围验证适用状态。

Unity Localization 项目使用现有 String Tables 与插值方式维护相同表达和显示条件；未采用该包的项目沿用已有本地化方案。不要把图标/符号重新扩写成解释句。逐项验证项目选择的语言：默认 `zh-CN`，英语 `en` 等其他语言按初始化决定追加：

- 检查每种语言的实际必要翻译、字体回退、容器适配及单行/换行策略。
- 用实际必要翻译中占用空间最长的表达及合理边界输入检查布局、换行并确认无截断；最长表达按具体节点和显示状态判断。
- 不为适配凭空增加说明段落；遇到空间不足时先按现有布局与文案取舍流程处理。

按当前项目 UI 技术和可用的无障碍实现检查图标控件名称、焦点与必要反馈；没有实测的辅助技术支持标记为未验证。
