## 资源拆解与界面实现

- 通用工作流步骤见[完整规范](../../app-domain-toolkit/references/ui-game-copy.md#资源拆解与界面实现)。

Unity 的文字拆解发生在 V3，节点显示内容与来源指向玩家可见表达。
- **文字来源**：按[文字路线判定](./visual-decomposition-routes.md#文字路线判定)区分原生文字、效果无法还原时的图片文字、可复用字形与品牌图形。路线变化不删改文案，系统文本保留独立拆解编号，动态数值与本地化保持可变；既定字形和效果不得在实现时静默简化。
- **V4 组合**：按已确认文字路线装配；原生文字默认先评估 UniText，按[完整还原标准](visual-decomposition-routes.md#完整还原的判断标准)核实路线，未核实则待验证；实施前检查安装，异常时由用户选择修复或回退 TMP，详见[文本与 JSON 国际化](text-and-localization.md)。无法原生还原效果的文字直接采用图片，图片文字、品牌图形、复用字形与效果依赖按实际路线接入，文案语义由原功能组件保留。动态数值和本地化文字来自同一玩家可见表达及真实玩法数据，不直接绑定 GDD、brief 或验收描述。固定本地化文案可从 JSON 生成语言/状态图片；动态数值和插值采用可组合字形或明确有限的状态变体，不能固化为不再更新的结果。
- **V5 运行**：验证正常运行与适用的重复反馈、事件峰值、同屏叠加情境中，文字、数值、条件和来源是否正确；沿用[美术质量合同](./art-quality-contract.md)和[阶段人工确认](../../unity-domain-contracts/references/stage-confirmation.md)，不以本指南取代既有人工验收。

消费时按以下约定保持显示内容与运行状态一致：

- 动态数值读取权威玩法状态或已确认的事件参数；效果图代表值只用于表达布局，不作为实现常量。
- 数值格式、单位、正负号、倍率和精度按玩家可见表达及项目现有本地化规则转换；不要通过拼接内部调试说明补足上下文。
- 同一状态在首次进入、数值变化、暂停/恢复或事件重播后仍应显示当前真实值；按 Work Item 的行为范围验证适用状态。

翻译唯一来源为[固定 JSON 文案配置](text-and-localization.md#固定-json-模板)，由统一服务读取并通过键、命名参数绑定原生文字或图片表现；所有文案消费者均禁止按语言条件内联翻译，不限组件或显示位置。Unity Localization String Tables 如有使用，必须由 JSON 单向派生，不能手工维护第二份文案。不要把图标/符号重新扩写成解释句。逐项验证项目选择的语言：默认 `zh-CN`，英语 `en` 等其他语言按初始化决定追加：

- 检查每种语言的实际必要翻译与所选路线依赖：原生核对字体回退，图片核对资源及语言/状态映射和更新；均验证容器适配及已声明的单行/换行策略，不向图片套用原生字体属性。
- 用实际必要翻译中占用空间最长的表达及合理边界输入检查布局、换行并确认无截断；最长表达按具体节点和显示状态判断。
- 不为适配凭空增加说明段落；遇到空间不足时先按现有布局与文案取舍流程处理。

按当前项目 UI 技术和可用的无障碍实现检查图标控件名称、焦点与必要反馈；没有实测的辅助技术支持标记为未验证。
