# S00 基础工作流

## 何时读取

全局技术基线与项目语言范围确认后、正式场景实现前，或基础能力需要变更时读取。国际化初始化与代表性功能验证在 S00 完成，不等待全局视觉稿或全部对象 V2–V5；正式字体外观与布局仍在对应视觉阶段确认和验收。

## 输入

- 已通过的项目发现、用户确认且状态为 `APPROVED` 的 `project-profile` 与 `decomposition-plan`、module-manifest、场景 DAG 和当前有效的 Visual Bible。视觉稿未冻结不阻塞已确认技术与语言范围内的国际化基础实现，不提前宣称视觉验收通过。
- 已确认的项目语言清单、固定 JSON 文案配置路径及本批真实文案，TDD 中的唯一初始化入口、语言优先级和统一绑定接口；具体规则按[国际化初始化时机与阶段职责](text-and-localization.md#初始化时机与阶段职责)。
- 全部场景 manifest 草案与共同能力清单。
- 已按 `unity:unity-cli` 当前规则发现并唯一绑定的 Unity Editor 目标。

## 执行步骤

目标包含 Android 或 iOS/iPadOS 时，在基础工程内按[系统启动屏规范](../../app-domain-toolkit/references/system-launch-screen.md#任务安排与完成条件)落实平台配置与随包资源、首个稳定帧衔接、工程检查及用户人工显示检查三项任务。Unity 内建 Splash 是引擎画面，单独核对与系统启动屏、首场景之间的重复及闪屏，遵守锁定版本和许可要求；Editor/Game View 不能证明原生启动链路通过。复用现有技术方案、路径和验证记录，不增加视觉阶段门。

1. 深度校验当前拆分决策的对象 ID、用户确认、模块/场景边界、恢复出口和活动指针；确认仍处于批准状态且用户确认覆盖当前实际范围。版本号、`sourceRevision`、`projectStateVersion` 用于识别来源与记录变更，不单独构成失效或验收阻断条件；只有批准范围实质变化、确认已撤回/被拒绝或对象身份不明时才停止 S00。
2. 创建 S00 任务并冻结共享骨架范围。
3. 建立最小目录、程序集、Composition Root、启动入口、场景加载、输入、时间/随机抽象、配置、存档版本边界、uGUI/UniText 基础、固定 JSON 文案加载与统一语言绑定、公共安全区适配、日志与测试骨架。屏幕 UI 统一复用 Toolkit 的 `SafeAreaRectTransform` 或 `SafeAreaVisualElement`；全屏背景和遮罩留在安全区节点之外。游戏显示默认全屏；尺寸、方向或安全区变化后重算显示与输入映射。目标包含 Android 时，纳入冷启动无系统标题栏、沉浸式全屏，以及应用恢复前台/窗口焦点后重新建立沉浸显示的要求。
4. 国际化作为项目级启动基础能力在 S00 完成，不以两个场景共同消费为前置；即使单场景项目也须落实[国际化基础能力验收](#国际化基础能力验收)。其余可复用业务能力仍须由拆分决策证明至少两个场景共同需要，避免预建空壳。
5. 项目采用的 SDK 必须通过[TDD 中唯一映射的统一初始化入口](./sdk-initialization.md)独立投递初始化任务；不等待 SDK 批次完成再显示首帧或启动首个场景，也不绕过 SDK 自身真实官方前置。
6. 按[产物存放规则](./artifact-storage.md)固定源文件、正式资源、临时/候选文件、人工审阅/验证、确认成果和机器 `evidenceRoot` 的路径；冻结引用不得为目录整理批量迁移。
7. 可并行准备不写 Unity 的契约、测试清单和资源说明。
8. 串行执行 asmdef、场景、资源和共享状态的 Unity 正式写入。
9. 运行 Schema、静态、编译、Console、EditMode 与 PlayMode 基线。
10. 通过 `unity:unity-cli` 为 `primaryDevelopmentPlatform` 生成可启动空壳构建，记录平台、Build Profile、场景列表、脚本后端、选项和任务结果；该构建只证明主开发平台基线，不代表其他目标平台已适配。
11. 独立审查 S00 证据，通过后选择代表性场景进入 G1 垂直切片；不得把空壳骨架本身视为垂直切片完成。

## 子代理角色与并行边界

- 契约、测试设计和资源盘点可由子代理并行准备。
- Foundation 开发代理串行写入 Unity；QA 代理和架构审查代理独立验证。
- 后续场景代理可以只读准备需求，但不得提前写正式共享状态。

## 所需锁与 Unity 权限

- S00 是全局骨架代码的正式实现时点，写入持有 Foundation、Shared 和启动场景路径的独占锁。
- 任何写调用前按 `unity:unity-cli` 当前规则复核唯一目标，并显式绑定项目绝对路径。
- 空壳构建阶段持有构建输出目录独占锁。

## 机器可读输出

以 `schemas/s00-report.schema.json` 和 `templates/s00-report.yaml` 输出 `s00-report.yaml`。国际化实现记入 `scope`、实际 `changedPaths` 和 `qualityReports`，后者引用本次真实初始化、运行绑定和错误路径证据；不得仅凭配置 CLI 成功填报通过。`sharedCapabilities` 只列有至少两个场景需求的可复用业务能力，不为国际化伪造第二个场景。报告其余拆分、模块、Console、构建与独立审查沿用现有字段。S00 进入 `PASS` 前由 Codex 核对当前对象身份、批准范围、实际变更及证据，通过实际插件/API 回读 Unity 事实；Toolkit 未提供的 UniText 信息按实际可用入口补证，不用 TMP 报告代替。SHA/hash 不作为验收硬门。

## 通过条件

- 最小骨架可编译、可运行且 Console 无新增错误。
- [国际化基础能力验收](#国际化基础能力验收)逐项完成，有本项目真实配置及最小宿主运行证据；初始化或统一绑定未完成时，S00 不得记为 `PASS`。
- 游戏显示为全屏，且尺寸、方向及 `Screen.safeArea` 改变后显示与输入映射正确更新；需要屏幕 UI 时，HUD、页面与弹窗内容均复用公共安全区边界，装饰背景仍可覆盖全屏。
- 目标包含 Android 时，冷启动没有系统标题栏并启用沉浸式全屏；从后台、失焦或系统窗口变化恢复后重新应用显示状态。未获明确设备验收请求时保留设备运行状态为 `NOT_RUN`，不自动启动真机。
- Android/iOS 目标的系统启动配置与资源、首帧衔接和相应工程验证按[系统启动屏规范](../../app-domain-toolkit/references/system-launch-screen.md)检查；实际显示由用户人工确认，未执行的运行或设备检查如实标记未验证。
- 音频生命周期通过暂停原因集合实现幂等暂停与原位置续播；全部阻断原因解除前不恢复，已停止/销毁播放不复活，后台新播放请求不补播。目标平台的真实系统回调证据按用户授权的验证方式记录。
- EditMode、PlayMode 基线和主开发平台空壳构建实际通过。
- 拆分决策仍为当前批准版本，模块清单与场景草案未越过用户确认边界。
- 列入 `sharedCapabilities` 的可复用业务能力均有至少两个场景的需求证据；国际化等已明确的项目级启动基础能力按自身验收记录，不伪造消费者。独立审查已批准。

## 国际化基础能力验收

1. **实际插件可用**：记录 UniText 版本、包来源、依赖、程序集与组件/字体/材质检查，编译及 Domain Reload 无相关错误，并实际调用本工作项所需绑定能力。安装异常须先由用户选择修复或 TMP 回退；选择 TMP 时验证其可用性，后续仍使用同一 JSON 源，未决定时相关项保持未完成。
2. **正式 JSON 可加载**：从登记的项目正式路径和加载入口读取固定模板配置，校验语言范围、默认语言、键唯一性、逐语言翻译及命名参数，建立实际查找索引。记录真实文件、加载方式和校验结果，不能用内存样例或硬编码翻译替代。
3. **启动状态可验证**：唯一入口落实已确认的启动语言优先级；实际记录所用语言来源和最终语言。正式文案就绪前不展示依赖文本，损坏/缺失配置不会被当作空表成功；重复初始化或重新进入不会创建第二套服务与订阅。
4. **统一绑定可运行**：最小运行宿主中代表性消费者以文案键和真实参数驱动已选文本表现（默认 UniText；用户明确选择回退时为 TMP；无法原生还原效果时为图片），首次显示和参数变化均来自同一 JSON。多语言项目验证切换后所有已挂载的代表性消费者更新；单语项目验证默认语言、重复选择及参数刷新，不为测试追加语言。按实际存在的动态创建、禁用/重启用和池化消费验证补刷与取消订阅，不新增无业务用途的显示对象凑数。
5. **失败和范围不被掩盖**：对缺键、缺参数、缺翻译及配置错误执行可重复的定向检查，保留可定位失败和受控结果；不通过组件语言分支、硬编码多语或默认语言掩盖缺失。检查覆盖本批所有文案消费入口，不限定 HUD 或名称带“国际化”的组件；完整项目覆盖留到后续功能及集成阶段。
6. **证据可追溯**：现有 `qualityReports` 引用真实命令/API、目标工程、配置与场景/对象、执行结果及未覆盖范围；独立审查核对上述链路。配置校验或容器几何通过不能替代运行绑定；截图显示仍由用户检查，未执行的目标平台、视觉或设备检查单独记录，不自动启动真机。

上述条件是 S00 实施与审查要求，现有报告 Schema 仅检查材料结构，不会自动执行插件安装、JSON 加载、绑定或行为验证。缺少所需运行环境或证据时如实保持相关项未完成，不把模板存在当作验收通过。

S00 的代表性绑定验证只证明本阶段启动与文案服务链路，不冻结未来各对象的文字视觉路线，也不证明任意标题效果已完整还原。具体目标仍按[四维标准与三种结论](visual-decomposition-routes.md#完整还原的判断标准)核实；未核实的目标保持待验证，不因 S00 已通过就自动归为原生。

## 失败与恢复出口

- 骨架失败时保持 S00，不得启动正式场景写入。
- 非共同能力下沉到所属场景后重跑门禁。
- 共享接口变化时重新编译 DAG，并评估所有场景影响。
