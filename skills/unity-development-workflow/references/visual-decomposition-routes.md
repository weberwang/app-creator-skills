# 文本与色彩拆分路线

在 V3 拆解冻结效果图、选择视觉来源时使用；V4 资源生产和组合、V5 接入沿用同一拆解结果。本文只补充路线判断，使用既有 `visualRouteAnalysis`、`assemblyAnalysis`、`layoutBinding` 和资源记录，不新增 schema、阶段或审批。

## 完整拆解与视觉显著性

以已确认的 V2 为持续目标，逐项识别显著文字造型、图标、底板、色彩填充、边框、光影、装饰和空间结构，不能仅按标题、按钮、数值等功能名称列清单。每个可见特征须对应稳定编号，明确独立生产、复用、原生实现，或包含在某个原子资源内，并绑定消费节点及出现、变化的状态。系统文本及原生填充也必须进入拆解与图内标注；没有生产归属的可见特征属于拆解缺口，不能等用户逐项发现。

完整指职责与覆盖完整，不预设图片数量；同一原子部件内不可可靠分离的材质、边框和光影可合并生产，在该编号中明确所含特征，不按每个字、每种颜色或每个细节机械切碎。空间结构通过所属编号及节点间的位置、比例、层叠和留白关系记录，不必虚构图片。拆解是识别与独立生产；禁止裁切或抠取参考图作为正式资源，不解除对目标外形与构图的保留要求。

先判断视觉作用、特征显著性、内容变化与复用需求，再核对项目实际渲染能力。文字默认按 [UniText 与固定 JSON](text-and-localization.md)绑定，字体、材质与效果能够完整还原目标时使用原生路线；不能完整还原的文字效果直接走图片路线，保留已确认外观，不降级效果。可分离的非文字材质、纹理、轮廓、光影、填充和边框统一遵守[正式视觉实现优先级](../../app-domain-toolkit/references/reference-asset-asset-production-routes.md#正式视觉实现优先级)。可翻译文案无论采用哪条路线都来自同一 JSON，不把图片当作第二份翻译源。

拆开视觉来源不拆散功能归属。按钮、进度条等仍由原组件统一管理点击热区、输入、状态、动态更新、本地化、显隐和生命周期；装配按[节点树与组件分组](./ui-layout-and-hierarchy.md#细组件分组)记录真实依赖。位图与原生节点可以属于同一功能组件，但分别登记来源，不能用单一区域 `COMPOSITE` 隐藏混合来源，也不能把完整组件或整屏烘焙成不可交互的图片。

默认 `usability` 下，非文字的简单填充可在既有容差内说明轻微装饰差异。文字不因“低显著性”获得更换目标字体或简化效果的授权，始终按下述完整还原标准核对；超出已确认目标或容差时先更新受影响依据，不能靠用途或显著性降级。`exact` 或指定字体、效果时遵守对应精确要求。路线和依据写入既有分析与 brief，沿用阶段确认；实际显示由用户检查，技术检查不代替视觉验收。

## 文字路线判定

文字默认先评估 UniText，先按[文本与 JSON 国际化](text-and-localization.md)检查实际安装，异常时由用户选择修复或回退 TMP。默认评估不代表已验证原生还原：确认完整还原后采用原生，确认有无法还原的具体缺口后直接图片，尚未核实则待验证。两条路线复用相同文案键、JSON 和业务参数。编辑器 UI Toolkit 不属于 UniText 直接替换范围，不能默认不同组件支持相同效果。

### 完整还原的判断标准

唯一判据是：当前项目实际选用的原生文字方案，能否完整还原已确认的目标效果，并在要求的显示与内容变化条件下保持正确。以目标、实际字体/材质、插件版本和真实实现为依据，不按画面观感或效果名称直接分类。

| 维度 | 核对内容 |
| --- | --- |
| 字形 | 字体轮廓、字重、字距、字面比例、倾斜及定制变形是否符合目标 |
| 效果 | 填色、渐变、纹理、描边、阴影、发光、立体厚度、跨字装饰及组合关系能否完整实现 |
| 排版 | 实际尺寸、字号、行高、对齐、换行和缩放条件下是否保持目标效果，不以截断或失真掩盖失败 |
| 变化 | 项目所选语言、文字/数值更新及适用状态变化后，字形覆盖、效果、排版和绑定是否仍正确；仅核对实际需要的变化 |

按当前已确认目标及既有容差核对，不另造统一像素阈值。“支持渐变/描边/阴影”等功能名称不能证明效果已还原，复杂材质或定制字形也不能单凭“看起来像图片”判定原生不可行。生图、设计稿、宣传图或一张 PNG 只表达外观，不能证明采用了哪种运行时实现。

### 判定结果与证据

| 已掌握的实际情况 | 结论与处理 |
| --- | --- |
| 已验证当前原生方案完整满足上述适用维度 | 采用原生路线，保留字体、材质、参数、实现和有效验证依据 |
| 已确认原生方案存在无法完整还原的具体缺口 | 直接采用图片路线，记录缺失效果及依据，保留已确认外观，不简化目标 |
| 尚未核实或证据不足 | 标为待验证，安排与缺口相关的最小能力核查；不宣称原生可用，也不把缺少证据当作已经不能实现 |

V3 冻结路线前，记录目标版本、实际 renderer/字体/材质、代表性内容和显示条件，以及命令/API、实现检查或有效实测结果。同项目、同目标和实现条件下仍有效的证据可复用；只有理论可行、组件存在或显示相同文字不构成完整还原证据。已有明确不支持依据时直接转图片，不要求重复无意义的试错。

技术事实由实际实现和运行记录支撑；目标与实际画面的字形、材质及整体显示效果由用户人工对照检查。未完成相应显示确认时保留未确认项，不由代理分析截图或以配置/构建成功宣告视觉通过。待验证是分析与交接状态，不是新的 `selectedRoute` 枚举或控制器状态；路线未决时在既有 brief/工作材料中记录缺口，不伪填原生资格、资源或证据，核实后再冻结正式路线。

| 文字特点 | 拆分与实现 |
| --- | --- |
| 操作标签、正文、提示或数值 | 默认评估 UniText；核实完整还原能力后确定原生，未核实则待验证，确认不能还原则直接图片。登记字体、样式、内容来源与统一 JSON 绑定，不凭文字用途决定路线。 |
| 带金属质感、裂纹、立体光影或跨字装饰的标题与提示 | 核实原生字体、材质与效果；能完整还原时使用 UniText，不能完整还原时直接生产独立文字图片，可分离底板、徽章和非文字装饰另行登记。 |
| 需要更换文案、本地化或多处复用的统一字形风格 | 能还原时复用 UniText 字体栈；不能还原时按已定义语言/状态生产文字图片变体，或以字形图片/位图字体组合变化内容。保留同一 JSON 文案键、参数与语义。 |

显著文本使用 `UNITY_NATIVE` 时，机器条目以 `elementType: text` 和仅含 `TEXT` 的 `nativeSuitability.primitiveBasis` 标识纯文本对象；如实填写 `isDistinctive: true`、`NATIVE_ALLOWED` 和实际资格证据，不为通过校验把显著性改成 false。可分离底板、几何、Shader 或装饰使用独立条目，不能混入文字原语借用例外。该声明只允许表达原生文字路线，不证明已安装 UniText 或已完成 JSON 与运行绑定。

当前字体和 renderer 必须实现目标要求保留的字形、字重、倾斜、填色/渐变、描边、阴影、发光、材质与排版，并提供字体/材质来源、实际实现方法及可核验依据。采用 UniText 本身不证明效果已还原，能显示同样文案、同名字体或存在文字组件也不足以证明。确认不能完整还原时记录具体缺口并直接切图片路线，沿现有 V3–V5 更新生产与装配记录，不另设路线选择审批；涉及目标本身变化时仍更新受影响依据。不得删去效果、猜用默认字体或提高容差规避图片生产。

固定文案的图片按 JSON 中实际翻译和已定义状态生成，统一绑定按文案键、当前语言与状态选择正式资源；翻译或效果变更后同步重制图片与映射。动态数值、插值、名称与输入采用可组合字形图片、位图字体或已定义的有限状态图片，不把任意变化内容冻结成一张固定图；逐语言核对字形覆盖、字距、换行与效果，无法覆盖的内容如实记录未完成。非翻译品牌图形可保留完整图片。所有路线均保留原组件的可访问语义、交互、布局和生命周期。

图片文本的视觉来源登记 `elementType: text`、`selectedRoute: IMAGE_ASSET`；记录原生能力不满足的原因与证据，生产、交付和所有者字段遵守既有图片合同。符合目标且有真实身份绑定的现有图片可登记为 `REUSE`。实际 uGUI Image 视觉节点按 `renderKind: SPRITE` 和图片尺寸计划测量，不能伪标为原生 `TEXT`；文案键、语言、状态和语义由统一绑定与功能组件持有。映射沿项目资源配置及生产记录登记，不向现有受限 Schema 填入未声明字段，也不宣称 Schema 已自动校验图片文字与 JSON 一致。

例如战斗失败弹窗：「战斗失败」的金属字形与跨字火光若无法原生还原，直接生产按语言/状态绑定的标题图片；普通提示与「返回」能还原则使用 UniText。三者文案均来自 JSON，可分离底板独立登记，仍由原功能组件统一管理交互和状态，无需把标题伪称为品牌图形才能走图片路线。

字体、多语言与响应式接入遵守[文本与 JSON 国际化](text-and-localization.md)及[文本与响应式合同](./visual-workflow.md#文本与响应式合同)，TMP 图集仅用于用户选择的回退。参考图物理像素不能直接当作组件字号；结合 CanvasScaler、PanelSettings、实际字形度量与容器验证，保留字体来源事实，不把替代字体冒充原字体。

## 色彩填充路线判定

下述填充与非文字装饰沿用其视觉来源规则，不能据此推断文字路线。文字单独按完整还原标准判断；填充则核对颜色与材质、光影的视觉作用及实际实现能力，按适用约束依次评估已验收素材、独立制作和程序绘制。颜色和静态或动态属性均不能单独决定路线。

| 填充特点 | 拆分与实现 |
| --- | --- |
| 明显金属、玻璃、纹理、立体光影、复杂辉光或不规则色面 | 将材质表面独立生产为位图；与边框、装饰可可靠分离时分别登记，否则保留完整原子部件。 |
| 有统一风格、需多处复用的渐变或纹理表面 | 优先复用已确认的填充贴图，按实际需要使用九宫格、遮罩或分层装配；显示变化由组件控制，保留已确认的表面风格。 |
| 视觉特征不明显的纯色、透明色、简单规则渐变或规则边框 | 先评估可复用或独立制作的素材。素材无法满足已确认约束时，再记录原生绘制的形状、颜色、透明度、边界和适用状态，以及当前 UI 系统的实际实现依据。 |

拆开的填充、边框和装饰共用原组件的形状边界、圆角、裁切、布局与状态来源，避免接缝、重复叠色或透明度叠加。进度比例、选中/禁用颜色保持运行时可变；位图负责风格表面，程序负责实际比例或状态。填充与光影无法可靠分离，或拆分会损伤功能和既定外观时，保留完整部件并记录原因，不为减少位图强行拆分。

## 合同记录与交接检查

- 字体、字形/效果贴图、材质、填充表面与九宫格按[公共资源登记与使用](./shared-asset-usage.md)先查库再选择复用或生产；复用资格须逐项核对 V2 所需的实际轮廓、比例、配色、材质及状态，主题或风格相似不足以证明合格。多个本地拆解编号可以绑定同一公共资源身份，资源交接同步总表与消费关系。纯原生样式参数引用已有规范和实现，不虚构资产文件或 GUID。
- `visualRouteAnalysis.distinctiveVisual` 如实记录显著性，`routeReason` 说明变化/复用需求和依据。非文字的明显美术特征沿用资产优先规则；显著文字仍按四维能力判断，可完整还原则原生，确认不能则图片，不能伪报 `isDistinctive=false` 获得资格。
- 已确定的 `UNITY_NATIVE` 在 `nativeSuitability` 记录实际原语、理由与证据，使用既有 `TEXT`、`BASIC_GEOMETRY`、`PROGRESS` 或适用原语；具体参数放入已有 brief、规格与验证材料，不向 Schema 添加未定义字段。文字确认不能完整还原时直接图片，未核实则保留待验证材料，不以伪造的 `eligible` 或证据通过正式合同；Schema 通过只检查声明结构，不证明四维实际还原或人工显示确认已完成。
- `BASIC_GEOMETRY` 的资格用于 UI/布局、技术占位/Blockout、碰撞代理及非模型资产的原生渲染载体；不能因为造型简单、风格化或低面数，就把新增正式可见 3D 模型改为 Unity 基础体或程序网格创建。此类模型选 `MODEL_3D` 并走[Blender MCP 生产流程](./3d-asset-workflow.md)；合格既有模型可按 `REUSE` 记录真实来源和验证。粒子/Shader/VFX 仍按其真实职责路由，不能借它们的载体资格绕过模型生产。
- `assemblyAnalysis`、`semanticGrouping` 与 `layoutBinding` 绑定每项消费节点、真实父级及功能组件；所含特征与状态覆盖写入既有分析、brief 和规格，不新增 schema 字段。V4 同屏组合核对文字/表面依赖、裁切、状态同步、命中和无遗漏，并按[美术质量合同](./art-quality-contract.md#追溯与检查边界)从 V2 反查全链路；V5 验证真实数据、本地化、比例与输入，运行截图及显示效果由用户人工确认。

上述检查沿用现有 V3/V4/V5 交付与确认。图片生成、字体授权、付费、外部写入及运行验证继续遵守各自既有边界；本文不授权自动分析 Unity 运行截图、启动 Player 或真机。
