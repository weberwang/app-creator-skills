# Expo 验证与交付

按实际变更与[公共验证等级](../../app-creator-workflow/references/verification.md)先说明 T0–T3、覆盖与命令，再自动执行普通本地检查。复用项目的测试、lint、类型检查与锁定工具，按实际项目脚本或可用工具选择；`npx expo-doctor` 可检查当前 Expo 配置和依赖，但会受网络及本地工具条件影响，未运行须说明，不能把无关脚本名假设为已存在。

页面按功能和适用平台验证路由、交互、加载与错误状态、取消/重复进入、辅助功能及实际状态变化。新增或修改共享组件还要覆盖其消费页面；SDK 修改核查配置、授权前置、原生自动初始化及失败隔离。截图采集只证明生成了文件，代理默认不分析画面或代填用户视觉结论。单元测试、打包、Expo Go、development build、Web、模拟器和真机各自记录真实范围，不相互冒充。

## 系统启动屏

Android、iOS 系统启动屏按[公共系统启动屏](../../app-domain-toolkit/references/system-launch-screen.md)制作；在已选择 Expo 路线时，以当前版本支持的 `expo-splash-screen` 配置与实际原生配置为来源，检查图标、背景、深浅模式、方向及目标平台资源。系统屏和应用内加载层各司其职，不默认增加 Logo 文本品牌页；可显示稳定首帧时结束系统屏承接，不等待非必要 SDK、广告或网络。

Expo Go 与 development build 不能完整代表实际 release 启动屏；最终显示采用适用的 release 构建并由用户检查。获取实际设备结果需要对应授权；不能以配置存在或编译成功代替原生显示通过。[Expo 官方说明](https://docs.expo.dev/versions/latest/sdk/splash-screen/)

## 打包、内购和商店素材

发布默认 `prepare`。先确认候选源码与依赖锁、应用身份、平台配置、签名所需资料、构建方式、输出和环境，再生成或核对用户授权范围内的本地产物；工程构建、候选、签名、上传与发布各自独立记录。EAS 本地或云端只是选用的构建方式，不能默认要求 Expo 账户或付费服务。

每次打包前按[内购 SDK 必要性](../../app-release/references/release-readiness.md#内购-sdk-必要性与移除)核查真实业务。无内购、订阅、恢复权益等消费时，移除专用 JS 依赖、原生桥接、config plugin、初始化及仅由其使用的权限/能力配置；追踪传递和共享依赖，更新锁文件并重建受影响原生候选，核对实际依赖和包内内容。保留共享消费者，不通过隐藏按钮或关闭开关冒充 SDK 已移除；真实购买、退款和商店更改不包含在普通验证中。

选定商店时按[截图与宣传图任务](../../app-release/references/store-marketing-assets.md#任务安排与完成条件)核对目标平台的当前要求、游戏或应用卖点及多图脚本，采集稳定候选的真实画面，制作需要的系列截图和宣传图；原始截图与加工文件分别保留，最终显示由用户确认，不自动上传或投放。

## 更新与环境

EAS Update 只在项目确需 OTA 时配置。记录对应环境、channel、runtime version、兼容构建及回退策略；涉及原生依赖、配置或原生运行时变化时，判断兼容性并为改变的原生运行时构建新包，不能依靠 OTA 注入原生代码。更新预览、正式推送和回滚均记录真实结果，执行更新或任何外部写入须有对应明确授权。[运行时版本](https://docs.expo.dev/eas-update/runtime-versions/)

## 清理与结果

按[公共清理规范](../../app-artifact-cleanup/references/project-cleanup.md)维护正式源、资源制作源、配置与仍被消费的证据；构建包和可再生缓存按实际用途、引用与授权处理。CNG 下可重建目录不等于已授权删除，直接维护的原生源码不能清理为缓存。构建输入含 `.easignore` 时检查其排除规则和最终上传归档，发布包若误含 `.agents/` 作为缺陷处理。

交付区分：结构/工程验证、原生或 Web 实际运行、用户视觉确认、待补材料以及真实外部操作状态。没有设备、平台工具、账户或对应授权时明确未执行，不降低既定验收要求来填 PASS。
