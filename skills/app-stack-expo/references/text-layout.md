# Expo 文本布局与适配

以项目锁定 Expo SDK 对应的 React Native 版本为准，遵循[公共文本宽度缩放与换行](../../app-ui-layout/references/relative-layout.md#文本宽度缩放与换行)。在正式组件或设计 token、对应布局规格中记录文字语义、基准字号、行高、容器宽高、换行和允许的适配策略；不能只在截图备注里填写。React Native 原生 `Text` / `TextInput` 的 `style` 使用 `fontFamily`、`fontSize`、`fontWeight`、`lineHeight`、`letterSpacing`、`textAlign` 等项目版本支持的属性，尺寸为逻辑单位；系统文字放大与物理像素换算按实际平台处理，不把截图物理像素直接写成字号。

## 策略与平台能力

- `fixed` 保持已确认基准字号，按需允许容器扩展、换行或滚动；标题和正文按确认的断行与层级显示，正文优先换行，长内容由有明确所有者的滚动区域承接。
- `bounded-shrink` 只用于确有明确空间限制、已声明触发条件和最小可读字号的单行样式；基准情况先满足设计，只有内容超出时才在所声明的上下限内缩小。按钮及关键操作文案不能依赖截断掩盖不可读或不完整。
- `Text` 的 `adjustsFontSizeToFit` 与 `minimumFontScale` 是组件属性，后者是在启用前者时限制最小比例（官方文档给出 0.01–1.0），不是字体大小或系统文字缩放倍率；以项目锁定版本、平台及实际测量确认可用范围，不假设 `TextInput` 或所有平台提供相同行为。`numberOfLines` 和 `ellipsizeMode` 控制行数与省略，不能证明内容完整或有界字号适配；Android 多行省略能力按项目版本的实际平台限制核查。
- 某平台缺少符合合同的内置能力时，在可用宽度和实际字体/文案下采用最小、有限的候选字号测量方案，仅在超出时选择不低于声明下限的可读值；测量失败或下限仍不适配时扩展容器、调整已确认布局或报告无法适配，不进入无限测量循环。输入框按其自身原生能力处理，不能把 `Text` 的缩放属性当作 `TextInput` API。

`allowFontScaling` 控制跟随系统文字大小；不得关闭它来抵消系统放大。`maxFontSizeMultiplier` 是允许系统放大时的上限，不是内容溢出时自动缩小，任何上限都须有明确的可访问性依据并验证；不能将其当成已完成动态文字适配。检查默认及系统放大设置，按平台实际行为核对输入、占位符、焦点与键盘遮挡。

## 字体与验证

字体文件、字重和注册或加载方式按项目实际资源链保留；确定本地字体是否在使用前就绪、失败时的替代字体、目标语言及动态字符是否有字形。字体缺失、回退或平台字重映射变化须重新测量，不能仅凭文件存在认定显示一致。

至少覆盖基准字号与确认断行、最长本地化文案、窄宽度、系统放大、固定和有界收缩的边界、输入框编辑与滚动；记录目标平台、版本、字体身份和实际运行或组件测量结果。布局测量与截图文件不代替用户对可读性和显示效果的人工确认；未经明确要求不自动分析截图。
