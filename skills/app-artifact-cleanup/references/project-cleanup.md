# 项目整理与产物清理规范

本规范供游戏、应用和工具项目共用。整理指可追踪地调整目录、命名与分类；清理指识别后移除过期或可再生文件。两者分别计划和验证，重构目录不能顺带扩大删除范围。

产物用途、目录映射、命名与送审前保存按[工作流输出文件规范](../../app-creator-workflow/references/output-files.md)核对；清理不重新定义输出位置，也不为规范目录迁移已确认或绑定文件。人工审阅、机器证据、制作源和正式项目内容分别追踪真实消费者，不能按某一个目录名称整体判定可删。

范围、路径归属、授权和验证证据遵循[公共执行协议](../../app-creator-workflow/references/professional-execution.md)。各栈现有的 `artifact-cleanup` 与 `artifact-cleanup-execution` 源工作流仍作为 Cocos、Phaser、Three.js 原生补充；本规范提供各栈共同维护的一份完整流程。

## 清理范围与交付边界

工作流记录与实际项目内容一起纳入当前任务范围的盘点，分别说明用途、消费者与可恢复性；移动／重命名、删除、提交排除和发布排除是不同动作，不能相互替代授权。

普通项目盘点、变更/体积统计和宽范围清理跳过[项目根 `.agents/` 本地工具目录](../../app-creator-workflow/references/workflow.md#本地工具目录与项目范围)，不跟踪、不提交、不打包，也不因安装/缓存变化要求业务清理。排除不等于删除授权；明确的技能维护任务再单独限定范围，业务工作项/证据不能借此隐藏在工具目录。

| 范围 | 需要识别的内容与边界 |
| --- | --- |
| 工作流记录 | 计划、实施包、执行结果、确认、Evidence Manifest、原始输出、候选及预览；按下文有效引用与冻结规则保留 |
| 源码与配置 | 已被替换的实现、重复模块、临时调试入口、过期配置与脚本；须证明功能已替换／取消且实际消费者已迁移，不能顺带删减有效功能 |
| 场景与资源 | 临时场景、占位素材、重复资产及失效引用；核对动态消费者、共享所有权、生成源和原生导入身份 |
| 测试与文档 | 过期夹具、废弃测试入口、断链和重复材料；区分仍用于回归／恢复的历史样本与确已失效内容 |
| 构建与缓存 | 可再生成产物、临时导出、缓存与旧包；记录输入、版本、命令和恢复条件，正式交付／诊断所需产物不能只因可重建而删除 |

临时素材、占位实现和调试内容在正式交付前逐项替换、移除或记录保留用途；有意保留的诊断入口、测试夹具与样例不因名称含 debug、temp 或 old 就成为删除对象。目录名、日期、大小、内容相同或搜索无命中均不能单独证明可删；相同内容可能有独立路径、许可、身份或消费者。

| 去向 | 判定依据 |
| --- | --- |
| 本地保留 | 当前运行、检查、恢复、续接、并行任务或诊断所需的文件必须仍可读取 |
| 纳入提交 | 用户明确要求提交时，逐路径选择当前项目及有效工作流依赖所需内容；未跟踪不等于无用，不自动添加忽略规则掩盖必需文件 |
| 进入发布包 | 按真实构建与部署消费者选择正式内容；本地续接记录不因需保留就全部打包，排除发布也不代表删除本地源 |

## 清理任务拆解与安排时机

清理任务按[三项最小约定](../../app-creator-workflow/references/output-files.md#每项任务的最小约定)明确预期结果、允许路径／对象及完成条件／验证方式。当前代理默认负责，委派、并行或交接时才注明分工；有前置依赖时引用来源，涉及移动／删除时必须给出精确动作、消费者排除及恢复依据，不能因精简降低删除保护。下表按实际范围采用，不强制新增工作项、子代理、报告或控制器字段。

| 任务 | 责任归属 | 前置依赖与交付条件 |
| --- | --- | --- |
| 盘点清理范围 | 主编排者／模块负责人 | 明确本轮产物、工作区与活跃任务归属；交付目标路径、排除项和已授权动作 |
| 核对工作流记录 | 工作项负责人 | 从当前及仍有效的引用根追踪直接／间接依赖；交付必须保留集合、候选及依据 |
| 核对项目内容 | 对应代码／场景／资源所有者 | 核实功能替换与真实消费者；交付引用证据、移动映射、精确删除集及逐项恢复方式 |
| 执行整理清理 | 指定实施者 | 依赖当前有效清单、授权与无冲突条件；逐项记录实际变更、引用同步、跳过原因和恢复结果 |
| 验证并收尾 | 质量／集成负责人 | 依赖实际执行后的输入；交付工作流可读／可续接、导入／构建及受影响回归结果，说明保留和待定事项 |

任务规划只补尚未明确的产物位置与临时用途；实施结束核对本轮产物，集成、候选准备或用户要求提交时再核对相应记录与去向。已有证据直接复用，只检查变化及受影响范围；没有候选时可在对话说明“已核对，无需变更”，无需为此生成报告或虚构删除结果。

有候选清单但尚未执行或未验证时，不能标为“已清理”。有效授权范围内的明确操作连续推进；未知归属、不可恢复或范围外候选保留并报告，不默默追加删除目标。任务覆盖由编排者核对，现有控制器不会自动生成或逐项强制校验上述清理任务。

## 建立候选清单与引用关系

1. 锁定仓库根、单一技术栈、目标目录、用户期望结构、排除项、清理类型与工作区快照。查看版本控制状态及未跟踪文件，将用户改动和当前任务证据显式标出；同时按下文核对正在写入、占用目标或可能并行改动目标的工作。
2. 阅读项目目录约定和实际构建/打包入口，先界定何为源文件、运行时资源、生成代码、导入索引、构建输出、缓存、锁定文件、正式交付和证据。只按本栈原生适配的边界判定可再生成资源。
3. 枚举文件消费者和依赖关系。至少检查静态代码引用、动态路径/键拼接、运行时清单或Addressables/资源数据库、打包与导入清单、平台/flavor配置、测试夹具、构建脚本、部署文档和工作流证据。资源被反射、名称拼接、服务器返回键、热更新/远程配置或运行时扫描消费时，应追到消费位置。
4. 结合构建系统、编辑器数据库、项目资源索引和文件格式推导引用图；记录每个候选的路径、类型、大小、哈希（适用时）、最后消费位置、生成输入/命令、可重建条件和恢复成本。搜索无命中只说明该种搜索未发现引用，不能证明文件无人使用。
5. 按当前证据分类：保留、允许整理、可再生成候选、可删除候选、待确认。引用边界模糊、来源不明、构建依赖或恢复条件不清的内容归入待确认，不因“旧”“重复”或“未提交”直接删除。

优先使用此表作为审阅清单；未知值写明待确认，不要用推测填充：

| 路径 | 当前用途/类别 | 消费者与引用证据 | 计划动作 | 可重建/恢复方式 | 结果 |
| --- | --- | --- | --- | --- | --- |

## 工作流记录保留与归档

- 从当前工作项、有效规格／确认、实施包、执行状态与结果、证据清单、候选及发布交付引用出发，同时考虑并行工作、仍需续接的任务及被当前项目复用的已完成历史工作项，追踪直接和间接文件依赖。包括记录中的源／资源／计划、实际命令输出、图像候选、用户决定和其引用链，而不只保留最外层 JSON 或摘要。
- 用控制器实际只读 `check` 和适用原生合同核对仍被消费的记录，结合运行／构建入口补齐控制器未检查的消费者；单个工作项 `check` 通过不证明其他工作项或所有动态引用均安全。状态为 COMPLETE、记录位于历史目录、创建时间较早或未被当前任务直接引用，均不能单独证明失效。
- 当前运行、验证、恢复、确认与复用所需集合必须保留完整可读取内容。Git 历史中存在一份文件，不代表工作区中被控制器或消费者要求的路径可以缺失；再生成普通产物的能力也不能替代真实历史原始输出。不得删除必要证据，再重新生成日志、重算摘要或改写确认冒充原记录。
- 无有效依赖且已失去诊断用途的重复预览、临时输出、废弃候选和失败尝试可列候选，但仍须排除冻结／绑定保护内容并核实恢复条件。诊断未结或引用无法追清时保留；不能清空整个 evidence、候选、日志或工作项目录，也不为减少体积合并不同执行的证据。
- 冻结记录、确认、绑定交付及其引用路径沿用下文保护规则。需要归档时优先在已有索引中说明历史用途与当前引用，逻辑归档不搬迁原文件；确需物理迁移时使用实际原生／控制面支持的流程，否则保持原路径。已无当前引用也不自动解除既有冻结保护。
- 将保留集合及依据写入已有清理报告，分别记录本地保留、提交选择及发布选择，不建立另一份长期证据总表或另造控制面状态。仅修改普通未绑定索引不能改变被冻结内容的语义、确认或路径绑定。

## 核对活跃写入、并行工作和锁

在候选分类和执行前，核对当前技术栈会写入或占用这些文件的进程与任务，例如 Unity Editor/AssetDatabase/导入器、Cocos Creator 编辑器与资源导入、Phaser/Three.js build 或 watch 进程、Flutter build、Expo Metro/Prebuild/原生构建、代码生成器/资源生成器，以及仍在进行的构建或导入。检查工作流/Work Item 记录里是否有并行任务声明或文件归属冲突。按本机可用方式核对相关进程身份、实际工程路径和正在操作的目标；只查进程名称不足以确认它是否属于当前项目。

检查仓库已有的应用锁、生成器锁、AssetDatabase/导入占用及工作流事务状态，并按其原生规则识别所有者和活动范围。锁文件存在本身不能证明持有者仍运行；锁文件不存在也不能证明不会有进程随后启动。不得通过杀掉编辑器、构建或生成进程，移除锁文件，或绕过原生锁来强行清理。

如果目标正被活动工作使用、存在并行归属冲突，或进程/锁的归属与活动状态不能确认，则跳过这些候选并报告原因；只有路径和所有者明确分离的其他候选仍可继续。写入、整理或删除前紧邻地再次核对活动进程、工作项/归属、锁状态和候选文件内容/状态。若发生竞争、锁变化、候选变更或无法建立无冲突条件，停止该候选，刷新工作区和引用关系后重新判定。此检查属于防覆盖和防竞态的本地保护，不增加授权门，也不把一次进程/锁快照描述成无活动的证明。

## 分开计划整理和删除

- **目录与命名**：先写期望目录树、文件用途和命名规则，检查已有约定、大小写敏感差异、平台路径长度、模块边界、生成器输出路径和公开打包路径。命名简洁且稳定，不为了视觉对齐批量改名。
- **移动与重命名**：单独生成旧路径→新路径映射。逐项列出代码导入、场景/序列化引用、清单、测试、资源加载 key、脚本、文档、编辑器索引和 CI 中需要同步的引用。确认文件身份/跟踪文件、二进制导入标记、大小写变化和历史路径消费者的处理方式；没有消费者迁移计划就保留原路径。
- **删除**：使用另一份精确文件删除清单，写明引用扫描结果、再生成命令、备份/恢复点以及删除后验证。只有已在任务范围内得到授权的路径才执行；已有对相同目标、相同动作的明确授权可复用，不重复询问。遇到范围新增或用户数据、共享内容、外部系统等边界时按公共协议处理。
- **路径保护**：执行前把路径解析到仓库根下，核对包含链接、junction、挂载或大小写别名的路径及实际目标。不得用宽泛通配符或递归删除代替清单。不要更改锁文件、用户数据、秘密、证书、发布产物、唯一源文件或可复现证据来“收拾干净”。
- **冻结与绑定路径**：已冻结的交付文件、V0–V5记录、机器证据、Evidence Manifest、控制面日志、审批/确认回执、工作流绑定文件及其引用路径默认按原路径保留；不批量搬迁、不自动改写其内容、路径绑定或验收记录。需要整理相邻普通文件时排除这些绑定路径；确需移动须由当前原生/控制面流程给出明确操作方式和用户范围，无法按该流程安全迁移就保留原处。
- **迁移和证据**：普通资源路径变动时更新已明确纳入范围的消费者引用，保留新旧路径映射，并检查生成器/工作流是否会重新生成旧结构。清单生成后若工作区内容、资源关系或依赖有变化，已做的候选分类失效；执行前重新读取工作区并复查受影响引用。校验源适配/控制面的既有哈希或事务保护约束，无需额外要求用户为普通文件手工提供哈希。

## 按计划执行与复验

执行前输出整理树和逐项变更预览，区分移动、改名、新建目录、删除和保留项，并校对影响到的运行时/发布消费者。紧邻每次实际变更前再次核对上述进程、活跃工作、锁和候选状态；目标发生变化时重审清单，不默默追加。

逐项应用获准变更并记录完成或跳过原因。随后按变更类型执行最小充分验证：

公共执行单元的纯删除结果使用 `files: []` 和非空 `deletedFiles`，不为满足交付字段制造占位源码。删除路径必须已列入单元所有权，并由控制器在该批次实施前冻结真实文件基线；登记时验证不存在，后续重建使删除结果失效。报告、命令输出和清理恢复材料仍按真实用途保留，不能删除控制记录或证据保护路径。

| 变更 | 需要覆盖的验证 |
| --- | --- |
| 移动/重命名源码或资源 | 导入/引用解析、关键静态检查及引用该路径的测试/构建输入 |
| 移除已替换实现、配置或测试内容 | 原功能替代路径、实际配置／脚本消费者和相关功能回归；不能只验证删除后的文件数 |
| 清除可再生成构建输出或缓存 | 用声明的干净命令重建目标、核对打包/部署清单和文件数量/大小预算 |
| 清理未使用资源 | 运行本栈资源索引或导入检查、动态加载用例和目标包资源包含性检查 |
| 处置工作流记录及相邻中间产物 | 对受影响当前／复用来源工作项执行实际只读检查和引用核对，确认计划、结果、原始输出、确认及证据仍可读，并能按既有流程续接／恢复；不为验证而改写阶段、制造新批准或重跑受保护操作 |
| 仅更新文档分类 | 确认链接、索引与工作流入口可达 |

实际执行前按影响、风险和成本推荐 T0–T3 及真实命令，再自动执行普通本地验证；类型、范围及成本变化时更新验证范围。构建／生成类清理还须确认生成器没有重新产生废弃路径，发布选择变化时核对最终包必需内容；现有有效证据可复用，不能把静态扫描当成已运行的导入／构建。真机、外部系统、发布及其他受保护操作仍按对应明确授权执行。

若验证失败，先恢复相关路径或文件，再判断引用映射遗漏、生成规则或动态消费者是否缺项；不要通过扩大删除范围让验证变绿。完成后报告最终变更集、重新验证结果、保留/未知项和逐项恢复路径。删除文件无法仅凭“磁盘已腾出空间”判定正确。

清单内事项均有实际执行、保留或跳过结论且相应验证完成后停止；待确认项可保留，但不能因此宣称“全部清理完成”。恢复只针对本轮所有权内的改动，不能重置仓库或覆盖其他工作。最终报告区分已盘点、已执行、已验证、保留及待确认，并引用当前清理材料；清理报告、恢复映射和验证原始输出本身也是本轮交付，不能在收尾时一起删掉。

## 原生身份与专业边界

Unity `.meta`、GUID、`fileID` 与序列化身份由 Unity 专项维护；Flutter 的 `pubspec.yaml` 资源声明、代码生成文件、资源键以及打包资源清单按项目 Flutter SDK/生成工具核对。Expo 按已选 CNG 或原生源码维护方式检查组件、静态资源引用、配置插件及生成入口，不统一删除 `android/ios`；`.expo/` 与构建缓存不是业务源，`.eas/workflows/` 仍是正式配置。Cocos UUID/AssetDB、Phaser运行时资源键、Three.js模块/URL资源和构建清单各自按原生适配核对。不能手写或孤立删除身份文件以绕过编辑器数据库、重导入流程或项目生成器。

每次任务只应用当前技术栈明确采用的规则与工具。多栈仓库分成独立计划；共享文件的消费者归属未核清前保持待确认。
