# 游戏音效设计与生产

适用于游戏的事件音效方案、制作、接入和返修。需求明确的独立音效可以直接设计和交付；相关游戏功能可在 V1 前准备代表样本并在 V1 验证反馈。纯音频沿用现有 MODULE 或资源实施单元；涉及可见表现变化时，显示对象继续执行适用 V0–V5。沿用已有工作项、GDD、音频计划和资源登记，不增设状态机、必填账本或逐音审批。

<a id="design"></a>

## 声音方向与事件设计

产品／玩法策划交付体验目标、玩家行为、事件权威及频率、平台和已确认约束；关卡与场景设计职责交付玩家路线、空间、材质、声音地标、视线／遮挡及对玩法有意义的听觉提示。区分实际事实、暂定方案和待验证假设，已有依据有效时复用。

**音效设计师**根据这些输入定义整套声音的情绪、音色与材质、节奏、动态范围、空间感和与美术／玩法的关系；按需要关联实际参考、来源与日期，说明采用依据。为本批事件确定玩家应辨认的结果、触发和结束时机、重要性、出现频率、可观察反馈和静音时的可理解方式。声音作为反馈消费玩法事件，不能决定业务状态或替代可访问的视觉／文本语义。

事件按需要设计起音、主体、材质细节和尾音，并标记各层用途、相对强度、时序、声音来源及重叠风险；不以层数衡量质量。高频操作选择适用的多个受控变体，保持事件身份、材质及总体强度一致，明确来源、配方／种子、触发参数、选择及避免立即重复的规则，并按玩法约束频率、并发和节奏。低频或已有合格资源的事件不为凑数制造变体。

先选能代表本批风格和最大风险的事件制作可试听样本，向用户说明设计依据和需要判断的问题；已有依据足够时可继续设计与生产，涉及体验、范围或成本的实质取舍才沿既有流程决定。声音方向确定后同风格分批扩展，不要求每个音效建立独立审批。**音效制作职责**将方案变成真实音频、制作源及参数；玩法／音频实现者负责触发、资源和生命周期。两类设计制作职责可由现有代理承担或按宿主规则委派；共享计划、音频服务和引擎资源保持唯一写者。

## 动态混音与空间关系

从实际事件与听觉重要性确定组别、优先级、重播／合并／限频、并发上限和中断清理。需要压低其他组时明确触发条件、目标组、压低幅度及进入、保持、恢复时序，避免密集事件把背景长期压低；真实参数依据当前项目与试听确定，不指定通用阈值。复用既有音频服务及原生 Mixer，按所选栈遵守[音频生命周期与跨场景规则](../../app-domain-toolkit/references/audio.md)，不新增平行播放实例或自建混音框架。Roblox 跨 Place 使用新的运行上下文，按[平台边界](../../app-stack-roblox/references/engineering.md#平台边界)记录允许的衔接与恢复，不假定旧实例仍存在。

按玩家任务设计声音位置：界面与结算提示可保持稳定位置；世界声源按实际视角和引擎能力选择距离、方向、遮挡与空间／环境混响。关卡或场景变化时交叉核对声音地标、声源与交互对象的对应关系，避免位置表达掩盖重要提示；同时检查密集事件、静音、后台暂停和恢复的适用条件。实际实现与验证继续遵守所选技术栈和目标设备的原生规则。

<a id="production"></a>

## 制作与接入

1. 核对现有合格素材及许可，依据声音风格、材质和用途选择复用、本地程序合成、已有录音／素材编辑或当前可用的生成工具。短电子声、钟琴与风格化提示可按需本地合成；复杂自然拟音、角色语音和完整配乐须使用适合目标的素材或工具，不把简单合成结果宣传为这些能力已具备。
2. 按本批方案制作代表样本，再按反馈和已定方向生产适用事件及变体。保留实际文件、制作源／配方、参数、种子、工具及版本、参考与来源许可；使用的工具不能复现时说明限制。素材供他人试听或平台需要时按需导出压缩版本，记录原文件与转换关系。
3. 在当前已安装技能目录运行本地合成工具；预设适用于胜利、拾取、点击和失败四类风格化短音效。由现有脚本的 `--recipe-out` 导出实际配方，调整后以 `--recipe` 重渲染；按工具的实际 `--help` 查看字段和边界。该工具输出的客观指标不等于专业响度或听感判定。

   ```text
   node .agents/skills/app-audio/scripts/sfx.mjs render --preset victory --out <输出.wav> --seed 42 --variant 0 --recipe-out <配方.json>
   node .agents/skills/app-audio/scripts/sfx.mjs render --recipe <配方.json> --out <新输出.wav>
   node .agents/skills/app-audio/scripts/sfx.mjs check --file <输出.wav>
   ```

   维护技能仓库时将 `.agents/skills/` 换为 `skills/`。本工具使用 Node 本地生成 PCM16 WAV；已安装 FFmpeg 时可按需独立解码或转换目标格式，不能将未执行的转码或播放标为通过。受控变体以实际生产参数和选择规则交接，不靠文件名推断已产生的变体。
4. 检查实际文件可解码、格式、声道、采样率、时长、静音、削波、头尾边界及适用循环；记录采样峰值、RMS 等实际测得指标及条件。采样峰值、RMS 不等于真峰值、LUFS、音质或玩家感受；需要其他指标时使用可用工具并记录实际结果，缺失则标为未测。按目标引擎导入并核对消费入口、事件、素材身份、并发和生命周期。
5. 沿用 GDD、音频计划或唯一资源登记关联文件、制作／许可事实、规格、消费者及当前版本；共享记录由唯一所有者更新。Roblox 分别记录本地源、平台资产 ID、所有者／权限、审核和实际加载结果；平台上传、付费工具和其他外部写入仍须实际授权，不能用本地文件冒充平台已接入。

<a id="audition"></a>

## 试听与返修

按本次范围组织三种互补试听：**单音**检查起音、音色、尾音和杂音；**连续操作**检查重复疲劳、相邻变体与并发；**实际上下文**结合相应玩法、背景音乐、环境、其他提示和玩家操作检查辨识、时序和混音。独立文件任务可以只交单音及适用模拟材料，实际游戏片段未运行时保持未验证，不虚构引擎播放或真实参与者。

对比候选尽量匹配听感响度并记录条件；按实际目标和授权选择耳机、扬声器、单声道及目标端检查。保留用户／参与者原始观察，区分“听到什么”和原因假设；围绕事件、分层、素材、时序或混音做局部修订，在尽量相同的场景、操作频率、设备和音量下复验，达到本次目标或证据不足以继续判断时停止。没有用户反馈时不代写人工确认，不默认发起真机运行。

文件技术检查、真实引擎运行和用户人工听感分别记录实际结果、证据、未覆盖和待确认范围；工具成功、波形指标及文件存在不能代替后两者。相关适配与结果写入已有工作项、音频计划或 QA 材料，受影响机制与生命周期按原有规则复验。
