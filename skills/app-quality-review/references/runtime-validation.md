# 运行验证与试玩执行

实际需要运行验证时，按当前项目、技术栈和已授权环境选择可用的引擎、应用、浏览器、服务端或自动化工具。复用[验证等级与交付](../../app-creator-workflow/references/verification.md)、现有 QA 材料、工作项和证据目录；本规范不提供新的运行工具、测试桥、控制器状态或必填报告。纯静态检查及无运行需求的文案改动不因此启动实例。

## 选择范围与实例

依据本次变更和验收目标确定对象、版本、宿主、运行路径和最小需要检查的行为：V1 验证实际机制和本批路径；V5 对正式资源与真实组合检查受影响行为；最终集成验证实际需要的跨对象或跨页面完整路径。小范围修复仅覆盖受影响流程与必要回归，已有仍有效的证据按其适用条件复用。

游戏可检查输入、反馈、暂停／重试和实际机制；非游戏 App 按实际页面、数据、导航和错误恢复检查。Node.js 等无界面服务使用其真实接口、后台任务、日志和关闭行为，不创建场景、试玩、截图或视觉验收要求。真机运行验收不自动发起；签名、上传、发布和外部系统写入仍按各自授权边界处理。

启动前先发现并核实可复用进程、实例和工具：确认项目路径、版本、环境、宿主及实例所有权，再决定是否需要建立新的本地实例。只使用当前实际可用的 API、命令与工具 Schema；工具文档或插件已安装不代表已连接、目标正确或能够执行操作。目标不可核实、工具缺失或权限不足时，将相关检查标为 `NOT_RUN` 或 `BLOCKED`，说明缺口并继续不依赖它的检查。

已有测试桥或项目工具可提供状态快照、复位、固定随机种子或推进步骤时，先确认它们实际可用及影响范围，再用于到达或核对难以复现的状态。只有桥接结果不能冒充用户输入、真实宿主或画面验证；普通检查不为此新增测试桥。关键状态无法稳定到达时，说明缺口并在已授权范围内选择最小可行验证，未执行部分如实保留。

## 执行与证据

1. **打开或复用**：检查被测候选、宿主和入口与本次范围一致；记录实际会话／实例身份及其所有权。复用用户或并行任务的实例时，先核对可安全使用的范围，不重置其数据或关闭已有工作。
2. **检查初始状态**：读取实际可用的启动结果、错误日志、失败请求和必要状态；检查加载入口与可操作条件。报告工具、环境和限制，不凭窗口存在、构建成功或模拟结果宣称运行通过。
3. **操作受影响路径**：执行本批实际输入、页面／场景切换和必要异常。按变更覆盖进入、操作、结果、退出及适用的失败／取消／重试，区分测试替身、模拟、真实宿主和真实数据。需要固定种子或复位时只在允许的测试范围内执行，不改写用户或正式业务数据。
4. **采集实际材料**：沿用现有 QA、实施包与 `evidenceRoot` 合同，关联候选版本、对象、宿主、初始条件、操作、预期／实际和日志、轨迹等真实输出；必要时采集截图／录屏并提供检查要点。缺少原始结果时保留未执行或待补证据，不以计划、文件名或工具声明代替实际执行。
5. **清理并交接**：成功、失败、取消或超时都执行与 `finally` 等价的清理。停止本任务发起的输入、录制和监听，关闭本任务创建的会话／窗口并释放其句柄；复用实例只清理本次拥有的资源，不关闭用户、并行任务或常驻服务。清理失败如实报告并保留恢复线索。

截图／录屏采集只证明生成了文件。显示效果、可读性、视觉还原和用户体验默认由用户人工检查；未经用户明确要求自动视觉验证，不得自动分析截图或据此判定视觉通过。即使获得自动分析授权，机器结果也不等于用户已确认体验。

## 任务安排与完成条件

沿用当前实施计划和原生项目路径，每项只明确目标、相关路径及完成验证；分工、依赖和其他信息按实际协作补充，不为每次执行新建独立表格或占位文件。

| 任务 | 结果及路径 | 完成验证 |
| --- | --- | --- |
| 确认运行范围 | 在现有计划中关联候选、对象、宿主、路径和适用工具 | 目标与现有实例真实一致，未具备能力及未覆盖范围明确 |
| 执行运行检查 | 当前项目已有入口、测试、工具及按需创建的本任务会话 | 实际执行受影响操作与必要异常；结果、错误和环境可复现 |
| 采集与核对 | 现有 QA 记录及合同要求的证据路径 | 原始输出绑定当前候选；构建、状态、交互与待人工显示结论分别记录 |
| 结束与交接 | 本任务拥有的会话、输入、录制和句柄；已有交付记录 | 成功及异常路径均已释放本任务资源；共享实例保留，未清理项和未验证项明确 |

控制器继续只核对现有证据材料和引用关系，不能独立证明运行事件、日志内容或截图视觉事实。需要真实参与者评价的理解成本、手感和节奏按[人工试玩与调参](../../app-domain-toolkit/references/game-content-playtesting.md#playtest)处理，不能由代理操作结果替代。

## 复用现有命令采集

当前项目已有可执行的运行检查、原生 CLI 或文件检查命令时，复用[命令采集器](../../app-workflow-control/scripts/capture-command.mjs)，不再创建一套通用运行工具。先在现有计划与实施包中声明真实验收命令，进入 `IMPLEMENTING` 后按活动单元及命令序号执行：

```powershell
node .agents/skills/app-workflow-control/scripts/capture-command.mjs --repo . --work-item .workflow-control/work-items/current.json --unit check-current --index 1 --output .workflow-control/evidence/current/check-current.json
```

示例 ID 和路径须换成当前真实工作项、活动单元、命令及合法 `evidenceRoot`。采集器会执行已冻结的指定命令并独占创建 `command-capture-v1`，保存真实命令、退出码、stdout 和 stderr；已有输出不覆盖，命令失败保留失败结果。采集器不创建计划、实施单元或额外编排运行实例；被采集命令自身可能创建实例，命令及调用方仍须遵守所有权和清理要求。采集不替调用者授权真机／外部操作，也不把长期启动服务的命令当作有界验收。需要更新冻结命令时按现有返修／RETURN 流程处理，不手改计划或补造日志。

图形编辑器、浏览器或设备操作仍使用实际已连接的工具与已有会话；不能因为采集器只支持命令就伪造原生 CLI 或把工具操作改写成已运行命令。命令采集证明的是实际进程及其输出，输出中的业务断言、真实交互和人工显示结论仍按其对应证据核实；截图只采集及交接，不自动分析。
