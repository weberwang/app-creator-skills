# 验证与交付

涉及性能定位或优化时，遵循[公共性能优化规范](../../app-domain-toolkit/references/performance-optimization.md)，按实际瓶颈检查 Flash、内部 RAM、PSRAM、峰值及最大连续可分配空间，以及图片解码与显示刷新传输成本；分别记录主机模拟、静态构建和已授权设备实测，不以主机结果推断硬件运行性能。

## 分开记录验证环境

| 范围 | 能证明什么 | 不替代什么 |
| --- | --- | --- |
| 静态检查、逻辑单测 | 类型、接口、业务状态、协议和独立逻辑 | 固件可构建、实际外设行为 |
| 目标固件构建与 size | 当前芯片/配置下编译链接、静态资源体积 | 运行峰值、显示驱动、输入、流畅度 |
| 配套主机 GUI 模拟 | 相同 UI 源、资源、事件和导航的主机运行结果 | 真机总线、触控校准、DMA、供电、实际性能 |
| 已授权的设备运行 | 指定板卡、固件与场景的实际运行结果 | 其他板卡、未测场景或用户视觉确认 |

ESP-IDF Linux host target 不是通用 ESP32 模拟器，支持范围及主机平台须按 SDK 核实；Windows 上不要因此默认安装 Linux 或启动 WSL。可评估与工程 LVGL 版本、配置、字体、业务和界面源配套的 SDL 主机程序，不能用另写的 HTML/Flutter 示意图充当固件运行证据。已有模拟进程先复用，新增进程前确认无可复用实例。

## 测试等级与命令

遵循公共 T0–T3，先推荐理由、覆盖和实际命令，再自动执行普通本地验证。ESP-IDF 工程已激活对应环境时，最小构建为 `idf.py build`，静态体积为 `idf.py size`；业务测试和主机测试使用工程实际脚本、CTest 或 Unity Test 等已有工具。没有工程和工具时标记未执行，不为生成一份报告虚构通过记录。

新增驱动、缓冲策略、任务调度或固件资源时，扩大模块/集成验证范围。未授权硬件时继续构建、逻辑和适用的主机验证，设备验收保留未执行；不能把 T3 当成设备、烧录或 OTA 授权。

## V5 运行证据

按[领域合同](domain-validation.md)绑定当前对象、候选、设备规格、布局与资源。实际运行上下文明确 `host-simulator` 或 `device`，记录源版本、构建/固件身份、屏幕条件和真实输出。设备运行还须关联对应明确授权及实际板卡，模拟器报告中不得伪造设备测量。

覆盖相关导航/返回/重入、状态更新、输入与资源释放；显示层覆盖打开、关闭及焦点恢复，不适用项提供原因。性能结论附实际采集方法、原始输出和场景，区分主机数据、设备静态体积和设备动态内存/刷新数据。没有采集的指标保持未知，不用估算冒充实测。

用户检查点包括文字可读与缺字、颜色/字节序、边缘裁切、触控或焦点可达、动画与响应。可生成并提供截图或运行资料，但默认不自动分析画面。人工确认必须来自用户实际消息，并绑定对应运行上下文。

## 发布准备

准备固定版本、构建命令、目标芯片/板卡、分区配置、资源清单、固件摘要、测试结果和未完成硬件项。本地构建不等于已烧录或可量产。烧录、擦除、OTA、签名密钥操作、secure boot、flash encryption、熔丝写入与上传发布分别按具体动作取得授权；不在通用验证脚本中夹带这些命令。
