# 动画制作与接入

先判断任务是制作/接入动作资产，还是维护Unity 2D动画制作工具与校验流程。两种工作有不同的输入、交付和写入边界，不能把技术美术管线支持当成角色动画制作授权。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。以下共用步骤不能跳过所选原生适配规定的操作顺序、资源格式与平台边界；必要的用户确认按协议执行。

## 输入

- 目标动作、对象和运行场景；动作参考、源资产与帧率；目标尺寸、方向、播放触发和引擎资源限制。若任务是技术管线支持，还需提供现有候选资产、生产约定、工具/校验器和诊断需求。

## 共用操作步骤

1. 先分类：资产模式记录目标动作、播放环境和资源路线；Unity 2D TA模式读取已有候选、制作约定和待解决的工具/校验问题，不接管具体角色资产。
2. 资产模式按动作阶段标注准备、主要动作、接触/峰值、缓冲和恢复，指定关键姿势、时长、速度曲线、循环接缝和必须读清的轮廓；TA模式把所需检查/工具的输入、输出、变更影响和可复现诊断列清。
3. 资产模式冻结源文件、导出序列/骨架、命名、帧序、透明边缘、尺寸、压缩、变体和资源归属；TA模式只围绕获准范围改造共用工具、导入导出规则或校验，不写角色动画资产。
4. 仅资产模式制作代表动作候选，并在真实尺寸、背景和播放速率下检查节奏、轮廓、重量感及接缝；TA模式复用现有候选验证约束、工具结果和诊断能力，不创作Clip、Controller或角色动画内容。
5. 按当前技术栈导入后验证帧/骨架映射、循环、状态切换、暂停恢复、缩放与资源预算；工具验证只证明约定或诊断可用，动画表现仍由资产负责人审查。
6. 交付对应模式所需的时间轴和源/导出映射，或工具/校验器改动及复现样例，并列出运行验证与待人工判断。

## 关键边界

- 逐帧、2D骨骼和3D骨骼是不同生产路线；按当前栈和对象选模式。Unity 2D TA原生规范不授权制作Clip/Controller或写角色资产；实际2D动作制作必须选择清单中明确标注的动作资产模式。
- 结构和播放的技术检查不代替动作质量评审；序列或骨架细节见所选原生适配。

## 交付

- 资产模式交付动作规格、时间轴、源/导出映射、状态接入和人工审查记录；TA模式交付受限的工具/校验改动、输入/输出约定、代表性诊断样例和独立生产责任说明。

## 当前技术栈的原生流程

先根据仓库实际依赖与项目配置确认当前 `app-stack-*`，再打开同目录的 [native-adapters.json](native-adapters.json)。按 `when` 选择 `mode`，从 `path` 指向的本栈原生手册中定位 `section` 章节，只读取该模式及其明确需要的脚本、模板和校验器；同栈同能力的多个模式在同一本手册内维护。
使用共用读取工具：`node .agents/skills/app-skill-runtime/read-native-mode.mjs <技术栈> app-animation [sourceSkill]`。单模式可省略来源，多模式必须指定清单中的 `sourceSkill`；输出所选章节、直接公共依赖及按需资源路径，不递归加载其他模式。维护本技能仓库时将 `.agents/skills/` 换为 `skills/`。
若 manifest 未列当前栈，继续使用该栈 `app-stack-*` 中的原生规范/索引及适用公共流程；这本身不代表能力缺失。仅当已声明并选中的原生手册或模式章节未随安装提供时才报告阻断。公共工作流只在 `sharedWorkflows[].stacks` 包含当前栈时读取；`onDemand: true` 的参考按当前任务选择，读取器仅列出路径。不要加载其他栈模式或臆造接口；栈未确认且会影响实现时先澄清。
