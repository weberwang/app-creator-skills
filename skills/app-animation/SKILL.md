# 动作设计、动画制作与接入

先按用户要求区分仅做动作设计、动画资产制作与接入、Unity 2D 动画技术管线支持。三个分支分别限定交付和写入范围。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。涉及制作或接入时，遵循所选原生适配的操作顺序、资源格式与平台边界，并按协议记录适用的用户确认。

## 输入

- 游戏项目中的动作先定位所属工作项和消费场景，复用仍有效的玩法与视觉记录。读取动作目的、触发与状态、关键事件及切换权限，再核对游戏实际镜头或 UI 显示层、目标显示尺寸与真实美术基线。
- 将已确认的玩法规则与当前生效配置和已有运行证据核对。发现会改变动作方案的冲突时，在工作项记录来源及版本、具体差异和受影响动作，并请用户确认采用的规则与版本。缺失且无法推导的关键信息同样按受影响动作确认；只暂停依赖该决定的动作，收到答复后将决定与用户消息引用写回原工件。
- 资产模式同时读取已有源资产、目标平台与引擎限制，并据游戏内表现推导帧率和输出尺寸。技术管线支持读取现有候选资产、生产约定、工具/校验器和诊断需求。

## 仅做动作设计

用户只要求构思、评审或交付动作方案时，先查阅已有玩法状态、事件与美术基线。由目标感受推导关键姿态、空间路径、阶段节奏和连接条件，再安排时间轴。帧动画按适用的[意图推导方法](../app-domain-toolkit/references/frame-reference-intent-driven-design.md)与分类参考细化；其他路线只在项目约束影响设计时查阅对应技术栈规范。

交付可供制作的动作规格，包括玩法目的与表现意图、起止状态、关键姿态与阶段时长、已有输入/生效/取消/衔接窗口、设计取舍、待决规则和可观察的人工检查点。采用帧动画的多段攻击另按[多段攻击的输入窗口与分岔](../app-domain-toolkit/references/frame-reference-action-timing.md#多段攻击的输入窗口与分岔)记录各条路径。将已有规则与建议值分开记录；需要新增或改变玩法规则时，交给[游戏玩法工作项](../app-gameplay-development/SKILL.md)决定。缺失且无法推导的玩法条件只阻塞受影响的动作。

有现行工作项时复用其设计工件，独立设计请求可直接交付方案。本分支在交付规格后结束。后续若进入制作，沿用原生流程对当前方案的确认要求及有效确认记录。

## 制作、接入与技术管线

1. 资产模式按所属对象的现有流程定位本次增量 V0 范围、V1 功能验证和 V2 视觉目标，再选择资源路线；Unity 2D TA模式读取已有候选、制作约定和待解决的工具/校验问题，不接管具体角色资产。
2. 资产模式在 V3 用同一份动作时间轴连接游戏状态或事件、玩家应看到的变化和可观察的验收点，并记录关键姿势、时长、速度变化及衔接。正式制作前，向用户展示影响玩法体验的关键时点、分支、结束去向和待决项，与设计理念一并确认当前方案；TA模式把所需检查/工具的输入、输出、变更影响和可复现诊断列清。
3. 资产模式冻结源文件、导出序列/骨架、命名、帧序、透明边缘、尺寸、压缩、变体和资源归属；TA模式只围绕获准范围改造共用工具、导入导出规则或校验，不写角色动画资产。
4. 资产模式在 V4 按已确认的时间轴和游戏显示条件制作、审阅并导入正式素材，检查帧或骨架映射，并在目标尺寸和播放速度下审阅轮廓、节奏与衔接；TA模式复用现有候选验证约束、工具结果和诊断能力，不创作Clip、Controller或角色动画内容。
5. 资产模式在 V5 按同一时间轴核对正式游戏中的触发、事件、循环和状态切换，按需检查暂停恢复、缩放与资源预算，并由用户在实际镜头、显示尺寸和播放速度下检查表现。将复现步骤、预期与实际结果、运行证据和用户视觉结论绑定到同一正式场景及当前动作版本，记入现有工作项。TA模式交付可复现的工程验证。
6. 交付对应模式所需的时间轴和源/导出映射，或工具/校验器改动及复现样例，并列出运行验证与待人工判断。

Unity、Cocos、Roblox 任务新增显示元素时，统一遵循[显示元素的编辑器还原](../app-domain-toolkit/references/editor-display-authoring.md)，同步交付正式可编辑源及适用的动态预览。

## 关键边界

- 逐帧、2D骨骼和3D骨骼是不同生产路线；按当前栈和对象选模式。Unity 2D TA原生规范不授权制作Clip/Controller或写角色资产；实际2D动作制作必须选择清单中明确标注的动作资产模式。
- 结构和播放的技术检查不代替动作质量评审；序列或骨架细节见所选原生适配。

## 交付

- 按[三项最小约定](../app-creator-workflow/references/output-files.md#每项任务的最小约定)交付当前模式的结果、涉及文件的实际路径及验证结论。仅动作设计可直接交付规格；资产模式保留动作时间轴、源／导出身份、状态接入及实际人工审查事实；TA模式保留获准的工具／校验改动、输入输出及代表性诊断。复用已有工件和记录，局部任务不强制新建全部材料；委派或跨角色交接时才明确分工。

## 当前技术栈的原生流程

先根据仓库实际依赖与项目配置确认当前 `app-stack-*`，再打开同目录的 [native-adapters.json](native-adapters.json)。按 `when` 选择 `mode`，从 `path` 指向的本栈原生手册中定位 `section` 章节，只读取该模式及其明确需要的脚本、模板和校验器；同栈同能力的多个模式在同一本手册内维护。

Three.js 的二维位图序列（包括采用 billboard 表现的角色）选择逐帧模式。三维骨骼动画（包括带蒙皮和动画片段的 GLB）按[三维模型与关卡管线](../app-stack-threejs/references/native-contracts.md#mode-threejs-game-model-pipeline--模型接入与优化)交接并用 `AnimationMixer` 接入。读取该模式使用 `node .agents/skills/app-skill-runtime/read-native-mode.mjs threejs app-3d-asset-pipeline threejs-game-model-pipeline`。

使用共用读取工具：`node .agents/skills/app-skill-runtime/read-native-mode.mjs <技术栈> app-animation [sourceSkill]`。单模式可省略来源，多模式必须指定清单中的 `sourceSkill`；输出所选章节、直接公共依赖及按需资源路径，不递归加载其他模式。维护本技能仓库时将 `.agents/skills/` 换为 `skills/`。
若 manifest 未列当前栈，继续使用该栈 `app-stack-*` 中的原生规范/索引及适用公共流程；这本身不代表能力缺失。仅当已声明并选中的原生手册或模式章节未随安装提供时才报告阻断。公共工作流只在 `sharedWorkflows[].stacks` 包含当前栈时读取；`onDemand: true` 的参考按当前任务选择，读取器仅列出路径。不要加载其他栈模式或臆造接口；栈未确认且会影响实现时先澄清。
