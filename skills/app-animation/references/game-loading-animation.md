# 游戏加载动画设计

为已有的启动、关卡切换或资源加载设计主题动效时，从核心玩法选一个玩家能认出的动作，让该动作推动可见的场景变化。分镜机制可以跨画风复用。

加载画面的画风以项目当前确认的全局视觉基线为准。优先复用现有角色、场景素材和 UI 组件，按基线中适用的规则对齐色彩、材质、字体、镜头和动效节奏。进度条或全屏构图按显示空间和信息量选择。

## 从游戏元素推导分镜

从当前 GDD、模块设计和已确认素材提取场景、角色或代表物、核心动作、可见进度标记和完成镜头。结合加载入口与下一画面选取元素，例如关卡过渡可用即将进入的区域或任务目标。已有明确的进度表现时优先沿用。

| 玩法线索 | 进度表现 | 典型完成镜头 |
| --- | --- | --- |
| 探索、行进或解锁沿途目标 | **沿途解锁**。角色按进度向目的地移动，路标或区域沿路径依次激活 | 到达目的地，传送门打开 |
| 采集、补给或充能 | **分格累积**。角色可循环搬运，容器格、储量或能量逐步增长 | 容器满载离开，或装置启动 |
| 装配、修复或布置 | **逐件搭建**。部件按可理解的顺序出现并就位，逐步构成完整成果 | 设备开始运转，或商店开门 |

先写进场、加载中和完成三段。进场用一个清楚的目标建立期待。加载中区分可持续循环的动作和需要根据进度保留的变化。完成只选一个能接上后继画面的镜头。需要点按时，单列短反馈及适用的静音、限频和中断处理，沿用[交互反馈规范](../../app-feedback/references/interaction-feedback.md)。

例如地下矿洞采用逐件搭建时，矿工采集矿石并将载矿货箱依次卡入车厢格。就位的货箱保留在画面中，等待期间可循环采矿或搬运。收到加载成功事件后，满载矿车驶出隧道。

## 将画面绑定到加载状态

- **可测量进度**采用加载所有者提供的真实数值或阶段。将视觉变化映射到明确的阈值或阶段。进度跨过多个阈值时，直接同步到应有状态，避免串行补播阻塞进场。
- **不可测量进度**保留可循环的角色或场景动作，并显示等待文案。有实际阶段开始或结束时可同步更新场景。百分比只在存在可信数值时展示。
- **完成**由当前加载请求成功触发一次，再衔接既定场景。很快就绪时可直接进入完成态或切入游戏，衔接动作按项目设定的时间预算处理。
- **失败、取消与重试**沿用加载入口的恢复路径。离场或取消时清理播放、音效和订阅。重试从新请求的状态起播，过期回调不得推进当前画面。
- **表现资源**复用能随加载入口就绪的素材。正式动效素材尚未可用时，先显示轻量等待提示。点按、静音和减少动态效果均由表现层处理，加载所有者继续推进任务。

## 纳入现有模块交付

- **V1 方案**在现有 Work Item 或模块设计中记录使用场景、进度来源、三段分镜和可观察的完成及恢复条件。独立设计请求可以直接交付该规格。
- **V2 设计**在现有设计稿中确认关键画面、进度提示、循环方式、完成和适用的失败态。对照已确认的全局视觉基线及前后相邻画面检查视觉一致性。
- **V3 交接**按阶段标记事件来源、画面变化、建议时长、所需资产、音效触发和可跳过点。将需要制作的动作纳入现有动画拆解清单。
- **V4 制作**复用现有素材和当前技术栈适用的资产路线，按实际目标尺寸检查资源及首屏加载成本。
- **V5 验证**按实际入口核对快速完成、慢加载、进度跳变和适用的失败重试或取消。核对完成事件只触发一次，点按只触发表现。全局视觉一致性、节奏和衔接由用户人工检查。
