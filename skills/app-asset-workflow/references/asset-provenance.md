# 资源来源与消费者关联

适用于本次需要生成、制作、导入、替换或复用的视觉素材；无素材的非视觉任务不增加记录，仅使用原生组件时不因此制造图片。沿用现有素材清单、[素材生产规格](style-and-production.md)、[输出文件规范](../../app-creator-workflow/references/output-files.md)和本栈正式资源身份，不创建平行资源数据库、画布或新的阶段状态。

## 按实际素材关联

先检查当前对象及共享资产的真实消费者、适用范围和有效确认，复用合格素材；确有缺口再生成或制作。已经存在有效记录时引用它，生成、衍生或替换影响的关系才更新到同一权威素材清单，不为每张图片重复生成完整报告或强制追补历史材料。

现有素材规格中的 `assetId` 是同一逻辑素材在项目内的稳定身份；一个素材可被多个对象或状态消费，不为每个消费者重复生产。记录使用已有字段、项目原生索引或实际可解析引用，不能把新字段直接塞进不接受额外字段的控制器或原生 Schema；具体事实已有唯一来源时引用该来源。

| 应能追踪的关系 | 在已有资料按实际需要记录的事实 |
| --- | --- |
| 需求与参考 | 目标对象、功能／可见特征、状态与用途；实际使用的设计目标、参考路径和有效版本 |
| 生成或制作 | 真实制作源、生成输入与所选候选；可获取时记录工具／模型及版本、实际参数和生成记录位置，来源或权限不明时保持待核实 |
| 技术处理与导入 | 实际操作、输入／输出、必要参数及结果；正式工程路径、原生导入身份和子资源，具体方式按[技术处理与交接](technical-processing.md) |
| 运行消费者 | 真实场景／页面／显示层、组件或加载入口、适用状态及实际引用；动态资源须结合键、配置、运行入口和平台条件定位 |

无真实输入、版本或工具返回记录时如实说明未知，不推测供应商、生成参数或来源。引用源文件／候选时检查实际可读及引用关系，密钥、令牌、个人数据和带凭证链接不得写进提示词记录、资源清单或交付证据。需要保留再生产输入时按现有授权与输出合同保存，不以工具返回的预期位置或成功消息冒充实际产物。

## 区分各类材料与复用范围

参考、未确认候选、已确认目标、可编辑制作源和正式运行资源分别按[输出分类](../../app-creator-workflow/references/output-files.md#输出分类与唯一位置)保存及引用。参考和效果图用于表达目标，不能因文件存在就当作正式资源；用户确认的是当时实际展示的候选及适用范围，不能把目录名、复制文件或工具成功当作确认。

生成衍生素材、修改已有素材或替换消费者时，复核关联的需求、适用状态、格式／尺寸、许可、正式路径和真实消费者。保留仍有效的上游依据与旧版本引用；不把旧素材、旧消费者或旧环境的确认自动转移给变化后的结果。已冻结目标、候选和确认记录保持原路径与原内容，新结果按现有控制器和原生增量流程建立引用；不要覆盖、改写历史或重算旧摘要冒充已确认。

同一共享素材被多个对象消费时，记录各实际入口与适用状态；变化影响多个消费者时分别安排适用回归。仅修改内部制作源、没有改变正式资源时，按实际影响判断复验范围，不无故重新生产、导入或重复确认。

## 任务与完成条件

任务沿用[三项最小约定](../../app-creator-workflow/references/output-files.md#每项任务的最小约定)：明确结果、相关路径和验证方式；跨角色或有先决依赖时补充交接信息。以下职责并入已有对象／批次任务，不为表格额外建工作项。

| 时机 | 实际任务 | 完成条件 |
| --- | --- | --- |
| V0、V2／V3 | 梳理本次目标与状态、已有可复用素材、需要生产的特征和真实或计划中的消费入口；按既有流程完成目标、拆解及布局确认 | 清单能从本次需求与有效目标定位到素材职责；尚未生产或尚未绑定的项如实标记，不把计划当作已接入 |
| V4 | 依据确认的规格取得实际素材，保存必要输入和处理结果，导入正式工程并读回原生身份、子资源与实际引用 | 实际文件和所需依赖可读，适用技术检查与导入回读有真实结果；未导入、失败或来源不明保持未完成 |
| V5／最终集成 | 在当前正式组合中检查受影响的真实消费者、状态、引用和加载；按既有约定采集用户审阅材料 | 工程／运行结果与用户人工显示确认分别记录；节点、文件存在或截图采集成功不等于实际可用或视觉通过 |
| 清理与交接 | 按[项目清理规范](../../app-artifact-cleanup/references/project-cleanup.md#建立候选清单与引用关系)追踪素材、生成输入、确认及消费者，交接当前有效路径和保留依据 | 动态键、运行时扫描、远程配置、共享对象及并行任务按实际核对；静态搜索无命中不能证明无消费者，归属不明保留并报告 |

本规范描述工作安排和真实交接关系；控制器不会因存在本清单就自动扫描依赖、核验生成来源或判定视觉完成。产物身份和路径沿用已选栈及现有机器合同，未运行的导入、加载或人工检查如实保留未验证。

## 文件与声明引用检查

[素材文件工具](../../app-domain-toolkit/scripts/verification/asset-files.mjs)只读当前已有的单素材 `asset-task.json`，核对明确的 `sourcePath`、`runtimePath` 及按需提供的消费者文件身份。一个素材可绑定多个真实文件；原规格的 `consumer` 是语义描述，工具不会把描述猜成磁盘路径，不修改原规格或建立另一份资源数据库。

```powershell
node .agents/skills/app-domain-toolkit/scripts/verification/asset-files.mjs --repo . --task docs/item-asset.json --consumer item-icon=src/ui/item.ts
```

`--task` 与 `--consumer assetId=项目相对文件路径` 可以重复；本地路径按项目边界检查，远程资源不联网读取。工具将 `asset-files-v1` 结果输出到标准输出：`PASS`／退出码 0 表示本工具范围的文件与声明绑定可核对；`FAIL`／1 表示本地文件缺失、正式资源为空、重复身份／绑定或其他明确错误；`NOT_RUN`／2 表示缺少本地映射、只有消费者语义声明、远程资源、未知路线或原生回读不在检查范围。仅使用 `native` 路线时不要求制造图片，所需原生验证保持未验证。模板占位和未知值不能转为通过。

即使文件检查通过，也不证明代码真正引用素材、GUID／UUID 或原生资源已注册、动态加载成功、许可真实或视觉已确认；继续执行已有各栈校验和实际消费者回归，不据此判断“全部资源已使用”或删除未列资源。源与正式资源实际为同一文件时允许核对，缺少来源事实时如实保留。命令可通过[现有采集器](../../app-workflow-control/scripts/capture-command.mjs)执行并记录真实输出；非零结果不能登记为已通过的验收命令。
