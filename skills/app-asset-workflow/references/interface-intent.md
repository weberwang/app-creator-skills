# 无文字也能理解界面与意图

游戏与应用的界面美术遵循同一原则：不先阅读文字，也能辨认当前场景、主要目标、可以操作的对象、下一步动作，以及状态变化与操作结果。视觉先表达任务与因果，文字补充精确信息。制作与审阅时结合目标用户、既有组件约定和实际显示尺寸判断，不把陌生图标当作天然通用语言。

## 用画面表达任务

- **主次明确**：通过大小、轮廓、对比、留白、分组和位置关系，让主要目标及当前可执行动作先被看见；装饰不抢占主操作的注意力，也不伪装成可点击控件。
- **对象与动作相关**：图形、道具、图标与操作对象建立明确联系，复用用户熟悉的视觉约定。例如收集物与容器、滑块与轨道、对象与可放置区域之间应有可见关系；避免用随机符号或抽象插画代替功能含义。
- **可操作性可辨认**：按钮、拖拽把手、滑动区域、切换项、可放置区域和不可操作装饰有足够差异；仅靠一行说明才能发现的操作，需要调整形态、布局或情境线索。
- **状态有差异**：选中、未选中、禁用、焦点、加载、成功与失败使用形状、边框、填充、图形或位置等可辨识线索。颜色与动效作为补充；减少动态效果、静音或色觉差异情况下仍能理解关键状态。
- **变化有因果**：让输入对象、移动方向、目标位置和结果建立联系，反馈贴近操作发生处。相关反馈继续遵循公共 [app-feedback](../../app-feedback/SKILL.md)，不让装饰性动画替代真实操作结果。
- **系列语义稳定**：同一图形、颜色角色、控件形态和空间关系在不同页面表达相同含义；不同意图不套用难以区分的装饰模板。跨文化或陌生领域的符号需要结合上下文检查。

具体视觉风格仍按项目的视觉签名维护。具象、抽象、像素、写实或原生组件均可采用；关键是形式能够支持实际任务。

## 将去字检查放进现有审阅

在已有的目标候选、布局和最终组合审阅中增加一轮无文字检查，不新设状态、分数、固定通过比例或批准记录：

1. 准备同一候选的可恢复预览，只隐藏可见文字，保持原有空间、控件、图形和状态。保留原始版本；不修改正式页面的数据、事件、可访问名称或业务逻辑，也不把文字重新烘焙成图片绕过检查。
2. 由用户或目标受众在目标尺寸下人工观察，不先用文字解释布局意图，说明“当前是什么场景、主要要做什么、哪里能操作、操作后会发生什么、现在是什么状态”。检查相关的正常、选中、禁用、加载及成功/失败状态。
3. 记录具体误判，例如把装饰当按钮、混淆主要与次要动作、找不到操作对象、看不出成功或失败；定位到轮廓、层级、图形语义、位置关系或状态差异后返修，复验受影响部分。
4. 恢复真实文案，再确认精确信息、可访问语义、布局与操作完整。无文字预览用于判断视觉表达，带文字的正式组合仍需原有检查。

提供预览或截图及上述观察点，复用已有人工确认。代理默认不自动分析截图，也不据此填写视觉 PASS；尚未人工检查时记录待检查。

## 保留精确信息与无障碍

正式界面保留必要的控件标签、金额与数量、时间、具体错误原因、风险提示、确认信息和用户内容，也保留屏幕阅读器名称、键盘焦点及辅助技术语义。精确信息由可读文字承担，主要任务和交互关系由视觉共同表达；遇到歧义或后果重要的操作，用明确文案与既有确认行为消除歧义。

文字阅读、对话、表单和数据内容本身就是任务时，检查内容层级、入口、操作及状态是否直观，不要求用户在文字隐藏后仍能知道具体内容。不通过删文案、增加陌生图标、夸大动效或遮蔽风险来满足这一原则。
