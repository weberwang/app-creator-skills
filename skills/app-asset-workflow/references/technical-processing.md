# 素材技术处理

## 正式位图尺寸

V3 从真实消费者确定正式尺寸，SVG 重绘和直接生图按同一份[静态单图交付规范](../../app-domain-toolkit/references/svg-single-image-reconstruction.md#正式静态单图共同交付规范)执行。V4 在复制到正式资源目录和原生导入前完成所需尺寸处理及实际文件核对。工具返回的画布尺寸只代表制作源，不能直接作为正式尺寸；生成成功、比例相符或导入成功均不能替代此检查。

- **按用途定尺寸**：普通 UI／2D 图片先确定布局坐标空间中的目标显示宽高、实际导入密度及必要的最大业务缩放，得到包含该缩放的最大约定逻辑显示尺寸；尚未计入时先乘已声明最大业务缩放，已计入则不重复相乘。正式像素宽高分别按 `ceil(最大约定逻辑显示尺寸 × 明确的生产密度)` 计算，例如 30×20、已声明最大业务缩放 1.5、生产密度 1 时输出 45×30。采用满足当前用途的尺寸，不因工具默认输出、保留细节或“以后可能放大”提高规格。普通图片的运行缩放边界仍按[图片尺寸](../../app-ui-layout/references/relative-layout.md#图片尺寸)执行。
- **密度按本栈处理**：Cocos／Phaser／Three.js 有场景消费者的正式静态单图使用生产基线 `1`，Unity UI／2D 默认 `sourceScale=1`；Flutter／Expo 按实际资源密度与变体声明计算，不把设备像素比再乘一次。ESP32 按实际屏幕和 GUI 像素预算处理。3D 材质贴图按 UV、镜头可见贡献及纹理预算规划，不套用 UI 尺寸公式。
- **保留源图，导入成品**：工具返回 1254×1254、1024×1024 等大画布，而用途只需 64×64 且生产密度为 1 时，应保留制作源，在正式导入前交付 64×64 成品；明确的 2 倍密度变体才交付 128×128。不得将大图原样复制到运行目录，再靠节点缩小、修改 PPU、解码缩略参数或 Importer 最大尺寸掩盖源文件过大。没有统一的 512／1024 上限，确有对应显示、密度或贴图预算依据的大图仍可使用。
- **特殊资源使用各自合同**：九宫格按冻结的小图源帧和切片值以 1 倍基线生产，不按整个弹窗显示框制作大图；使用时的像素倍率／切片缩放严格为数字 `1`，不得采用前述普通图片的密度覆盖或额外业务缩放，具体按[九宫格硬性倍率要求](../../app-ui-layout/references/relative-layout.md#图片尺寸)检查。图集按单帧、帧坐标、padding 和整图预算核对；序列帧、像素图与法线图不得套用普通图片缩放。满幅装饰背景按实际覆盖视口、比例和既有背景规则计算，不把任意小图规格套给背景。
- **导入前核对实际文件**：沿用已有素材规格记录生成尺寸、正式输出尺寸、显示尺寸及密度依据；公共 `asset-task.json` 使用 `generationSize`、`runtimeSize`、`displaySize` 和 `designBasis.importDensityAndUnit`，已有原生合同则引用其对应字段，不维护第二份规格。实际解码待导入文件，宽高须精确匹配正式输出尺寸，过大、过小、缺少用途或密度依据均不能作为本项尺寸检查通过。保留源／输出路径、实际尺寸和处理结果，导入后再回读原生尺寸、切片与消费者。

按已确定生产规格对新制作素材做尺寸归一化属于 V4 素材交付，无需另行触发 `app-image-optimization`。已在用资产的批量压缩、格式迁移或优化仍遵守该技能的显式请求边界；不得借此改写冻结原件或擅自重排图集。只需要等比例缩小的生成结果，使用本栈已有归一化工具或确定性处理能力；比例不符、主体被裁掉、透明边缘损坏或细节不可辨时返回生产环节，不能拉伸、盲裁或插值放大伪装成合格成品。视觉预览仍交用户人工检查。

## 去背景与原生交接

本技能的 `scripts/png-raster.mjs` 和 `scripts/remove-background-local.mjs` 提取自 Unity 基准的无引擎工具，各栈共用，不重复维护。工具支持 8 位非隔行 PNG 解码，实际支持格式以脚本拒绝条件为准。

对已获得且符合纯色背景路线的素材，按需要显式运行：

```powershell
node <技能目录>/scripts/remove-background-local.mjs --source art/item.raw.png --output art/item.png --background-color "#00aa55" --tolerance 24 --require-solid-background --record art/item.background-removal.json --preview
```

算法从画布边缘做四连通颜色清除，不处理复杂背景、毛发、玻璃或发光半透明边缘；不能用它通用抠图。已有真实 Alpha 使用直接透明路线，不重复抠图。处理不覆盖原图、不改变尺寸，记录中包括算法、参数、Alpha、删除像素与失败原因。保留哈希仅用于该工具输出的来源诊断，不把它引入公共阶段确认或验收一致性门。

预览是交给用户检查的资料，不自动据此判定视觉通过。PNG 结构与 Alpha 检查仅证明技术事实；去背景不能去除模板感、结构错误或材质混乱。设计稿生图和编辑使用[初始化冻结的执行方式](image-generation.md)。只有当前工作流明确需要这项确定性后处理时才执行上述工具，不以像素脚本替代生成式编辑。

技术交接按所选技术栈执行：

- Unity：AssetDatabase、GUID/.meta、Importer、Sprite/Pivot/Clip 与实际消费者。
- Cocos：AssetDB UUID、导入子资源、SpriteFrame、Prefab 与资源加载路径。
- Phaser：纹理/图集 key、帧、Scale/Camera 与实际加载和渲染对象。
- Three.js：纹理色彩空间、UV/材质、glTF、实际渲染与 GPU 资源释放。
- Expo：按实际 Metro 静态资源引用或已选加载库登记，核对图片密度、字体注册、缓存与真实 React Native 消费者；不得用整页位图替代交互或强行采用其他栈图集。
- Flutter：pubspec 资产登记、逻辑/像素密度、Image 约束、缓存和真实 Widget 消费者。

源仓库中的其他图集、模型和布局工具并未自动打包进本技能；需要时按技术规范及当前项目能力选用，不能调用不存在的旧工作流命令。
