# 风格与制作规范

## 视觉签名不是关键词堆叠

从产品主题、目标用户、核心操作和实际观看尺寸出发，确定能复述的两个或三个视觉特征。例如“倾斜切角的厚纸剪影、有限双色印刷、关键信息使用大留白”，比“高级、精美、电影感、8K”更能约束一致性。具体风格由项目选择，不统一规定极简、低饱和、写实或手绘。

style recipe 至少约定：

- 轮廓与比例：形状语言、透视/机位、重心和尺度关系。
- 色彩与光照：功能色、材质固有色、主光方向及可用对比范围。
- 纹理与细节：表面工艺、笔触/颗粒尺度、边缘规则和真实目标显示尺寸下的细节预算。
- 系列特征：角色脸型/服装、图标笔画、道具透视、环境材质或品牌构图的稳定规则。
- 实现预算：原生组件、位图、矢量、3D、动画分别承担什么；不在效果图承诺无法交付的细节。

参考图先确认可用来源和实际用途：构图、色彩、轮廓、材质或角色身份。用户提供参考并指定改动时按其已授权范围执行，不无条件再加版权问卷；只有来源、复刻用途或批量范围存在实质歧义时询问。保持参考与正式素材的身份分离。

界面构图、控件与图形语义同时遵循[无文字意图可读性规范](interface-intent.md)，使主要任务和操作关系在去掉文字后仍可辨认；将检查纳入下述已有候选审阅。

## 三候选选择

全局首次恰好三张候选，题材内容、构图任务、视口和制作预算保持一致，差异集中于可比较的视觉方向。每张保留主题贴合、受众适配、任务可读、观看舒适和美术完成度五项结果，未审为 NOT_RUN；最终选中候选必须五项均经有效人工确认。候选不能替用户选择，也不能用更细致的渲染掩盖任务不可读。

选定后提取制作规范和一个代表样本，后续素材按该样本生成或编辑；不要每个图标、页面和道具另起一份随机画风。三张候选只发生在首次全局方向选择，不要求每项素材生成三版。

代表样本沿用现有素材规格和布局依据交接。在目标显示尺寸与实际背景下，由用户检查视觉效果；代理可核对源帧与有效内容边界、透明留白、导入密度、元素尺寸和祖先变换，排除视觉偏移与重复缩放，并按适用性核对切片边角、边框厚度、透明边缘及真实字体/文案造成的排版变化。不能用放大普通图片掩盖内部图案偏小；按既有规则调整布局或重新生产合适素材，不改变已确认视觉目标。

现有 `asset-task.json` 的 `designBasis` 按需记录依据，不构成新门禁：`sourceAndVersion` 指向有效设计来源；`valueKind` 使用 `confirmed-target`、`measured`、`estimated` 或 `adaptation-rule` 表明该组值的性质，混合来源时在已有说明中逐项区分。边界、留白和密度使用本栈实际单位，未知保留 `null`，不能填写虚构测量；这些字段是交接说明，未接入校验器时不宣称机器已验证。

## 紧凑提示词

按“视觉用途 → 必要内容与结构 → 已选视觉特征 → 关键限制 → 输出规格”写最终提示词。PRD、流程 ID、审查理由、路径和长篇实现说明留在内部资料，不送入画面。

示例：

```text
为纸艺探险游戏制作侧视医疗包图标，显示于 64 像素背包格。
保留倾斜切角、厚纸层叠和两色印刷，形体清楚、右上方柔光。
只画一个完整医疗包，中央十字清晰，避免小字与微小饰件。
透明背景，正方形 PNG；边缘不带背景色或落地阴影。
```

透明是实际像素需求，不能用棋盘格背景代替；图标制作尺寸与运行尺寸分别记录。不要把“no AI”当成具体制作约束，也不通过“增加噪点、做旧、滤镜”统一掩饰生成痕迹。

## 拆解与系列生产

每项资产有稳定 assetId、目标对象、可见特征编号、消费者和状态；同一共享资产只生产一次。参考图中的主要形状、材质、边框和空间关系必须有生产或原生实现归属，不能在拆解时无意简化丢失。

游戏分别约定角色/道具/场景/UI/特效/贴图的一致性；App 分别约定品牌插画、图标、照片和空状态。真实文案、功能图表和数据用原生组件，不把生成图中的假文字和假数据接入正式页面。3D 的模型、UV、材质、骨骼与动画走技术栈 DCC 交接，不能把平面效果图冒充可用模型。
