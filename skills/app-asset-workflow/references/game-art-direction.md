# 阶段 4 游戏美术方向

适用于游戏图片视觉基线。先交付调研与参考依据，再给出一张推荐稿；有分歧时才制作针对性对照。最终图由用户人工确认，其规则供 V2 模块稿复用。[无图 3D 场景](../../app-workflow-control/references/world3d-scenes.md)按空间与方向合同表达三维世界，需要出图的游戏界面采用本节 UI 规则。

## 调研与参考交付

出稿前按[统一分析](../../app-creator-workflow/references/professional-conventions.md#product-market-research)完成或核实复用市场、竞品、受众和美术参考。向用户交付两项内容，完整依据写入现有[调研清单](../../app-workflow-control/templates/visual-research.json)和视觉 brief。

- **调研摘要**写目标平台、同类体验、玩家使用情境和最需要一眼辨认的内容，并把每项重要结论转成当前视觉取舍。结论注明来源，区分事实、玩家反馈和待验证假设。
- **美术参考清单**逐条写来源、看到的特征、为何采用或舍弃，以及如何用于全局、原画或 UI。例如「同类游戏用亮色突出可操作目标，本项目将亮橙用于拾取物，森林背景用低饱和色」。

## 三层风格规格

沿用 [style-recipe.json](../templates/style-recipe.json) 记录制作规则。全局基线引用实际代表稿与调研依据，风格规格根据最终确认稿更新。每层只选择当前项目适用的规则。

| 层级 | 阶段 4 确定的规则 |
| --- | --- |
| 全局美术方向 | 整体气质、色调和饱和度、代表色与含义、形状语言和共用材质特征。 |
| 原画 | 角色、道具和场景的部位色及主次分工，明暗、边缘、纹理、材质和细节密度。 |
| UI | 背景、文字、控件、主操作及状态的颜色分工，字阶与对比，面板、按钮和图标的画法。 |

| 对象 | 常见配色方式 | 常见渲染方式 |
| --- | --- | --- |
| 原画 | 部位分色、限色、邻近色、冷暖对比、主体和背景分色。写清颜色落在哪个部位或区域。 | 平涂的大色块、赛璐璐的硬边阴影、手绘厚涂的笔触和软硬边、半写实的材质反光、像素画的离散色阶、风格化 3D 的倒角与接触阴影。 |
| UI | 中性色底配操作色、深浅分层、功能色、类别色、HUD 前景与场景分色。功能色按需搭配可辨的图形。 | 扁平填充、统一线粗与剪影、纸木金属等材质化边框、浅倒角和层次阴影、半透明 HUD 底板。写清纹理、边缘和阴影用在哪些控件上。 |

例如纸艺游戏共享米白、墨绿、暖橙和剪纸切角。原画的森林用纸层、纤维和叠层阴影表现深度。HUD 的内容区用平整色块与高对比数字，纸纹集中在边框。

## 推荐稿与反馈

1. 用有代表性的可达游玩状态、实际玩法镜头和目标视口制作一张推荐稿。适用时在画面里展示常用 HUD，代表稿覆盖不到的重要表现按需补小样。随图说明推荐依据、可见取舍，请用户看游戏的感觉是否合适、关键目标或操作是否一眼能找到。
2. 用户能明确说出想改什么时直接修。例如「森林再亮一点、按钮更明显」转成提高场景明度、拉开主按钮与面板的对比。提交修订后的实际图供人工确认。
3. 用户明确希望比较，或对某个视觉取舍难以决定时才追加对照，默认针对分歧给推荐版和另一版。比较原画时固定镜头、玩法内容和 HUD，比较 UI 时固定场景、状态和功能内容。整体方向存在分歧时，保持同一任务、视口、状态、示例值及可比预算，分别表现有实质区别的造型、材质、光影和 UI 语言。
4. 用户用日常语言确认最终稿。按[人工质量与冻结](../../app-domain-toolkit/references/reference-asset-global-visual-control.md#game-visual-freeze)记录真实选择和主题贴合、受众适配、任务可读、观看舒适、美术完成度五项结果。未确认的项保持未验证。把涉及的实际提交图、最终图版本、决定和风格规则交接给后续阶段。
