# 多张场景设计稿

## 确定视图范围

相关功能先完成 V1 验证，白盒按需使用；按当前功能影响范围，再根据游戏内容、地图范围、镜头移动、玩家会到达的区域及关键状态判断一张目标视口是否足以清楚表达。新场景先制作包含必要环境和常驻界面的完整关键视图；已有场景复用已确认目标，优先只调整受影响区域并展示足够上下文。仅改变内部逻辑或数值且不影响视觉时不强制生成设计稿。内容多、场景大或状态互斥时，按需要生成多张可独立审阅的视口设计稿；不把所有内容缩小、挤进一张图，也不规定固定张数。范围较小且一张可清楚表达时仍可只用一张。

在现有场景规格或视觉设计记录中列出视图清单：所属场景、区域或镜头位置、玩家可见状态、目标视口和方向、必须展示的玩法内容与常驻 HUD、相邻视图及共享对象。以当前任务的需求和玩家路径核对覆盖，标明未覆盖范围；必要时补充整体示意图说明区域关系，但示意图不能代替各视口设计稿。按既有显示层流程分别处理弹窗等瞬态层及其宿主上下文，不把互斥状态同时塞入基础场景图。

## 生成与确认

首批相关功能的 V1 验证后、V2 之前，首次全局方向按既有流程生成同内容、同视口的三张候选并由用户选择；这三张是方向备选，不是场景覆盖清单。选择并冻结全局基线后，按视图清单生成需要的设计稿，而不是为每张图重新产生三种风格。所有图沿用相同的基线、锚点、角色身份、尺度、镜头规则、光照和 UI 语法；图中内容、区域特征和状态可以按各自职责变化。相邻区域保留可辨认的共同地标或其他衔接线索，记录世界位置、方向和共享元素关系，避免把同一对象画成不同身份。

每张图记录其视图身份、目标场景与状态、视口、来源、实际文件和生成记录，并关联清单及全局基线。按真实目标尺寸生成清楚可读的画面；不要用拼贴或长图代替可独立审阅的视口图，也不要把图当作正式运行界面的单张背景。将全套图片和对应范围、衔接及检查要点交给用户人工确认；有遗漏或冲突时只调整受影响的图和记录。未取得实际确认的视图保持未确认，代理不代替用户判断画面通过。

## 拆解、实现与验收

每张被指定为正式运行视觉目标的图分别冻结目标及条件，依次完成 V2 目标、V3 拆解和布局确认、V4 资源验收与 V5 正式场景验证。V1 的功能验证可以由相关对象共享，但不能替代每个视觉目标的确认。每张图的区域、布局、状态和证据绑定其对应目标，不能用另一张图的确认或一个代表视图替代。每张图内可以包含基础场景与相应常驻 HUD；瞬态显示层仍走独立的宿主上下文流程。

同一场景只建立一个 SCENE 工作项，并在其视觉目标清单中逐视图登记身份、目标和确认；每张图使用独立的单目标领域合同，均绑定同一工作项。为共享场景文件和资源指定唯一所有权、依赖及顺序，不为每张图创建一份重复的运行场景。共享对象只建立一份资源及稳定身份，记录各视图中的位置和状态；存在差异时明确是否为允许的状态变化。

在场景整体交付前，逐项核对视图清单、各目标的确认与阶段证据、共享资源及相邻区域的衔接；V5 提供各目标对应的正式运行画面，以及适用的镜头移动或区域切换资料，由用户人工检查。跨场景功能在正式组合后另验证完整路径及状态衔接。未完成或未人工确认的视图明确列为未覆盖，不能以某个视图通过冒充整场景通过。控制器逐目标检查冻结范围、目标文件与各次确认的 SHA-256、领域合同、V5 证据类别及整体衔接确认；它不判断图片内容，实际覆盖与视觉衔接仍由用户人工检查。
