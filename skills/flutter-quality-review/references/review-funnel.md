# F0–F3 审核漏斗

漏斗以变更和风险为输入，以最小必要审核为输出。实现者、Controller 和只读审阅者保持职责分离；普通审核绑定可复算 `snapshot-id`，不是强制提交。

## 四级职责

| 级别 | 执行者 | 只做什么 | 输出 |
|---|---|---|---|
| F0 | 实现者 | 实际执行任务所需的项目原生分析、测试、构建、审计或回归命令 | 命令证据、变更路径、snapshot 输入 |
| F1 | Controller | 检查范围、风险、验收、输入指纹和 F0 证据，选择触发通道 | 路由及理由，或退回实现 |
| F2 | 独立只读审阅者 | 只检查被触发的专业维度和同一 snapshot | 结构化通道结论 |
| F3 | Controller | 收敛有效结论、阻塞和当前层级集成条件 | 通过、退回或阻塞 |

`light` 将 F0/F1/F3 合并为一次自检且不创建审核工件。其他等级仍按风险启用漏斗；F1 不得把未触发的专业通道变成必做。

## 路由不变量

| 场景 | 风险 | 默认路由 |
|---|---|---|
| 文案修改 | `light` | 自检；无 F2 |
| 普通 Bug | `standard` | 行为/验收变化时 QA F2，否则 F1 自检 |
| 页面功能 | `standard` | QA + 视觉 F2；技术只在对应事实变化时触发 |
| 认证迁移 | `high` | QA + 技术 F2；涉及用户范围或视觉才追加对应通道 |
| 发布准备 | `release` | QA + 技术 + Release F2；Product/视觉按变化触发 |

这是默认路由；安全、数据、外部影响或验收边界变化可以提升风险，不得降低已确认通道。

## Snapshot 与失效

`workflow:snapshot` 以基线 commit、排序后的变更路径/状态、每个当前工作树文件的 Git blob ID（含未跟踪文件）计算稳定 ID。输出只到 stdout，不写状态。删除项保留路径并使用空 blob 值；重命名同时保留旧路径与新路径；空工作树仍输出确定的 snapshot。

F2 返回后，Controller 只把输入指纹变化的通道标为失效。修复只重跑失败或受影响命令，再从 F1 重新分诊；未变化的审核结论可继续使用。

## 返回契约

```text
通道：Product / QA / technical / visual / Release
Snapshot ID：<workflow:snapshot 输出>
覆盖事实与证据：<路径或命令证据>
发现：<Critical / Important / Minor，含路径和行号>
缺失证据：<无则写无>
结论：approved / changes_requested / blocked
```

F2 不写共享 `review.md`。视觉通道另报审美和关键对齐结论；F3 不重复 F2 细节，也不能替代缺失的专业结论。

## 持久记录与边界

仅在 `high`/`release` 的持久独立验收、跨角色交接或用户明确要求时创建 `review.md`。Controller 是唯一写入者，记录 snapshot、F0/F1 引用、F2 结论和失效历史。Markdown 不是运行时状态、自动合并信号或发布授权；PR、外部写入、发布和真机验收仍需单独明确授权。
