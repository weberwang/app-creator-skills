# UI 相对布局与定位

本规则适用于五个技术栈的游戏和应用 UI，包括页面、场景 HUD、控件及浮层内部。布局、草图、素材拆解和正式实现使用同一规则；原生组件、坐标空间与资源约束仍按当前技术栈执行。

## 相对关系

- 每个 UI 元素以实际父容器或明确允许的参照对象为依据，声明布局归属、参照、对齐或锚点、间距及尺寸策略。页面或场景根可参照实际视口、安全区等稳定边界；明确独立参照时同时保留真实父子关系。
- 位置由流式布局、容器约束、锚点、兄弟/祖先参照或其他已声明关系计算；父级、参照、内容、可用尺寸或安全区变化后重算受影响布局。不能把普通 UI 单独固定在屏幕坐标上来代替这些关系。
- 相对布局不要求所有尺寸、间距或偏移使用百分比：固定内边距、固定尺寸及相对参照的偏移可以使用；运行时或测量结果中的绝对坐标、矩形也可以记录，但它们应由声明的关系计算得到。
- CSS `position: absolute`、Flutter `Stack`/`Positioned` 等是实现方式，不自动证明或否定相对关系。普通 UI 使用它们时仍须绑定父容器或明确参照，并随参照变化保持约定关系。

## 浮层本体的例外

弹窗、浮窗和 Toast 的**本体容器**可以按任务需要独立决定其相对宿主的落位；可按视口、输入位置、用户拖动结果等选位，也可以采用相对定位。其本体仍需满足项目的可见范围、安全区、遮挡、输入与生命周期要求。

该例外只适用于这些浮层自身的容器，不传递给内部任何后代。按钮、图标、文字、徽标、列表及其他内部 UI 仍须相对其父容器或明确参照布局与定位。普通 HUD、按钮和其他 UI 不因为标记为 overlay、处于 `DISPLAY_LAYER` 或使用叠层组件就获得例外；三维世界对象按各栈世界坐标规则处理。

## 验收

记录需要验证的 UI 层级、父级与定位参照、锚点或布局约束，以及适用视口和内容状态；普通 UI 出现直接依赖固定屏幕坐标时须修正。分别检查：

1. 参照或父容器移动、缩放以及视口/安全区变化时，受影响的普通 UI 维持声明的相对关系并重新布局。
2. 浮层本体移动或可用尺寸变化后，内部控件仍相对浮层内容区或各自声明的参照保持关系；长文案、动态数据和滚动不得破坏操作与可读性。
3. 对目标栈的代表性尺寸、状态和输入方式提供实际布局与交互证据。静态合同通过只能证明其已检查的字段，不能单独证明浮层本体身份、后代关系或真实运行效果；显示效果仍由用户人工检查。

## 模板与机器检查

校验器从正式原生节点读取实际父级与定位参照，调用同一[相对布局检查模块](../scripts/relative-layout-policy.cjs)。它拒绝普通 UI 的独立定位、未知定位模式、缺失或成环的父级/参照，以及浮层内部引用外部视口或祖先的逃逸。不能另建一份与正式节点无关的关系图代替检查。

| 工件 | 必须维护的节点事实 |
| --- | --- |
| Cocos、Phaser、Three.js 普通布局 | `regions[].parent_id`、`reference_id`、`positioning`；本体类型用受控的 `floating_root_kind` 声明并与真实区域身份绑定。 |
| 三栈效果图布局 | 使用唯一布局源中的真实父级、锚点和参照；`ui_layout.positioning` 与 `floating_root_kind` 随同一节点身份传递。Cocos 引用式合同直接校验其引用的真实节点文件。 |
| Unity | 使用 `parentElementId` 与 `layoutBinding`；本体的 `uiLayout.floatingRootKind` 必须绑定独立显示层，`positioning: absolute` 时以 `independentPosition` 记录目标落位。普通计划中的位置由既有父级和锚点关系派生。 |
| Flutter | 每个 region 声明 `parent_id`、稳定且唯一的 `flutter_key` 和 `positioning`；浮层本体还需与相同 ID、相同类型的 overlay 绑定。实现信号与高保真测量必须引用同一实际节点与参照。 |

定位模式只允许 `relative` 或 `absolute`。只有显式且合法的 `popup`、`floating`、`toast` 本体可使用后者；所有内部子孙仍须相对定位，不能重复声明本体来获得豁免。已有强制父级、锚点和参照的原生结构，在未声明独立模式时仍表示相对布局；显式非法值不能当作缺省值放行。

独立本体仍须保留必要的结构、初始几何与真实测量事实；几何矩形的存在不把其变成必须跟随宿主的普通控件。运行时本体自由落位时，内部节点继续对实际本体和内部参照验证。静态检查不代替对应用中真实节点、动态随动或显示效果的运行采集与人工验收。
