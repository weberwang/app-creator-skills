# 游戏数值与经济

将游戏数值设计变成显式公式、约束和可复算情景，避免孤立调参破坏成长节奏、资源循环或公平性。

执行前阅读[公共执行协议](../app-creator-workflow/references/professional-execution.md)。以下共用步骤不能跳过所选原生适配规定的操作顺序、资源格式与平台边界；必要的用户确认按协议执行。

## 输入

- 玩法规则、目标节奏与玩家分层；数值表/配置和初始状态；掉落、消费、成长与失败数据；目标区间和限制。

## 共用操作步骤

1. 列出影响结果的参数、单位、范围、默认值、读写入口和负责人；标出哪些为设计目标、观测值或暂定假设。
2. 写出玩家状态和资源的转移方程，包含产出、消耗、上限、刷新、保底、失败损失及离线/重试情形。
3. 构造快/慢/极端玩家情景，逐关或逐周期计算关键指标，检查单调性、可达性、死锁、负值、溢出和资源无限循环。
4. 比较相邻难度/成长节点，检查奖励与成本、时间投入和失败惩罚的比例；确认每次调整背后的目标指标与副作用。
5. 用数据脚本或表格重算候选参数，并保留基线、变更差异和代表性情景，必要时对随机系统固定种子或使用批量模拟。
6. 先在最小可玩的切片回归体验，再冻结版本化参数并复算所有关键情景，记录待观察指标和回滚阈值。

## 关键边界

- 不虚构玩家行为数据或声称模拟能替代真实体验；没有定义目标区间时只报告曲线和决策缺口。
- 参数存储格式、随机数、热更新和资源约束必须使用当前栈的实际实现规则。

## 交付

- 带单位的参数表、公式/状态转移、情景计算、异常检查、调整理由和可回退的候选版本。

## 当前技术栈的原生流程

先根据仓库实际依赖与项目配置确认当前 `app-stack-*`，再打开同目录的 [native-adapters.json](native-adapters.json)。按 `when` 选择 `mode`，从 `path` 指向的本栈原生手册中定位 `section` 章节，只读取该模式及其明确需要的脚本、模板和校验器；同栈同能力的多个模式在同一本手册内维护。
使用共用读取工具：`node .agents/skills/app-skill-runtime/read-native-mode.mjs <技术栈> app-game-balance [sourceSkill]`。单模式可省略来源，多模式必须指定清单中的 `sourceSkill`；输出所选章节、直接公共依赖及按需资源路径，不递归加载其他模式。维护本技能仓库时将 `.agents/skills/` 换为 `skills/`。
若 manifest 未列当前栈，继续使用该栈 `app-stack-*` 中的原生规范/索引及适用公共流程；这本身不代表能力缺失。仅当已声明并选中的原生手册或模式章节未随安装提供时才报告阻断。公共工作流只在 `sharedWorkflows[].stacks` 包含当前栈时读取；`onDemand: true` 的参考按当前任务选择，读取器仅列出路径。不要加载其他栈模式或臆造接口；栈未确认且会影响实现时先澄清。
