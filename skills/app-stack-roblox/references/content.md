# Roblox 内容、地形与 GUI

## 内容路线与所有权

先阅读现有 GDD、目标视图和正式资产，记录对象职责、显示层、世界/屏幕坐标、单位、尺度、父子关系、交互、来源与消费者。优先复用满足需求的正式对象与平台能力；按形态、重复性、参数化、碰撞、绑定、拓扑和可编辑性选择 Studio Part/Model、程序化模型、AI 网格、Creator Store/库存或外部制作。用户已指定的创作方式优先，不因工具可用而自动引入新资源。

在 `Edit` 中建立或修改正式可编辑内容，保存 Place 并读取回来；启动或刷新脚本不得重建编辑器已配置的静态内容。动态对象按实际业务使用模板或池，明确产生、所有权、销毁及重入。工具创建成功只证明工具返回，仍需检查实例、正式引用、运行时消费及用户视觉确认。

`generate_procedural_model`、`generate_mesh`、`generate_material`、纹理生成、对象分件与资源导入仅在当前 Studio 能力列表中实际存在时使用；异步任务保留真实结果和失败信息。参数化模型记录参数与重新生成影响；网格检查实际尺寸、朝向、枢轴、碰撞、材质、形态和预算。角色自动设置及动画工具按实际版本执行，不能承诺自动生成可用骨架、动作或符合目标的拓扑。

资产登记区分本地源、平台资产 ID、所有者/使用权限、审核状态、目标版本和消费者。Creator Store/库存资源先检查来源与附带脚本，再按任务授权接入。导入器可能涉及上传；上传、生成和外部操作按实际行为与公共权限执行。许可、审核或实际加载不明时保留未验证，不以插入 ID 代替运行加载。

## 地形

Terrain 是世界空间对象，按当前 Studio/Terrain API 的实际能力与体素规则使用；可在 Editor 中生成、雕刻、导入高度图，或在授权范围内通过 Luau 构建地形。先记录目标 Place、边界、素材/地形材质、受影响区域、现状和恢复依据；已有环境只改当前允许区域，不默认清空整个 Terrain，不把非本任务区域重建为副作用。

按类型选择碰撞/路径、出生点、梯度、跳跃距离、水体与遮挡、地图边缘及性能用例；可达性依真实角色能力和正式数据，图连通不足以证明实际可到达。V1 先验证相关机制与空间，V4 读取正式源和素材，V5 在真实目标镜头及播放条件检查通行和输入；画面及体验交用户检查。

## GUI 与世界

声明 `SCENE` 中世界对象与常驻 HUD 的宿主；弹窗、抽屉等独立瞬态层由 `DISPLAY_LAYER` 绑定真实 hostId/layerType，复用代码与资源时分别验证实际宿主。每个关卡是否为不同 Place 取决于实际内容及运行边界，不由关卡数量强制决定。

GUI 以实际 `ScreenGui`、父级、位置约束、尺寸、层序、屏幕安全区及真实输入命中定义；区分 Edit 的配置模板和运行期间的 PlayerGui 克隆。世界空间以 studs、相机投影、碰撞和遮挡约束为准；不把二维设计像素当作世界单位。按目标 PC、移动、手柄等选择 Roblox 实际支持的尺寸、方向和输入，不套用其他技术栈的固定画布或原生启动页。

普通 GUI 相对实际父级或经允许的参照停靠；原生 `Position`/`AnchorPoint` 能表达时直接使用，列表和网格的子项由父布局负责。编辑态与运行克隆分别核对节点、原生组件与控制权，动态拖拽记录独占和恢复；世界中的二维 GUI 仍在自身容器内相对布局，世界宿主的位置和相机投影独立处理。

展示类特效、镜头和声音按规则事件驱动；会改变游戏时序、位置、碰撞或输入权的动作由玩法所有者定义。显示层和弹窗与宿主共同处理输入隔离、关闭销毁、任务取消和运行时克隆，不能只看层级数字。
