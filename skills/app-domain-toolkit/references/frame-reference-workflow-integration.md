# 帧动画资源与工作流接入

执行公共规则时，同时读取当前技术栈参考中的原生补充和“本栈配套资料”。各段仅适用于标注的技术栈；结构化证据不代替用户对显示效果的人工验收。

## 通用帧动画工作流接入合同

> 适用技术栈：cocos、phaser。

执行者按“执行代理”（见本栈配套资料）中的用途类型与职业映射分配设计师，并按“导演与动作指导”（见本栈配套资料）安排简单任务由设计师兼任、复杂任务独立委派导演。任务包明确复杂度依据、导演安排、职业职责、负责动画/区域和跨类型交接；导演与各设计师使用约定的 `gpt-6.1-sol`、`max` 子代理。主代理交接人工确认、实际来源、生成授权和限定任务包，同一 Work Item、同一职业职责范围的连续制作与修正复用该代理。实际图片生成/编辑另交图片生成代理，动画执行代理集成。

> 适用技术栈：cocos、phaser。

帧动画先按 “SKILL.md 的分类入口”（见本栈配套资料）选择普通、角色、特效或 UI 帧动画规则，再按“来源路线”（见本栈配套资料）处理素材：未指定时默认视频抽帧，固定画布图片递归补帧须有用户明确选择或切换确认。动作时间轴内部推导并记入设计工件后，向用户阐述设计理念并暂停；取得用户明确确认当前动作方案后，才制作真实素材和推进具体实现。视频必须人工验收当前实际抽帧输入后才能抽帧，图片逐张确认首尾、必要关键帧和递归父图后再推进。帧动画不制作灰盒或可播放占位示意。全局视觉阶段为 V0、V1、V2、V3、V4、V5；V3 保存动作设计记录与用户方案确认，V4 制作并验收真实素材，不改写全局 `visualStage`。

> 适用技术栈：cocos、phaser、threejs。

用途类型、来源路线、行为单元、播放方式、来源批次与 key 数量分别确定。按“区域规划”（见本栈配套资料）组织兼容的多区域来源；各区域分别记录类型、有效源区间或帧位和游戏时间映射，每个输出独立绑定图集、报告及实际生成的预览与播放设置。分类与优化参数放在设计工件中。视频沿用现有 schema；图片来源、报告和 accepted 使用独立 schema，避免伪造视频证据。

> 适用技术栈：cocos、phaser。

多区域视频的内容按各区域自己的设计时长结束，短区域无须继续生成以等待长区域。提示词、来源映射、实际抽帧输入和人工验收沿用同一有效区间；例如 A 为 5 秒、B 为 3 秒时，B 仅制作和验收前 3 秒有效内容，抽帧前分别准备对应时段的输入，不把共享视频余段追加到 B。区域终点及结束方式纳入用户待确认的动作方案，细节见“生成参数核对与来源空间”（见本栈配套资料）。

## 动作设计与素材确认

> 适用技术栈：cocos、phaser。

方案完成后、制作前，主代理按“设计理念说明”（见本栈配套资料）主动向用户阐述目标感受、关键动作依据、节奏取舍和观看重点；执行代理须及时交接这段说明。详细时间轴和提示词仍内部维护，说明后暂停等待用户明确确认当前动作方案；记录确认版本与范围后，才在已有操作授权内推进素材制作和具体实现。

> 适用技术栈：cocos、phaser。

方案同时按“效果与性能平衡”（见本栈配套资料）说明推荐 FPS、帧数、输出尺寸及取舍依据，内部记录已有预算和预期资源规模。用户确认后制作，最终由真实素材人工验收与实际资源、运行性能证据共同判断；只有估算或独立预览时，保留性能未验证状态。

> 适用技术栈：cocos、phaser。

按“动作分析规则”（见本栈配套资料）和“玩法与意图推导”（见本栈配套资料）在内部推导并记录行为、运动、衔接/循环与节奏，用户确认当前动作方案后再采用对应参数写提示词并制作真实候选。设计工件区分首次反馈、实际生效、既有控制/切换窗口与动画结束；制作和接入沿用同一依据，不能用美术节奏改写玩法权限。只有确实缺失且无法从现有规则推导的玩法事件、时长或行为权限才询问用户，并只暂停受影响动作；其它明确动作可继续设计，制作仍须取得对应方案确认。

> 适用技术栈：cocos、phaser。

视频方案按“合批消耗比较”（见本栈配套资料）内部比较能覆盖全部动作的候选排布、768p/2K 实际宽高、条数、生成时长与整组消耗依据。先选最少可行条数，再选该条数下整组消耗最少者，同等条件优先 768p；把推荐和简短检查点随真实候选交付。已有预算与外部生成授权边界仍有效，方案不扩大授权。图片按“图片分辨率约定”（见本栈配套资料）处理，不套用视频合批优先级。

> 适用技术栈：cocos、phaser、threejs。

按“共用时间轴”（见本栈配套资料）规划各独立动画，将可读阶段表和文字说明保存在内部工件。工件记录用途类型、来源路线、当前类型的表现依据、行为边界、批次分组、尺寸推理、区域布局、游戏时长、阶段区间、关键姿态/视觉状态意图、事件、允许位移和播放方式。图片路线记录固定画布、目标帧位和必要关键帧；这些是完整时间轴的采样设计，不把完整行为拆成不同技能。多阶段或组合行为记录整组时间轴，循环明确周期与闭合要求，单次明确结束去向，终态保持明确结束条件。设计中的范围与尺寸区分实测值和推断值，实际可读性、完整入框及跨区干扰留待真实素材检查。

> 适用技术栈：cocos、phaser、threejs。

角色按“衔接与循环设计”（见本栈配套资料）说明既有前置/后续行为的入姿、出姿与切换条件；循环说明进入、周期内运动与退出，单次或组合说明结束去向与已定义分支。缺失的相邻动作或玩法条件标为待定，只在无法推导时询问；不自行编造切换路径，也不让该问题阻塞无关动作。内部时间轴记录不能证明真实姿态、重量感、尺度稳定或循环连续性通过。

> 适用技术栈：cocos、phaser。

用户对真实素材的确认绑定当前候选、来源和实际表现时序。目标感受、核心动作方案、来源路线或玩法语义实质变化时先重新确认；同一目标下调整阶段、关键姿态、播放细节或局部纠错时更新内部工件并直接返修，展示前后对照，不重新索取已有生成授权。实际视频输入改变仍须重新人工验收；图片帧变化后重新检查当前帧，并检查后代是否继承缺陷，只对实际受影响帧返修并重新确认，保留仍可用的后代及其真实旧父图来源。纯技术记录变更不新增文字确认。真实素材审阅与最终序列验收分别记录，不用内部设计记录替代。

## 真实素材审阅与验收

> 适用技术栈：cocos、phaser。

先由用户在正常速度、目标显示尺寸下完整观看真实素材，判断目标感受、吸引力、性格、节奏和核心表演是否成立，再逐帧定位身份丢失、无因跳变、接触穿帮或事件错位。合理的转身、侧身、翻腾、透视、遮挡和形变按连贯运动判断，不以某帧偏离正面基线作为失败依据；技术结构通过也不代表观看体验通过。

> 适用技术栈：cocos、phaser。

视频先核对真实内容、显示尺寸、朝向、音轨和区域，再按“视频节奏整理”（见本栈配套资料）完成必要的有效区间选择与阶段重定时。将最终实际抽帧输入连同简短检查点交付用户人工验收；原视频已经适配时直接使用原视频，发生整理时验收派生视频。逐区域提供当前实际输入路径、有效区间与游戏时间映射，按内部时间轴检查关键姿态、动作节奏、完整运动范围、身份延续与资源映射、设计中的透视/位移、阶段/外部动作衔接、事件同步及循环/终态。用户确认实际视频也接受其表现时序，无需另交文字方案复述；尚未验收或判定失败时先修正并重新交付，不能先抽帧再用图集代替视频验收。

> 适用技术栈：cocos、phaser、threejs。

视频验收绑定当前实际输入的文件身份、区域、时间映射和用户结论，保存到设计证据。视频实际内容、有效区间、重定时或区域变化时重验受影响内容，摘要变化不影响验收，重新人工验收后才抽帧；仅改变输出 cell 等抽帧参数时重新检查图集，不要求重新制作视频。内部设计记录、修正意图、旧版本通过或文件门通过，都不能替代当前实际视频验收。共享视频各区域独立验收，未通过区域不进入抽帧，保留其它区域有效成果。

> 适用技术栈：cocos、phaser、threejs。

图片路线在真实首尾、必要关键帧与每层递归帧上执行“一致性及衔接门”（见本栈配套资料），人工确认当前帧后才放行依赖它的制作。关键帧未填满的序列标明缺失槽位，不能宣称完整动作通过。两条路线最终用真实完整帧序列检查单次/循环/终态、相邻动作衔接及目标显示尺寸；预览提供播放/暂停、重播和逐帧查看，阶段、事件、锚点和区域标记仅放在预览界面。特效检查不同背景叠加，UI 检查实际布局边界。视觉显示由用户人工验收，不自动截图或启动真机。

## 设计与美术的边界

> 适用技术栈：cocos、phaser、threejs。

时间轴向制作交接文字或结构化的行为、时间、关键姿态意图和功能参数。正式美术的视觉依据只能来自当前任务选定的真实美术基线、用户指定图片与已确认的实际父帧，分别记录文件身份。没有现成美术时按用户需求建立真实基线；设计图表、历史占位图、骨架或几何示意不能进入生成/编辑工具的视觉参考，也不能约束正式造型、身体比例、材质或细节。

> 适用技术栈：cocos、phaser。

资源布局依据真实美术及完整运动范围推理。出现空间冲突时保留真实美术基线，先复核画布、统一缩放、留白与语义锚点；同一目标下需要改变空间参数时更新内部设计并直接制作受影响的真实候选供用户审阅。不得让正式美术贴合占位图或以文件边界通过证明比例与动作正确。

## 视频提示词

> 适用技术栈：cocos、phaser。

动作分析、时间轴参数记录及用户对当前方案的明确确认完成后编写，描述须沿用内部工件中的参数与关键事件。按“意图到制作的交接”（见本栈配套资料）把表现意图写成姿态、运动间距、速度变化、保持和连接要求，并沿用检查点审阅真实素材，不能只堆叠形容词。多区域提示词逐组写明独立的有效时间区间、阶段节奏、事件和结束方式，区分批次视频长度与各自动画时长；不能用统一时长或统一节奏的笼统要求覆盖独立时间轴。详细依据见“游戏时间先于来源”（见本栈配套资料）。

> 适用技术栈：cocos、phaser。

提示词先表达完整动作过程与表现亮点，再补专业规律、身份与资源要求，保留当前候选的实际参数，不把类型规则写成笼统的“流畅”“有张力”：

> 适用技术栈：cocos、phaser。

| 层 | 内容 |
| --- | --- |
| 表演过程与当前参数 | 导演或兼任设计师的目标感受与亮点、连贯动作段落、关键姿态/状态、主体朝向演变、轨迹、透视与节奏；落实行为边界、游戏时长、阶段区间、事件、既有衔接与结束方式 |
| 当前类型规则 | 只从选中的分类参考提取本动画适用的判断，例如材质运动、身体发力与惯性、特效峰值/消散或 UI 反馈质感；将夸张、停顿和跟随运动写成可见变化，避免无差别添加禁止旋转、始终正面、身体不动等限制 |
| 身份与资源要求 | 当前真实基线与身份特征、镜头安排、区域布局、资源锚点与画内位移、完整运动范围、背景/透明处理、输出尺寸、FPS、来源时间映射及实际交付路径；固定分区镜头不等于主体不能转身，不把每帧相同轮廓或投影比例作为要求 |

> 适用技术栈：cocos、phaser。

视频分辨率在 **768p/2K** 中按“合批消耗比较”（见本栈配套资料）选择，沿用内部动作分析所得的实际宽高、最少可行视频条数与整组消耗方案，不增加确认门。音频及角色素材中的特效、声音、镜头反馈按任务合同选择，不默认烘入。多区域逐项描述类型、`x/y/width/height`、局部锚点和完整时间轴，各区域独立呈现，不能串动作；完整运动范围默认入框，不绘制标签或边框。只有明确授权后才逐项描述裁剪例外。尺寸推理与实际视频校准见“区域规划”（见本栈配套资料）。

> 适用技术栈：cocos、phaser。

独立精灵区域不混入无关 UI、文字或场景；场景层与 UI 帧动画遵循自身资源合同。位移、转向、透视与形变服务于表演，按连贯过程检查身份和轨迹，修正无因漂移或生成穿帮，不把静态一致性作为动作上限。各区域关键状态与事件须在目标尺寸和 FPS 下可读。颜色去背景只用于已确认纯色硬边，实际抽帧须显式传入 `--edge-profile hard-edge --color-separation-verified`，裁剪区域整圈为背景；复杂或半透明边缘使用真实 Alpha、遮罩或图片修复。提示词交付后等待真实视频，收到文件后记录实际动作、时机与裁剪缺陷；提示词不能替代内容检查。

## accepted 资源文件门

> 适用技术栈：cocos、phaser。

文件门只证明产物身份和结构一致，不证明分类、表现或节奏正确。提交 accepted 前须在 Work Item 设计证据中保留用途类型与优化依据、内部完整动画计划及对应版本的用户方案确认、实际抽帧输入视频或关键帧的人工验收依据、每个区域的有效源区间/游戏时间映射及最终完整序列验收结果。按类型检查可读性、节奏、主次、连续性和事件同步，核对时长误差不超过一个目标帧间隔、关键事件不缺失、阶段间无未计划重置、运动/保持和播放边界符合计划；不新增 schema 字段来替代设计证据。

> 适用技术栈：cocos、phaser。

视频发生剪辑或重定时时，`source_video` 绑定实际用于抽帧的派生视频，`quality_report.input.video_sha256` 仅作可选追踪；原始视频身份、剪辑命令/配置与时间映射另存设计证据，不新增未经工具支持的 manifest 字段。结构校验器不会自动执行上述人工节奏检查。

> 适用技术栈：cocos、phaser。

`settings.width/height` 是最终 cell 尺寸，`settings.region.width/height` 是源视频裁剪尺寸，两者可以不同。区域模式下，清单的 `settings.region`、报告的 `input.region` 与 `settings.region` 必须逐字段一致；显示画布宽高必须有效且完整容纳区域。整画布模式不填区域字段。以上 SHA 字段可省略，摘要不参与验收。

> 适用技术栈：cocos、phaser、threejs。

合法空透明帧保留帧索引和来源时间，例如特效消失或 UI 隐藏；整段全空时抽帧工具拒绝，不能通过删除空终态来缩短动画。单帧空结果仅由动画调用显式允许，不改变普通静态资产去背景的空图拒绝规则。

> 适用技术栈：cocos、phaser、threejs。

内部选定的 768p/2K 视频方案与按合同选择的音频属于生成计划和接收检查项，记录当前档位选择依据、视频条数、实际显示尺寸、时间映射、消耗估算与 `input.has_audio` 事实；图片仍沿用自身约定。比较与取舍放在设计工件，不扩展报告或 accepted schema，也不把估算变成文件门的新要求。结构通过不等于生成参数或人工验收通过。原视频与派生视频保留来源身份和空间布局；源中存在且任务要求保留的音轨随时间整理维护，图集交付不代表游戏音效已接入。

> 适用技术栈：cocos、phaser、threejs。

视频初始帧数由整理后的抽帧输入时长和目标 FPS 决定，不再要求 `3、5、9、17…`；输入时长应匹配已确认的游戏时间轴，而非生成器的固定交付时长。替换实际输入时先人工验收新视频再重抽；仅调整抽样 FPS 或输出尺寸可使用仍有有效验收的同一视频重抽并审阅，保留已修图成果。修改提示词或发现动作错误不默认重新生成视频。背景与外观修正优先直接处理抽帧图片，时间问题按“视频节奏整理”（见本栈配套资料）处理。图片按目标槽位补齐，不能套用视频的严格源时间戳规则。

## 抽帧后的动作与图片修正

> 适用技术栈：cocos、phaser、threejs。

- 当前视频先经人工验收后抽帧；后续图像处理暴露的动作或外观问题可局部修正对应图片或图集 cell，原视频不作为阻止纠错的硬约束。保留验收与来源记录，不以预先打算抽帧后修图为由跳过视频验收；需要更换来源时沿用明确变更与授权边界。

> 适用技术栈：cocos、phaser、threejs。

- 动作修正包括姿态、动作轨迹、朝向、阶段时序/关键事件/终态与循环衔接；外观修正包括造型、颜色、背景残留、透明边缘、局部缺陷和锚点对齐。按修改范围检查相邻帧，保留可用帧，以最终游戏动作要求而非视频中的错误验收。

> 适用技术栈：cocos、phaser、threejs。

- 保留真实原视频及初始抽帧来源记录，来源身份不代表最终动作必须与视频相同。外观修正保持当前帧索引、帧数、FPS、cell 尺寸与锚点合同；节奏修正允许按来源顺序移除未计划保持帧或修正已有帧槽位的过渡姿态，并更新索引、时间映射、产物与合同；需新增帧或改变来源顺序时，保存新的真实抽帧来源，人工验收新视频后重新抽帧并迁移已有修图，不能只修改声明或伪造来源。抽样参数错误可使用仍有有效验收的同一视频重抽，但不能覆盖已完成的修图而不保留修正成果。

> 适用技术栈：cocos、phaser、threejs。

- 在修正记录中列出实际修改帧索引、动作或外观问题、处理方法和修正前后文件身份。图片改动使旧图集验收失效，完成更新与复核后再提交 accepted；不能只改报告而不处理实际图片。

> 适用技术栈：cocos、phaser、threejs。
