# 产物清理 通用工作流

本规范只承接三栈内容一致且不依赖引擎接口的完整规则块；专业入口继续维护各自的资源路径、API、版本与运行时约束。

## 判定边界

“过期”需要项目保留策略、用户指定期限或已被新版本替代的事实；修改时间早不等于过期。“未使用”需要完整引用检查和明确归属；文本搜索零匹配不等于无引用。任务完成、证据已失效、文件被 Git 忽略、文件未跟踪或内容重复，都不能单独作为删除依据。

## 清理流程

1. **限定范围**：读取当前任务、Work Item、允许路径和现有保留策略。确认仓库绝对根路径，记录 Git 已有修改及暂存内容；识别并行任务和正在写入产物的进程。没有既定保留期限时，不自行发明“超过 N 天删除”的策略，先处理能证明无用且可再生成的文件。

3. **列出候选**：逐文件记录项目相对路径、解析后的绝对路径、类别、所属任务、大小、SHA-256、过期/未使用依据、引用检查范围、再生成命令与输入、建议动作和保留原因。缺少可用输入、工具或可执行再生成途径时，不标记“可再生成”。内容相同只用于识别重复候选，不自动合并路径或更新引用。

5. **逐对象清理**：只操作已复核清单中的具体文件，不递归删除整个记录目录，不执行 `git clean`、`git reset` 或批量历史清理。未知所有权、他人改动、仍活跃工作项、写入中的文件和再生成所需输入一律保留。遇到失败记录实际结果，停止依赖该失败的后续动作，继续无依赖对象；不扩大通配符范围或自动提权重试。

## 路径与恢复

- 删除前解析最终绝对路径，确认位于项目根与允许清理目录内；拒绝根目录本身、`..` 越界、指向范围外的软链接/junction/reparse point，以及经此类目录转向范围外的子文件。Windows 下按实际文件系统大小写规则判断路径边界，不能只用字符串前缀判断。

- Windows 文件操作全程使用 PowerShell 7 与 `-LiteralPath`；不要把 PowerShell 枚举结果拼接到 `cmd /c` 或另一 shell 删除。优先逐文件 `Remove-Item -LiteralPath <已复核绝对路径>`，不把示例占位路径当作可执行清单。

- 可恢复操作优先使用项目已有的回收/隔离方式；只有在明确允许的项目内目录中才移动，且核对移动目标不会覆盖文件。报告隔离占用空间，不把移动伪称为释放空间；隔离目录继续受到保留规则约束，不能无限增长。

- 删除 Git 跟踪文件前确认其可从当前提交恢复且没有未提交内容；恢复只针对本任务精确路径，不覆盖他人修改。未跟踪且不可再生成的记录若没有恢复副本，按不可恢复删除处理，不以“未跟踪”为授权。

## 结果报告

优先复用当前 Work Item 的结果/证据位置或直接在最终回复报告，不为每次清理创建长期独立日志、备份与报告副本。报告本身若属于验收证据则加入保留集合。

- 清理范围、保留策略及引用检查覆盖；

- 实际删除、隔离、保留、失败和跳过的精确文件与理由；

- 实际删除字节数、隔离字节数及恢复/再生成方法；

- 执行的测试等级、命令、结果与未验证项；
