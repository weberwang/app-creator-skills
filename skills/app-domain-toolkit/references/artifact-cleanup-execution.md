# 产物保留与清理执行

本规范是列入迁移清单的技术栈共用的完整规则。每段标明适用栈；执行时同时读取本栈技能的原生约束与“本栈配套资料”，资料路径和具体工具由栈入口维护。公共状态与授权仍由 app-workflow-control 管理。

## 完整流程

### 判定边界（cocos、phaser）

原视频可能用于重新抽帧，去背景原图可能支撑生产记录与质量复核，`review.html` 可能是人工审阅所需的实际产物。不要按扩展名、目录名含 `output`/`temp`，或体积大小批量判断。产物路径和人工作业证据与机器证据根的边界见“产物存放与证据边界”（见本栈配套资料），证据语义见“控制模型”（见本栈配套资料）。

### 判定边界（cocos、phaser）

Git 收尾按“最小提交集”（见本栈配套资料）纳入运行/构建必需文件和当前工作项有效引用的完整依赖，包括仍需的图片、视频、Spine 文件、审阅页、截图、日志和源输入，不能只提交路径字符串。未入库或被忽略的长期产物仍按本 Skill 保留，不因不属于最小提交集自动清理；本地删除检查继续覆盖所有保留任务的引用，不能只检查本次准备提交的文件。

### 清理流程（cocos、phaser、threejs）

**建立保留集合**：从所有仍保留的 Work Item、实施包、审批/返工记录、证据清单、资源清单、加载入口、构建/测试配置和交付清单追踪路径与 SHA；递归保留其依赖，不只检查当前 Work Item。引用解析覆盖相对路径基准、动态加载、目录扫描、HTML/CSS/JSON 内嵌引用和软链接。无法确认的动态引用或引用记录无法读取时保留对应候选，不猜测安全性。

### 清理流程（cocos、phaser、threejs）

**验证与收尾**：先推荐 T0-T3 等级、理由、覆盖与命令，再自动执行适用检查。复查所有保留记录及引用文件存在且实际内容满足当前要求，不比较 SHA，运行控制面 `check`；涉及资源或构建产物时运行受影响资源检查/构建，启动服务前复用同项目健康实例。文件删除成功不代表证据门通过，验证失败先修复并复验，报告无法恢复项，不手写状态绕过门。
