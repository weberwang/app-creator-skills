# 图片任务确认与文案

执行公共规则时，同时读取当前技术栈参考中的原生补充和“本栈配套资料”。各段仅适用于标注的技术栈；结构化证据不代替用户对显示效果的人工验收。

## 图片优先的确认方式

> 适用技术栈：cocos、phaser。

| 任务 | 用户看到的候选 | 内部处理 |
| --- | --- | --- |
| 场景目标 | 效果图或宿主上下文预览 | 明确需求与基线按 AUTO 推导；真实方向、玩法或结构歧义才询问 |
| 拆解 | 编号拆解 PNG 与图中简短说明 | 先完成状态分析、组件清单、生产路线和技术 JSON，直接产图 |
| 布局 | 拆解确认后的布局 PNG 或审阅页 | 自动维护父子关系和对齐决策，不先请求文字方案确认 |
| 静态资源 | 批量图片画廊或可放大的参考/输出对照 | 保留独立资产与工程检查，文字只列失败、缺项和待处理项 |
| 返修 | 参考、修改前与修改后对照 | 已确认目标范围内直接修复，不单独确认文字修复方案 |
| 动画 | 动作方案与设计理念说明；确认后展示真实视频、首尾/关键帧及序列预览 | 先说明目标感受和动作依据，等待用户明确确认当前方案后再制作；真实素材仍按路线人工验收 |

## 不可绕过约束

> 适用技术栈：cocos、phaser、threejs。

- 程序化文本纳入实施与审查硬约束：默认实现简体中文 `zh-CN`，并实现项目确认的英语 `en` 等其他语言，并以各语言真实字形宽度、基线、字体回退和容器适配完成显示验证。文案在语义准确、玩家可理解的前提下保持短促、游戏化，优先使用 `x3`、`+10`、图标+数值等熟悉表达，不写可由符号直接表达的说明句。按[固定宽度与用途排版](../../app-ui-layout/references/relative-layout.md#文本宽度缩放与换行)检查标题/按钮等单行自动缩放、长描述自动换行及具体最小可读字号，各语言模式与组件用途一致；禁止截断、内容撑宽或低于字号下限。单行达到下限仍放不下时调整文案或正式布局，不擅自换行。
