# 游戏流程典型任务演练

用于维护游戏特点规范、生产模板和能力路由，按改动选择相关案例，不是普通游戏任务的新阶段、固定测试套件或审批。演练检查代理如何选范围、组织验证与交接，不能证明游戏运行、手感或画面通过。

## 演练方式

给独立评估者提供当前策划、玩法、QA 技能、[游戏特点规范](game-characteristics.md)及下列请求和原始事实。评估者先只读这些输入，提交应补事实、专项选择、拟选测试等级及理由、涉及的现有阶段、V1/正式组合验证、证据复用及未验证边界；提交前不提供本页的评判要点或历史结论。不提供真实工程时不执行游戏、不要求编造命令，不以关键词命中代替行为判断。

维护者依据已确认规则逐项核对输出，记录实际发现、修正和复验；发生文件修改时按现有测试等级执行对应工程检查。仅演练本身不调用控制器登记项目 PASS，也不自动启动引擎、服务、真机或截图分析。

## 请求与原始事实

| 案例 | 请求和可用事实 |
| --- | --- |
| A 动作时序 | Unity 连击动画由 0.6 秒缩为 0.4 秒，但原有伤害时刻仍为 0.3 秒。当前由动画归一化 0.5 位置的事件接入伤害；已有伤害公式单测与旧动作片段，碰撞体不变 |
| B 混合类型与生成 | Phaser 卡牌游戏增加随机地图，入口/出口必须连通；现有费用 3 点、出牌扣 2 点和卡牌效果保持。生成地图与抽牌暂时共用随机流，已有出牌用例；没有新增成长机制的要求 |
| C 纯数值调整 | Cocos 单机放置游戏离线收益上限由 8 小时改为 12 小时，基础产出 10 金币/分钟；公式其余部分与页面显示方式保持，已有可控时钟、存档及领取入口，无联网 |
| D 联机重投 | Three.js 射击游戏重连后重投尚未确认的命中请求；已有操作 ID 与预测火花，服务端决定伤害。可用本地模拟传输器和接口规格，无真实服务环境，无新增显示元素 |
| E 非游戏边界 | Flutter 设置页将“保存”改为“保存设置”；已有中文语言配置和固定宽度按钮，没有其他功能要求 |
| F 局部换色 | Phaser 角色只换贴图配色，纹理 32×32、帧数、锚点、碰撞体和输入明确不变；规则与几何验证有效，画面由用户检查 |

## 提交后评判要点

| 案例 | 核对行为及可观察判据 |
| --- | --- |
| A | 应发现旧归一化事件将落到 0.2 秒，不能把它认定为仍满足 0.3 秒规则。把事件接线/时序交回玩法与动画协调，在正式动作重验命中、中断/暂停等受影响轨迹；保留未变公式证据，旧动作片段不替代新运行证据，不改用户要求的伤害时刻 |
| B | 选择卡牌结算与程序生成的交叉风险，验证固定版本/随机条件、入口出口连通及生成失败的既定策略；检查共用随机流对出牌复现和抽取的影响。先核实项目承诺的是固定序列还是分布，不把同种子序列变化自动解释为规则错误，也不借机增加成长机制 |
| C | 保持数值变更范围，复算上限边界及实际领取/保存恢复；10×60×12=7200 是原始累计上限，若项目另有倍率/容量规则以实际规则为准。零间隔、回拨、超过上限、重复领取按现有用例复验；公式计算与实际余额分开，避免无依据重做视觉或引入联网 |
| D | 同一逻辑命中重投保持操作身份，检查延迟/重复/乱序、迟到确认、重连与最终权威状态；超时、过期及去重责任以现有协议为准，不擅自定义服务端规则。模拟只证明本地协议处理，不宣称真实服务端已完成去重或端到端通过 |
| E | 不启用游戏专项；使用原中文配置，检查固定宽度/单行与长文案风险，按实际影响选 T0 或最小定向检查；未经运行或用户确认不宣称布局/视觉通过 |
| F | 沿用可见增量的 V0–V5 适用流程，复用未变化的规则/几何证据与有效视觉基线；验证新纹理导入、实际绑定和正式场景显示，用户人工检查配色/可辨识性。无变化依据时不重做整局机制、白盒或关卡求解 |

共同核对：不增加阶段、审批、必填控制器字段或无关功能；局部任务不强制生成 QA 文档或全项目记录；未知规则与未运行结果明确保留；项目命令从真实工程取得；技术、模拟和人工体验结论分别说明。
