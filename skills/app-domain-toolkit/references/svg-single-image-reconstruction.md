# 正式单图路线与 SVG 还原

本规范适用于阶段 5 按确认稿独立制作的静态单图。已有可用素材先按[正式视觉实现优先级](reference-asset-asset-production-routes.md#正式视觉实现优先级)评估。Cocos、Phaser 和 Three.js 使用下述机器清单映射与文件门。其他技术栈可采用这里的制作与转换方法，生产证据、导入和验收采用各自现有合同。

## 初始化冻结生产路线

工作流首次适用的初始化使用 `--formal-image-method` 固定项目和技术栈的正式单图生产路线，默认 `svg-to-png`。用户明确选择直接生图时，初始化登记 `direct-image-generation`。后续工作项通过 `imageRoutesRef` 继承记录中的 `formalImageMethod`。V3 为每个唯一 component × required state 沿用该冻结路线，使用单素材规格时设置 `route=bitmap`，将同一冻结值写入 `bitmapProductionMethod`，在 `routeReason` 引用初始化依据。多个相同外观的 placements 共用该资源，具有独立外观的状态分别登记。

- **SVG 重绘转 PNG**依据确认稿制作独立 SVG，交用户审阅并确认该版本后，再转换为正式 PNG。实际游戏消费 PNG，制作时保留可见材质、阴影和装饰。
- **直接生图**保留完整确认原图、同源局部参考、提示词及实际生成记录，继续执行原有透明路线和尺寸归一化。

冻结路线遇到工具或表达能力限制时记录具体阻塞，调整该路线内的制作方式并按原路线恢复。V3、V4 和返修沿用冻结方式。

## 正式静态单图共同交付规范

SVG 重绘和直接工具生图遵循同一份设计与成品规格。V3 从已确认的 V2 稿件及实际消费者确定唯一部件、适用状态、参考区域、画面构图、轮廓、比例、主色、材质、光影、装饰及全局视觉基线。登记目标显示尺寸、最大业务缩放、生产密度、正式像素尺寸、布局关系、背景与 Alpha、有效内容边界、透明留白、锚点和适用的九宫格切片。具体尺寸按[正式位图尺寸](../../app-asset-workflow/references/technical-processing.md#正式位图尺寸)和当前技术栈合同计算。Cocos、Phaser、Three.js 的场景单图按最大 placement 与业务缩放使用生产基线 1；九宫格使用冻结源帧和切片规格。其他技术栈采用本栈密度及导入约束。

V4 两条路线均按冻结规格检查实际成品的格式、像素尺寸、Alpha、边缘、内容范围、切片及原生导入和消费者，并将成品与已确认参考按实际显示尺寸交用户人工审阅。透明成品使用 PNG，不透明成品格式按本栈和消费者规格确定。V5 继续核对正式运行时的资源消费、状态和画面组合，由用户人工确认实际显示。结构、转换记录和生成记录用于核对可测事实，视觉效果须取得用户的实际判断。

SVG 路线在转换前按下述规则取得源稿确认并保存源文件与转换记录。直接生图保留实际生成提示词、参考附件、原图及适用的透明处理和尺寸归一化记录。两条路线沿同一视觉目标、成品尺寸和验收范围交付。

## SVG 还原与质量要求

当前部件和状态在已确认设计稿中的可见内容，是 SVG 重绘的唯一视觉标准。只还原稿中已有的轮廓、比例、色彩、纹理、光影、描边和装饰，保持原有细节密度及强度。全局风格、其他参考和工具默认效果均不能作为新增图案、材质、光效或装饰的依据。细节看不清时先核对同一稿的原尺寸或局部放大，仍不清楚且影响还原的部分交用户确认设计稿。

1. **冻结依据和画布**。以已确认目标、区域 ID、状态和实际参考区域为依据，记录目标显示尺寸、最终像素、缩放倍率、原点、内容边界、透明边距、主体锚点和裁切安全区。`viewBox` 与输出画布采用一致坐标方向和比例，明确图形与四边的实际距离。绘制前计算画布到目标像素的缩放关系，不能通过非等比拉伸改变轮廓；需裁切时须保留确认稿的主体及效果安全边界。
2. **按视觉层次重绘**。先对照整体比例、轮廓和关键节点，用贝塞尔曲线与可编辑几何还原转折、曲率、孔洞、对称关系和遮挡顺序。再逐层还原稿中已有的底色、边缘、内部分区、高光、阴影和装饰。描边匹配稿中的宽度、连接、端点与位置，避免笔画外溢后改变可见边界。复杂主体保持原稿的形状和语义。
3. **保留外观和效果**。只为确认稿中实际可见的渐变、透明度、柔边、投影、内阴影、发光和纹理选择相应的矢量表达。渐变和滤镜的定义域须覆盖稿中的效果边界，避免滤镜裁切、透明光晕被烘成底色或重叠时出现接缝。渲染器或目标像素限制还原时，调整绘制方法以匹配确认稿的可见效果。
4. **处理缩放和状态**。预先对齐独立状态、透明安全区和 pivot。九宫格按最终源图像素确定四边、最小显示框与中心区，确保边框、角和效果处于正确切片范围。SVG 送审时提供可放大的实际源稿，获确认后再提供原尺寸 PNG，并在最终像素及目标 1× 显示尺寸核对小尺寸图标和细线的边界、线宽和抗锯齿。必要时调整矢量几何，再对改变后的源稿取得用户确认。
5. **保持确定性和可移植性**。SVG 使用独立完整的 XML 与明确 `viewBox`，图形、渐变、滤镜和裁切定义均保存在该文件中。转换工具支持基础形状、路径、分组、局部引用、线性和径向渐变、`clipPath`、`mask` 及常用滤镜，元素属性须符合工具实际支持范围。只使用本地片段 ID 引用，禁止外部资源、实体引用、嵌入位图、脚本、动画、`foreignObject`、`style` 元素及 CSS `style` 属性。固定美术字只有在文字路线允许且字体或字形授权明确时转成轮廓路径，动态或本地化文字继续交由原生文字合同处理。逐项记录素材来源及授权。
6. **检查实际结果**。导出 PNG 后核对尺寸、格式、真实 Alpha、主体和效果边界、清晰度及九宫格边缘。透明图在浅底和深底分别生成预览，检查缺口、黑白边、残底、半透明和辉光。把冻结参考区域与最终 PNG 在相同显示尺度并排提供，可逐张放大，文字描述只列出失败、缺失和待处理差异。用户人工检查轮廓、比例、颜色、材质、光影、层次和状态差异；代理可核查文件及数值，默认不自动分析截图或代替用户作视觉判断。

## SVG 源稿人工确认

V4 制作 SVG 后暂停，将实际 SVG 源文件和已确认设计稿的对应区域交给用户人工审阅。说明素材、状态、目标尺寸及观察要点，重点对照细节有无增添、遗漏或强化。等待用户对该源稿版本明确确认后，才能转换正式图片和导入。用户退回时根据反馈修改并重新提交，源文件发生改变时须对新版本重新确认。未经确认的 SVG 保持待审，不生成 PNG 作为待审预览。代理可检查源文件结构与数值，视觉结果由用户判断。

沿用 Human Review 记录真实决定。确认记录须包含 `schemaVersion: "1.0"`、`stage: "V4"`、`purpose: "svg-source"`、`decision: "APPROVED"`，以 `objectId` 指向素材的 `assetId`，填写当前 `workItemId` 和 `candidateId`。`targetRef` 指向项目相对 SVG 路径，`targetSha256` 记录实际源文件 SHA-256，`userMessageRef` 指向用户确认该版本的真实消息。记录保存在项目内 JSON 文件，正式转换时引用。用户未确认时保持待审，不能预填批准。

## SVG 到正式 PNG 的交接

取得 SVG 源稿人工确认后，从项目根目录使用公共转换工具，按本批冻结尺寸和背景合同填写实参，以 `--source-review` 传入确认 JSON 的项目相对路径。标准输出保存为实际转换记录。项目尚未安装共享 Node 工具依赖时，先运行 `npm ci --prefix .agents/skills/app-skill-runtime`。

```sh
node .agents/skills/app-domain-toolkit/scripts/visual/svg-rasterization.mjs --source assets-source/example.svg --source-review evidence/review/example-svg.json --output assets/example.png --width 128 --height 128 --alpha transparent
```

`--alpha` 在需要透明背景时用 `transparent`，不透明成品使用 `opaque`。工具按自身支持的自包含 SVG 范围转换，报错时修正源文件并按冻结路线处理。通用单素材规格使用 `sourcePath` 登记 SVG 制作源，使用 `runtimePath` 登记正式 PNG，并随生产证据保留实际转换记录。

Cocos、Phaser、Three.js 将 SVG 路线登记为 `production_origin=independent-production`、`production_method=authored-raster`、`delivery_kind=raster-image`、`image_generation_required=false`、`generation_record_required=false`。V3 冻结 PNG 的 `expected_assets.source_file/runtime_file` 与独立 `svg_source_file`。V4 的资产 `svg_rasterization` 使用转换工具实际输出的 `svg-rasterization/2.0` JSON，以 `source_review_ref` 绑定确认文件的项目相对路径和 SHA-256，并绑定源 SVG、最终 PNG、尺寸及处理事实。独立 PNG 的状态与消费者依旧按现有生产合同校验。

转换工具直接在目标像素尺寸渲染，SVG 源最大 4 MiB，输出每边最大 4096 像素。清除编辑器导出中的注释和 CSS 后提交源稿审阅，源稿确认后再转换。默认拒绝覆盖已有文件，更新已确认源稿对应的正式 PNG 时显式传入 `--overwrite`。两条 PNG 路径不同时，把同一次转换的文件原样复制到另一条路径。文件门核对源稿确认及两端摘要，并按同版本渲染器复算 PNG。

受阶段工作流管理的视觉目标，把已选路线纳入 V3 布局确认的 `layoutSpecRef`，V4 和 V5 会复核这个已确认版本。V4 按当前视觉单位和状态把正式 PNG 与应显示文字一同接入并保存，完成同批原生回读、资源检查及既有用户图片审阅。V5 验证正式运行中的消费、状态与完整组合。只返修受影响的资源或实现，若确需更改已确认的目标、拆解或布局，按现有变更和确认流程处理。
