# 玩法实施与交接

本规范是列入迁移清单的技术栈共用的完整规则。每段标明适用栈；执行时同时读取本栈技能的原生约束与“本栈配套资料”，资料路径和具体工具由栈入口维护。公共状态与授权仍由 app-workflow-control 管理。

各技术栈统一使用 V0–V5，V1 验证功能且白盒可选，V2–V5 依次完成视觉目标、拆解布局、资源导入和运行验收。

## 完整流程

### 所有权（cocos、phaser、threejs）

完整边界见[玩法与美术职责](#玩法与美术职责)。

### 所有权（cocos、phaser、threejs）

涉及汁水感或动态反馈时按需参考“汁水感设计指南”（见本栈配套资料）。玩法继续拥有规则结果、碰撞、状态及反馈触发条件；击退、顿帧或输入窗口等会改变实际玩法的行为仍由玩法定义和验收，纯表现偏移不覆盖玩法状态。

### 实现（cocos、phaser、threejs）

玩家可见内容遵守“游戏内文案”（见本栈配套资料）：正式界面只绑定当前场景/状态的可见表达、短标签/本地化键与动态数值，不直接显示 GDD/brief 的规则段落、功能描述或验收字段。此规则覆盖无效果图路径、HUD、按钮、弹窗、Toast 和奖励浮字；必要引导与操作后果按已定义条件保留。

### 实现（cocos、phaser、threejs）

读取 GDD、TDD、控制面、总控的审核漏斗和游戏实现规则。视觉任务同时读取视觉质量门、玩法视觉契约；UI 读取 “本栈 UI 布局技能”（见本栈配套资料）；参考还原读取视觉还原规则。

### 实现（cocos、phaser、threejs）

按当前场景 Work Item 的阶段门推进玩法交付：V1 实现并验证功能，白盒按需使用；V2 确认视觉目标，V3 冻结拆解和布局事实，V4 验收正式资源，V5 直接消费 V3/V4 产物实现正式 `SCENE`/`DISPLAY_LAYER`，并完成功能与视觉联合验收。foundation-only 的基础能力和跨场景 `INTEGRATION` 由控制面计划调度；本领域不得把玩法实现提前放入基础包或另建场景生命周期。

### 实现（cocos、phaser、threejs）

在 V1 需要证明结构、交互或节奏时可建立隔离的可运行白盒，记录稳定 ID、层级、交互区和资源依赖。已冻结结构不为形式重复灰盒；灰盒不得作为场景完成证据。

### 实现（cocos、phaser、threejs）

foundation-only 阶段先完成场景无关的 `SHARED`/`MODULE`；V1 按已授权范围实现并验证功能；V3 布局确认与 V4 资源验收通过后，在 V5 完成正式 SCENE 集成。场景实现只闭环玩法、正式资源、场景自有 UI/常驻 HUD、清理和场景证据。modal/popup 等弹窗必须拆为独立 DISPLAY_LAYER Work Item，读取自己的 V3/V4 证据并在自身 V5 验收；弹窗不属于大厅或其他宿主场景实现，也不阻断其验收。`hostSceneId` 仅用于公开接口和运行上下文接线。

### 实现（cocos、phaser、threejs）

在 V5 与美术重放动态可玩轨迹，检查识别、预警、命中/受击/奖励反馈、遮挡、响应式、性能和功能契约。忠实还原在冻结目标视口/状态提供同条件完整 viewport 并更新逐状态、逐区域忠实度矩阵，其他视口验证布局关系不变量；玩法处理规则/交互失败，美术处理纯表现失败，跨域问题进入 F3。

### 实现（cocos、phaser、threejs）

正式结构通过后，玩法清除低保真代码、纹理键、资源、fallback 和运行时引用，重新执行测试与生产构建。场景功能、资源、接入、场景自有显示层、占位清理和验证关闭后即可标记当前场景完成；独立弹窗另行验收。

### 证据（cocos、phaser、threejs）

截图对比记录相同视口、设备像素比、状态、操作轨迹、语言、时间点、ROI、预先定义的项目容差、稳定帧和遮罩说明。完整 viewport 为主证据，ROI、叠加和像素差仅作补充；生成式内容、动画和 VFX 不得只靠像素差判断。未解释或超容差差异、缺同条件双方证据、缺已批准例外或仅凭主观结论不得报告完成；源码、固定坐标、类型检查、构建成功和元素存在只能证明结构或工程状态。

### 证据（cocos、phaser、threejs）

F0 只校验任务范围与流程，F1 核对既定规格，F2 由非作者验证玩法领域质量，F3 绑定当前候选工程证据，F4 只做带副作用的 A4-A6 集成/发布操作批准。行为或验收变化建立 Change Request 并记录用户决定。新增或修改的类、函数、实体及复杂逻辑使用简体中文注释。

## 玩法与美术职责

> 适用技术栈：cocos、phaser、threejs。

玩法独占玩法规则、状态、碰撞、交互代码、功能灰盒和低保真清理。美术可以拥有纯表现层资源配置、布局/表现预制数据和视觉集成调整，但不得改变玩法规则、碰撞语义或状态所有权；V5 由玩法与美术协作完成运行态联合验收。发现职责、公开契约、状态所有权或依赖方向变化时停止受影响实现并交回所有者，返回模块审计和风险触发的专业审核；只有仍存在受保护取舍时 grilling。
