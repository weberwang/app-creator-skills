# 工具与接入能力核实

用于基础工程、引擎／插件／SDK 接入、运行验证及候选准备。只核实本次实际需要的操作，沿用现有 TDD、计划、QA 和[最小任务约定](../../app-creator-workflow/references/output-files.md#每项任务的最小约定)；不增加能力状态机、统一检查表或审批阶段。

## 区分资料、连接、执行和结果

| 核实内容 | 可用依据 | 不能据此推断 |
| --- | --- | --- |
| 有指导资料 | 当前 Skill、官方文档、适用版本及原生路线 | 对应工具、SDK 或桥接已经存在 |
| 工具已连接 | 实际目标工程／宿主、当前工具清单及实时参数 Schema；CLI 的实际版本与帮助 | 所有宣称的操作都可执行，或任何写入已完成 |
| 操作可执行 | 授权范围内最小实际操作的命令／参数、退出结果及原始输出 | 引擎已保存、构建已完成、游戏可运行或平台已接受 |
| 结果已验证 | 正式源回读、目标产物检查、真实回调或当前宿主运行证据 | 无关操作、其他平台或用户视觉验收也已通过 |

这些是证据层次，不是四个必须逐项创建的工作项。已有有效材料直接引用；一次操作可以同时提供多层依据，最终结论只覆盖实际核实的操作与环境。

## 按操作选择工具

1. **先查现状。** 按任务读取当前栈的正式源、版本、依赖和运行／编辑器实例；复用已连接的 CLI、MCP、编辑器与项目测试，不为文档列出某个工具就安装它。选择新依赖仍遵循[官方优先](../../app-creator-workflow/references/professional-conventions.md#solution-selection)，只补实际缺口。
2. **定位具体能力。** 明确本次需要读取、修改、保存、构建、运行或采集中的哪些操作，再检查实际工具及参数。不要把“能运行脚本”“插件已安装”或“SDK 已入包”概括成所有能力已接通；不存在的命令或 API 不写成执行计划中的现成能力。
3. **执行最小验证。** 在已有授权和所有权内操作，检查真实完成信号和下游结果。打开构建面板、任务已受理、worker ready 或外部任务 ID 只说明对应进度；需要等待完成时按当前工具合同跟进，失败或超时不转为成功。普通本地验证按推荐测试等级自动执行，真机、签名、上传、外部写入等仍按既有授权边界处理。
4. **只限制受影响范围。** 缺少工具、权限、平台或账号时，说明具体缺口、受影响任务及可继续的独立工作。仅在替代方案符合本栈规范且能证明相同所需结果时采用；命令退出成功但无法回读／运行的部分如实标为未验证，不能降低完成条件或自动替换技术路线。

浏览器、引擎编辑器、模拟器、真实宿主和设备分别记载。客户端需要验证实际交互时按[统一运行验证](../../app-quality-review/references/runtime-validation.md)执行；Node.js 等无界面模块只核实相关接口、数据、任务、日志和生命周期，不增加 GUI、截图或设备要求。

## SDK 与渠道接入

按[独立 SDK 管理](../../app-domain-toolkit/references/reference-architecture-sdk-initialization.md)核对实际依赖、装配入口与就绪信号；有接入说明、依赖下载完成、成功编译和运行时初始化成功分别成立。业务能力还须验证实际调用、授权限制及失败恢复，不能用初始化通过替代登录、广告、支付等结果。

已选渠道按[渠道接入](../../app-release/references/channel-platform-integration.md)核实引擎导出路线和平台支持；同包场景验证真实宿主识别及 SDK 选择，专用包验证其正式配置和产物。插件只提供 Skill 时，记录为指导能力，不能描述成已经提供广告桥接、转换器或已完成真实渠道接入。

## 任务安排与完成条件

| 时机／任务 | 沿用的结果与位置 | 完成验证 |
| --- | --- | --- |
| 基础工程：核实工具入口 | 现有 TDD／计划中的目标工程、操作、工具版本和实际命令 | 实例与工程身份明确，必要操作有真实入口；缺口及可继续项明确 |
| 功能接入：验证实际操作 | 相关实现、正式源及当前证据根内原始输出 | 保存、导入、构建、初始化和业务调用按实际范围分别验证 |
| 质量检查：对照宣称与结果 | 现有 QA 的执行条件、结果、引用和未验证项 | 指导、连接或受理没有被写成操作／运行成功，人工视觉结论独立 |
| 候选准备：核对实际交付 | 现有发布清单与候选材料 | 使用当前产物及目标环境；依赖／配置变化后复核受影响能力 |

本规范提供执行与交接要求，不探测全部工具、不安装依赖或自动发起 SDK 调用。已有[命令采集器](../../app-workflow-control/scripts/capture-command.mjs)可执行当前活动单元的冻结命令；按需使用[候选文件工具](../scripts/verification/candidate-files.mjs)及[素材文件工具](../scripts/verification/asset-files.mjs)核对明确文件，具体操作和证明范围见[候选绑定](../../app-release/references/release-readiness.md#只读候选文件快照)和[素材引用检查](../../app-asset-workflow/references/asset-provenance.md#文件与声明引用检查)。这些工具不执行构建、原生注册或视觉判断；控制器仍只校验已有合同中的材料及关系，不能独立证明工具操作或日志真实发生。
