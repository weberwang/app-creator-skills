# 动态反馈生命周期

本规范是列入迁移清单的技术栈共用的完整规则。每段标明适用栈；执行时同时读取本栈技能的原生约束与“本栈配套资料”，资料路径和具体工具由栈入口维护。公共状态与授权仍由 app-workflow-control 管理。

各技术栈统一使用 V0–V5 的阶段含义；先按[资源与视觉流程分流](../../app-feedback/references/interaction-feedback.md#资源与视觉流程分流)自主选择特效，分别判断设计稿、图片与受影响阶段，不默认重走全链。V1 验证功能且白盒可选，适用 V2–V5 分别负责视觉目标、拆解布局、资源导入和运行验收；有效前置事实按控制面复用。

## 完整流程

### Cocos Creator 3.x 游戏汁水感（cocos、phaser、threejs）

把当前任务内的玩家操作和规则变化转成及时、可理解、符合主题的反馈。先保证信息和因果清楚，再选择形变、粒子、声音、镜头或时间表现；安静反馈可以成立，不以数量或强度作为质量标准。

### Cocos Creator 3.x 游戏汁水感（cocos、phaser、threejs）

可见反馈遵守“游戏内文案”（见本栈配套资料）：奖励、消耗和状态优先用图标、数字、符号或局部变化表达；需要文字时沿用当前可见短标签与显示条件，不把事件规格中的原因、结算规则或设计意图直接做成浮字、Toast 或说明面板。

### 专业执行与交付（cocos、phaser、threejs）

- QA 自动核对规则、事件、参数、资源、清理和性能；截图、录像的显示效果及实际手感由用户人工验收。未经明确授权不自动分析画面，也不以机器通过推导视觉通过。

### 按需读取（cocos、phaser、threejs）

| 当前问题 | 读取内容 |
| --- | --- |
| 定义方向、选择效果或审查反馈缺口 | “完整设计指南”（见本栈配套资料）的概念、反馈库、情绪与类型章节 |
| 多通道冲突、长时间游玩、暂停和恢复 | 指南的组合、工程边界、平台与长期体验章节 |
| 制定项目事件规格与验收 | 指南的反馈语义、事件模板、覆盖核对表和实例章节 |
| 接入现有 GDD、场景阶段与领域交接 | “工作流接入”（见本栈配套资料） |

### 执行闭环（cocos、phaser、threejs）

新增或修改场景、页面、显示层、功能或机制，只要涉及显示元素设计或可见表现，先按[增量显示约束](reference-domain-display-ownership.md#新增显示元素的增量约束)从当前增量 V0 开始，复用素材、程序生成及局部参数/时序调整同样适用。功能在 V1 实现并验证，目标变化更新 V2，结构/布局变化更新 V3，正式资源变化更新 V4，正式组合与运行验收在 V5 完成。当前 V0/V1 完成后才按控制面复用仍有效的事实，不能冒用旧确认或重做无关宿主。纯音频、触觉或非视觉逻辑调整不自动进入视觉生产链。

### 执行闭环（cocos、phaser、threejs）

按测试等级规则推荐并自动执行适用检查，修复后复验受影响项；提供重复、叠加、中断和收尾的适用动态证据及人工检查要点。未运行、未观看的部分明确标为未验证。

### 交付（cocos、phaser、threejs）

只交付当前任务实际需要的事件规格或修订、配置/代码/资源差异、程序与性能证据、人工验收状态及剩余问题。设计完成、实现完成、工程验证和人工体验验收分别记录，不用“有汁水”“很爽”代替证据。沿用既有工件和有效确认，不为本 Skill 重开已完成工作或新增确认链。
