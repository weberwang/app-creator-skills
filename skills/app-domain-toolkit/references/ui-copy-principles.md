# 界面文案通用原则

适用技术栈：cocos、phaser、threejs、unity、flutter。适用于游戏和应用中所有用户可见文案，包括标题、按钮、弹窗、引导、奖励和状态反馈。

## 表达选择

所有文案都结合所在场景、相邻信息、操作对象与当前状态设计，优先用图片、图标、数字、符号、简短动作和视觉状态表达含义。上下文已经表达的信息不再重复说明，文字只补充仍无法直接理解的必要信息。

在拟稿和布局前确定本状态需要显示的内容。副标题、二级说明、说明卡、装饰性标签和空泛宣传语默认不占位；只有能补足决策所需信息、操作条件或结果、风险、首次必要引导或错误恢复时才添加。仅在特定状态有用的说明就在该状态显示。若删去一句后，用户能同样准确地理解并完成操作，就删去整句及为它预留的区域。保留内容本身就是任务的文字、必要的控件标签和无障碍名称。

- 先判断用户从当前场景、标题、相邻图标与数值、选中对象和操作状态中已经知道什么，再设计需要补充的表达。每条文案只承担当前仍需说明的动作、变化、状态或条件，不要求单个控件独立复述完整规则；同一信息组内避免标题、正文、图标标签和按钮反复说明同一含义。
- 根据当前意图选择表达：图标标识对象、资源或操作条件，数字表达数量、倍率或进度，简短动作表达将执行的操作，短状态表达已发生的结果。含义清楚的图标不再附带重复标签；必须有文字时使用短名称、短动作或短状态，如「领取」「升级」「已满」，避免完整解释句。
- 同一含义在不同页面、HUD、弹窗和反馈中保持一致，只有对象、显示状态、数据或语气确有区别时才调整表达；动作与结果分别对应真实操作和已发生的状态，不能混淆。
- 奖励、消耗、数量、倍率和进度优先用对应图标与数值；增减保留正负号，倍率使用 `x{value}`，进度可用 `3/10` 或进度条。上下文已明确基准时优先表达变化关系，结果反馈再显示真实结果；倍率、最终总额与额外增量不能混用。
- 数值要与对应图标相邻并形成同一信息组；余额、价格和变化量使用清晰上下文区分，不能靠颜色或孤立数字猜含义。图标控件保留无障碍名称，该名称不必成为可见文案，但须包含完整的必要语义。
- 图标已清楚表达的条件无需在可见文字中重复。例如激励广告尽量用广告图标标识观看要求，文字直接表达收益或动作，尽量不出现「广告」字样；图标与上下文仍须让用户识别观看要求，无障碍名称保留观看要求和动作含义。
- 不熟悉的机制、首次必要引导或有实质后果的操作保留最少的必要说明，按需呈现。不得为精简而丢失奖励类型、消耗对象、条件或操作后果；「免费」等描述必须符合当前实际条件，不能将有货币或道具消耗的操作标成免费。观看完成即可复活且无需消耗货币或道具时可用「免费复活」。

| 意图 | 优先表达 | 避免重复解释 |
| --- | --- | --- |
| 金币奖励 | 金币图标 `+100` | 获得 100 金币 |
| 钻石消耗 | 钻石图标 `-20` | 消耗 20 钻石 |
| 奖励倍率 | 奖励图标 `x3` | 获得三倍奖励 |
| 过关奖励已显示金币 `+50`，观看后领取三倍总奖励 | 广告图标 + `x3`；领取结果显示金币图标 `+150` | 按钮仅写 `150`，或重复说明看广告领取三倍奖励 |
| 观看完成后免费复活 | 广告图标 +「免费复活」 | 广告复活、观看广告免费复活 |
| 收集进度 | 目标物图标 `3/10` | 已收集 3 个，还需收集 7 个 |

示例仅说明如何运用通用原则，不限定适用场景，也不固定项目的资源、数值或界面内容。应先识别当前上下文和表达意图，再选择图标、数字与短文案的组合，不机械套用示例。

## 错误提示形式

五栈游戏与应用统一按以下规则选择提示形式；按事件是否需要用户确认、是否来自后台任务判断，不以异常类型或 SDK 原始错误级别决定。

| 场景 | 统一形式 | 行为要求 |
| --- | --- | --- |
| 普通业务错误，如操作失败、条件不满足、当前服务不可用 | Toast | 简短说明当前结果或可行下一步，不抢焦点、不阻断输入 |
| 需要用户确认、选择或明确处理后才能继续 | 弹窗 | 明确确认或选择按钮及后果，按实际模态行为隔离输入并恢复焦点；不能用自动消失的 Toast 替代 |
| 后台加载、预加载、自动刷新和重试失败 | 静默 | 不弹 Toast 或弹窗，不用声音、震动或遮罩提醒失败；保留脱敏诊断及既有恢复策略 |

Toast 不按文案或错误码去重，相同提示的每次有效触发均立即显示，不排队、不替换正在显示的实例。业务层仍通过操作身份拒绝重复、迟到或已失效的结果回调，避免同一结果被重复投递；这不合并不同有效触发的相同提示。前台操作失败已经提示后，后续后台重试失败仍保持静默；后台任务失败不能仅因其日志级别较高升级成弹窗。用户主动操作在当前状态下被拒绝时，按其业务结果选择 Toast 或确需确认的弹窗，不把后台每次重试作为新的用户操作。

复用项目现有统一 Toast 和弹窗组件；业务模块返回稳定错误码或结构化结果，由 UI 层映射为本地化短文案，不直接展示异常堆栈、SDK 原始消息或敏感参数。Toast 的独立实例、复用、消失与输入行为沿用[公共显示结构约定](reference-domain-display-ownership.md#游戏层内容层hud浮窗与弹窗)。

在现有功能规格或反馈矩阵中记录事件的提示类型、文案键、确认动作及结果回调有效性规则。验证覆盖普通业务失败、需要确认的失败、后台加载与重试失败、重复回调及前台失败后自动重试；技术检查不替代用户对实际显示效果的人工验收。

## Toast 独立实例与复用

每次有效提示请求独占一个 Toast 实例，文案相同也立即显示，允许多个实例同时播放，不去重、不排队、不覆盖或重置其他活动实例。实例独立持有展示身份、文案、位置、透明度、动画和计时器，不以一个共享视图轮换承载并发提示。

允许通过对象池复用已经结束展示的空闲实例；池中无空闲实例时按需创建，不能等待其他提示结束。回收时停止动画、取消计时器并解绑订阅；再次使用时重置文案、位置、透明度和展示身份。完成、关闭或延迟回调须核对本次展示身份，旧回调不得隐藏、移动或回收已被复用的新展示。宿主退出时统一取消和回收其活动实例。

验证相同文案连续触发、多实例同时播放、空闲实例复用及旧回调到达；逐实例检查生命周期隔离，显示效果仍由用户人工验收。

## Toast 上飘与淡出动画

五栈 Toast 统一使用以下默认时间线，每个实例独立播放；参数在统一 Toast 组件中集中配置，不在调用方分别实现。

| 阶段 | 时长 | 位置与透明度 | 缓动 |
| --- | --- | --- | --- |
| 出现 | 180ms | 起始位置不变，透明度由 0 到 1 | `easeOutCubic` |
| 停留 | 1800ms | 位置不变，透明度保持 1 | 无 |
| 消失 | 500ms | 从停留位置向屏幕上方移动 200 个逻辑单位，同时透明度由 1 到 0 | `easeInCubic` |

上飘与淡出在消失阶段同时开始、同时结束，不额外增加入场位移、缩放或弹跳。200 个逻辑单位按项目既有 UI 逻辑坐标与视口适配映射，不能当作物理像素、世界单位或额外乘设备像素比；向上方向按当前技术栈坐标系换算。起始落位预留上方运动空间并检查安全区及裁切，小视口无法完整容纳轨迹时在布局规格中明确处理，不擅自改小位移。

动画结束后仅回收本次展示实例；复用前恢复起始位置、透明度和展示身份，取消旧动画及计时器，旧完成回调不得回收新展示。同样内容每次有效触发仍立即播放独立动画，不去重、不排队，不等待其他 Toast 完成；动画期间不抢焦点、不拦截输入。

启用“减少动态效果”时取消位移，保留淡入、停留和淡出。验证分别核对时间线、逻辑位移、透明度终值、多实例并发、复用重置及旧回调隔离；实际上飘效果、安全区和阅读体验由用户人工检查，不以技术检查代替视觉验收。

## 规格与交接

在现有产品或场景规格中按场景与状态区分内部规格和用户可见表达：内部规格记录规则、条件、计算、操作后果、设计理由与验收说明，用于理解和实现功能，不直接作为画面文字来源；用户可见表达记录图标或图片、数字或符号、必要短标签、允许出现的文字及其显示条件，无需文字时明确为空。动态数值标明数据来源、格式与效果图示例值，必要引导标明何时出现。

交接每组可见表达时，记录其依赖的场景、相邻信息、操作对象、图标含义与适用状态，明确哪些信息已由上下文表达、哪些需要文字补充。相关数值与变化关系读取同一业务规则；图标作为独立视觉元素交接，不把图标的内部描述绘制成文字。控件移位、组件复用或状态变化时，重新核对上下文是否仍足以说明其含义。
