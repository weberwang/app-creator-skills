# 界面文案通用原则

适用技术栈：cocos、phaser、threejs、unity、flutter。适用于游戏和应用中所有用户可见文案，包括标题、按钮、弹窗、引导、奖励和状态反馈。

## 表达选择

所有文案都结合所在场景、相邻信息、操作对象与当前状态设计，优先用图片、图标、数字、符号、简短动作和视觉状态表达含义。上下文已经表达的信息不再重复说明，文字只补充仍无法直接理解的必要信息。

- 先判断用户从当前场景、标题、相邻图标与数值、选中对象和操作状态中已经知道什么，再设计需要补充的表达。每条文案只承担当前仍需说明的动作、变化、状态或条件，不要求单个控件独立复述完整规则；同一信息组内避免标题、正文、图标标签和按钮反复说明同一含义。
- 根据当前意图选择表达：图标标识对象、资源或操作条件，数字表达数量、倍率或进度，简短动作表达将执行的操作，短状态表达已发生的结果。含义清楚的图标不再附带重复标签；必须有文字时使用短名称、短动作或短状态，如「领取」「升级」「已满」，避免完整解释句。
- 同一含义在不同页面、HUD、弹窗和反馈中保持一致，只有对象、显示状态、数据或语气确有区别时才调整表达；动作与结果分别对应真实操作和已发生的状态，不能混淆。
- 奖励、消耗、数量、倍率和进度优先用对应图标与数值；增减保留正负号，倍率使用 `x{value}`，进度可用 `3/10` 或进度条。上下文已明确基准时优先表达变化关系，结果反馈再显示真实结果；倍率、最终总额与额外增量不能混用。
- 数值要与对应图标相邻并形成同一信息组；余额、价格和变化量使用清晰上下文区分，不能靠颜色或孤立数字猜含义。图标控件保留无障碍名称，该名称不必成为可见文案，但须包含完整的必要语义。
- 图标已清楚表达的条件无需在可见文字中重复。例如激励广告尽量用广告图标标识观看要求，文字直接表达收益或动作，尽量不出现「广告」字样；图标与上下文仍须让用户识别观看要求，无障碍名称保留观看要求和动作含义。
- 不熟悉的机制、首次必要引导或有实质后果的操作保留最少的必要说明，按需呈现。不得为精简而丢失奖励类型、消耗对象、条件或操作后果；「免费」等描述必须符合当前实际条件，不能将有货币或道具消耗的操作标成免费。观看完成即可复活且无需消耗货币或道具时可用「免费复活」。

| 意图 | 优先表达 | 避免重复解释 |
| --- | --- | --- |
| 金币奖励 | 金币图标 `+100` | 获得 100 金币 |
| 钻石消耗 | 钻石图标 `-20` | 消耗 20 钻石 |
| 奖励倍率 | 奖励图标 `x3` | 获得三倍奖励 |
| 过关奖励已显示金币 `+50`，观看后领取三倍总奖励 | 广告图标 + `x3`；领取结果显示金币图标 `+150` | 按钮仅写 `150`，或重复说明看广告领取三倍奖励 |
| 观看完成后免费复活 | 广告图标 +「免费复活」 | 广告复活、观看广告免费复活 |
| 收集进度 | 目标物图标 `3/10` | 已收集 3 个，还需收集 7 个 |

示例仅说明如何运用通用原则，不限定适用场景，也不固定项目的资源、数值或界面内容。应先识别当前上下文和表达意图，再选择图标、数字与短文案的组合，不机械套用示例。

## 规格与交接

在现有产品或场景规格中按场景与状态区分内部规格和用户可见表达：内部规格记录规则、条件、计算、操作后果、设计理由与验收说明，用于理解和实现功能，不直接作为画面文字来源；用户可见表达记录图标或图片、数字或符号、必要短标签、允许出现的文字及其显示条件，无需文字时明确为空。动态数值标明数据来源、格式与效果图示例值，必要引导标明何时出现。

交接每组可见表达时，记录其依赖的场景、相邻信息、操作对象、图标含义与适用状态，明确哪些信息已由上下文表达、哪些需要文字补充。相关数值与变化关系读取同一业务规则；图标作为独立视觉元素交接，不把图标的内部描述绘制成文字。控件移位、组件复用或状态变化时，重新核对上下文是否仍足以说明其含义。
