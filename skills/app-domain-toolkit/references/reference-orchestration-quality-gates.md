# 游戏生产里程碑

执行公共规则时，同时读取当前技术栈参考中的原生补充和“本栈配套资料”。各段仅适用于标注的技术栈；结构化证据不代替用户对显示效果的人工验收。

各技术栈统一使用 V0–V5；V1 是功能实现与验证，白盒可选，正式功能不必等待视觉目标。

## G0-G3 阶段门

> 适用技术栈：cocos、phaser、threejs。

G0–G3 是游戏生产里程碑，不是控制器的 `stageId` 字段，也不自行授权动作。实际阶段、状态、门禁和证据以当前 Work Item 与公共控制器 Schema 为准。

> 适用技术栈：cocos、phaser、threejs。

| 里程碑 | 业务检查与交付 |
| --- | --- |
| G0 | 建立任务范围和工程基线；正式视觉选择在相关功能验证后进行。 |
| G1 | 完成必要基础能力，按功能切片和对象范围推进公共 V1→V2→V3→V4→V5；跨场景行为可先用真实功能或可选白盒验证，无需等待全部场景视觉完成。 |
| G2 | 检查全场景集成、预算、响应式、性能、存档/恢复、正式资源完整性与全功能回归。 |
| G3 | 发布工作项汇总逐渠道候选、合规、风险和回滚事实；外部发布等具体动作须取得明确授权并记录真实证据。 |

> 适用技术栈：cocos、phaser、threejs。

各里程碑依据当前 Work Item 的适用门禁和真实证据执行。需求、基线、实际代码行为、模块边界、路径所有权或游戏外部目标变化会使受影响覆盖事实的证据失效；普通候选身份变化只重验受影响单元，不触发整项回退。真机、商店、生产迁移与发布等外部动作须有用户对具体目标和动作的明确授权，不自动执行。
