# 游戏特点识别与专项验证

适用于 Unity、Cocos、Phaser、Three.js 游戏的需求、玩法实现与质量审核。类型用于发现风险，实际存在的机制决定检查范围；混合类型组合选用，局部增量只更新受影响部分。普通应用、设备 GUI 和无界面服务器不因共用编排入口承担游戏检查。

沿用当前 GDD/技术设计、Work Item、实施包及证据清单，不新增阶段、控制器字段、审批或独立登记文件。下文表格是现有规格和用例的内容示例，不是机器 Schema；不要向控制器 JSON 添加未声明字段。具体引擎接口和测试命令仍由当前 `app-stack-*` 及实际工程确定。

<a id="identify"></a>

## 游戏特点识别

新游戏在需求与全局基线中识别特点；已有项目先读现有规则、配置和测试，仅补当前功能真实缺失的信息，不为换素材或局部修复重做全游戏分类。

| 维度 | 从实际规则中确定的内容 |
| --- | --- |
| 核心操作与体验 | 玩家反复执行什么，成功/失败如何发生，一局或一个周期如何结束、重试；类型名称与体验假设分开 |
| 时间与输入 | 实时、回合、节拍或离线累计；输入顺序、动作窗口、暂停与恢复，以及实际使用的时间权威 |
| 空间与内容 | 连续物理、网格、路径或纯规则；镜头/碰撞/可达性约束；手工关卡还是程序生成 |
| 结算与随机 | 效果优先级、连锁终止、随机来源及复现条件；预览、预测与已确认结果的区别 |
| 进程与状态 | 局内/局外成长、资源产消、保存时点、重试损失、撤销或离线收益，仅记录已存在的机制 |
| 权威与平台 | 单机或联网，谁决定状态与结算；目标输入、平台生命周期和资源预算 |

将特点关联到具体规则、受影响功能/对象、主要风险和验收预期；事实引用来源，建议、假设与未决项明确区分。只澄清会影响方向或实现的实质缺口，不要求用户逐项确认维度。某维度未涉及当前任务时可略去；会决定专项选择但尚不清楚的事实保留未决，不能按“不适用”消除。

多个特点冲突时，以已确认的核心操作与规则裁决，例如节奏判定不能被装饰性顿帧改变，联机预测不能提前确认抽牌结果；仍有玩法取舍时按现有决定流程处理，不新设类型审批。

涉及关卡/内容批次或体验调整时，按[关卡内容与试玩调参](game-content-playtesting.md)交接教学/挑战意图、正式数据、最小检查、实际观察和同条件复验；专项工具按当前项目实际规则选用，不预建通用框架。

## V1 专项验证

在当前功能切片中，先验证最可能使方案失效的机制，再扩展其他适用检查。可直接实现、复用仍有效的运行证据或使用可辨识白盒，不强制额外原型；操作、时序、碰撞和空间结论需要实际运行，离线计算仅证明模型。选择下表与当前机制相关的行，再按已确认规则写出预期，不为覆盖示例添加新机制或统一阈值。

| 特点或类型入口 | 实施前明确的规则 | V1 优先验证的风险与代表性用例 |
| --- | --- | --- |
| 动作、平台跳跃、射击 | 输入缓冲与取消窗口、移动/碰撞、命中及重复伤害规则、镜头与瞄准关系 | 连续/同时输入、窗口边界、边缘碰撞与高速穿透；在项目支持的不同帧率下检查规则时序和结果符合预期；中断/恢复不残留输入或判定 |
| 解谜、消除 | 合法操作、胜负、死局策略、连锁终止；存在时定义撤销/重排 | 已知解复现、非法操作不改状态、无可用操作的处理、连锁能终止；撤销/重排不损坏目标或资源。随机或物理机制不能凭有限样例宣称全局可解 |
| 卡牌、回合制、战棋 | 阶段交接、费用与目标、效果优先级、连锁/递归边界、隐藏信息 | 同时触发、目标失效、重复提交、资源不足、回合结束；预览与结算一致或按规则解释差异，信息不提前泄露 |
| 塔防、即时策略 | 路径与阻挡、索敌切换、波次/胜负、单位规模与预算 | 堵路/路径失效、目标死亡切换、波次重叠与漏怪结算；以当前预算内代表性负载检查规则及性能，不以平均 FPS 代替峰值数据 |
| 经营、放置、增量 | 时间权威、产消/容量、离线收益上限与领取策略、数值范围 | 无时间增量、长间隔、时钟回拨/跳变、重复领取、存档恢复；核对资源守恒或明确的产消规则、溢出及进程可达性，模型计算与游戏实际状态分别验证 |
| Roguelike、程序生成 | 生成器/配置版本、种子及随机状态、地图约束、构筑叠加、局内外进程 | 固定条件重现、入口/出口可达、异常组合、生成失败的既定处理、死亡/重开状态隔离；批量检查记录种子集合和样本规模，不把抽样通过说成所有种子正确 |
| 联机、合作、对战 | 权威状态、允许预测范围、操作关联标识、同步及重连/结算策略 | 延迟、乱序、重复消息、断线重连、迟到结果、状态收敛与一次性结算；模拟传输只证明本地协议行为，真实服务未测则保留未验证 |
| 节奏、音乐 | 判定时钟、校准偏移、输入时间戳、音画同步与暂停策略 | 判定窗口边界、不同帧率/音频延迟条件、暂停恢复和音频中断；记录实际偏差及约定容差，表现效果不得改写判定时基 |
| 竞速、驾驶、物理模拟 | 步进/时间策略、控制与接触、检查点及圈数/计时规则 | 不同步长下稳定性符合项目预期、碰撞/重置、漏过/逆向通过检查点、重复冲线；不强求浮点物理跨平台逐位确定性 |
| 叙事、分支选择 | 分支条件、变量、选择后果、存档/读档及跳过策略 | 关键分支可达、快速推进/跳过不重复结算、读档恢复分支状态；恐怖或探索项目再按已定目标交接线索、节奏与人工体验检查，不添加战斗或奖励机制 |

玩法拥有状态与判定，数值负责公式/随机情景，动画与反馈消费已定义事件，QA 核对规则及用例覆盖。数值专项复用 [数值平衡](balance.md)；动态反馈按适用栈复用[反馈指南的类型矩阵](reference-feedback-design-guide.md#类型适用矩阵)，其效果候选不自动变成玩法要求。

记录本切片已验证的机制约束、输入/初始状态、运行环境、操作或时间轨迹、预期与实际、证据位置和剩余假设；随机用例同时保留种子、配置及必要的随机状态/调用顺序。同一机制的有效证据可跨对象引用，但要说明实际覆盖范围。

V1 的功能结果可供受影响对象进入后续设计；尚未证实且会改变该对象操作、空间或时序的约束，应先验证或解决，其他工作继续。V2–V4 制作不替代功能验证，V5 以正式资源重验受影响的判定、输入、时序和状态；手感、可读性及显示效果由用户人工检查。未经明确授权不自动分析截图或发起真机验收。

<a id="qa"></a>

## QA 用例映射

QA 从本次特点和已确认规则推导用例，沿用已有测试计划/用例与证据记录。每个会影响验收的特点关联规则来源、具体功能/对象、检查方式及结果；可以多条特点共用一个用例，也可以一个特点关联多条用例，不按类型机械凑数量。

用例至少可追溯到前置状态、输入/操作、可观察预期、实际结果与证据；时序、随机、负载或联网用例追加实际需要的环境、版本、时间、种子、样本规模或网络条件。复用项目既有编号，不要求新编号体系或文件。未确定预期时报告规则缺口，不能用实现结果反推正确答案。

以下是同一功能在既有计划中的映射示例，只有项目确实包含这些机制时才采用：

| 特点 → 规则来源 → 功能 | V1 用例及预期 | 正式组合后的回归 |
| --- | --- | --- |
| 卡牌＋随机 → GDD 当前费用/触发顺序 → 出牌结算 | 固定初始手牌、种子和输入顺序；重复提交同一次操作，费用与效果只按规则结算一次，日志可复现触发次序 | 正式动画加速/跳过、切场景或恢复后，不改变结算及卡牌去向 |
| 放置＋保存 → 当前时间/收益上限规则 → 离线领取 | 用可控时钟覆盖零间隔、回拨和超过上限，重复领取不重复入账；分别记录公式结果与实际余额 | 完成一次保存、退出、恢复、领取周期，核对库存和下一次累计起点 |
| 联机＋动作 → 当前权威/预测规则 → 命中结算 | 注入延迟、重复及迟到消息，预测表现与可信结果可区分，最终状态按规则收敛且不重复伤害 | 正式表现、中断及重连后重放同类操作；未接真实服务的范围仍标未验证 |

在现有 V1 记录专项功能证据，V5 验证正式资源与运行组合的影响，最终集成覆盖范围内完整的一局或业务周期：开始、推进、成功/失败、重试及适用的保存/恢复与跨场景衔接。长周期和极端组合按当前风险选取，不把局部单测或离线模拟视为完整游玩通过。

测试等级、命令与结果沿用[验证与交付](../../app-creator-workflow/references/verification.md)：分别报告通过、失败、未运行及人工待确认；不适用的候选检查说明机制不存在的依据，不给未执行用例填写 PASS。自动验证状态、公式、事件和协议等工程结果，用户检查手感、节奏与实际显示；人工意见未取得时保留待确认，不新增审批。

规则、参数、生成器、时基、权威协议或正式表现改变时，按下文回归清单沿这份映射重验受影响用例和必要的完整周期，保留未受影响的有效证据。只修改测试计划不等于执行测试；出现失败按现有 repair/revalidate 闭环处理。

## V1 到正式组合的回归清单

在当前 TDD/实施计划和 QA 记录中，关联本次变化、受影响的规则/消费者、既有 V1 用例和后续验证位置。GDD 保持规则来源，TDD 记录实现与计划，QA 记录实际执行及证据，使用已有编号互相引用；QA 文档尚未建立时沿用当前验证材料，不为本清单强制初始化可选文档。

1. 比较实际变化：检查代码、配置、正式资源元数据及绑定，判断其是否写入玩法属性、改变事件触发/顺序、影响输入命中或生命周期。表现标签、文件扩展名和“只是换皮”的描述不能代替影响核查。
2. 按下表选择相关回归，沿真实依赖扩展到共用消费者及跨场景链路。用例记录前置、输入、预期、实际及证据，命令来自目标工程；范围变化时更新原计划和测试等级，不增设审批。
3. 分别记录可复用的旧证据、当前重验结果和未验证项，不改写旧输出。无法确定影响时先检查写者、事件及消费者，仅对仍不明确的范围保留未验证；当前失败按 repair/revalidate 修复，只有上游目标或范围真实失效才按原流程 return。

| 实际变化 | 需要重验的用例与阶段 | 可继续引用的证据及边界 |
| --- | --- | --- |
| 动画时长、速度、根位移、事件或中断 | 回放原 V1 输入轨迹，核对伤害/费用发生时刻、动作窗口、位移写者、取消/暂停/重入；V5 用正式动作重复检查。改变规则先更新对应玩法范围 | 仅表现变化且判定/位移/事件来源未变时，可引用未受影响的纯规则单测；旧运行片段不证明新动作接入。手感与节奏仍待人工检查 |
| 碰撞体、角色尺度、地形、路径或镜头 | V1 中受影响的接触、可达性、索敌、目标/瞄准映射；V5 复核正式场景及高低速/边缘条件；共享资产按实际消费者扩展 | 与空间无关的公式可复用；换模型未改碰撞也须核对真实绑定。不能由单个测试场景推断所有关卡可达 |
| 按钮/拖拽区域、HUD 布局或输入层序 | V5 真实输入命中、拖拽落点、世界坐标转换、模态输入隔离，覆盖项目已支持的代表性视口；规则同时变化时再回到受影响 V1 用例 | 纯规则测试可保留；旧布局的命中证据不能证明新布局。显示效果按既有视觉流程由用户确认 |
| 时钟、步进、全局时间、暂停或系统恢复 | V1 的窗口边界、帧率变化、暂停叠加、时钟跳变及离线收益；V5/集成验证正式反馈/音频与保存恢复。只选实际存在的机制 | 未依赖时间的结算可复用；可控时钟只证明注入条件下逻辑，不证明系统音频延迟或未运行的平台生命周期 |
| 随机调用、生成器、配置或构筑组合 | 保存版本、种子及随机状态/调用条件，重放代表性种子与失败种子；检查地图约束、抽取/掉落与局内外重置，共用随机流的消费者一并回归 | 未涉及随机的规则可复用；同一个种子不能保证算法/调用顺序改变后结果相同，新版本应满足已定规则。抽样规模与未覆盖种子明确保留 |
| 费用、掉落、容量、成长或离线参数 | 重算受影响模型及极端情景，V1 核对实际扣费/收益、上限与重复领取；集成覆盖适用的保存、恢复和一个完整周期 | 未变接口、独立输入映射等证据可复用；表格重算不能替代实际运行。目标区间未知时报告数据，不自行给出平衡通过结论 |
| 联机权威、预测、消息标识或恢复协议 | V1 注入延迟、乱序、重复、迟到和断线，检查收敛及幂等结算；V5/集成重验正式反馈、重连和跨场景状态交接 | 独立纯规则可复用；本地网络模拟与真实服务证据分开，未接真实服务不能标记端到端通过 |
| 场景切换、保存点、对象池或资源替换 | 当前功能退出/重进、取消后迟到回调、订阅与输入清理、实例重用及状态回读；最终集成重放受影响的完整一局/周期 | 未变的资源导入检查可引用；仅重新构建不证明旧状态已清理或保存恢复正确 |

例如“连击动画缩短但规则未改”，先核对动画事件是否仍参与正式伤害接线，再决定受影响的动作轨迹回归；“随机地图加入同一个随机流”，需核对是否扰动既有抽牌/掉落的规则与复现条件。对未变化消费者保留已有证据，不因新候选或进入 V5 就重做全项目 V1。

维护本流程、模板或读取链时，可按[典型任务演练](game-characteristics-exercises.md)核对代理在不同任务中的选择与交接。该演练用于技能维护，不是游戏项目的新阶段或验收门。
