# 发布准备 通用工作流

本规范只承接三栈内容一致且不依赖引擎接口的完整规则块；专业入口继续维护各自的资源路径、API、版本与运行时约束。

## 发布准备与依赖审查

准备可提审交付物不等于已经提交或上架。账号、签名密钥、令牌和个人数据只可放在受控外部密钥系统。

目标包含商店展示时，按[商店截图与宣传图制作任务](../../app-release/references/store-marketing-assets.md#任务安排与完成条件)安排平台要求、卖点/截图脚本、真实多图采集、所需宣传图与导出交付。复用已有市场依据和有效素材，原始截图与营销加工分开，最终显示由用户人工确认；商店上传和投放不在制作授权内。

打包前按[内购 SDK 必要性与移除](../../app-release/references/release-readiness.md#内购-sdk-必要性与移除)核实当前内购功能；没有功能时移除专用 SDK、直接/传递依赖与相关接入，有功能时只保留实际必需项。移除后重建受影响候选并核对最终包，不以配置关闭或购买按钮缺失代替验证；恢复购买、订阅和共享依赖按实际消费者判断。

2. 新渠道先新增独立平台矩阵行，完成适配、资料、合规和测试评审后再纳入候选。

4. 涉及 API 或生产服务时核对契约版本、认证授权、幂等/重试/超时、客户端兼容、迁移/回滚、测试、部署监控和备份恢复；服务端不在范围时只核对外部依赖、所有者和客户端边界。
