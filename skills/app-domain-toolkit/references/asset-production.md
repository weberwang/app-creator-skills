# 视觉素材生产与还原

本规范是列入迁移清单的技术栈共用的完整规则。每段标明适用栈；执行时同时读取本栈技能的原生约束与“本栈配套资料”，资料路径和具体工具由栈入口维护。公共状态与授权仍由 app-workflow-control 管理。

## 完整流程

### 工作流（cocos、phaser、threejs）

生成全局候选、场景效果图或宿主上下文图前必须按“游戏内文案”（见本栈配套资料）将内部规格与玩家可见表达分开，并把可见文字范围和禁止绘制内部说明的约束发给生成器。拆解与正式界面只沿用当前可见表达；冻结后的原子资源仍忠实还原目标，不从 GDD 添加文字或自行删除冻结文字。

### 工作流（cocos、phaser、threejs）

涉及美术方向、效果图、正式资源或动态视觉时，先读取“游戏美术体验与质量契约”（见本栈配套资料）。生产输入必须携带适用的主题、受众、体验目标、视觉层级与常态/操作/峰值预算；全局三候选逐项人工评估，所选候选任一质量项失败或未验证都不得冻结。正式资源在 V3 验收，V4 验收实际场景组合与动态表现；持续游玩片段由用户检查，不增设逐资产确认链。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

`effect-image` 表示正式 Scene 的视觉事实与结构关系还原，不是独立 PNG 生产。场景 Work Item 只记录自身常驻 HUD；modal/popup 等弹窗按“独立工作项规则”（见本栈配套资料）建立 DISPLAY_LAYER Work Item，并在 required state 冻结宿主同屏图。弹窗未完成不阻断场景 V4；弹窗自身仍须完成 V2/V3 和打开→交互→关闭/恢复的 V4 轨迹。运行态默认使用 `visual_validation.mode=usability`，只有明确精确需求时才启用严格像素/全矩阵验证。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

效果图/参考图是否适用只看当前场景 Work Item 是否把它指定为正式运行画面的视觉目标，与是否生成、制作或新增资源无关。适用时，参考还原是同一场景实现生命周期内的视觉模式与合同叠加，必须进入 `effect-image` 的 V1→V2→V3→V4 还原链，包含 `scene_reconstruction_contract`、布局绑定、coverage、宿主场景同屏组合和 fidelity 验收；即使所有区域都用 `reuse-existing`/`runtime-program` 实现、零新资源且零生成式位图也不例外。不创建第二个场景 Work Item 或第二条生命周期。仅仅生成新资源，或仅把图片作为灵感、说明或临时参考，不足以触发 `effect-image`，仍按普通资产、组件或场景路径分类。`image_generation_required`、`generate-now`、资源数量和 `production_method` 只能在已经触发后由 V2 决定生产路线，不能参与 V0 applicability 判定。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

effect-image 生成式位图的完整提示词模板、asset_prompt 事实继承规则、透明生产要求和 generation_record 结构化字段统一见“《Effect-image 生成式位图忠实还原提示词合同》”（见本栈配套资料）。生产分类统一使用 `production_method=image-generation`，具体 `generator`/`generator_version` 由系统根据提示词、参考输入、主体材质、透明需求和已验证能力选择并如实记录；工具版本未暴露时记录 `not-provided`，不得编造。透明路线按冻结边缘事实选择受控纯色去背、已验证的真实 Alpha 或独立遮罩/人工创作；提示词或工具参数声明不能代替 PNG 像素解码验证。已有真实透明图按资源复用合同接入；本 Skill 只保留路由和硬不变量，不在此复制模板。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

V3 将当前已确认生产范围内相互独立的静态 component × required state 待生成图片汇总为一个批量任务，一次编排提交，禁止逐张创建任务或等待上一张验收后才生成下一张；每项仍输出独立位图，详见“图片批量生成”（见本栈配套资料）。批次完成后直接提供图片画廊或联系表，每项可单独放大查看；文字只汇报失败、缺失和仍需处理的差异，不先发文字方案等待确认。存在父图依赖的图片帧动画按“帧动画合同”（见本栈配套资料）逐张确认后推进，不能用静态图片批量规则跳过确认；已满足父图与确认前置的独立区间可按该合同并行。V4 直接在正式场景中实现并验收资源组合，默认验证代表性完整画面、关键内容可用性、实际交互和正式 Scene 消费证据，仅 exact 模式要求完整逐区域精确测量和差异材料。资源 loaded/used、missing=0、resize 稳定只属于工程子门，不能单独驱动 COMPLETE。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

确定功能和拆分场景时，先按“功能与场景阶段的共享规划”（见本栈配套资料）总结共用资源与局部部件、消费位置、共同规格和需保留的差异；已明确同一部件可提前规划一次生产、多处引用，依据不足者保持候选。正式图片生成并完成透明处理与尺寸归一化后，再按“正式图片生成后的共享与复用”（见本栈配套资料）复核早期规划及新发现的需求，记录权威资源身份、消费位置、使用限制与依据，供后续任务先查再复用。功能相同或视觉相似不能单独决定共享；待人工视觉检查者保持候选，不改写既有独立生产合同与真实生成记录。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

读取项目配置、GDD、visual-design、TDD、控制面和资源登记；执行“视觉生产管线”（见本栈配套资料）。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

V0 先判断任务属于原子资源、组件/资源集，还是场景/整套 UI/视觉系统/重做；参考还原是否适用只由当前场景 Work Item 的正式运行视觉目标声明决定，不由新资源或图像生成需求决定。原子资源只有在结构、布局、交互和视口行为不变，且已有适用视觉契约、视觉可交付结论与预算基线时才能跳过 V1/V2；任务内小幅适配可更新计划并重验，不必重新授权。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

当前场景 Work Item 按控制面定义的 V1→V2→V3→V4 阶段推进；本领域负责在 V2 依次完成拆解 PNG 和布局 PNG 两次独立人工确认后生产正式资源，在 V3 完成资源级验收，V4 直接在正式场景实现、校准并验收运行态画面。正式代码只消费当前场景或合规 `shared` 且 V3 `accepted` 的资源；公共正式资源只允许至少两个场景稳定复用或属于运行必需。场景联合验收前必须清除灰盒、占位和 fallback。

### 场景还原合同（effect-image 强制）（cocos、phaser、threejs）

效果图生产必须先引用已冻结的全局视觉基线；全局候选选择、冻结状态和跨 Work Item 引用规则以“控制模型”（见本栈配套资料）及“全局视觉控制”（见本栈配套资料）为准。本领域只补充生成记录、锚点继承和资源合同要求；场景仍在同一 Work Item 内按 V1→V2→V3→V4 完成。

### 条件参考（cocos、phaser）

- 装饰性屏幕空间满幅背景：读取 “满幅背景”（见本栈配套资料）；世界空间关卡、Tilemap 或玩法环境改读资产生产路线。

### 条件参考（cocos、phaser、threejs）

- QA 测量、动态 resize、完整 viewport 截图和只读 Hook：读取 “响应式视觉验证”（见本栈配套资料），不得在资产文档复制其字段或阈值；观看舒适和持续游玩验收使用共享美术契约。

### 审核与交付（cocos、phaser、threejs）

所有候选先通过 F0-F3；F4 只处理带外部写入、付费、真机、破坏性或外部删除、发布副作用的 A4-A6 操作。无副作用本地 A4 集成不因等级标签额外等待批准。V1/V2 确定性机器检查必须执行；需求明确时自动采用 `AUTO` 并直接出预览，仅真实方向/玩法/结构取舍才记录一次 `USER_DECISION`。用户在 V2 只需分别确认拆解 PNG 与布局 PNG；静态资源批次和范围内返修通过画廊/前后对照图审阅。技术 JSON、状态分析、coverage、合同和证据由代理持续维护，不额外发起文本确认。每个交付包记录当前任务范围、候选身份、基线、来源/许可（如适用）、预算和证据；普通任务不要求独立授权记录。

### 视觉确认边界（cocos、phaser、threejs）

F2 机器证据核对文件、结构、绑定和实际参数，不能单独给出美术通过结论。代理可提供截图、录屏和检查要点；未明确授权自动视觉验证时，不自动分析画面。用户对主题、完成度与舒适度的实际评价纳入现有选图、V2 布局确认和 V4 运行验收材料，不能代填或用旧确认覆盖已变化的画面。

### 场景还原合同（effect-image 强制）（phaser、threejs）

foundation-only 基础实施完成后，V1 建立功能规格、玩法视觉契约、必要低保真/灰盒与预算，只定义契约，不写正式场景功能代码；Work Item 指定效果图为还原目标时，V1 同时按“视觉还原”（见本栈配套资料）生成或接收并冻结 scene master/reference target、宿主上下文效果图、参考身份、对比条件、可观察视觉事实和初步还原草案。需求或基线已明确时，V1 记录 `AUTO` 并直接提供场景目标/宿主上下文预览；只有产品方向、玩法语义或结构存在实质歧义时才询问。V2 保持“拆解图确认 → 布局图确认”的串行硬门：阶段 A 在内部完成状态分析、组件/placement、生产路线、技术 JSON 与 `decomposition_elements`，直接展示按确认顺序编号的拆解 PNG，只请用户看图确认；技术记录供代理和机器门使用，不另行要求阅读或确认。阶段 B 在拆解图确认后自动生成逐元素对齐决策、布局 PNG 和 `review.html`，直接请用户检查最终布局图/预览并确认；无需先提交文字布局方案。用户发现图中真实歧义时再澄清。布局只在冻结原图上叠加父子框与说明，不重新生成或替换视觉参考图，也不提供多个布局方案。

### 场景还原合同（effect-image 强制）（phaser、threejs）

布局生成的标准交付除 PNG 外必须包含同一候选目录的 `layout-nodes.json`、`layout-decision.json`、自包含 `review.html` 和 `generation-result.json`。布局审阅页只用于可读的人工作业，不能替代拆解确认、独立布局确认或 PNG/F2 机器门；其模板、真实文件与业务绑定、候选状态和离线边界见 “离线布局审阅产物”（见本栈配套资料）。

### 场景还原合同（effect-image 强制）（phaser、threejs）

V2 拆解 UI 底板、按钮皮肤和框体时，必须按可观察固定角边与可伸展区域评估九宫格，记录适用/不适用原因及源图尺寸、四边切片值；采用九宫格时，选择随已有拆解确认冻结并贯穿 V3 小图生产与 V4 正式场景实现。具体合同读取“九宫格 UI”（见本栈配套资料），V3 生产按冻结切片参数执行。

### 视觉确认边界（phaser、threejs）

同一场景 Work Item 的 V0→V1→V2→V3→V4 链在 V2 依次完成拆解图确认和布局图确认，冻结还原方案。用户面对的是编号拆解 PNG 与布局 PNG/`review.html`；技术 JSON、提案和决策文件在后台用于机器校验和身份绑定，不构成额外文字确认门。`visual-decomposition-confirmation/1.0` 绑定 annotation/proposal/decision SHA、target、V2 candidate、diff、baseline、全部编号和用户原文；已确认的目标或方案发生实质变化时重新确认受影响部分，普通运行态布局微调不重开 V2。V2 拆解图、技术 JSON、合同回对、coverage 和结构化机器检查必须齐全，布局确认另行绑定最终布局图与决策文件。V3 资源验收和 V4 正式场景的代表性完整画面及关键可用性证据绑定当前身份；overlay、diff 和完整逐区域精确 fidelity 仅在 exact 模式强制。根节点 PASS、布尔值、AI reviewer 字段或旧 `human_review` 均不能代替两次 V2 图像确认。
