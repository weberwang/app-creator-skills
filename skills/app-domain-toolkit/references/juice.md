# 反馈表现 通用工作流

本规范只承接三栈内容一致且不依赖引擎接口的完整规则块；专业入口继续维护各自的资源路径、API、版本与运行时约束。

## 模块职责边界

- 玩法拥有规则、状态、碰撞和结算；顿帧、击退、吸附、输入缓冲等会改变玩法时，交由玩法及适用的数值领域确定，不能伪装成纯表现改动。

- UI 负责布局、焦点表现与布局坐标合同；玩法保留交互代码，架构维护跨模块坐标约定。反馈通过明确的视觉偏移或表现节点增强，不争抢基础布局属性和输入处理。

## 按需读取

指南是一份完整参考，但局部任务只读取和采用相关章节；不默认加载全类型清单或为不适用项制作效果。

## 执行闭环

1. 读取当前范围、GDD/brief、实际当前技术栈版本、现有事件和表现组件，确定正在解决的事件、问题与可观察结果。已有反馈契约可复用，不重复创建相同事实。

2. 按类型适用矩阵选择能力，写清准备、发生、结果、持续和收尾中的适用部分，以及成功、拒绝、取消、中断和待确认的语义。

3. 在现有规格中补充事件表；独立反馈任务且原文档不便承载时，可按需使用 `docs/game-feel.md`。记录职责、参数单位、重复策略、时间与坐标空间、资源和清理方式；这是领域事实，不是新机器 Schema。

4. 先确定最小组合，再按重要性增加效果。普通高频事件局部、短促、可合并；危险和当前操作保持清晰。固定数值仅是调参起点，实际阈值由项目定义。
