# 显示结构与场景职责

执行公共规则时，同时读取当前技术栈参考中的原生补充和“本栈配套资料”。各段仅适用于标注的技术栈；结构化证据不代替用户对显示效果的人工验收。

各技术栈统一按 V0–V5 推进；V1 先验证功能，白盒可选，V2–V5 依次完成视觉目标、拆解布局、资源导入和运行验收。

## 公共显示结构约定

本节适用于 Unity、Cocos、Phaser、Three.js、Flutter。代码目录表达实现归属，运行时显示树表达挂载、布局、变换与生命周期；两者分别说明，不要求一一对应。渲染前后顺序、布局参照和业务依赖也分别声明，不能从文件夹或节点父子关系直接推断。

| 显示职责 | 组织边界 | 工作项与依赖 |
| --- | --- | --- |
| 应用显示宿主 | 拥有实际渲染入口、内容挂载位置和退出清理；只有跨页面确需常驻的内容才驻留 | 由基础工程或实际宿主负责，不为根节点额外创建视觉工作项 |
| 导航框架 | 承载跨页面稳定导航及内容槽，控制选中项与内容显示的同步 | Flutter 确需独立视觉验收时可为 PAGE；游戏使用实际宿主及共享组件，不虚构导航场景 |
| 页面或场景内容 | 主页、业务页面、玩法世界及其自有常驻 HUD；私有内容随所属对象管理 | 实际 SCENE/PAGE 各自验收，主页不承担全局路由注册或所有弹窗内容 |
| 瞬态显示层 | 弹窗、抽屉、Toast 等通过明确槽位或覆盖入口挂载；生命周期与宿主上下文明确 | 独立 DISPLAY_LAYER，绑定单一真实宿主；物理挂载在宿主下不改变独立交付归属 |
| 区域与功能组件 | 页面内按用户任务分组，按钮、卡片、列表项等共同管理自己的状态和命中 | 普通组件不机械拆工作项；共享实现可复用，运行实例和宿主分别管理 |

显示结构使用下列按需组织的职责关系，名称、层数与具体树形由原生布局决定，不能为凑齐示例创建无用途容器：

```text
应用显示宿主
├── 导航框架（确需常驻时）
│   └── 内容槽 → 当前页面／场景内容 → 区域 → 功能组件 → 实际显示元素
├── 当前内容的世界渲染分支（有玩法世界时）
└── 瞬态层挂载入口 → 当前显示层实例 → 面板／内容组件
```

这是职责示意，不要求将世界节点挂到 UI 树或把全局覆盖入口置于同一物理根。没有常驻导航时内容直接由实际宿主承载。装饰背景与前景内容分别按职责挂载，不因图片几何包围内容就让其成为功能父级；底板确实承担简单组件根职责时遵循本栈已有规则。

## 游戏层／内容层、HUD、浮窗与弹窗

统一将基础画面称为“游戏层／内容层”：游戏中是地图、角色、世界特效等玩法画面，应用中是当前页面的主要业务内容。屏幕 HUD、浮窗和弹窗使用独立覆盖职责。默认从后到前的合成关系为：

```text
后方／底层
游戏层／内容层
HUD（常驻状态、导航与操作）
弹窗层（非模态面板，以及成对的模态遮罩与弹窗）
浮窗层（Toast 等全局短时提示）
全局加载层（前台阻塞任务期间覆盖全部下层）
前方／顶层
```

| 显示职责 | 层序与范围 | 输入与关闭 |
| --- | --- | --- |
| 游戏层／内容层 | 基础场景或页面；内部可再分背景、主体、前景与世界特效 | 接收未被上层消费或模态阻断的操作；被遮挡不等于自动暂停业务更新 |
| HUD | 位于内容之上、弹窗层之下；屏幕常驻信息与操作，不随世界相机滚动 | 可交互控件消费自己的命中，装饰部分不无故吞输入；是否常驻由实际宿主决定 |
| 弹窗层 | 高于 HUD、低于浮窗层；包含独立面板、抽屉与模态弹窗。非模态面板低于当前模态遮罩，遮罩紧贴对应模态弹窗下方 | 非模态面板仅消费自身区域命中，外部保留宿主操作；模态弹窗阻断下层指针、键盘、手柄与可访问焦点，关闭后恢复有效宿主或下一个模态层 |
| 浮窗层 | 常规提示最上层，覆盖弹窗，低于全局加载层；承载 Toast、全局短时反馈等提示 | 默认无交互、不抢焦点、不吞输入，避免遮挡关键操作；显示期间保持当前模态的输入隔离 |

全局加载层只在前台阻塞任务期间存在，按下文“弹窗按需加载与全局加载状态”管理，覆盖浮窗与弹窗并阻断下层输入。

浮窗层、弹窗层是合成职责，不新增控制器类型，也不与 `layerType` 一一对应：Toast 使用现有 `toast`，非模态工具面板使用 `popup`，抽屉按实际形态使用 `drawer`，模态面板按实际合同使用 `modal` 等现有类型，并明确其模态行为；不能仅凭 `popup`、`drawer` 名称推断是否阻断输入。独立瞬态显示层仍归 DISPLAY_LAYER 并绑定单一宿主；HUD 属于实际宿主，不能为了层序将其改成瞬态工作项。

弹窗层内部由明确的窗口栈或既定顺序管理，激活/置前规则在本层内生效，不能让非模态工具面板越过当前模态边界。多个模态共存时按“遮罩 A → 弹窗 A → 遮罩 B → 弹窗 B”成对叠放；只有最顶层模态及其附属交互接收输入，关闭 B 后恢复 A，全部关闭后再恢复宿主。浮窗层提示仍显示在这些窗口上方，但不改变输入权。模态输入限制不等于强制暂停游戏模拟，暂停与恢复策略单独说明。

下拉列表、Tooltip 等附属浮层跟随自己的窗口：弹窗内部浮层在该弹窗上方，但仍低于后来打开的模态遮罩；随所属窗口隐藏、关闭或卸载，不因名称带“浮”就提升到全局浮窗层。Toast 在常规最上层浮窗层（低于全局加载层）按[独立实例与复用规范](ui-copy-principles.md#toast-独立实例与复用)立即显示，每次有效触发使用独立实例，相同提示不去重、不排队；仅复用已结束展示的空闲实例；需要用户确认的提示按弹窗处理，不能伪装成 Toast 绕过输入隔离。

世界空间的血条、标签或交互提示仍属于游戏层内部的世界深度关系，不因称为 HUD 就自动覆盖屏幕 UI。应用页面内的普通卡片和区域属于内容层，不为其创建 HUD；无实际职责的层可省略。上述是合成顺序而非强制父子树或引擎全局数值；各栈必须将其落实到自己的 Camera/Canvas、场景组合或 Overlay，并同时验证输入链路。

V1 先验证面板内外命中、模态隔离、嵌套关闭恢复、Toast 不抢焦点/不阻断当前有效输入及适用的返回键行为，白盒可选；V2/V3 在现有视觉与布局材料中明确实际层序，V5 在正式宿主验证 Toast 覆盖弹窗等同屏组合。局部层序值只在同一合成域比较，不增加一份全局层级合同或重复确认。

## 弹窗按需加载与全局加载状态

本节适用于五栈所有应用自有弹窗，包括确认框、模态窗口、非模态面板和抽屉；系统或 SDK 原生窗口由其公开接口触发，不伪造资源生命周期。Toast 继续作为短时反馈独立管理。

- 所有弹窗仅在首次实际打开请求触发时加载自身资源并创建实例，不在启动、场景进入或宿主初始化时批量预加载或预实例化。加载成功后由明确的缓存所有者仅保留预制体、模板、图片/纹理及其依赖资源，不缓存弹窗运行实例。每次打开均从缓存资源创建新实例并读取当前业务数据；关闭时销毁实例、移出有效输入与焦点链，但不释放已加载资源或卸载资源包，也不按关闭次数、空闲时间自动淘汰资源。缓存仅在其所有者生命周期结束或明确执行缓存失效/清理时统一释放，不能误释放其他消费者仍在使用的资源。
- 资源缓存不持有运行实例、实例闭包或关闭前的执行活动。关闭时停止计时器、定时刷新、协程、动画/缓动和轮询，取消可取消的在途请求，解绑事件订阅及输入监听；不可取消的异步操作通过展示身份失效，旧回调不得访问已销毁实例、恢复任务或影响新实例。释放本次打开仍持有的全局加载令牌，不释放缓存资源。再次打开为新实例分配新的展示身份并初始化必要任务与订阅，每项只启动一次，不沿用旧实例状态、计时器或绑定。
- 全局加载状态由唯一服务管理，状态至少表达空闲和加载中；每个前台阻塞任务领取独立令牌，在成功、失败、取消、超时及宿主退出时幂等释放。只要仍有有效令牌就保持加载中，不能由任意请求直接设置全局布尔值或关闭其他任务的蒙层。后台加载和自动重试不领取令牌、不显示蒙层。
- 全局加载视图的最小资源随应用显示宿主就绪，不依赖将要打开的弹窗或远程资源，避免加载蒙层自身再次等待加载。弹窗触发后先登记任务并显示蒙层，再开始异步加载；缓存资源命中且新实例可同步创建并显示时直接创建，不为走流程而闪现蒙层；仍需异步获取前台必要数据时按相同令牌生命周期显示蒙层，不人为增加等待时长或编造进度。
- 蒙层覆盖整个当前应用视口及安全区，显示在弹窗和 Toast 之上，并提供清晰的加载状态。阻断下层指针、触摸、键盘、手柄及可访问焦点；不得通过点击穿透、快捷键或返回键再次触发下层业务。默认点击蒙层不关闭；确需取消时只保留明确的取消入口，先取消所属任务再释放令牌。蒙层只阻断交互，不隐含暂停游戏或终止其他业务。
- 资源与数据就绪后，核对打开请求身份及宿主仍有效，完成实例挂载和输入边界设置后再释放该任务令牌，避免蒙层消失与弹窗接管之间出现输入空隙。最后一个任务结束时移除蒙层，将焦点交给最顶层有效弹窗或恢复有效宿主；若其他任务仍在加载，蒙层继续遮挡。
- 加载失败或超时须清理未完成的实例与任务、释放该任务令牌（保留已成功缓存的图片和资源），并按[错误提示形式](ui-copy-principles.md#错误提示形式)反馈；不能在失败提示前遗留自身蒙层。需要用户确认的恢复弹窗必须有随宿主可用的最小后备视图，不能再次依赖同一失败资源。取消或宿主退出后迟到的完成不得打开旧弹窗、重新显示蒙层或影响新任务；同一打开请求的重复投递应复用进行中的操作。

在现有技术方案与显示规格中登记弹窗资源入口、按需加载边界、预制体/模板与图片等资源的缓存所有者及显式释放时机、关闭时任务清理、全局服务与令牌所有者、超时及取消策略。V1 验证首次打开、关闭后实例已销毁、缓存仍持有预制体和图片引用且所有执行任务停止、缓存命中重开创建新实例而不重复加载资源或绑定、旧回调隔离、并发任务分别结束、失败/超时、取消、路由离开、迟到回调和输入隔离；V5 由用户人工确认蒙层覆盖、加载显示与正式弹窗组合。沿用 DISPLAY_LAYER 及现有合同，不新增控制器状态类型，也不要求在本技能仓库中实际启动引擎。

## 显示树与组合边界

- 在现有技术设计、布局规格或场景/Prefab/Widget 源中说明实际根、稳定对象身份、父级或挂载槽、坐标空间、布局/滚动/裁切所有者、合成顺序、输入与焦点、创建和销毁责任。使用现有合同字段和本栈结构，不新增一份重复清单或虚构通用字段。
- 每个实例在同一时刻有明确的实际挂载父级及创建、解绑、销毁责任；应用级路由可发出打开/切换请求，具体显示实例由确定的宿主或显示层控制器管理。共享资源释放与实例销毁分开，不能关闭一个页面就释放其他消费者使用的资源。
- 区域按功能语义分组，组件内部协调文字、图标、底板、状态和命中；拆出独立资产不拆散功能归属。容器只在确有布局、裁切、状态、变换或生命周期职责时创建，不按所有文字/所有图片分组，也不增加无用途包装层。
- 模态层按实际行为阻断下层输入并恢复焦点；Toast 等非模态层按适用性声明，不强制暂停游戏或抢占焦点。隐藏、缓存、路由离开及再次进入时明确输入、更新、订阅与状态恢复，不让不可见分支继续响应同一操作。
- 渲染顺序按实际 Camera、Canvas、渲染通道、DOM/Overlay 等合成域说明；局部 sibling/depth/z-index 不能充当跨域全局顺序。布局调整不授权额外缩放普通图片，图片尺寸、九宫格与装饰背景 cover 仍遵循[尺寸规则](../../app-ui-layout/references/relative-layout.md#图片尺寸)。

## 节点最小化

Unity、Cocos、Phaser、Three.js、Flutter 在还原场景、页面和显示层时，必须采用满足已确认视觉与功能要求的最简层级。按实际职责判断节点是否必要，覆盖各栈的场景节点、容器和声明式组件。保留承担显示、布局、裁切、变换、状态、输入、焦点、无障碍、资源绑定或生命周期职责的节点，并维护有效的稳定身份与引用。

- **V3 拆解**：先核对正式源和现有组件，优先复用职责、挂载关系与生命周期均适合的节点或模板。已有节点或原生组件能承担同一职责时直接复用；只有确需独立职责时才新增节点，并在现有拆解材料中说明用途。清理本次范围内无职责的空节点、包装层和重复容器，确认拆解前核对其引用及实际行为。
- **V3 布局**：基于已确认拆解确定最简父子关系、槽位、定位参照、尺寸与层序，使用已有容器承载可共享的布局职责。确需空槽时，在现有材料中说明其实际用途和生效条件。拆解与布局仍分别确认，确认后的最简层级作为正式还原依据。
- **V5 还原**：按 V3 确认的最简层级保存正式源并接入实际宿主。动态实例按确认的模板与挂载关系生成。核对正式源和运行组合中的父子关系、节点职责、引用、层序与交互，避免重新引入冗余包装层。发现确需增加节点或调整已确认的父子关系时，先回到受影响的 V3 拆解或布局确认，再继续还原。

## 随动与父子关系

Unity、Cocos、Phaser、Three.js、Flutter 的场景、页面和显示层统一遵循此规则。V3 拆解先判断移动行为：当同一组件中的显示对象移位时，如果其他元素必须随它移动才能保持相对位置，就将它们划为随动组。组内由承担该组移动且显示层较低的对象作为父级，跟随元素作为子级并继承位移。层序仅用于确定已识别随动组内的父级，显示层序相邻、画面重叠或静态对齐本身均不能建立父子关系。

V3 布局记录父级、跟随元素、触发移动的状态和要保持的相对位置，分别确认拆解与布局。优先复用底层对象已有的容器能力。原生视觉叶节点无法容纳子元素时，以承载该底层视觉的组件根作为父级，保留原有绘制顺序、布局约束与输入归属。例如按钮底板带动图标和文字，弹窗面板带动标题和关闭按钮，固定在视口的模态遮罩与可移动面板分别挂载。

V5 按确认后的父子关系还原到正式源，并在实际宿主验证父级移动后子级仍保持约定的相对位置、层序与命中关系。通过本栈的原生层级或组件布局继承位移，避免在多个节点上分别复制同一移动逻辑。确需调整确认关系时，回到受影响的 V3 环节更新确认。

## 新增显示元素的增量约束

本节适用于五个技术栈的新项目、既有页面或场景增量，以及复用组件、动态生成内容和临时功能原型。新增文字、图标、按钮、HUD、弹窗、装饰、特效或世界对象时，须按其真实显示职责沿用当前工作流约束，不能以“只加一个元素”跳过结构、布局或资源规则。

新增或修改场景、页面、显示层、功能或机制时，先判断是否涉及显示元素的设计或可见表现；只要涉及，就必须从 **V0** 开始定义本次显示增量，再完成 V1 功能验证及适用的 V2–V5。范围包括新增元素，以及修改既有元素的外观、可见状态、布局、层序、特效参数或动态时序。复用已有图片、组件或程序生成方式不能直接从 V1、V4 或 V5 开始；是否生成新设计稿、图片与是否从 V0 开始是独立判断。纯非视觉逻辑或内部重构且不改变显示设计与可见表现时，仍按实际影响处理。

V0 在现有计划中写清新增或修改的元素、触发状态、所属真实对象与宿主、功能意图、影响区域、输入/遮挡关系、可复用目标与素材，以及后续阶段的交付和验证范围。SCENE、PAGE、DISPLAY_LAYER 的新增与修改均适用；普通子元素按所属对象的增量管理，不为每个文字、粒子或按钮机械拆工作项，独立弹窗等仍沿既有对象规则。从 V0 开始只覆盖本次增量及其受影响组合，不重做无关宿主或全项目阶段。

尚在 V0 的工作项直接纳入本次范围；已完成对象的新需求使用绑定同一真实对象的视觉增量工作项，从其 V0 开始。进行中工作项已越过 V0 时，按控制面既有范围变更机制处理；需要本轮 V0 起点时建立对应增量工作项，不手改阶段、覆盖冻结记录或借非视觉 MODULE/轻量模式跳过起点。已有模板按已确认规则正常生成实例、播放动画或切换状态属于既定运行行为，不为每次运行重开 V0；设计或实现任务改变这些规则或可见表现时适用本约束。

当前 V0 和 V1 完成后，才能按[视觉确认的增量复用](../../app-creator-workflow/references/workflow.md#视觉确认的增量复用)引用仍有效的上游事实；旧确认只能覆盖未变化的范围。新增或修改的元素及其组合须有适用的视觉目标、拆解、布局、资源与运行证据及人工确认，不能把旧对象通过结论直接扩展到变化部分。仅时长或幅度调整也先在 V0 明确变化与复用依据，再按控制面复用仍有效的目标、拆解和布局；不因从 V0 开始就强制重新设计或生图。

同一工作项已定义的 V0 范围内，连续实施、调参和返修沿用当前闭环，不为每次编辑再次启动 V0；只有新增需求或范围变化才重新界定本轮增量。阶段内失败仍按既有 repair/revalidate/RETURN 规则处理，不把 V0 起点要求变成无限返工或新增人工审批。

采用可视化编辑器的项目，同时遵守[编辑器位置关系的控制权](editor-display-authoring.md#编辑器位置关系的控制权)。新增和既有元素均不得在无明确功能需要时被程序重设位置、父级或布局约束；运行时按正式配置执行原生布局，不另设覆盖编辑器结果的静态排版。

- 实施前读取所属对象的现有显示树、有效视觉目标、拆解、布局及资源约定；在已有材料和正式节点源中补齐新增元素的稳定身份、功能归属、真实父级或挂载槽、定位参照与坐标空间。位置须说明锚点/对齐、相对间距或偏移及重算条件，不能只给孤立的屏幕坐标。
- 明确宽高或尺寸计算策略、尺寸参照及适用的最小/最大约束；同时处理父级尺寸变化、内容极值、安全区、裁切与滚动。UI 按[相对布局与尺寸规则](../../app-ui-layout/references/relative-layout.md)执行，普通图片保持源逻辑尺寸，合法九宫格与装饰背景沿用各自规则；世界对象按当前栈的世界坐标、变换和相机合同处理，不套用屏幕 UI 约束。
- 将元素挂入承担实际布局、变换、状态或生命周期职责的父级，明确合成顺序、遮挡、命中/焦点及创建和销毁责任；不为方便定位挂到无关根节点、装饰图或全局覆盖层。复用组件须核对本次宿主、实例尺寸与输入上下文；动态实例消费同一正式模板或生成配置。
- 从本次 V0 范围出发，按实际影响更新已有目标、拆解、布局和资源绑定，并补齐新增部分的阶段材料与人工确认。V1 原型先满足当阶段的结构与可操作约束，不提前冻结正式视觉几何，也不重做无关部分。
- 验证实际节点或实例的父子关系、位置来源、尺寸和祖先变换，并覆盖受影响的视口、内容状态、层序与交互；运行证据须包含新增元素与宿主的真实组合。Unity、Cocos 同步按[编辑器还原](editor-display-authoring.md)保存并回读正式源。结构检查、静态合同和运行结果分别报告，显示效果由用户人工确认；不新增独立节点清单、审批门或第二套布局源。

## 融入 V0–V5

| 阶段 | 显示结构工作 |
| --- | --- |
| V0 | 识别现有显示宿主、导航与内容边界、共享组件消费者和实际交付范围；复用有效结构 |
| V1 | 验证挂载/卸载、导航参数、返回、状态恢复及适用的输入隔离；可直接实现，白盒保持可选 |
| V2 | 依据已验证行为确定可见层、页面状态及跨场景组合的视觉范围，大场景按需多图 |
| V3 | 优先复用已有节点，按[节点最小化](#节点最小化)确定最简父子树、功能组件、槽位、尺寸参照和合成策略，分别确认拆解与布局 |
| V4 | 正式资源绑定确定的节点/组件消费者，复用已验收资源，不从临时候选路径加载 |
| V5 | 按 V3 确认的最简层级还原，在实际宿主和正式组合中验证结构、层序、命中、关闭恢复、尺寸变化及重入，显示效果由用户人工验收 |

V3 沿用已有规格，按[还原依据](../../app-ui-layout/references/relative-layout.md#还原依据与变更边界)记录受影响目标及其来源、元素布局与适配约束；V5 分别核对基准条件下的目标值、正式源值和运行值，以及不同条件下的合法适配。正式可编辑源可以是原生场景、界面文件、声明式 UI 或组件代码，不要求每个技术栈使用编辑器。结构、工程和人工视觉结论按[验证与交付](../../app-creator-workflow/references/verification.md#三类验收结论)分别报告。

功能切片可以跨多个显示分支，通过公开接口与[跨对象依赖](../../app-workflow-control/references/function-dependencies.md#导航框架与共享路由)推进，不按显示树重新拆成互相等待的功能任务。共享路由为非视觉 MODULE 或 feature INTEGRATION；早期功能验证不等待目标场景 V5，最终集成才使用本批次完成的正式对象。共享组件不携带其他宿主的验收通过结论。

结构更新按真实影响处理：仅内部重构且功能及视觉约定未变时，不重做未受影响的视觉确认；纯显示名称调整只有在冻结稳定 ID 与运行绑定均未改变时才属于此类。代码移动、实际引用或实施包所有权/结果路径变化时，仍按[实施执行规则](../../app-workflow-control/references/implementation-execution.md)更新引用和执行闭环；源码变化后完成真实工程重验，并按[功能基线规则](../../app-workflow-control/references/function-dependencies.md)刷新受影响基线，不重算旧证据摘要冒充新验证。安全等价路径与数组顺序变化继续沿用已有语义比较规则。真实父级/布局参照、合成、交互或宿主语义变化时更新受影响材料并重验；宿主变更遵守[单目标领域合同](../../app-workflow-control/references/single-target-domain.md)，不能用内部重构名义复用旧宿主证据。

## 弹窗工作项与场景解耦

> 适用技术栈：cocos、phaser、threejs。

场景工作项和弹窗工作项独立规划、实现、验收。场景只负责自身玩法、场景画面及属于 scene master 的常驻 HUD；modal、popup、drawer、toast 等瞬态显示层建立独立 `DISPLAY_LAYER` Work Item 和独立 Implementation Package。`host_scene_id` 只描述弹窗打开时的运行上下文及接线目标，不表示弹窗归属于宿主场景实现，也不把弹窗完成状态并入场景 V5。

> 适用技术栈：cocos、phaser、threejs。

- 场景 `display_layer_planning.inventory` 只记录场景自有的常驻显示层；没有自有显示层时显式使用 `inventory=[]`。`deferred_layers` 已移除，不得把未完成弹窗作为场景待办。

> 适用技术栈：cocos、phaser、threejs。

- 弹窗 Work Item 的 `inventory` 记录本任务实际交付的瞬态层，并独立完成参考、拆解确认、布局确认、正式资源、代码和 V5 运行轨迹。required state 仍必须绑定真实宿主上下文图，V5 仍验证打开→交互→关闭→恢复。

> 适用技术栈：cocos、phaser、threejs。

- `SCENE` 与 `DISPLAY_LAYER` 不得出现在同一个 Implementation Package。独立弹窗包可包含多个写范围和状态所有权互斥的 DISPLAY_LAYER 单元；每个单元保留 `displayLayerId` 和 `hostSceneId`。

> 适用技术栈：cocos、phaser、threejs。

- 大厅或其他宿主场景只实现自己范围内的稳定触发事件/公开接口。弹窗内容、资源、状态、接线和验收由弹窗 Work Item 负责；弹窗未开始、失败或延期均不阻断宿主场景验收。

> 适用技术栈：cocos、phaser、threejs。

- 弹窗与宿主需要联合调试时，在弹窗 Work Item 内消费宿主已冻结的公开接口与上下文证据。联合调试结果证明弹窗自身可用，不回写为场景完成前置，也不要求重新打开已通过的场景验收。
