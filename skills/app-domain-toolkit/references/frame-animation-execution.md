# 帧动画生产与执行约束

本规范是列入迁移清单的技术栈共用的完整规则。每段标明适用栈；执行时同时读取本栈技能的原生约束与“本栈配套资料”，资料路径和具体工具由栈入口维护。公共状态与授权仍由 app-workflow-control 管理。

## 完整流程

### Cocos Creator 3.x 通用帧动画制作（cocos、phaser、threejs）

使用统一生产流程，按用途选择制作、优化和人工验收规则，来源默认使用视频抽帧。视频作为动作草图；用户明确选择图片路线时，以真实生成的首尾、阶段关键帧及双图参考补帧形成序列。最终动画以游戏要求和视觉基线为准。当前 Work Item 的资源交付回到既有控制面，不另建动画状态机。

### 游戏时间轴与交付追溯

同一游戏工作项沿用现有的功能验证和视觉目标记录，按本次变化补齐适用证据。设计工件关联消费场景、玩法规则来源、真实美术基线、游戏镜头或 UI 显示层及目标显示尺寸。独立动作设计交付规格和待确认项，后续进入项目制作时再绑定实际消费场景。

- **V3 动作方案。** 用共享时间轴把每个游戏状态或关键事件关联到可见变化、发生时点和验收点。例如命中由玩法裁定，动画应让接触姿态在命中时清楚可见。对接招、未接招和已有打断路径记录衔接条件及去向，区分已有规则、表现建议和待确认事项。

  同一次方案确认中，向用户说明目标感受、关键姿态和验收点，同时展示影响体验的关键时点及玩法分支。多段攻击说明命中、输入窗口、立即切换或固定时点切换、未接招收势去向，以及适用的取消和打断。列出待决项及受影响动作，按确认的方案版本与动作范围记录用户决定。完整毫秒表、采样参数和提示词仍留在内部工件。

- **V4 视频与素材。** 从已确认的动作时间轴和游戏显示条件推导视频机位、构图、关键姿态、分段及输出尺寸。源视频可以剪辑或重定时，游戏时长、事件和切换条件沿用玩法约束。记录视频有效区间、源时间到游戏时间的映射及输出片段，按[视频节奏整理](./frame-reference-action-timing.md#视频节奏整理)人工验收实际输入后抽帧。图片路线沿用同一设计工件及其自身验收流程。

- **V5 正式游戏验收。** 用同一时间轴核对正式场景中的触发、事件与状态切换；多段攻击覆盖正常接招、未接招、窗口边界及玩法允许的打断。逐条在现有工作项记录正式场景和适用的构建版本、当前动作方案和实际消费的资源版本、复现输入、预期与实际事件顺序及运行证据。由用户在实际镜头、显示尺寸和播放速度下检查可读性和衔接，将视觉结论及消息引用绑定到同一路径和动作版本。仅有素材预览、缺运行证据或缺用户视觉结论时，将对应检查分别标为未验证。

### 来源路线（cocos、phaser、threejs）

用户未指定来源时默认使用视频抽帧，并在内部动作时间轴记录中注明；图片递归补帧仅在用户明确选择或确认切换时启用。沿用当前任务明确选择的来源；来源切换按既有变更边界处理并更新内部记录，不因默认值变化丢弃已确认成果。视频来源或生成能力暂缺时报告缺口，不能自动改用图片路线。两条路线共用分类、游戏时间轴和人工验收，只读取当前来源细节。

选定视频路线时，在 V3 工作项里确定视频提供方及交付物，区分复用现有视频、代理在已有授权内生成，以及用户或项目方提供。需要生成时，先核对拟用工具支持的参考输入、输出规格和关键过渡能力，例如收势是否能使用分岔短片，或能否用相邻帧与运动说明承接。能力不足或需要超出已有授权时，说明缺口及受影响素材，按既有规则决定调整方案或明确交接给提供方。交付提示词后等待外部视频时，将素材标为待提供；收到实际文件后再进入 V4 素材验收。

### 共用流程（cocos、phaser）

视频路线接收真实视频并核对画布、区域和音轨，按需要选择有效区间、阶段重定时并保存派生来源，交付用户人工验收实际最终抽帧输入。原视频已适配时直接验收原视频；只有实际视频内容、区域和时间映射已经人工验收才抽帧，SHA 不参与验收。未通过先修正并重提；修正说明或文字方案不代替新视频验收。图片路线核实实际输出尺寸，固定统一画布并确认首尾；同一连续行为的必要关键帧按时间顺序逐张制作，与真实基线及相邻已确认帧比较，人工确认当前帧后才推进下一关键帧。关键帧齐备并确认后，再按内部推导的时点递归补齐目标帧位。实际依赖与“一致性及衔接门”（见本栈配套资料）集中维护；父图有缺陷先修正，不继续传播。

### 动作设计与真实素材确认（cocos、phaser）

动作分析与时间轴写入内部设计工件，方案完成后主动阐述设计理念与目标感受，暂停等待用户明确确认；确认后才推进素材制作和具体实现。视频路线由用户审阅真实视频候选及完整序列；用户对实际视频的确认可同时接受其中表现的时序。图片路线以真实首尾、关键帧和递归父图逐张确认，再验收完整真实序列。真实序列预览提供播放/暂停、重播和逐帧查看，检查标记只放预览界面。正式美术使用真实基线及已确认素材，设计图表和历史占位示意不得作为生图视觉参考。同目标局部修正直接返修并展示前后对照；目标感受、核心动作方案、玩法语义或来源路线实质变化时须重新确认。详细要求见“动作设计与素材确认”（见本栈配套资料）、“真实素材审阅与验收”（见本栈配套资料）及“设计与美术的边界”（见本栈配套资料）。

### 共用质量与关键约束（cocos、threejs）

- 每个动画的时长与节奏先依据游戏特点、玩法响应、对象性质和表现目的独立确定。同一视频中的多组动画可以有不同总时长、阶段比例、停顿、循环周期和 FPS，不为合批强行统一；具体规划见“游戏时间先于来源”（见本栈配套资料）。游戏时间独立于源视频时长，同一完整行为共享自己的时间轴，内部可标事件和输入衔接；制作分组不增加攻击次数、自动连击或伤害，也不改变现有输入机制。

### 共用质量与关键约束（cocos、phaser、threejs）

- 时间轴推导记录在内部工件；人工确认聚焦真实视频、图片关键帧和完整序列，文件门只验证结构与身份。可采集截图供用户人工检查，未经明确授权不得自动分析截图或代判；不得自动启动真机验收，外部写入、付费、发布沿用独立授权边界。

### 执行代理（cocos、threejs）

同一工作项的连续修正优先复用代理；范围实质变化或工作项完成后结束该生命周期。位图生成/编辑仍交给图片生成代理，动画执行代理提供时间轴、帧槽位和素材约束并集成结果。指定工具或模型不可用时报告限制，不静默换模型。委派不扩大文件、视觉自动验证或外部操作授权。
