# 视觉依赖生产次序

执行公共规则时，同时读取当前技术栈参考中的原生补充和“本栈配套资料”。各段仅适用于标注的技术栈；结构化证据不代替用户对显示效果的人工验收。

本顺序适用于声明视觉依赖的基础包和视觉任务；纯工程基础包可先按当前工作项完成。示例中的确认枚举属于本栈领域视觉合同，不是公共控制器字段；动作及状态按公共规范执行。

各技术栈统一按 V0–V5 推进；V1 先验证功能，白盒可选，V2–V5 依次完成视觉目标、拆解布局、资源导入和运行验收。

## 弹窗工作项与场景解耦

> 适用技术栈：cocos、phaser、threejs。

```text
建立全局视觉基线 brief
  → 生成三张同条件候选效果图并同屏交给人工
  → 人工选择确认一张，写入唯一 SINGLE_HUMAN/CONFIRMED 决定
  → 正式冻结全局静态 visual_baseline（global-static-baseline-frozen）
  → foundation-only：SHARED 最小项目骨架 + MODULE 场景无关基础模块
  → 各场景 Work Item：任务范围与功能规格
  → V2 生成或接收并冻结 scene master/reference target、宿主上下文效果图、视觉合同和初步还原草案
  → V3 先自动生成拆解图与技术 JSON，人工修改并确认最终拆解
  → 依据明确设计参数、用户已确认标注或经明确授权的自动截图分析结果生成双轴对齐决策（截图未经明确授权不得分析；事实不足时标记待定并集中澄清，不得按几何距离猜测），仅消费已确认元素与该决策生成布局图，人工修改并独立确认
  → V3 完成布局确认与合同回对/coverage/生产方案
  → V4 正式资源生产与验收
  → V5 直接消费 V3 拆解与目标布局、V4 正式资源，实施并校准正式 SCENE，完成运行态视觉接入与功能/视觉验收
  → 各弹窗 DISPLAY_LAYER Work Item 独立完成 V2→V3→V4→V5，可与场景按公开接口并行
  → 跨场景 INTEGRATION/联合验收 → 按当前 Work Item 完成集成（受保护副作用按 action.approval 核对）
```
