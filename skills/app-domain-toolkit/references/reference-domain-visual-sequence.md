# 视觉依赖生产次序

执行公共规则时，同时读取当前技术栈参考中的原生补充和“本栈配套资料”。各段仅适用于标注的技术栈；结构化证据不代替用户对显示效果的人工验收。

本顺序适用于声明视觉依赖的基础包和视觉任务；纯工程基础包可先按当前工作项完成。示例中的确认枚举属于本栈领域视觉合同，不是公共控制器字段；动作及状态按公共规范执行。

第 4 阶段依据产品规格确认并冻结全局视觉方向与代表稿。第 5 阶段 V1 确认完整模块方案，V2 基于全局方向生成并确认覆盖模块全部适用状态和进度的设计稿，V3 拆解同一确认稿，V4 准备资源，V5 完整实现与验收。模块稿变更在 V2 更新确认，全局方向变更回第 4 阶段。

## 弹窗工作项与场景解耦

> 本节图片目标、候选图及拆解布局条款适用于图片／UI；世界模型按[内容分流](game-design-exploration.md#implementation-routes)交接，常驻 HUD 仍用原 UI 合同。

> 适用技术栈：cocos、phaser、threejs。

```text
第 4 阶段：SHARED 项目骨架 + MODULE 场景无关基础模块
  → 依据已确认产品和状态规格建立全局视觉基线 brief
  → 生成一张推荐稿，有分歧时再同屏展示同条件对照
  → 人工选择确认一张，写入唯一 SINGLE_HUMAN/CONFIRMED 决定
  → 正式冻结全局静态 visual_baseline（global-static-baseline-frozen）
  → 生成并冻结目标版本全部适用场景、流程和状态的整套视觉目标，覆盖相关弹窗及宿主上下文
  → 第 5 阶段各模块 V1 确认完整方案、状态、进度和验收
  → V2 生成并确认模块全部适用状态和进度稿，分别绑定 scene master/reference target、视觉合同和初步还原草案
  → V3 从 V2 已确认稿生成拆解图与技术 JSON，人工修改并确认最终拆解
  → 依据明确设计参数、用户已确认标注或经明确授权的自动截图分析结果生成双轴对齐决策（截图未经明确授权不得分析；事实不足时标记待定并集中澄清，不得按几何距离猜测），仅消费已确认元素与该决策生成布局图，人工修改并独立确认
  → V3 完成布局确认与合同回对/coverage/生产方案
  → V4 正式资源生产与验收
  → V5 直接消费 V3 拆解与目标布局、V4 正式资源，实施并校准正式 SCENE，完成运行态视觉接入与功能/视觉验收
  → 各弹窗 DISPLAY_LAYER Work Item 消费统一 V2 目标，独立完成 V3→V4→V5，可与场景按公开接口并行
  → 跨场景 INTEGRATION/联合验收 → 按当前 Work Item 完成集成（受保护副作用按 action.approval 核对）
```
