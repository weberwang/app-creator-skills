# 可交互组件结构、命中与输入职责

适用于 Web、原生应用、跨平台框架和游戏引擎，覆盖按钮、链接、卡片、列表项、表单控件及自定义交互区域。具体控件、命中 API 和事件机制以所选技术栈的原生章节为准。

## 操作所有者与命中范围

- 每个操作由一个语义控件统一管理激活、禁用、焦点与状态反馈。优先使用平台或框架提供的语义控件和输入机制。图标、文字、背景、装饰可以分层，纯展示元素默认不独立接收同一操作。多个输入方式可以汇入同一个激活入口，每次有效操作只执行一次。
- 已有控件的命中范围满足平台触控和布局要求时，直接使用该控件。同一操作的视觉、命中和状态反馈能共用节点时按[节点最小化](reference-domain-display-ownership.md#节点最小化)优先合并，确需分开时仍由同一个控件管理。避免叠放同位置、同尺寸且执行同一操作的透明 Input、Hit、Hotspot 或事件层，命中面将输入交给唯一所有者。
- 命中范围可以大于可见图形。小图标、整卡点击、自定义手势或不规则区域按需要使用内边距、原生命中扩展或控件根管理的命中面。保持图形设计尺寸，在布局中标明命中边界、所有者、裁切关系及相邻控件的有效区域。范围按实际布局和输入坐标核对。
- 含独立操作的卡片或列表项使用一个布局宿主组织主操作与收藏、更多等独立语义控件。分别声明命中与焦点入口，子操作区域从主操作的有效命中中排除，明确事件路由，使触发、取消或禁用子操作时都不会误激活主操作。平台或布局合同限制交互目标嵌套时，将这些控件布置在同一个非激活宿主下的不同分支。

## 输入职责与竞争

滚动视口、拖拽层、模态遮罩、手势区域承担独立输入职责时可以单独保留。对重叠区域说明先由谁处理、哪些事件继续传播、何时取消待激活状态及如何恢复焦点。滚动或拖拽接管后取消候选点击，释放或取消时清理捕获和临时反馈。模态覆盖阻断下层适用的指针、键盘及焦点输入，关闭后按现有约定恢复。

## 审查、迁移与验收

- 在现有规格和正式源中核对命中配置、事件绑定、焦点导航、状态反馈、生成器和测试引用。确认旧输入节点已无独立职责，核对并迁移消费者后清理。由模板或生成器产出的结构同步更新制作源、正式资产和相关验证，确保重新生成仍得到同一结果。
- 按项目支持的平台及触控、鼠标、键盘、手柄等输入方式验证中心与边缘命中、相邻控件隔离、单次激活、禁用、焦点和状态反馈，并覆盖适用的滚动、拖拽、取消和模态交互。适用时检查无障碍名称、角色、状态、焦点顺序及目标平台要求的最小触控范围。
- 沿用[公共显示结构和节点最小化](reference-domain-display-ownership.md#节点最小化)。V3 在现有拆解和布局中记录所有者、命中范围及竞争规则，V5 对照已确认的结构验证真实运行输入。视觉验收按[现有验证与交付流程](../../app-creator-workflow/references/verification.md)执行。

## 示例

- 普通图标按钮：使用现有按钮范围接收输入，图标负责显示，按钮统一提供名称、焦点、禁用和激活。
- 小图标扩大触控范围：保留图标尺寸，以按钮内边距扩大可点范围，核对边缘及相邻按钮仍能独立命中。
- 含独立操作的卡片：卡片宿主承载详情入口和收藏按钮。详情覆盖卡片内容的有效区域，收藏区域独立命中和聚焦，点击收藏只更新收藏状态。
