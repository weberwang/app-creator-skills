## 工作流接入

> 适用技术栈：cocos、phaser、threejs、unity。

在现有 GDD、场景规格或 `visual-design.md` 中按[界面文案通用原则：规格与交接](ui-copy-principles.md#规格与交接)区分和交接内部规格与玩家可见表达，不另建审批门。先按[无文字意图可读性](../../app-asset-workflow/references/interface-intent.md)完成“判断 → 场景线索 → 行动 → 反馈 → 尚需精确信息”，每项文字说明它补充的缺口；保留必要金额、数量、错误、确认文案与无障碍语义。白模中的调试标签、阶段说明、任务解释与临时操作提示不自动进入正式稿。

> 适用技术栈：cocos、phaser、threejs。

例如内部规格可以解释金币结算规则；玩家可见表达只交接「金币图标 + 本次收益（带正号）」及数据来源。效果图采用代表值 `+100`，实现读取真实收益，不把规则段落变成奖励提示。

## 效果图生成

> 适用技术栈：cocos、phaser、threejs、unity。

适用路线的全局候选、场景主效果图和弹窗宿主上下文图在生成前都读取同一份玩家可见表达，并按[生图文案约束](../../app-asset-workflow/references/style-and-production.md#生图文案约束)将当前状态的可见内容及绘制限制写入实际发送的提示词。所有候选使用相同内容与示例数值，按[视觉语言定义](../../app-asset-workflow/references/style-and-production.md#三候选选择)各自完整描述形体、比例、材质、明暗边缘、功能色、UI 图标及制作路线，不因共用内容而锁死同一种造型。候选数量沿用当前路线，不由本节新增。

> 适用技术栈：cocos、phaser、threejs。

实际发送的提示词必须包含以下约束，并填入当前场景/状态对应的可见内容：

> 适用技术栈：cocos、phaser、threejs、unity。

```text
按已交接的信息链，以场景、物件、角色动作、空间关系与状态反馈表达玩法。白模调试标签不进入画面。
位置相关信息按已定义的世界物件、地面区域、角色附属、场景浮层或屏幕HUD承载，遵守承载面、朝向、空间归属、触发范围和显示状态；贴地付款区与地面共享透视并联系待解锁区，不替换为悬浮牌或屏幕卡片。
本图只表现指定状态的代表瞬间，按状态决定元素显隐；自动作业不显示暗示反复点击的常驻动作按钮。进度优先通过对象、覆盖范围、剩余目标和结果表达，仅按指定缺口绘制进度条或说明。
逻辑地块和网格仅在玩法需要辨格时显式呈现，不为解释功能增加无关建筑、NPC、按钮、装饰或机制。
```

> 适用技术栈：cocos、phaser、threejs、unity。

在生成记录或内部交接中注明可见内容的现有文件/章节来源，实际提示词写入已解析的画面事实、承载位置、代表状态及允许文案，不把内部路径作为画面文字。生成记录按现有字段保存完整实际提示词，不增设 Schema 字段。上述约束按任务适用性填写，单图标不机械携带整场扩建示例。先确定最小表达，再安排文字与布局；不要生成满屏说明后再压缩字号。是否实际画对由用户看图确认，提示词含有约束不代表画面通过；动态行为仍须按方案交接并在实现后验证。

## 资源拆解与界面实现

> 适用技术栈：cocos、phaser、threejs、unity。

冻结效果图之后，文本拆解只登记目标中实际存在的玩家可见文字与数值，不从 GDD 追加说明节点。原子资源提示词继续忠实还原所属区域，不能把全局效果图的文案精简规则当作删除冻结文字的指令；图标、皮肤不附加业务说明，动态数值不烘焙进固定图片。

> 适用技术栈：cocos、phaser、threejs。

V4 按 V3 确认的可见表达还原文字，并与同一状态的视觉资源一起试装。V5 在正式界面复验该还原结果。`text_decomposition` 的 `content/source` 指向实际显示内容与来源；`node_presentations[layout_node_id].text` 填入对应短标签或代表性数值，不填业务描述。运行时文字组件、本地化键和动态更新读取同一表达与真实数据，不能直接绑定 GDD/brief 的描述、设计理由或验收字段。此规则覆盖按钮、HUD、弹窗、Toast 和奖励浮字；普通资产和无效果图路径同样适用。

> 适用技术栈：cocos、phaser、threejs。

本地化保留相同表达与显示条件，不把符号重新扩写成解释句。`longest_copy` 和长文案测试使用实际必要文案的最长翻译或边界输入验证适配，不要求给正式画面添加说明段落。编辑器操作、拆解标注与内部审阅说明不属于游戏内文案。

## 检查与返修

> 适用技术栈：cocos、phaser、threejs、unity。

生成前核对实际提示词中的可见内容与内部规格分离；实现时核对文本配置、绑定来源与适用状态，不以字数、关键词或 `copy_style` 字段判定语义合格。

> 适用技术栈：cocos、phaser、threejs、unity。

候选效果图冻结前及 V5 正式运行时，按[最少必要文字](ui-copy-principles.md#最少必要文字)提供实际画面和人工检查点，并核对画面是否误用内部规格、数值是否归属明确。显示效果由用户人工确认，代理不得自动分析截图或替用户填通过；复用原有确认节点，不增加独立文案确认。

> 适用技术栈：cocos、phaser、threejs、unity。

已冻结参考中的文字不擅自删改。用户指出标签多或操作难懂时，先检查信息链、承载位置和状态反馈的共同原因，再按当前授权范围修订目标、方案与提示词，不只删除点名的几个词。保留已认可的视角、玩法和空间关系，再继续拆解或实现；只有存在实质未决取舍才询问。不靠隐藏文字、缩小字号或烘焙整屏掩盖问题。
