# 显示元素的编辑器还原

适用技术栈：Unity、Cocos Creator。Phaser、Three.js、Flutter 不因本规范被要求建立引擎编辑器场景；项目明确采用其他可视化编辑器时，按其实际源资产和保存机制落实相同职责。

## 编辑器还原

- 编辑器中新增元素同样遵循[增量显示约束](reference-domain-display-ownership.md#新增显示元素的增量约束)，将真实父级、定位参照、锚点/对齐、尺寸策略及层序保存到正式源；节点可见或已保存不等于满足布局要求。
- 新增显示元素必须同步还原到编辑器可查看、可选择和可调整的正式场景、预制体或原生 UI 源文件中，包括文字、图标、按钮、HUD、弹窗、场景实体、装饰和特效。要求覆盖新项目、既有工程增量、普通组件及复用素材，不限于效果图还原或 V3 已有节点。
- 不得只在运行代码、Play Mode、临时对象或截图中显示新增内容，退出运行后编辑器中的正式场景不能仍缺少对应结构、模板或挂载关系。脚本可辅助制作，但其正式结果必须按本栈方式保存并回读。
- 编辑器源与运行实现共用同一套资源、组件、层级、布局约束和生成配置；编辑器调整应能作用于正式运行。不另建只供展示的假场景、独立预览布局或手写快照来代替真实可编辑源，也不把整屏截图当作元素还原。

## 编辑器位置关系的控制权

- 编辑器正式源中设定的位置、父子关系、锚点、对齐、布局参照、间距及相关尺寸约束是运行布局的依据。没有明确功能需要时，禁止业务脚本在初始化、启用、刷新、逐帧更新或尺寸变化回调中重设这些关系，也不得通过更换父级、修改祖先变换或附加偏移间接覆盖。
- 固定排版和静态外观调整回到编辑器正式源中修改、保存并回读；不能用“运行时校正”“保险重置”或硬编码坐标覆盖编辑器结果。业务代码不维护第二套布局常量，不让编辑器调整在运行后失效。
- 功能性修改仅限明确需求所需的行为，例如拖拽、移动、滚动、跟随、布局状态切换或过渡动画。在已有规格或任务包中说明功能依据、受控节点、允许修改的属性、触发条件、范围及结束后的保持/恢复策略；实现只控制必要属性，复杂分支用中文注释解释原因。仅添加“功能需要”的标签不能作为依据。
- 编辑器已配置的原生布局、锚点、安全区及内容自适应系统按原约束计算位置，属于执行既有规则；程序新增或改写规则仍须有上述功能依据。功能实现读取正式配置和当前有效基准，不重复硬编码静态落位；动画或临时偏移结束后按约定恢复，避免累计漂移或与布局系统争抢同一属性。
- 验证时核对位置写入点、调用时机及功能依据，并在本次允许修改的范围内调整编辑器配置、保存回读后验证运行实例确实消费新配置。覆盖初始化、重新启用和相关刷新路径；功能性修改另验证触发范围与结束状态。不得以程序重置掩盖配置未生效，显示效果仍由用户人工检查。

## 动态元素

- 动态列表、对象池、运行时弹窗、程序生成图形、Shader 和粒子仍可按实际状态创建、更新和销毁；同时必须交付同源的可编辑模板或生成配置、实际宿主挂载点，以及编辑态可查看和调整的代表性布局或状态预览。仅保存一个无可见内容的空宿主或仅提供截图不算还原。
- 运行实例消费这些正式模板和配置，不在业务脚本中再硬编码另一套外观与布局；无需把全部动态实例、真实用户数据或整段运行快照永久写入场景。编辑预览使用明确样例数据，与正式业务状态隔离，清理临时实例和监听器。
- 编辑态预览不得触发真实 SDK 初始化、网络请求、广告、支付、奖励发放或持久化业务写入。不为查看显示内容要求先进入正式业务流程；程序化显示路线仍保留原合同，编辑器模板或配置不因此被误记为生成位图资产。

## 保存与交付

1. 列出新增元素对应的正式源资产、层级或模板节点、资源引用、宿主绑定和编辑预览方式；动态元素注明样例状态及运行实例的配置来源，沿用现有规格和交付记录，不新增独立审批门或第二套节点树。
2. 通过本栈编辑器或受支持的原生工具创建、修改和保存资产，保留原生资源身份、引用与单写者约束。不能直接手写引擎序列化文件，也不能把运行态临时修改当作已保存结果。
3. 保存后重新打开或通过编辑器回读，核对真实节点、组件、布局、资源引用及挂载关系；确认退出运行或重载后仍可编辑。运行时另外验证数据变化、动态生成、布局与交互，不能用编辑器结构存在代替运行验证。
4. 提交实际资产路径、回读结果、编辑预览操作和未还原项。需要截图时提供编辑态与运行态资料及检查要点，显示效果由用户人工确认；截图采集、结构回读和构建成功均不代表视觉验收通过。缺少编辑器环境或未完成保存回读时明确标记未验证。

编辑器源回读支持“结构完成”结论；运行布局及交互检查支持“工程通过”；只有用户对实际组合画面人工确认才可记为“视觉通过”。各结论的适用范围与未验证项按[验证与交付](../../app-creator-workflow/references/verification.md#三类验收结论)分别报告，画面受后续修改影响时重新确认受影响范围。
