# AdMob 顶层聚合约定

本约定适用于 Android/iOS 明确选择 AdMob 聚合的项目。复用[移动 SDK 实现](mobile-sdk-integration.md)，不得加载 MAX 专属模式、MAX 固定七网络清单或同时初始化第二个聚合。

所有广告遵守[SDK 不阻塞应用流程](reference-architecture-sdk-initialization.md#sdk-不阻塞应用流程)：初始化和预加载后台执行，展示只尝试当前可用广告；受限、未就绪、失败或取消立即继续正常玩法，不能排队等待授权、加载或奖励回调，也不能拦住关卡和结算。

- 使用引擎对应的 Google Mobile Ads SDK 或已经核实的原生插件；网络 adapter、版本、App ID、广告位和后台配置按 [Google 官方聚合说明](https://developers.google.com/admob/android/mediation)核实。不能将添加客户端广告位视为已配置聚合。
- 初始化可能触发预加载，初始化授权和全部已启用网络的请求设置须先满足。每次 Google 广告请求启用非个性化参数；其他网络按各自官方参数落实，不能仅凭 `npa=1` 声称全部聚合请求符合要求。复用项目已有授权来源与官方要求的 CMP，不自动增建隐私业务。
- 插屏、激励与 Banner 分别配置 Android/iOS 广告位。先加载再展示，未就绪、无填充、超时与失败立即回退，不阻塞玩法。仅真实奖励回调发奖，关闭不是奖励，重复和迟到回调必须关联原请求并去重。
- Banner 显示前检查安全覆盖区域，动态内容进入该区域时隐藏，不遮挡操作、HUD 或有效内容；不要为广告缩小游戏画面或增加空白占位。
- 模块测试覆盖请求配置、初始化幂等、失败隔离、奖励关联和释放；真实依赖编译与明确授权的平台验收单独记录。使用官方测试广告，不自动写入正式账户或发布配置。
