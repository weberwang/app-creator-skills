# 系统启动屏制作与交付

在 Android、iOS/iPadOS 客户端新建基础工程，或修改启动配置、应用图标、主题和首帧衔接时读取。适用于游戏和非游戏 App，按目标操作系统实施；不因采用 Unity、Cocos、Phaser、Three.js、Flutter 或 Expo 而另建一套系统启动屏。

## 范围与归属

系统启动屏是操作系统在应用尚未绘制首帧时显示的原生画面。它不是品牌开场、引导页、隐私页面、登录页或应用内加载页，也不属于场景/页面/弹出层的全局加载显示层。Unity 内建 Splash 是引擎画面，不是系统启动屏；只在本任务检查两者衔接，不默认新增品牌开场或更改引擎许可标识。

只处理已选的 Android、iOS/iPadOS 目标。纯 Web、桌面、小游戏、ESP32 GUI 与 Node.js 服务不自动创建移动系统启动屏；宿主有独立要求时再按其实际能力处理。使用当前基础工程的 SHARED/MODULE 范围及已有技术设计、平台清单和证据，不为系统启动屏另建 PAGE/DISPLAY_LAYER、V2/V3 视觉生产门或确认账本。

原生方案按项目实际路线分流：Cocos 使用 Creator 自身的原生构建与工程配置，不套用 Capacitor/WebView；Phaser、Three.js 等 Web 应用只有在明确选择移动宿主时才按下文封装原生规则处理。Unity、Flutter、Expo 沿各自原生工程配置，不能为了统一启动屏换一条打包路线。

## 内容与制作

先读取已确定的应用身份、图标、主题与实际首屏，复用其正式素材和配置，不把“Logo＋文本”作为跨平台默认模板。

### 制作输入与资源交付

基础工程开始时，在现有技术设计或资源清单中确定目标 Android API、iOS/iPadOS 版本、引擎或宿主版本、已支持方向、明暗模式、应用标识、正式图标和首屏背景。项目已有的品牌、颜色与正式素材直接引用，首屏尚未完成时先以已确定的最小稳定首帧为衔接目标，后续首屏变化再检查影响。

| 制作项 | 制作与交付要求 |
| --- | --- |
| 设计依据 | 记录本平台启动画面的组成、背景颜色、图标或固定元素、尺寸参照、裁切范围及与首帧的交接。预览用于说明目标，交付包含实际可消费的原生资源和配置 |
| Android 资源 | 依据当前图标与平台蒙版确定主体安全区域，分别准备适用的图标前景、背景或动画资源及窗口颜色。按目标平台和宿主支持导出 drawable、mipmap 等实际资源及所需密度变体，记录图标背景与品牌图的适用性 |
| iOS/iPadOS 资源 | 按实际首屏制作静态背景和允许的固定元素，使用 Asset Catalog 及实际 launch screen 配置或 storyboard，按目标工程维护缩放、布局和明暗模式。背景为纯色时直接使用颜色配置 |
| 制作源与许可 | 保留所用图标、必要品牌图的可编辑源、来源和许可，以及导出到正式资源的对应关系。矢量图形沿用可编辑矢量源，生成或编辑位图时使用现有图片制作技能与委派规则 |
| 原生配置来源 | 明确正式维护入口和最终消费路径，包括原生主题、资源、Manifest、launch screen 或既有生成器配置。重新生成或构建后回读结果，确认资源引用与当前制作输入一致 |

制作时先用少量代表资源接入实际原生配置，核对图标蒙版、透明边缘、缩放和背景衔接，再完成其他适用变体。Android 与 iOS/iPadOS 各自按下表制作，尺寸与文件格式以目标版本及现有原生工具的真实合同为准。图片生产结果保留制作源，导出文件放入实际平台资源链，资源身份和移动操作遵守所属引擎的正式导入规则。

交付在现有材料中关联“制作输入与源文件 → 平台导出及配置 → 当前原生候选 → 工程检查与人工显示确认”。修改图标、主题、方向、原生生成配置或首屏背景后，检查受影响平台与变体，定向重制、重新构建并复验相关衔接。制作本身在基础工程范围推进，画面检查沿用现有人工验收。

| 平台 | 内容与资源要求 |
| --- | --- |
| Android | 以应用图标和单色不透明窗口背景为基础；图标背景、品牌图和短动画按需采用，遵守目标 API 的裁切、安全区域及资源格式，不把任意整屏效果图当作 Android 12+ 系统启动屏背景。默认不新增文本内容；既有品牌标准字如确需保留，按平台品牌图能力制作，不额外叠加重复产品名。 |
| iOS/iPadOS | 接近实际首屏的背景与固定结构，匹配当前方向和系统明暗模式；避免文字，不承担广告或品牌介绍。Logo 仅在实际首屏固定包含时沿用，不能照搬 Android 的居中图标方案。使用目标工程已有的原生 launch screen 配置或 storyboard。 |

- 系统启动屏不放宣传语、版本号、加载进度、交互按钮或首次使用说明；这些内容属于相应的应用内功能，不能通过保持启动屏展示来实现。
- 所需图标、颜色及适用品牌资源必须本地随包可用，不依赖网络、远程配置、运行时字体加载、业务资源缓存或尚未完成的场景加载服务。按项目原生资源目录保存，源图与平台生成配置的唯一维护位置须明确。
- 核对深浅主题、屏幕尺寸、已支持的方向、图标裁切、透明边缘和背景对比；不通过拉伸 Logo 适配屏幕。Android 可选图标动画应简短且可自然提前结束；官方建议手机上的图标动画不超过 1000ms，该值不是必须展示的时长，也不是应用总启动时限。
- 优先沿用现有配置和官方现成能力；只有工具覆盖存在真实缺口时才选插件或最小自研，不为修改启动背景安装整套启动框架。

## 首帧衔接与加载边界

1. 原生启动配置、正常运行主题与首个稳定画面的背景、明暗及窗口状态相衔接，避免重复 Logo、黑白闪屏、异常标题栏和布局跳动。平台自动出现或跳过系统启动屏的行为按实际生命周期处理，不在每次热恢复时重新播放应用自制启动页。
2. 首个稳定画面可显示时结束原生启动承接，不设置凑展示时长的固定等待，不为播完动画延迟可用内容，也不等待全部 SDK、广告就绪或网络数据。SDK 仍遵循其[真实官方前置与失败隔离](reference-architecture-sdk-initialization.md)，单项受限不扩张为全应用启动屏障。
3. 首帧之后仍需等待的数据、登录判定或场景资源，由应用内真实加载、错误与恢复状态承接；需要全局加载显示时复用[场景与弹出层加载](reference-domain-display-ownership.md#场景与弹出层统一加载)。系统启动屏不显示伪进度，也不无限延长来掩盖无响应。
4. Unity 检查原生启动屏、引擎 Splash 与首场景的连续性，按项目锁定引擎版本、平台和许可决定引擎画面配置；Editor/Game View 看不到原生系统启动链路，不能据此判断已通过。Flutter 的首个 Widget 页面不能替代 Android 原生启动主题或 iOS launch screen；如使用资源生成工具，核对实际修改的主题、Manifest、storyboard 和资源，避免手工配置与生成器互相覆盖。

## Web 封装原生的启动衔接

本节适用于已经选择 Android、iOS/iPadOS 宿主的 Web 应用，包括 Phaser、Three.js 的现有 Capacitor 路线；其他宿主按锁定版本的官方能力核对，不为启动屏迁移宿主、额外安装插件或给纯浏览器项目创建原生工程。

1. 明确宿主版本、Web 生产构建命令、实际输出与 `webDir`（或对应字段）、copy/sync 与原生构建入口。核对“Web 生产输出 → 宿主资源同步 → 原生制品”的真实消费链，入口 HTML、脚本、字体、媒体及首屏必需本地资源须已进入当前包；开发服务器可访问、Web 构建成功或同步完成各自不能代替原生构建和启动验证。生产候选不得无意依赖开发服务器地址。
2. 启动主题、图标、iOS launch screen 和 WebView 初始背景由实际原生工程维护，HTML/body、Canvas/WebGL 首屏背景按同一目标衔接。复制 Web 页面或额外 Logo HTML 不能替代系统启动屏；CSS 背景也不能覆盖原生窗口尚未显示 Web 内容的时段。系统屏、宿主/插件过渡层和 Web 加载视图各自只有一个所有者，存在中间承接时明确交接，不新增重复品牌页。
3. 宿主首帧不等于 Web 内容首帧。首屏就绪依据为必要本地资源和显示初始化完成、DOM/Canvas/WebGL 已呈现稳定画面；`DOMContentLoaded`、桥接可用、渲染器创建或请求受理不能单独当作已显示。仅当现有宿主确需显式交接时，由平台适配层消费该有效信号，按其真实接口管理过渡层，应用入口只负责装配，不在多个场景重复关闭或重播启动画面。
4. 按锁定宿主/插件版本核对自动隐藏、手动关闭和重入行为；不照搬统一的固定秒数，不为等待全部 SDK、广告或网络数据长期保持系统屏/过渡层。Web 初始化失败、必需资源缺失或就绪信号丢失时保留有界故障出口，交给实际宿主错误/恢复状态，不无限遮挡、循环启动或暴露不可交互的空白画面；失败不得伪装成首屏就绪。
   Capacitor 程序调用 `SplashScreen.show()` 的显示路径不等同于系统启动屏；Android 12+ 启动路径并不支持所有插件外观参数，须核对原生主题与当前版本能力。若采用手动关闭，Web 脚本/桥接失败而无法发出关闭信号时也须有可恢复出口，超时只能触发失败处理，不能冒充画面已就绪。
5. 同步或生成原生工程后回读有效主题、Manifest、launch screen、资源与实际加载入口。配置保存在项目源配置或可重复的生成/扩展机制中，不能只修改会被覆盖的生成目录。最终包同时核对本地 Web 资源与原生资源；浏览器预览不能证明原生启动衔接通过，授权范围内的实际运行和用户显示检查仍分别记录。

## Creator 原生构建的启动衔接

Cocos 的 Android/iOS 目标通过项目锁定 Creator 版本自己的原生构建生成平台制品。按实际项目配置、该版本支持的构建模板/扩展或原生源工程维护系统启动资源，核对重新构建后的有效结果；不引入 Web `webDir`、Capacitor copy/sync 或 WebView 就绪判据。系统画面、Creator 适用的引擎启动画面与首场景分开识别，原生渲染稳定首帧才是内容衔接依据；Creator Web 预览与构建面板就绪不证明原生运行通过。

## Expo 原生构建的启动衔接

Expo 的 Android/iOS 使用实际原生启动资源，遵守上文各平台内容要求，不套用 WebView 的 `webDir` 或 DOM 就绪判据。采用 `expo-splash-screen` 时按锁定 SDK 和已有 config plugin 配置维护本地素材；CNG 将应用配置与插件作为正式来源，直接维护原生工程的项目同时核对实际主题与 launch screen，避免下次生成覆盖。

首个 React Native 稳定画面就绪后交接，若使用显式隐藏则只由应用启动所有者调用，并处理必要字体或本地资源失败；不等待所有 SDK、广告或远程数据，不为品牌展示延时。Expo Go 与 development build 不能完整证明最终启动屏，最终显示在对应 release build 上采集材料交用户检查；未运行时保留未验证，不为验收自动启动设备、云模拟器或付费构建。

## 任务安排与完成条件

新项目在基础工程阶段安排；已有项目仅改受影响平台与衔接。按现有三项最小约定记录，默认当前执行者负责；有协作时再划分品牌素材、原生配置和验证的写入所有权，不另加必填表单。

| 任务 | 改哪里与交付 | 怎样算完成 |
| --- | --- | --- |
| 设计与制作平台资源 | 按[制作输入与资源交付](#制作输入与资源交付)记录设计依据、正式源、平台变体、颜色及导出位置 | 资源与应用身份和首帧目标一致，所需变体完整，原生消费路径与制作源可追溯 |
| 配置平台启动屏 | 已选平台的实际原生主题/launch screen、图标及所需本地资源，既有技术设计中记录路径和配置来源 | 按 Android/iOS 内容规则实施，配置与打包资源可解析，目标平台和深浅主题来源明确 |
| 接通首帧衔接 | 现有启动入口、运行主题及必要的首帧交接逻辑，各栈按原生构建或 Web 宿主实际路线补充 | 无人为停留或全 SDK/网络屏障；慢加载和失败由真实应用状态接管，无重复自制启动入口 |
| 验证与人工检查 | 实际平台构建/资源检查命令、绑定候选的结果与适用运行材料；路径沿原生输出及证据合同 | 工程检查和用户显示确认分别记录，未执行的平台或运行场景明确未验证，不用模板/计划代替结果 |

按改动推荐并自动执行适用的本地测试等级，检查主题/资源引用和必要平台构建；涉及真实原生运行时，仅在已有明确授权范围内覆盖冷启动、暖启动及热恢复、启动到首帧切换、已支持方向和明暗模式。截图/录屏可生成后交用户检查图标裁切、背景、重复开场、闪屏与跳动，代理不自动分析或代填视觉通过。无原生宿主或设备条件时记录缺口，不自动启动真机；源码、构建、Editor 预览通过均不等于原生启动显示通过。

发布候选只复核当前制品所含的配置、资源与有效证据；输入未变时复用既有结果，不为发布准备重复生成素材、重新审批或自动真机验收。系统启动屏资源不因独立于场景而遗漏提交或打包，已绑定证据不随清理删除。

## 官方依据

Android 与 Apple 内容及制作边界于 2026-11-12 核对，实际执行时按目标版本复核资源规格；其余技术栈接口按项目锁定版本读取。

- [Android Splash screens](https://developer.android.com/develop/ui/views/launch/splash-screen)：系统画面组成、资源与动画边界。
- [Android 启动屏迁移](https://developer.android.com/develop/ui/views/launch/splash-screen/migrate)：避免系统启动屏与自定义 Activity 重复。
- [Apple Launching](https://developer.apple.com/design/human-interface-guidelines/launching)：系统启动画面接近首屏，避免文字与额外品牌展示。
- [Unity Splash Screen](https://docs.unity3d.com/6000.1/Documentation/Manual/class-PlayerSettingsSplashScreen.html)：引擎 Splash 与自制首场景的区别；执行时核对实际锁定版本。
- [Flutter Android 启动屏](https://docs.flutter.dev/platform-integration/android/splash-screen)、[Flutter iOS 启动屏](https://docs.flutter.dev/platform-integration/ios/launch-screen)：原生宿主配置与框架首帧的衔接。
- [Expo SplashScreen](https://docs.expo.dev/versions/latest/sdk/splash-screen/)：原生启动屏的配置、首帧交接与 release build 验证边界，执行时核对项目锁定 SDK。
- [Capacitor Splash Screen](https://capacitorjs.com/docs/apis/splash-screen)、[构建与同步](https://capacitorjs.com/docs/basics/workflow)、[配置](https://capacitorjs.com/docs/config)：系统启动与程序显示路径、版本适用配置，以及 Web 资源到原生工程的消费链；执行时核对项目锁定版本。
