# 从玩法与意图推导动作设计

在动作分析阶段读取本文件，将结论写入既有时间轴设计工件。四类动画和两条来源路线共用此方法；类型相关的运动与造型仍读取对应分类参考；职业分配、混合任务所有权和跨类型交接见 [SKILL.md 执行代理](../../../../app-stack-threejs/references/native-contracts.md#mode-threejs-frame-animation--执行代理)。以下流程综合动画原理和开发实践，不是能自动算出最佳时长的公式；当前动作方案须按下述流程向用户说明并取得确认，不另建报告或 schema。

## 先建立设计依据

> 通用工作流步骤见[完整规范](../../../../app-domain-toolkit/references/frame-reference-intent-driven-design.md#先建立设计依据)。

| 依据 | 需要说明的内容 |
| --- | --- |
| 玩法作用与观看者 | 谁触发、谁观察、玩家应理解什么、是否需要立即操作或应对；装饰动画也说明服务的环境或情绪目的 |
| 表现意图 | 要表达的性质及可观察手段，例如敏捷对应快速响应与释放，沉重对应承重和惯性，危险对应清楚的准备与方向；不只写“流畅、有力、好看” |
| 玩法时间约束 | 读取当前输入、状态、伤害、交互或 UI 合同，记录首次反馈、生效、已定义的取消/衔接窗口和结束条件；不适用项省略，未定义项标待确定 |
| 视觉与运动依据 | 当前真实美术基线、参考运动和类型规则，以及哪些运动规律或夸张手段适用于此对象；参考时长不自动等于游戏时长 |
| 职业与协作 | 指定普通动画、角色、特效或 UI 动效设计职责；混合任务按可独立设计的动画/区域划分所有权，记录事件时点、锚点、依赖及版本交接，见 [SKILL.md 执行代理](../../../../app-stack-threejs/references/native-contracts.md#mode-threejs-frame-animation--执行代理) |
| 资源预算与目标平台 | 已有目标平台、显示尺寸、下载/解码/纹理驻留和并发绘制预算；标明实测、估算与未知项，不自造阈值 |

> 通用工作流步骤见[完整规范](../../../../app-domain-toolkit/references/frame-reference-intent-driven-design.md#先建立设计依据)。

## 从关键事件推导时间轴

1. **确定必须读懂的状态。** 围绕玩法作用选择初态、关键变化、事件姿态和终态；攻击可使用准备、释放与收势，机关可使用解锁、展开与就位，UI 可使用响应、结果与退出。只采用实际需要的阶段，不把攻击阶段模板套给所有类型。
2. 通用工作流步骤见[完整规范](../../../../app-domain-toolkit/references/frame-reference-intent-driven-design.md#从关键事件推导时间轴)。

## 方案完成后阐述设计理念

动作方案设计好后、开始制作真实素材前，主动用简短中文向用户说明设计理念，不等用户追问。单个动画说明希望带来的感受和最关键的动作依据；多个动画可合并共同方向，但要逐项指出各自的表演亮点。详细阶段表留在内部工件，说明只保留用户判断方案所需的信息：

- **目标感受与作用。** 说明希望玩家感到什么，以及这种感受如何服务当前角色、场景或交互目的。
- **动作与感受的因果。** 点出关键姿态、重心、轨迹、速度变化、停顿、跟随或收尾如何形成目标感受，只解释当前方案实际采用的手段。
- **节奏与资源取舍。** 简要说明时长、FPS、尺寸、区域时序或预算怎样支持关键表现；指出已知限制、估算与未验证项，不把技术参数堆成方案说明。
- **观看重点。** 提醒用户方案确认后审看真实素材时最值得留意的表现，例如关键状态是否清楚、事件与峰值是否对齐、动作连接是否成立。

设计理念与当前方案版本保存在既有设计工件。说明后暂停等待用户明确确认方案；确认范围和版本也写入工件。确认前不编写正式提示词、不生成真实候选或调用图像生成。已获素材生成授权、沉默、等待时间或开始处理其它工作都不能代替当前方案确认。确认后再制作，实际视频、图片首尾/关键帧/递归父图与完整序列仍各按来源路线人工验收。已确认目标内的小幅修正无需重新确认方案；若调整目标感受或核心动作方案，先更新说明并重新确认。

## 带入现有阶段与交接

| 工作流位置 | 如何消费设计依据 |
| --- | --- |
| V2 动作分析与时间轴记录 | 在内部工件保存玩法目的、表现意图、时间约束、推导理由、阶段表和检查点；方案完成后向用户说明设计理念并等待当前方案明确确认；不可推导且影响玩法的条件须先澄清 |
| V3 提示词与真实素材制作 | 用户确认当前动作方案后，把意图翻译成可执行提示词并在已有操作授权内制作真实候选：何时进入何种姿态、怎样加减速、何时出现事件、如何保持或结束；视频逐区域安排独立有效区间，图片按关键姿态与目标槽位制作 |
| V3 真实素材人工验收 | 方案确认后展示真实候选/预览和简短检查点，由用户先完整观看目标感受、节奏与表演亮点，再检查关键状态、事件和阶段连接，记录具体结论；视频素材确认可同时认可其实际时序，但不替代先前的方案确认；文件门或总帧数不能证明意图达成 |
| V4 ThreeJS 接入与验证 | 核对实际播放率、触发、事件和既有切换机制，确认运行时没有加入额外等待或把装饰运动变成输入锁定；视觉显示仍由用户人工检查，运行测试按工作项等级执行 |

验收依据复用当前工件，分别保留设计意图、用户对当前方案的确认版本、结构/时序核对和真实素材人工观察结论。反馈要能定位到阶段或事件，例如“输入后没有可见响应”“预告方向看不清”“峰值晚于生效”“收势被截断”，而非只有“节奏不对”。

返修按问题归因：阶段长度或事件错位修时间映射；姿态、轨迹或幅度不足修关键帧和相邻过渡；运行时额外等待修接入逻辑。同一已确认目标下的纠错直接返修并展示前后对照，更新内部时间轴记录；目标感受、核心动作方案、玩法语义或来源路线实质变化时重新说明并确认。实际素材变化仍按来源路线重新人工验收。
