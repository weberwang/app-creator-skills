## 制作与优化判断

- 通用工作流步骤见[完整规范](../../../../app-domain-toolkit/references/frame-reference-ui-frame-animation.md#制作与优化判断)。
- **让反馈及时且可区分。** 用户触发后，视觉变化应能清楚表明当前状态；相邻状态在实际尺寸下容易区分，但不以高频闪烁或大幅跳动制造响应感。响应时序依现有交互合同和视觉基线决定，不设通用固定时长。
- **保护信息可读性。** 图标语义、提示文字和按钮标签在动画过程中仍应清晰；逐帧图形不能遮挡文字、降低关键对比或让装饰成为主要信息。若变化会损害小尺寸辨识度，简化细节或将反馈交回适合的程序动效路线。
- **稳定布局与点击语义。** 帧图的轮廓变化或透明边距不能让按钮看似移动、缩放命中区域或改变相邻控件间距。锚点、布局框和实际点击边界按现有 UI 合同保持；动画外观不代表命中区本身变化。
- 通用工作流步骤见[完整规范](../../../../app-domain-toolkit/references/frame-reference-ui-frame-animation.md#制作与优化判断)。

## 人工验收重点

1. **交互响应：** 按照已有控件状态逐项触发，确认反馈出现在正确状态，能及时表达按下、焦点、禁用或提示变化，并在状态退出后结束、隐藏或恢复。
2. **状态辨识与可读性：** 在产品实际尺寸、主题背景和文本组合下检查图标与提示含义；文字、对比和关键轮廓在整个播放期间保持清晰，没有装饰性闪烁干扰阅读。
3. **布局与点击边界：** 动画各帧没有可见跳位、裁切或侵入相邻控件；按钮视觉变化没有让用户误判布局或点击区域，实际命中范围仍由既有 UI 合同控制。
4. **取消与切换：** 快速离开、重新进入、失去焦点、取消输入或切换到禁用状态时，检查旧反馈不会继续播放或覆盖新状态。行为以现有交互约定为准，未定义的边界记为问题。
5. **播放方式：** 循环状态跨周期检查接缝和视觉疲劳；单次反馈检查结束态和恢复/隐藏。单纯变换是否应走程序动效路线也应在验收中复核。
