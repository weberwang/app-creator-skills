# Flutter 资产与视觉质量

## 制定产品辨识度

定义页面所服务的真实目标用户和主要动作，再确定一个可被复述的产品视觉签名：字体、色彩、编排、图像材质和一个可识别页面瞬间。综合用户信任要求、品牌方向与页面任务配置视觉表达强度，避免两个反面的问题：随意堆叠对比渐变、玻璃卡片、随机图表和填充头像，或过度只用平台默认组件让产品完全没有个性。

装饰应该强化信息层次、反馈、叙事或产品性格。高级感来自字体、间距、资产质量和有意设计的构图；发现签名不足时提出具体改法，不把“越少越好”当唯一模板。

## 图片提示词和资产来源

工作流计划保留需求映射、评审理由和实现分析；图片模型只接受面向产出的简要描述：

1. 图片要完成的真实任务及用户结果。
2. 决定正确性的核心区域、对象、可见文字或页面状态。
3. 已确认的视觉签名与少数具体可感知线索。
4. 影响品牌、用户信任、可访问性、状态、范围或合成的不可妥协项。
5. 视角、用途、背景要求和有意义的实际输出规格。

逐字检查每句是否改变内容、视觉方向、可信度、组件状态、合成行为或资产适用性。其他细节留给创作空间，不重复堆形容词、token、过度精确的影子/圆角或否定提示。图像资产要服务特定 UI/剧情、真实内容、符号和状态；图像生成不替代 Flutter 实际 Widget、屏幕文本的可访问语义或交互逻辑。

## 审核候选

按产品工件审阅模型图而不是孤立插画：首要任务是否清晰、功能和 MVP 合规、签名是否支持该页、图形是否一致并有适当表达预算、文字和控件尺寸、默认与错误状态、资产完整清单、可实现性、遮罩/透明边缘、flutter 页面重排表现。明确指出随机装饰图表、无意义玻璃卡片、填充头像和装饰性标签。高预算页或 Wow 要求的页面同时判断是否缺少可识别的产品视觉签名。

效果图只是用户目标之一，用户检查通过才是确认。代理检查生成素材的缺失/伪影、许可元数据、透明和来源；仅运行 Flutter Widget/视口构建不能声明目标图已经人工验收或运行 UI 与之匹配。截图由用户检查，除非用户明确要求代理自动验收。

## 项目资产

项目按需声明 `pubspec.yaml` 内资源资产，按页面/功能的归属整理 `assets/`；源素材与运行正式资源分开保存。Flutter 经约束实现关系与文本，而特定品牌插画、照片、Texture 或需要蒙版的独特形状可由登记的 bitmap 组件提供。说明载入密度、透明性、合成背景、运行时重裁/主题适配策略和发布许可。不能在不了解生成与许可时默认选用网络素材。
