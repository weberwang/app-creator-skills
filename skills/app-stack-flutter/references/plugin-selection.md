# Flutter 插件与技术方案选型

用于技术设计、新增依赖和插件替换。本规范是仓库约定；候选不是强制安装清单，不保证覆盖全部平台。能力档与包清单集中维护在 [dependency-profiles.md](../../flutter-project-init/references/dependency-profiles.md)。

## 选型顺序

1. 明确产品能力、数据敏感性、实际目标平台与离线要求；无需求的能力记录为“不采用”。
2. 先检查已有插件与项目原语；命中下方触发边界后，优先使用通过准入的成熟插件实现，不以“SDK 也能手写”为由重新实现通用能力。未命中边界的简单局部逻辑直接使用 SDK。
3. 按能力档比较候选和至少一个替代方案，结合维护、平台、性能、体积与生成成本选择；不要求先证明 SDK 无法实现。一项能力设一个权威实现，多个包协作时说明分工。
4. 核查发布者一手文档、许可证、维护状态、已知安全问题、SDK 约束、生成器与传递依赖，不仅按热度或评分决策。
5. 按 FVM SDK 与锁定版本核实目标平台、最低系统、原生工具链、权限与服务要求；记录来源、核查日期、版本和不确定性。仓库不固定全局版本。
6. 将决定写入 `docs/architecture/technical-design.md`；初始化时同步实际安装项到 `docs/architecture/flutter-init.md` 和项目本地 `flutter-dev`，后续修改同一记录。

任务已授权范围内的常规选型按此执行；只有影响产品范围、成本、账号或外部服务所有权的未决选择才提交用户决定。选型不构成真机、服务开通、外部写入、付费或发布授权。

## 插件优先的实现触发边界

本规范中的插件方案包括纯 Dart 包、代码生成器和原生平台插件。以下任一能力进入实际需求即触发对应选型；通过平台、维护、安全与成本准入后，代码实现应优先调用插件提供的能力。项目已有同职责方案时复用，不机械更换候选包，也不为一次触发安装整套能力档。

| 能力 | 触发条件 | 优先实现 | 可直接使用 SDK 的边界 |
|---|---|---|---|
| 状态与注入 | 跨组件共享业务状态、共享异步状态或可测试依赖注入 | 已有状态包；新方案优先 Riverpod，派生状态和加载/错误状态沿用其机制 | 单 Widget 的开关、选中值、临时输入与控制器，不建立全局状态容器 |
| 生命周期组合 | Widget 同时消费 Provider 并组合控制器、焦点或动画生命周期 | 评估 hooks 组合，复用已采用 hooks；不另写一套 hook 框架 | 单一控制器或简单 State 的创建与 dispose |
| 路由 | 深链/URL、声明式重定向或独立导航分支 | 已有路由包或 GoRouter，不手写通用 URL 匹配、重定向和路由栈同步器 | 少量页面的简单 push/pop |
| 网络 | 实际远端 HTTP API；另有拦截、取消、上传下载或进度需求时升级客户端 | 普通请求用 http，复杂传输评估 Dio，不从底层自行封装通用 HTTP 框架 | 无网络需求不装包；协议特有的业务规则仍由业务层实现 |
| 序列化与模型 | 持续维护的多字段/嵌套/多 DTO 序列化，或反复出现等值、复制和联合状态样板 | 分别采用 json_serializable、Freezed 等生成方案，不复制生成器职责 | 少量一次性简单映射、无复制/联合需求的简单模型；不按模型数量单独硬设门槛 |
| 本地持久化 | 需要跨启动保存偏好、敏感会话或结构化业务数据 | 按数据职责采用偏好、安全存储或数据库插件，不手写通用存储、SQL 访问或加密容器 | 进程内临时状态；简单文件格式的业务解析可自写，平台目录仍复用插件 |
| 原生设备能力 | 权限、媒体、链接、定位、通知等进入实际功能 | 优先对应成熟插件及其平台实现，不先写 MethodChannel 或原生重复实现 | SDK 已直接提供且满足需求的能力，例如基础触觉反馈 |
| 服务与商业 | 接入已选认证、推送、监控、商店支付服务 | 优先供应商官方或经准入的成熟 SDK，不自行重建通用协议客户端 | 产品特有的授权、权益、数据规则仍由业务层/可信服务拥有 |
| 通用 UI 能力 | 已确认复杂能力，如富文本编辑或复杂图表，超出基础 Widget 的直接组合 | 先检索成熟组件并核验设计、无障碍、平台和性能，再编写业务组合层 | 普通表单、列表、约束布局、基础动画与主题，直接组合 SDK Widget |

业务适配只补插件未覆盖的产品规则、接口映射与生命周期装配；不再维护与插件并行的状态机、路由器、缓存引擎或序列化框架。仅“自己会写”“减少一个依赖”不足以绕过已触发的插件方案。

## 自研例外

允许自研的条件：实际候选均不能满足必须的平台/API；许可证或数据安全要求不允许采用；有测量证据证明候选无法满足性能/体积预算；或维护状态、依赖冲突、服务成本使方案不可接受。先检查是否有其他合适插件；无需为证明不可用而安装所有候选。

例外记录到技术设计或当前任务：触发能力、已核查候选及来源、拒绝的具体证据、自研最小范围、维护 owner 与验证方式。只实现真实缺口，不顺带建设通用框架。缺少关键证据时保留选型未决，不默认自研；需要产品或费用决定时再交用户决策。

## 架构方案

- 按 feature 组织页面、状态和数据访问，共享能力在真实复用后提取。Widget 负责显示与交互，控制器或 ViewModel 负责页面状态，Repository/Service 隔离数据访问和 SDK。简单本地页面不创建空 Repository 或用例层。
- 默认采用最小 UI/数据分层；业务规则复杂或跨功能重复时再引入领域层，不强制每个 feature 有相同目录和接口数量。
- 局部状态优先 SDK；需要共享异步状态与可测试注入时，新方案优先评估 Riverpod。已有 Bloc、Provider 等满足目标时保留；替换需有明确收益和影响范围，不为统一风格迁移。
- 构造注入复用当前方案；采用 Riverpod 后用其提供依赖，不为同一依赖另增服务定位器。独立 DI 工具只在明确框架边界需要时评估。
- 本地优先、API 驱动、托管后端按数据权威与同步需求选择。离线同步须定义冲突规则、重试与一致性，数据库不默认提供同步；不默认建设后端、多后端切换或历史兼容层。
- 布局遵循 [PAGE 与布局](pages-and-layout.md)，国际化优先 Flutter 本地化与 `gen_l10n`；图片、缓存、动画和 UI 库按实际缺口选包，不引入第二套主题或尺寸系统。

## 平台插件准入

逐目标平台记录以下检查；包页面的平台标记不证明所需 API、后台行为或分发渠道均可用。

| 检查项 | 必须明确 |
|---|---|
| 运行环境 | 实际 Android/iOS/Web/Windows/macOS/Linux 目标、最低系统、插件和原生依赖版本 |
| 原生配置 | 适用的 manifest、构建工具、plist、entitlements、签名与桌面沙箱配置 |
| 权限与能力 | 请求时机、拒绝/永久拒绝/撤销、设备与服务不可用、恢复时状态刷新 |
| Web 差异 | 安全上下文、CORS、浏览器存储、用户手势限制；Web 路径不依赖 `dart:io` |
| 生命周期 | 初始化 owner、订阅、取消、迟到回调、后台/恢复、释放与重复调用 |
| 数据与服务 | 数据出端、同意策略、脱敏、密钥来源、配额/费用与外部 owner |
| 不支持平台 | 条件导入或能力接口隔离；按产品决定隐藏、禁用并解释或阻断交付，不以空成功掩盖缺失 |

第三方 SDK 遵循[独立管理与初始化规范](../../app-domain-toolkit/references/reference-architecture-sdk-initialization.md)。实现归拥有它的 feature，跨功能能力可放 `lib/core/integrations/<sdk>/`；装配入口不实现 SDK 状态机，插件类型不直接泄漏到整个 Widget 树。现有包不能满足已确认平台能力时才编写原生桥接；类型较多的通道可评估 Pigeon，并明确原生与 Dart 的错误和生命周期责任。

## 安全与交易边界

- `shared_preferences` 只存非敏感偏好，不存令牌、关键业务记录或交易凭据。安全存储须按平台核验；Web 存储不能承诺原生密钥库同等保护。
- 客户端只持有允许公开的服务配置和必要会话信息，不嵌入服务端私钥或管理密钥。`--dart-define`、资源文件和混淆都不能保密客户端秘密；服务端执行鉴权与资源授权。
- 网络层明确超时、取消、错误映射和重试责任，仅对可安全重试的操作重试。令牌刷新合并并发请求；退出/账号切换使旧请求失效；日志不输出令牌和敏感请求体。
- 支付按商品、商店和分发渠道核实；购买、恢复、重复回调、挂起、取消及退款后的权益分别处理。服务端或受信任服务核验交易并维护权益，客户端成功回调不直接成为永久授权依据；监听与交易完成按锁定 SDK 的官方要求执行。
- 崩溃、分析、推送分别按需启用，明确采集字段、同意前后行为与撤回处理。服务密钥、环境、配额和隐私配置也是方案输入，不以默认初始化替代决策。

## 交付与验证

技术设计至少记录：能力、采用/不采用、候选与替代、原因、锁定版本、一手来源及日期、目标平台、实现 owner、原生配置、数据与费用风险、命令和未覆盖项。插件变更同步更新权限、原生配置及失败路径。

按范围执行适用的 `fvm flutter analyze`、定向 unit/widget 测试与必要平台构建；只为实际生成输入运行生成器。边界测试用 fake/替身覆盖拒绝、失败、取消与释放，替身不证明原生实现可用。

原生插件接入还需按 `docs/architecture/verification-platforms.md` 记录已授权代表平台烟测。`pub get`、静态分析、mock 测试、单平台构建各自只证明对应范围。缺少主机工具链或凭据时记录阻塞与负责人，未运行平台标记未验证。

启动验证服务前先检查可复用进程。不得自动发起真机验收；截图默认交用户人工检查。真实支付、消息发送、外部控制台写入、服务开通和发布需各自明确授权，普通测试不隐含这些操作。
