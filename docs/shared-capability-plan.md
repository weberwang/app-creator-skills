# 公共能力抽取边界

## 当前决策

整合单位包括能力入口、完整规则、模块、模板和校验算法。原专业名称只标识原生资源包，公共能力才是可发现入口；同一份流程和实现维护一份，技术栈约束和工具留在原生规范。能力完整性以行为和依赖核对为准，不以目录数量为目标。

同职责只保留一个公共能力 SKILL，77 个专业来源的正文集中到五份技术栈手册，不保留旧根入口或 ADAPTER 占位。专业脚本、模板、校验器和原生参考继续按来源保留，通过能力 manifest 按当前栈和模式读取；共 30 个根入口，详见[入口迁移](capability-entry-migration.md)。

- 公共状态、授权、拷问、证据和恢复继续使用统一控制器。
- 非引擎图片处理、帧规划、通用视觉合同、字库、格式/预算校验等，经源代码与依赖核对后抽入 `app-domain-toolkit` 公共资源库。
- 专业流程中的重复步骤提为具体公共生产规范；各专业入口引用完整规范，并保留本栈资源导入、生命周期、坐标、版本及平台约束。
- 正文复查覆盖五栈全部专业入口：音频与数值使用 Unity 和三个 Web 游戏栈的完整统一规则；建模统一几何生产流程；素材、布局、QA、玩法、制作、架构、Spine 换皮与帧动画按实际共用范围抽取正文。仅部分技术栈适用的段落显式标记范围。
- Unity `.meta/GUID`、Editor 单写者和序列化，Creator UUID/AssetDB，Phaser Scale/Scene/Input，Three.js 世界投影和 renderer，Flutter Widget/SafeArea/文字缩放等继续独立维护。

## 实现边界

先抽取完全相同且不依赖技术栈的纯模块，明确检查导入与资源依赖闭包。只有配置差异的实现通过明确参数或适配器注入；不能只把引擎名字符串替换成通用名便认定等价。

专业脚本入口可保留为薄适配层，调用公共实现并维持具体输入、输出及 CLI 行为。公共模块不能反向依赖某个技术栈的私有实现；也不能借公共库恢复已退役的旧全局状态机。公共正文须保留完整规则和可执行接口，不能改成能力概述。

公共正文按资料名称调用原生配套参考，真实链接保留在专业入口的“本栈配套资料”，避免安装单栈时依赖另一栈目录。通用权限、状态和执行要求只维护在公共执行协议；专业正文保留混合原生限制，不逐段重述公共协议。

Schema 仅在数据结构和语义均相同的情况下共用；名称相近而坐标、运行证据或导入规则不同的合同不强行统一。实际项目的 `docs/Assets/assets` 等输入输出路径不作为源码目录搬迁路径改写。

## 追溯与验证

逐项清单继续覆盖五源的所有正式入口、模板和跟踪文件，并增加公共实现及技术适配的对应关系。每项共用必须列明源文件、判断依据、实际公共目标、保留接口、适配入口与行为回归；不能把删除副本记成删除能力。

`npm run audit:bodies` 扫描专业入口仍重复维护的完整段落，辅助发现正文回流。它只统一资料链接的表示，不把引擎名、API、坐标或参数差异当成等价；结果仍需结合语义及原生合同判断。

`npm run audit:references` 另外扫描实际分发的领域参考正文，不设置最短长度，保留有序编号、完整围栏、字段、API 和链接差异。控制器原生合同单列；候选仍需核对实际接口、来源格式和适用范围，不能仅凭出现其他引擎名称就判断内容错误。

按需参考与其能力入口从同一主题清单生成。来源元数据集中归档到 `migration/source-metadata`，不分发旧入口的 `agents`；真实技能和 Flutter 项目内嵌模板按实际来源保留，不补造来源中不存在的元数据。CommonJS 作用域只为实际使用该模块系统的脚本生成，不创建空专业资源根。

本轮公共能力抽取推荐 T3：先运行受影响公共模块和各栈适配回归，再执行全仓测试、完整源映射/依赖闭包验证、真实安装副本调用、技能/引用/语法检查和打包内容核对。普通测试自动执行，不启动引擎、开发服务、设备、实际生图或外部写入。显示效果仍由用户人工验收。
